# 系统改进报告 · 20 条

> 视角：**宏观流程生产力**（不是单点功能堆料）
> 日期：2026-10-27
> 说明：以下为**建议**，不代表已实施；每条含「做什么 / 为什么 / 怎么落地 / 成本 / 风险 / 收益」。

---

## 一、现状亮点（先说不好的反面）

1. **全链路已经打通**：演员 → 小说/改编 → 剧本/分镜 → 关键帧 → 视频 → 整集成片 → 后期精修 → 交付包。
2. **后期精修是完整闭环**：多轨、审片打点、版本树、审计、工程包（EDL/FCP7/OTIO 双向）、AI 辅助、电影感档、竖屏智能对焦。
3. **工程底子不差**：114 项自动化测试、10/50 进程压测、占位产物门禁、错误中文翻译、启动引擎管家。
4. **成本可控**：渲染、剪辑、包装全部本地 ffmpeg，零 API 费用；只有写故事/出图/出视频花钱。

---

## 二、宏观短板（按优先级）

### P0（不解决就无法稳定量产）

- 外部模型是**单点**：Seedream/Seedance 一被限额或限流，整条链路停摆，没有自动换供应商。
- 长任务**不能断点续跑**：2000 章大纲、整集渲染被打断后只能人工重跑。
- **没有"生产订单"**：每个模块各管各的，跨模块状态、责任、进度靠人记。
- **没有质量闸门**：占位画面/离群镜头/空字幕也能流到交付环节。

### P1（影响效率与一致性）

- 人物跨镜一致性弱：角色圣经刚做出来，还没接进关键帧生成。
- 成本台账有盲区：LLM token 不计费、方舟余额查不到。
- 队列串行且没有预计完成时间。
- 资产只增不减：交付包/图片/视频没有保留策略。

### P2（规模化与协作）

- 审片没有指派/通知/SLA。
- 多语言、配音、交付合规报告还不成体系。
- 多项目/多集没有宏观看板。

## 三、20 条改进清单

### A. 生产调度与稳定性（P0）

#### 1. 模型路由与自动降级
- **做什么**：一个能力对应多个供应商（出图：Seedream→Pollinations→本地；视频：Seedance→Kling→Runway→本地）。
- **为什么**：现在一个模型挂掉就全线停，人工换配置太慢。
- **怎么落地**：新增 `model-router` 配置（优先级/可用性/成本上限），任务失败按错误类型切换，记录"实际用了谁"。
- **成本**：3–5 人天。
- **风险**：不同厂商参数差异大，需要适配层。
- **收益**：链路可用性从"看运气"变成"可兜底"，停机时间预计降 60%+。

#### 2. 长任务断点续跑
- **做什么**：大纲/章节/关键帧/视频/渲染分段落 checkpoint，重启后从断点继续。
- **为什么**：2000 章任务被重启打断只能重跑，直接浪费数小时和费用。
- **怎么落地**：每批写 `job_steps`（已完成/失败/跳过），启动时扫描未完成任务并恢复。
- **成本**：5–8 人天。
- **风险**：幂等要严格，否则重复扣费。
- **收益**：长任务成功率大幅提升，重复成本接近 0。

#### 3. 原子渲染与失败清理
- **做什么**：先写 `.tmp`，成功后再改名；失败/中断自动删半成品。
- **为什么**：本次 9:16 中断留下不可播放的 7.6MB 残片。
- **怎么落地**：渲染输出统一走临时文件 + `rename`；启动时清理 `.tmp`。
- **成本**：1–2 人天。
- **风险**：磁盘空间瞬时占用略增。
- **收益**：不再出现"看起来有文件、其实播不了"。

#### 4. 生产级质量闸门
- **做什么**：占位画面、真人审核失败、黑帧、静音、人脸离群、字幕 CPS 超标 → 阻断进入下一环节。
- **为什么**：现在占位视频也能一路走到交付包。
- **怎么落地**：在"关键帧完成/视频完成/成片完成"三个节点跑质检，未过则标红并给出重跑建议。
- **成本**：3–5 人天。
- **风险**：阈值过严会误伤，需要按项目配置。
- **收益**：交付合格率显著提升，返工提前暴露。

#### 5. 统一"生产订单"对象
- **做什么**：一个订单 = 项目 → 集 → 镜 → 素材 → 成片，全链路状态机与看板。
- **为什么**：现在 6 个模块各管一段，跨模块状态靠人记。
- **怎么落地**：新增 `production_orders` 表 + 状态机；各模块完成后回写订单状态。
- **成本**：8–12 人天。
- **风险**：要改多个模块的边界，需先冻结接口。
- **收益**：宏观产能、瓶颈、阻塞原因一目了然，是"工厂化"的地基。

### B. 一致性与质量（P1）

#### 6. 角色圣经接入关键帧
- **做什么**：把 4 角度 + 3 表情的角色图自动作为参考条件喂给出图。
- **为什么**：现在角色圣经生成了，但关键帧还是单图参考，跨镜容易变脸。
- **怎么落地**：出图请求携带角色图 + seed 锁定 + 参考权重。
- **成本**：3–5 人天。
- **风险**：免费引擎不支持多图参考，需 Seedream。
- **收益**："像同一个人"这件事从碰运气变成可控。

#### 7. 跨镜一致性闭环
- **做什么**：QC 检出离群镜后，自动只重跑那几镜。
- **为什么**：现在 QC 只报告，人工去点重跑。
- **怎么落地**：QC 结果 → 生成重跑清单 → 自动提交任务 → 复检。
- **成本**：2–3 人天。
- **风险**：重跑仍可能离群，需要次数上限。
- **收益**：一致性返工从"全片重来"变成"只修几镜"。

#### 8. 项目级风格圣经
- **做什么**：一个项目统一 LUT、镜头语言、光线、色彩、画幅，自动注入提示词与渲染。
- **为什么**：现在风格靠每镜提示词，容易一镜一个样。
- **怎么落地**：项目配置里放风格模板，出图/出视频/渲染三处共用。
- **成本**：2–4 人天。
- **风险**：模板太强会压制创意。
- **收益**：整片观感统一，后期返工减少。

#### 9. 分镜覆盖率与连续性检查
- **做什么**：检查台词是否都有镜头、道具/场景是否前后矛盾、角色是否无故消失。
- **为什么**：现在这些靠人眼看分镜表。
- **怎么落地**：基于剧本+分镜做确定性检查 + LLM 抽检。
- **成本**：3–5 人天。
- **风险**：LLM 检查有误报。
- **收益**：开拍前发现剧本漏洞，省下后期返工。

#### 10. 镜头级版本谱系
- **做什么**：每个镜头记录"哪版、哪个模型、什么提示词、多少钱、为什么重跑"。
- **为什么**：现在版本多了以后说不清哪版最好、为什么重跑。
- **怎么落地**：`shot_renders` 增加模型/提示词/费用/重跑原因字段。
- **成本**：2–3 人天。
- **风险**：字段膨胀，需要归档策略。
- **收益**：可追溯、可复盘，避免重复试错。

### C. 成本与资源（P1）

#### 11. 成本台账与预算熔断
- **做什么**：LLM token、图片张数、视频秒数按项目/集/镜记账；超预算自动暂停。
- **为什么**：现在 token 不计费，方舟余额查不到，容易超支。
- **怎么落地**：统一 `usage` 记录 + 价格表 + 月度/项目双预算闸门。
- **成本**：3–5 人天。
- **风险**：厂商价格变动需维护。
- **收益**：从"花了才知道"变成"花之前可控"。

#### 12. 资产生命周期管理
- **做什么**：图片/视频/交付包去重、引用保护、保留策略、冷热分层。
- **为什么**：交付包已 400MB+，只增不减。
- **怎么落地**：按引用关系保护，按"最近 N 个 + 总容量上限"清理。
- **成本**：2–4 人天。
- **风险**：误删需备份与干跑。
- **收益**：磁盘可控，备份/打包更快。

#### 13. 队列 ETA 与优先级调度
- **做什么**：显示"前面还有多少、预计多久"；支持按集/镜头优先级插队。
- **为什么**：现在只显示进度百分比，不知道要等多久。
- **怎么落地**：按历史 p50 耗时估算 + 优先级队列。
- **成本**：3–5 人天。
- **风险**：估算不准会有落差。
- **收益**：排期可预期，减少干等。

#### 14. 供应商健康度看板
- **做什么**：余额、限额、限流、可用模型、最近错误，一屏看清。
- **为什么**：这次排查 Seedream/Seedance 限额花了不少时间。
- **怎么落地**：定时探测 + 缓存 + 红黄绿状态。
- **成本**：1–2 人天。
- **风险**：探测本身可能被限流。
- **收益**：故障 5 秒定位，不用猜。

### D. 协作与交付（P2）

#### 15. 审片协作
- **做什么**：批注可指派、有截止时间、有通知、可导出审片单。
- **为什么**：现在批注是"写给自己看"。
- **怎么落地**：批注加 `assignee/due_at`，站内提醒 + 导出 PDF。
- **成本**：3–5 人天。
- **风险**：单机无账号时只能署名，不能真正追责。
- **收益**：返修闭环，少扯皮。

#### 16. 多语言字幕/配音流水线
- **做什么**：字幕翻译 → CPS 适配 → TTS → 混音 → 多语版本。
- **为什么**：出海是明确需求，现在只有字幕文件。
- **怎么落地**：复用现有 TTS/字幕模块，加翻译与音色映射。
- **成本**：4–6 人天。
- **风险**：翻译质量与配音自然度。
- **收益**：一鱼多吃，摊薄单集成本。

#### 17. 专业后期回灌增强
- **做什么**：代理素材、媒体重链接、回灌差异、冲突解决。
- **为什么**：已支持 EDL/FCP7/OTIO，但外部改完后合并还靠人。
- **怎么落地**：manifest 记录素材哈希，回灌时自动 relink + diff。
- **成本**：3–5 人天。
- **风险**：外部 NLE 格式差异。
- **收益**：与专业后期协作更顺，减少来回导。

#### 18. 交付合规报告
- **做什么**：一页报告：质检、响度、黑帧、占位、水印、字幕 CPS、素材清单。
- **为什么**：交付时说不清"这版到底合不合规"。
- **怎么落地**：汇总现有 QC + 门禁结果，生成 PDF/Markdown。
- **成本**：2–3 人天。
- **风险**：报告口径要统一。
- **收益**：交付更专业，减少返工争议。

#### 19. 多项目/多集生产看板
- **做什么**：所有项目/集的进度、阻塞、成本、预计完成时间一屏看。
- **为什么**：现在一次只能盯一集。
- **怎么落地**：订单表 + 聚合查询 + 看板页。
- **成本**：3–5 人天。
- **风险**：数据量大时需要索引。
- **收益**：从"作坊"变"工厂"，宏观调度有依据。

#### 20. 自动复盘
- **做什么**：每集自动统计耗时、失败原因、成本排名、返工次数，给改进建议。
- **为什么**：现在复盘靠人回忆。
- **怎么落地**：任务/费用/质检数据定期聚合，生成周报。
- **成本**：3–5 人天。
- **风险**：指标定义要稳定。
- **收益**：持续改进有数据支撑，产能逐周提升。

## 四、契合度说明

以上 20 条全部落在本项目既有方向内：
- 不换技术栈（Node + SQLite + ffmpeg + 现有 Web 前端）；
- 不换业务主线（小说/剧本/分镜/成片/后期）；
- 不引入第二套并行的生产体系；
- 都是把现有模块"串得更顺、更稳、更省"。
