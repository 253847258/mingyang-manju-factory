# 模块地图（含混淆边界与"影子层"登记）

> 目的：让任何人接手时能立刻回答三个问题——**这个能力在哪个文件**、**改动该落在哪一层**、**哪一份是权威实现**。
> 背景与理由见 [开发评估与痛点清单.md](./开发评估与痛点清单.md) 的 **P0-2**。

---

## 一、硬规则：混淆层只读，开发面在明文层

现实约束：`src/` 下 **64 个核心文件是单行混淆代码**（合计约 3.4 MB），无法安全地就地修改。因此采用 **策略 A**：

1. **禁止编辑混淆文件的正文**。需要新能力时，一律新建明文模块（必要时做明文包装层）。
2. 需要"改混淆层行为"时，先在本文件第三节**登记**：为什么要包一层、边界在哪、**以哪一份为准**。
3. 新增 HTTP 接口走 `src/routes/`，不允许往混淆路由里加。
4. 任何提交如果改动了混淆文件的行数或体积，必须在评审里解释原因。
5. 回归门槛：`node scripts/simulate-all.js`（全模块离线，当前 83/0）；有了 `npm test` 后跑 `--fast`。

> 判断标准很简单：**.bak 与混淆文件只读，明文模块可写**。如果改动被迫落在混淆文件里，说明该能力还没有合法边界，先补明文模块。

## 三、影子层登记（哪一份是权威）

| 明文模块 | 为什么要包一层 | 与混淆层的关系 | 以谁为准 |
|---|---|---|---|
| `src/pngd.js` | 占位出图原本是 SVG，而 `video.js` 只接受栅格图，离线出片/拼图会断 | 自实现 PNG 编解码 + 占位渲染；`image.js#placeholderImage` 已改为调用它 | **pngd** |
| `src/image-sheets.js` | 人物/环境九宫格与 3×3 合成，混淆层没有 | 复用 `prompts.js#buildPrompt` 与 `data/styles.js` 风格包 | **image-sheets** |
| `src/canvas-consistency.js` | `consistency.js#scoreConsistency` 只吃镜头渲染记录，无法对任意图片打分 | 同算法思路（8×8 aHash + 中位离群）独立实现，优先用 sharp 解码 | **canvas-consistency** |
| `src/prompt-quality.js` | `prompts.js` 的 system role 与规则库够不到"专业级"，且剧本侧缺体检 | 自成体系，供 演员 / 资产 / 剧本镜头 三处调用 | **prompt-quality** |
| `src/describe.js` | `modules/actors.js#describeActor` 直接写库，无法"先预览再确认" | 复用 `prompts.js#optimizePrompt(mode='describe')` 取数据，落库仍走 `updateActor/updateAsset` | **describe** |
| `src/script-integrity.js` | `routes/script.js` 混淆，无法在其内加体检/修复 | 独立实现引用体检、提示词体检与专业化 | **script-integrity** |
| `src/script-review.js` | 审核状态机（draft→review→approved→locked）在混淆层没有 | 独立 schema + 流转 + gate | **script-review** |
| `src/script-budget.js` | 项目级预算闸门在混淆层没有 | 复用 `modules/render.js#estimateRender` 口径 | **script-budget** |
| `src/scripting-schema.js` | `shots.locked/speaker/emotion/voice_id` 与 `script_snapshots` 需要增量建列 | 增量 DDL，不改混淆层 schema | **scripting-schema** |
| `src/dub-bridge.js` | `dub.js` 只按 `speakerId` 取演员音色，读不到新加的 `shots.speaker/voice_id` | 数据层桥接：补 `speaker` 并把它同步进 `refs.characters` | **dub-bridge** |
| `src/production-bridge.js` | "改编项目 → 正式小说/剧本"的物化在混淆层没有 | 新增能力，写 `novels/novel_chapters/novel_outlines/scripts` | **production-bridge** |
| `src/novel-adapt.js` / `src/novel-ai.js` / `src/novel-outline-ai.js` / `src/novel-writing.js` / `src/novel-assets.js` | 小说改编工作台、故事框架自动填写、大纲逐节规划、2500-3500 字长章正文写作、人物/环境/物品 ID 索引是新能力 | 新增 schema 与 LLM 编排；不修改混淆核心 | **各自的明文模块** |
| `src/routes/scripting.js` / `routes/canvas-enhance.js` / `routes/novel-ai.js` / `routes/novel-adapt.js` | 混淆路由不能加新接口 | 新增 REST 面，服务端注册在 `server.js` | **新路由** |
| `src/restore-guard.js` | 恢复主库后自动续跑旧任务的防护 | 独立闸门，配合 `jobs:paused` | **restore-guard** |

> 变更规则：**任何"同一逻辑两份实现"都必须在上表登记**，并写清"以谁为准"。如果哪天把某条能力搬回单一实现，请同步更新本表。
