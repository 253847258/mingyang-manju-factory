# 模块3 使用说明 · 剧本 / 分镜工厂

> 目标：把**一部已写完的小说**（模块2 的 `novels` + `novel_chapters`）转换为**对应画风的漫剧 / 电影剧本与分镜提示词**，输出可直接喂给文生图 / 图生视频流水线。

---

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `src/data/scriptskills.js` | 内置「小说 → 漫剧/电影剧本转换技能文档」模板（4 套：漫剧/短视频/网剧/电影），含改编原则、桥段保留·合并·删除规则、分集结构模板、钩子与卡点节奏、台词规则、镜头语言对应表、审查红线 |
| `src/data/shotgrammar.js` | 镜头语言语法表：景别/机位/运镜/转场/时间/情绪的中文→英文词条、成本级画像、时长权重与配平算法 `allocateDurations`、画面词英译词典、中文字符清洗 `stripCJK` |
| `src/modules/script.js` | 业务层：CRUD、分集规划、单集剧本、分镜生成、提示词拼装、时长配平、导出 |
| `src/routes/script.js` | HTTP 路由（`registerScriptRoutes`，`server.js` 自动挂载） |

| `tests/test-script.js` | 自测脚本（68~74 项断言，含 2~3 次真实 LLM 小调用与前端 DOM shim 冒烟测试） |

依赖关系：**只读** `novels` / `novel_chapters` / `novel_outlines` / `actors`；**只写** `scripts` / `script_episodes` / `shots`。未修改任何主控文件与表结构。

## 2. 使用流程（前端）

打开「🎬 剧本工厂」模块：

1. **① 配置**
   - 关联小说（下拉来自 `/api/novels`；接口不可用时可直接填小说 ID）
   - 剧本形态（漫剧 / 电影 / 网剧 / 短视频）——切换形态会自动带出推荐的单集时长与集数
   - 画风 `style_id`（10 种画风之一，决定提示词的风格头/尾）
   - 单集时长：预设 30s / 60s / 120s / 180s / 40min / 90min + 自定义秒数（≥15）
   - 每季集数（默认 100，1~500）与季数（1~50）
   - **转换技能文档**：可直接用内置模板，也可「下载模板 → 按项目改写 → 上传」；上传的文档**优先于**内置模板，生成时整篇注入 system prompt
2. **② 分集规划**：填「额外要求」（可选）→ 生成分集规划。每集得到 标题 / logline / 开场钩子 / 悬念收尾 / 覆盖的原文章节范围 / 场次概要
3. **逐集生成剧本正文**（场次 + 台词 + 动作）→ **生成分镜**（场 → 镜，自动配平时长）
4. **③ 分镜表**：表格视图 / 卡片视图切换、按集筛选、总时长与超时高亮、一键复制提示词、单镜编辑/新增/删除、重新配平时长、导出 JSON / CSV / Markdown / Fountain

## 2.1 本轮新增：生产闭环与质量体检

### 改编项目 → 正式小说/剧本/分镜

- `POST /api/adapt/projects/:id/to-production`：把「小说改编」项目物化为正式 `novels` + `novel_chapters` + `novel_outlines` + `scripts` + `script_episodes`。
- 角色自动创建/复用演员矩阵 `C-xxxx`；改编 beats 会转成剧本工厂的 `scenes.scenes` 结构。
- 带 `{sync:true}` 时会直接调用剧本工厂的分镜链路；重复调用幂等，不会重复建小说或剧本。
- 前端入口：小说改编页「🎬 生成可拍分镜」。

### 引用体检与修复

- `GET /api/scripts/:id/ref-integrity`：检查失效角色 ID、plan/canvas/shot 不一致、缺失地点、action 提到但 refs 没有的角色。
- `POST /api/scripts/:id/ref-repair`：按角色名把旧 ID 重映射到当前演员表；只改 `refs/plan/options`，不改 action/dialogue 原文；锁定镜头跳过。
- 前端入口：分镜页「引用体检」。

### 提示词体检与修复

- `GET /api/scripts/:id/prompt-audit?episode=`：检查重复 token、时间矛盾、无关道具、空角色锚点、超长提示词、缺负面词。
- `POST /api/scripts/:id/prompt-repair`：去重、按 `time_of_day` 统一时间、按 action/dialogue 过滤无关道具；锁定镜头跳过。
- 前端入口：分镜页「提示词体检」。

### 版本快照、锁定与声音元数据

- `GET/POST /api/scripts/:id/snapshots`：按集保存分集剧本和分镜快照，默认每集/每类型保留最近 20 个版本。
- `POST /api/scripts/:id/snapshots/:snapshotId/restore`：回滚快照；`keepLocked:true` 时保留当前锁定镜头。
- `PUT /api/scripts/:id/shots/:shotId/lock`：锁定/解锁镜头；重生成、引用修复、提示词修复和配平都会跳过锁定镜头。
- `PUT /api/scripts/:id/shots/:shotId/performance`：保存 `speaker / emotion / voice_id`，供后续 TTS 与唇形同步使用。
- 前端入口：分镜页「保存快照 / 快照/回滚」和单镜「锁定/解锁」；单镜编辑器新增说话人、表演情绪、音色 ID。

### 成本预估与扩展导出

- `GET /api/scripts/:id/estimate?episode=`：预估镜头、待出关键帧、M/H 视频数、总时长、LLM 调用次数和视频费用。
- `GET /api/scripts/:id/export-ext?format=fdx`：导出 Final Draft XML。
- `GET /api/scripts/:id/export-ext?format=html`：导出打印级 HTML，浏览器「打印 → 另存为 PDF」。

### 离线 / 降级开关（任一接口通用）

- `provider: 'mock'` 或 `offline: true` 或 `useLlm: false` → **完全不调用 LLM**，走离线规则分支（分集规划按字数占比切集、剧本按章节正文切场次与 beat、分镜按场次覆盖生成），流程与时长配平完全一致。
- `sync: true` → 同步返回结果；否则入队为后台任务（`/api/jobs/:id` 或前端 `ctx.watchJob` 轮询）。
- LLM 调用失败**不会中断流程**：自动降级为离线规则并在 `warnings` 里给出中文原因（服务不会被打崩）。

## 4. 提示词拼装规则

`prompt_pos` 的拼装顺序（`buildShotPrompt` → `src/prompts.js` 的 `buildPrompt`）：

```
风格头（style.head）
+ 角色锚点（actors 表按 ID 取 subjectFragment，原样保留）
+ 景别 / 机位 / 运镜 英文（shotgrammar 词表）
+ 画面英文描述（LLM 给的 action_en；缺失时用动作关键词 + 画面词典生成）
+ 环境与光线（地点英译 + 时间英文）
+ 情绪英文
+ BASE_QUALITY
+ 风格尾（style.tail）
```

`prompt_neg` = 风格负面 + `BASE_NEGATIVE` + 本镜专属负面（H 级加 `flickering, morphing face, frame jitter` 等；多人同框加 `merged faces, identity swap`）。

- 角色锚点来自 `actors` 表：`refs.characters` 里的 `C-xxxx` → `subjectFragment(actor)`；表里没有的角色退化为 `character named X`。
- `refs` 结构：`{characters:["C-0001"], location:"L-0001", style:"cn-guofeng"}`。
- **提示词保证纯英文**：`stripCJK()` 会剔除模型误写进英文字段的中文与中文标点。若需要中英混排（部分中文 T2V 模型），把 `scripts.options.bilingual_prompt` 设为 `true`，中文动作会以 `[...]` 附在末尾。

## 5. 时长配平与校验

- 目标时长 = `scripts.episode_seconds`（单集），每集镜头时长合计 0.5s 步长配平到目标值。
- 权重：成本级（L 1.0 / M 1.35 / H 1.7）× 景别系数 × 运镜系数 × 台词长度系数。
- 单镜上限按形态区分：漫剧/短视频 8s、网剧 14s、电影 20s；下限 1s。
- 超过 2% 容差时，接口在 `warnings` 里给出**中文告警但不报错**，界面把该集标红并可一键「重新配平时长」。
- `POST /rebalance` 可按集或全量重新分配。

## 6. 离线规则分支（无 Key / mock / LLM 失败时）

- **规划**：按章节字数占比把全书切成 `每季集数 × 季数` 集，逐集取章节标题、摘要、章末钩子生成 标题/logline/钩子/悬念收尾。
- **剧本正文**：把覆盖章节的正文切句，按 3~8 句一组切场景，识别台词（引号 / “说道”）与动作 beat，自动判定地点（匹配地点档案）、时间（夜晚/黄昏/清晨…）。
- **分镜**：每场先给定场镜头，再按 beat 生成镜头（对白→近中景+反应镜，动作→中景/全景，按关键词判定成本级），覆盖不足时用「反打 + 插入镜 + 空镜」补齐到目标镜头数，最后统一配平时长。

## 8. 已知限制

1. **LLM 调用预算**：规划每批（默认 8 集）1 次调用、单集剧本 1 次、分镜每集最多 4 次（默认每次约 18 镜）。默认上限：规划 12 次、单集分镜 4 次；超出部分自动走离线规则并在 `warnings` 提示。100 集全量 LLM 生成会非常耗时与耗 token，建议按需逐集生成。
2. **每集镜头上限**：默认 200（`maxShots` 可调）。电影长片（90 分钟）理想镜头数 900+，超过上限时单镜时长会被拉长并给出中文告警，请提高 `maxShots`。
3. **英文提示词质量**：LLM 分支的 `action_en` 由模型给出，质量取决于模型；离线分支的英文画面描述来自关键词词典（`shotgrammar.ZH_EN_LEXICON`），偏通用。中文动作原文始终保留在 `shots.action` 字段。
4. **地点档案**：优先读 `novel_outlines.payload.locations` 与章节 `locations` 字段；缺失时地点 ID 直接沿用文本，英译会退化为词典匹配。
5. **前端**：模块视图为纯字符串渲染 + 事件委托；镜头表已加**分页**（25/50/100/200 每页，默认 50），超大项目建议按集筛查。更细的虚拟滚动仍待做。
6. **导出为内存拼装**：超大项目（如 5 集 300 镜的 JSON 约 300KB）一次性写入响应，未做流式输出；FDX/HTML/OTIO/EDL/FCPXML 同样为一次性拼装。

## 9. 剧本工厂增强（P0–P2，已落地）

> 这一节对应用户要求的“按计划改进”。核心不在混淆的 `src/routes/script.js`、`src/modules/script.js` 内改，
> 而是新增**明文包装模块**，只做加法，保持原有 JSON/CSV/MD/Fountain 接口与字段不变。

### 9.1 数据与版本

- 新增字段：`shots.locked` / `shots.speaker` / `shots.emotion` / `shots.voice_id`；`script_snapshots` 表。
- 版本快照：`POST /api/scripts/:id/snapshots`（保存）、`GET /snapshots`（列表）、`POST /snapshots/:id/restore`（回滚，默认保留锁定镜头）。
- 参数化重生成前会自动写一份快照（`createdBy=system`），每集每类型保留最近 20 份。

### 9.2 引用与提示词体检 / 修复

- `GET /api/scripts/:id/ref-integrity`：失效角色 ID、plan/canvas 引用、动作里提到但 refs 缺失的角色。
- `POST /api/scripts/:id/ref-repair`：按角色名把旧 ID 重映射到当前演员表；只改 `refs/plan/options`，不改 action/dialogue 原文；锁定镜头跳过。
- `GET /api/scripts/:id/prompt-audit`：重复 token、时间矛盾（以镜头 `time_of_day` 为准）、无关道具、空角色引用、缺角色锚点、超长、缺负面词。
- `POST /api/scripts/:id/prompt-repair`：去重、按镜头时间统一时间词、按动作/台词过滤道具；锁定镜头跳过。
- **空镜判定**：无台词、无出场角色、提示词也没有人物锚点的镜头，视为空镜/环境镜，不再误报“角色引用为空”；
  但如果提示词写了 `1person/1girl…` 却没绑定角色，仍会如实告警。

### 9.3 审核流程（draft → review → approved → locked）

- 新增字段：`script_episodes` 与 `shots` 的 `review_status / reviewer / reviewed_at / review_note`。
- 接口：
  - `GET  /api/scripts/:id/review` 审核汇总（按集统计各状态镜头数）。
  - `GET  /api/scripts/:id/review-gate?episode=` 制作台前置校验（**只告警不硬阻断**）。
  - `POST /api/scripts/:id/episodes/:code/review` 单集流转。
  - `POST /api/scripts/:id/episodes/:code/review-batch` 整集批量流转镜头（跳过锁定镜头）。
  - `POST /api/scripts/:id/shots/:shotId/review` 单镜流转。
- 前端：分集表新增「审核」列与「审核」按钮；分镜表/卡片每镜有审核状态与「审核」按钮；「审核本集」弹窗可填审核人、修改意见，一键通过/退回/定稿，并可批量处理本集镜头。
- 制作台：关键帧 / 视频 / 整季流水线提交前会调 `review-gate`，未通过的集弹中文告警，**允许人工确认后继续**，不修改审核状态。

### 9.4 项目预算

- `scripts.options.budget = { enabled, limit, hard, currency, note }`，单项目独立于全局月度预算。
- 接口：`GET/POST /api/scripts/:id/budget`、`POST /api/scripts/:id/budget/check`（按 `estimateRender` 口径试算）。
- 规则：超上限时 `hard=true` 直接拒绝并给中文原因；`hard=false` 需人工确认（`needConfirm`）。
- 前端：「项目预算」按钮可设置上限/硬上限；「成本预估」弹窗会附带预算结论。

### 9.5 配音表演桥（接入 Module 4）

- 新增明文模块 `src/dub-bridge.js`：把 `shots.speaker / emotion / voice_id` 接到 Module 4 配音链路。
- `POST /api/scripts/:id/performance/sync`：按台词前缀 / 明确说话人 / 动作里的角色名推断说话人，补全 `shots.speaker`，
  并把该角色 `C-xxxx` 同步进 `refs.characters`，使 Module 4 的 `clipsForEpisode` 能稳定解析说话人 → 选对演员音色。
- 情绪 → 语速换算：平静 1.0、紧张 1.06、愤怒 1.08、悲伤 0.94…（`src/dub-bridge.js` 的 `EMOTION_SPEED`）。
