# 小说改编工作台 · 使用说明

**入口**：顶部导航「📥 小说改编」

**目标**：上传一本小说，自动产出剧本草案、角色、场景、道具、文生图提示词和资产清单。

---

## 一、怎么用

1. 打开 http://127.0.0.1:8788/#/adapt
2. 点「上传小说（txt / md / json）」
3. 选一个小说文件
4. 系统自动完成：

```text
上传 → 分章 → 抽角色 → 抽场景 → 抽道具
→ 生成分集剧本 → 生成文生图提示词 → 生成资产清单
```

5. 在右侧标签页查看：

| 标签 | 内容 |
|---|---|
| 总览 | 字数、章节、集数、beat、角色/场景/道具数量 |
| 剧本 | 每集标题、钩子、beat、景别、场景、时间、人物、动作、台词、时长 |
| 角色 | 角色名、主角/反派/配角、原文摘要、定妆提示词 |
| 场景 | 场景名、出现次数、原文摘要、环境概念图提示词 |
| 道具 | 道具名、出现次数、原文摘要、物品特写提示词 |
| 提示词 | 所有角色/场景/道具的正向和负向提示词，可一键复制 |
| 资产清单 | 建议 ID、目标模块、优先级、用途、建议文件名 |

6. 导出：

- 导出 JSON：完整数据，给程序用。
- 导出 MD：人看的资产包文档。
- 导出 CSV：资产清单表格，给表格和项目管理用。

7. 一键导入：

点「一键导入演员/画布/剧本」后：

- 角色 → 明星演员矩阵（同名角色自动跳过）。
- 场景 → 新建画布里的场景节点。
- 道具 → 新建画布里的物品节点。
- 剧本 → 剧本工厂里的草稿剧本 + 分集。

导入采用“能复用就复用、不重复建”的策略，适合先出清单、再进生产。

---

## 二、产出的资产 ID 规则

| 类型 | 建议 ID | 目标模块 |
|---|---|---|
| 角色 | `C-ADP-001` | 明星演员矩阵 |
| 场景 | `L-ADP-001` | 画布场景节点 |
| 道具 | `P-ADP-001` | 画布物品节点 |

优先级：

- `S`：主角、核心场景、关键道具
- `A`：重要配角、常用场景、剧情道具
- `B`：一般角色、普通场景、普通道具

---

## 三、接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/adapt/meta` | 支持格式和产出类型 |
| GET | `/api/adapt/projects` | 项目列表 |
| POST | `/api/adapt/projects` | 新建项目：`{title, sourceName, sourcePath}` 或 `{title, text}` |
| GET | `/api/adapt/projects/:id` | 项目详情 |
| POST | `/api/adapt/projects/:id/run` | 执行改编 |
| GET | `/api/adapt/projects/:id/export?format=json\|md\|csv` | 导出 |
| DELETE | `/api/adapt/projects/:id` | 删除项目 |

上传文件复用系统已有的 `/api/upload`，返回的 `path` 传给 `sourcePath`。

---

## 四、数据表

| 表 | 用途 |
|---|---|
| `adapt_projects` | 项目主表 |
| `adapt_sources` | 原文和章节 |
| `adapt_items` | 角色/场景/道具/提示词/资产/剧本 |

不会修改原有的 `novels`、`scripts`、`shots` 表。

---

## 五、当前版本能做什么

- 支持 txt / md / json。
- 自动分章。
- 规则引擎抽角色、场景、道具。
- 角色别名自动合并（短名/长名归并）。
- 生成分集剧本草案和 beat。
- 生成角色、场景、道具的文生图提示词。
- 生成带建议 ID 的资产清单。
- 一键导入演员矩阵、画布节点和剧本工厂。
- JSON / MD / CSV 导出。
- `AI 深度提炼`：LLM 可用时走模型抽取；mock 或失败时自动回退离线规则。

## 六、当前版本还不能做什么

- LLM 深度提炼目前是“能接就接、接不上回退”，还没有针对复杂人物关系和伏笔做专门优化。
- 别名合并是规则级，极端的称呼变化仍需要人工确认。
- 还不能自动生成正式的分镜表和视频提示词。

这些会在下一阶段补上。
