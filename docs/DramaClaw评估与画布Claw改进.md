## 三、给画布智能体 Claw 的改进清单（按性价比排序）

> 这些是**从 DramaClaw 的定位反推**出来的、我们确实还缺的能力；每条都写成可落地的形态。

1. **成片成本口径（最高优先）**：DramaClaw 用「每分钟成片多少钱」讲价值，我们的报表只有「调用次数 + 金额」。改法：`productionStatus`/一页纸报告里增加 `costPerFinishedMinute = 实际/预估金额 ÷ 成片总分钟数`，并在制片控制台与 `GET /api/capabilities` 里作为一等指标展示。**这是把「贵不贵」变成可直接比较的数字**，也必须能被 `tour-chain.js` 体检。
2. **画布 Claw 指令的「成本预估」意图**：现在支持 状态/计划/铺开/续写；再加一条 `「这条要花多少钱」` → 复用 `estimateRender` + `estimateProduction`，直接回答金额区间与成本级（未配单价时明确说明）。
3. **画布 Claw 指令的「批量重排/整理」意图**：例如「把这一集的关键帧按镜头序排好」「把成片节点移到最右」——属于纯布局（零副作用），可直接执行并记入撤销栈。
4. **模板化复用（对应它的「人人能拍」）**：把一次成功的制片固化为**模板**（`skills/*.skill.json` + 画布结构快照），下次「按模板开新剧」只换题材/剧名。我们已有技能文件与 `restoreCanvas`，缺的是「把当前画布导出为技能/模板」的一键入口。
5. **多语言出海作为链路内置环节**：我们有 `src/i18n.js` 与出海物料，但它是模块 4 的独立按钮；建议在制片技能里加一个可选阶段 `publish`（生成多语言字幕 + 封面 + 元数据），让「出海」成为流水线的一站而不是外挂。
6. **画布内 Agent 的「解释我在做什么」**：每次 Claw 指令执行后，把「读到的现状 → 判断的意图 → 采取的（无）副作用 → 下一步建议」写成结构化三条，落进画布的便签节点或执行日志，方便人类复核（对应 Claw 报告里「结构化留痕」）。

## 四、结论

- DramaClaw 与我们的**目标客户与终点一致**（都是 AI 漫剧/短剧的端到端生产），差异在于**表达方式**：它用「每分钟 20 元」讲成本与易用，我们用「人类审核闸门 + 可执行节点图」讲可控与可审计。
- 因此对我们最有价值的借鉴不是架构（我们的画布 DAG + 闸门更严），而是**成本叙事与模板复用**：把「每分钟成片成本」做成指标、把一次成功制片固化成模板。
- 待其文档精读后再补一版**逐文件对照**（节点模型、MCP 工具粒度、成本口径、审核机制）；本文件先给出可立即施工的 6 条改进。
