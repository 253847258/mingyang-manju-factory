# ai-video-factory 画布改造方案：卡片画布 → 可执行节点图

> 目标：把模块 1 的画布升级为 LibTV 式的**可执行节点图**（强类型端口 + 数据流边 + DAG 执行 + Agent 可操作）
> 约束：保持零外部依赖（Node ≥ 22 + 原生 ES 模块前端）、现有数据不丢、`verify-all.sh` 全绿
>
> **v2 修订说明**：本方案初版基于 2026-09-26 之前的一次代码快照，当时误判"画布只有演员卡片一种节点"。
> 复测发现画布**已经演进为多类型节点系统**（便签节点 + 分组框 + 撤销栈），且项目在调研期间**正被并行修改**
> （`web/views/actors.js` 由 1999 行增至 2752 行，`SCHEMA_VERSION` 由 6 升至 7）。v2 已按实测重写，
> 并下调了工作量评估。**所有结论均标注代码位置，复核时间 2026-09-26 09:10。**

### 1.2 真正的剩余缺口：边没有端口与顺序语义

`src/db.js`（当前版本）中 `canvas_links` **与初版完全一致，未动**：

```sql
CREATE TABLE IF NOT EXISTS canvas_links (
  id TEXT PRIMARY KEY,
  canvas_id TEXT NOT NULL,
  from_actor TEXT NOT NULL,     -- ← 仍以 actor 为端点
  to_actor   TEXT NOT NULL,
  label TEXT, color TEXT,       -- ← 仅语义标签（对手戏/亲属/敌对）
  created_at TEXT
);
```

全仓检索 `port` / `slot` / `canvas_edges` / `edge_order` 关键词：**除 `config.js` 里的服务端口外，无任何命中**——端口、槽位、数据流边**均未实现**。

这是唯一的形态级缺口，也是与 LibTV 差距的实质所在：

| 维度 | 现状 | LibTV |
|------|------|-------|
| 边端点 | `from_actor` / `to_actor`（人） | `from_node` / `to_node`（任意节点） |
| 端口 | 无 | `text` / `image` / `clip` 等强类型端口 |
| **顺序语义** | **无** | **槽位序号**（`{{Image N}}` ↔ CLI `--left`），多参考图/首尾帧靠它 |
| 连线绘制 | 中心→中心贝塞尔（`web/views/actors.js:1309`） | 端口锚点 |
| 连线校验 | 只校验"不能连自己"（`src/modules/actors.js:859`） | 按端口类型校验 |

### 1.3 一个被误判的约束

初版称 `actor_id NOT NULL`（`src/db.js:125-128`）是"致命约束 #1"。**实测该约束已被空串哨兵绕过**，不再阻塞——
真正需要提防的是它的副作用：`src/modules/actors.js:89` 的 `DELETE FROM canvas_nodes WHERE actor_id = ?` 在删演员时会连带删其卡位。
目前无伤（演员卡位本无独立价值），但**一旦新节点类型携带生成结果，这条语句就会变成"删演员＝删作品"**。方案里保留了对策。

## 二、决策：**不引入 React Flow / Vue Flow / X6**（结论不变）

1. **与卖点冲突**：项目自述"零外部依赖"，前端原生 ES 模块无构建；引入 React Flow ＝ 引入 React + 打包链。
2. **性能会退化**：现为 Canvas2D 命令式 + LOD 三档 + 视口裁剪，审计已验证"LOD 简时完全不解码图片"。DOM 节点库在 200 节点图片墙下吃不住。
3. **测试资产全废**：81 项审计的调试钩子（`zoom/panX/lod/items/drawn/screenItems/kind`）全绑当前实现。

**正确做法**：沿用项目自己的多类型节点范式，只补"端口 + 槽位 + 数据流边 + 执行引擎"。

## 三、新增节点类型的标准配方（照便签抄即可）

便签节点已经把"如何加一种节点类型"趟平了。新增任意类型（`image` / `video` / `text` / `shot` / `timeline`）只需 6 步：

| 步骤 | 改动 | 参照便签的实现 |
|------|------|--------------|
| 1 | 后端 CRUD：`createXxx` / `updateXxx`，写 `kind='xxx'` + `actor_id=''` | `modules/actors.js:428-447` |
| 2 | 路由：`POST /api/canvas/xxx`、`PUT /api/canvas/xxx/:id` | `routes/actors.js:262-271` |
| 3 | `getCanvas` 的载荷解析（若需从 `note` 列解析 JSON，或新增列） | `modules/actors.js:263-269` `parseNote` |
| 4 | 前端装载进专用数组 + `computeLayout` 里 push item（带 `kind` + 假 actor 垫片） | `actors.js:262`（`S.noteNodes`）、`401-407` |
| 5 | 绘制函数 `drawXxxNode(g, it)`（**必须实现 LOD 0/1/2 三档**） | `actors.js:783-822` `drawNoteNode` |
| 6 | `draw()` 分发分支 + 命中/拖动/缩放/撤销纳入 `snapshot`/`applySnapshot` | `actors.js:501`、`1745-1781` |

**统一节点类型描述表**（建议抽成 `web/views/nodeKinds.js`，替代现有 `else` 硬分支）：

```js
export const NODE_KINDS = {
  actor: { label:'演员', inPorts:[],                          outPorts:['image','ref'] },
  note:  { label:'便签', inPorts:[],                          outPorts:[] },
  text:  { label:'文本', inPorts:['in'],                      outPorts:['text'] },
  image: { label:'图片', inPorts:['ref1','ref2','ref3'],      outPorts:['image'] },
  video: { label:'视频', inPorts:['first','last','ref1','ref2'], outPorts:['clip'] },  // ★ 直连你已有的首尾帧能力
  shot:  { label:'分镜', inPorts:['clip'],                    outPorts:['timeline'] },
  output:{ label:'输出', inPorts:['in'],                      outPorts:[] },
};
```

端口类型校验表（连线时拒绝非法连接，给中文 toast）：

| 输出端口 | 可接输入端口 |
|---------|-------------|
| `image` | `ref1..refN` / `first` / `last` |
| `text` | `in` |
| `clip` | `in` / `timeline` |
