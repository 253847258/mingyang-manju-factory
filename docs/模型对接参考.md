## 一、LLM（文本生成）

### 1.1 DeepSeek（本项目默认，已核证到官方文档正文）

- **官方文档**
  - 首次调用 API：<https://api-docs.deepseek.com/zh-cn/index.html>
  - 模型 & 价格：<https://api-docs.deepseek.com/zh-cn/quick_start/pricing>
  - 创建对话补全：<https://api-docs.deepseek.com/zh-cn/api/create-chat-completion>
  - 错误码：<https://api-docs.deepseek.com/zh-cn/quick_start/error_codes>
  - 图像理解（多模态，`deepseek-flash`）：<https://api-docs.deepseek.com/zh-cn/guides/vision/>
- **鉴权**：`Authorization: Bearer <DEEPSEEK_API_KEY>`；Key 在 DeepSeek 开放平台控制台创建（文档「首次调用 API → 申请一个 API key」）。本项目还会自动回退读 `~/.dsh/.credentials.yaml` 里的 `DEEPSEEK_API_KEY`。
- **base_url 与端点**：OpenAI 格式 `https://api.deepseek.com`（官方示例直接 POST `https://api.deepseek.com/chat/completions`；`https://api.deepseek.com/v1` 亦可）；Anthropic 格式 `https://api.deepseek.com/anthropic`。**同步**为主（`stream: true` 则 SSE）。
- **模型 ID（官方文档当前列出的）**：`deepseek-flash`（对应 DeepSeek-V4.1-Flash）；`deepseek-v4-pro`（DeepSeek-V4-Pro-0813）。官方注明旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用但已下线，请求由最新 Flash 承接并按 Flash 计费。**本项目默认的 `deepseek-chat` 未出现在当前官方文档的模型列表中** —— 是否仍可调用请以官方控制台为准，建议直接改成 `deepseek-flash`。
- **关键能力（官方页面写明）**：上下文 1M、最大输出 384K、支持 JSON Output / Tool Calls / Responses API / Anthropic API；`deepseek-flash` 支持**图像理解**，`deepseek-v4-pro` 不支持；并发限制 2500（Flash）/ 500（Pro）。
- **请求示例**

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${DEEPSEEK_API_KEY}" \
  -d '{
    "model": "deepseek-flash",
    "messages": [
      {"role": "system", "content": "你是短视频编剧。"},
      {"role": "user", "content": "给我一集 3 分钟的都市悬疑大纲"}
    ],
    "response_format": {"type": "json_object"},
    "thinking": {"type": "enabled"},
    "reasoning_effort": "high",
    "stream": false
  }'
```

- **响应体**：正文在 `choices[0].message.content`（官方示例 `print(response.choices[0].message.content)`），用量在 `usage`。
- **常用参数与取值**：`thinking.type` ∈ `enabled|disabled`（默认 enabled）；`reasoning_effort` ∈ `none|low|high|max`（默认 high）；`max_tokens` 1~384K；`response_format.type` ∈ `text|json_object`；`stop` 最多 16 个字符串；`stream_options.include_usage` 必须与 `stream: true` 同用。
- **计费（官方价格表，人民币 / 百万 token）**：`deepseek-flash` 输入（缓存命中）空闲 0.02 元、高峰 0.04 元；输入（未命中）空闲 1 元、高峰 2 元；输出空闲 4 元、高峰 8 元。`deepseek-v4-pro` 对应为 0.15/0.30、4.5/9.0、13.5/27.0。**空闲时段**＝非「周一至周五 9:00-12:00、14:00-18:00（不含法定节假日）」。
- **错误码（官方列表）**：400 格式错误、401 认证失败、402 余额不足、422 参数错误、429 速率上限、500 服务器故障、503 服务器繁忙 —— 其中 429/500/503 属于本项目 `withRetry` 会自动退避重试的类别。
- **坑与限制**：JSON 模式必须同时在提示词里要求输出 JSON，否则模型可能一直输出空白直到 token 用尽；`finish_reason: "length"` 代表被截断；图片仅允许出现在 user 消息中（system/assistant 带图返回 400）。
- **本项目 llm 配置建议**

```json
{ "provider": "deepseek", "baseUrl": "https://api.deepseek.com", "model": "deepseek-flash",
  "temperature": 0.8, "maxTokens": 8000, "timeoutMs": 600000, "concurrency": 1 }
```

  端点拼接提醒：官方文档给出的 base_url 是 `https://api.deepseek.com`，官方 curl 示例的完整路径是 `https://api.deepseek.com/chat/completions`（**没有 `/v1` 段**）。而本项目 `src/llm.js` 在 baseUrl 不以 `/v\d+` 或 `/chat/completions` 结尾时，会**自动补成 `https://api.deepseek.com/v1/chat/completions`**。两种路径 DeepSeek 历史上都可用，但**只有不带 `/v1` 的写法被当前官方文档收录**；若你实测 `/v1` 路径报 404，请把 `llm.baseUrl` 直接填成 `https://api.deepseek.com/chat/completions`（源码检测到该结尾会原样使用）。

### 1.2 ⚠️ 接非 DeepSeek 厂商前必读：`provider` 只能填白名单里的值

`src/model-registry.js` 的 `PROVIDERS` 白名单里，**能承担 LLM 角色的只有 `deepseek`、`openai`、`mock`**（`generic-http` 只支持 image/video/tts）。所以下面每一家的配置片段里，`provider` 我都写 **`"openai"`**（把它当成「OpenAI 兼容端点」的通称），真正的厂商区别体现在 `baseUrl` + `model`。
- 若你写成 `"provider": "volcengine-ark"` 这类自造 id，功能上 `src/llm.js` 仍会照常调用（它只判断 `provider === 'mock'`），但 `GET /api/settings/models` 会报「未知提供方」、设置页下拉也显示不出来 —— **不建议**。
- 设置页的「提供方 provider」下拉只有三项：`deepseek` / `openai` / `mock`；接第三方就选 `openai`，然后把 `base_url` 改成下表的值。

下面所有 base_url 都已按 `src/llm.js` 的三条拼接规则核对过最终 URL，**结论：与官方文档端点一致，无冲突**（唯一需要「写全路径」的是智谱与 DeepSeek）。

### 1.3 OpenAI（Chat Completions / Responses）

- **官方文档**：Chat Completions <https://platform.openai.com/docs/api-reference/chat/create>；Responses <https://platform.openai.com/docs/api-reference/responses>。
  ⚠️ **核证限制（诚实说明）**：`platform.openai.com` 与 `developers.openai.com` 对本机所有 curl 请求都返回 **403（Cloudflare）**，因此本节的端点与字段是用 **OpenAI 官方仓库的 OpenAPI 规范** <https://raw.githubusercontent.com/openai/openai-openapi/master/openapi.yaml>（`info.title: OpenAI API`、`info.version: 2.3.0`）逐项核对的；**价格与 RPM/TPM 数值未能确证 → 未查到，需以官方控制台为准**。
- **鉴权**：规范 `securitySchemes.ApiKeyAuth = { type: http, scheme: bearer }` → `Authorization: Bearer <OPENAI_API_KEY>`；Key 在 platform.openai.com 的 API keys 页创建（页面 403，菜单名未逐字确证）。
- **base_url 与端点**：规范 `servers.url = https://api.openai.com/v1`；`POST /chat/completions`、`POST /responses`、`GET /models`。
- **模型 ID（规范正文里真实出现的字符串）**：`gpt-5.6`、`gpt-5.5`、`gpt-5.5-pro`、`gpt-5.3-codex`、`gpt-5`、`gpt-4o`、`o3`、`gpt-image-1` 等。**各模型上下文长度与价格未确证**，别凭记忆填。
- **字段**：`messages`（必填，至少 1 条）、`model`（必填）、`max_tokens` / `max_completion_tokens`、`temperature`、`top_p`、`n`(1~128)、`stream`、`stop`、`response_format`、`tools`、`seed`、`reasoning_effort`、`service_tier` 等。
- **结果位置**：`choices[0].message.content`（Responses 走 `output` 数组、另有 `output_text` 便捷字段，**该便捷字段未逐字确证**）。
- **JSON 模式官方警告（原文）**：用 `{"type":"json_object"}` 时**必须**自己在 system/user 消息里要求输出 JSON，否则模型可能一直吐空白直到 token 用尽，`finish_reason="length"` 时内容可能被截断。
- **本项目配置**：

```json
{ "provider": "openai", "baseUrl": "https://api.openai.com/v1", "model": "gpt-5.6",
  "temperature": 1, "maxTokens": 4096, "timeoutMs": 120000, "concurrency": 4 }
```

  拼接：`/v1` 命中 `/v\d+$` → `https://api.openai.com/v1/chat/completions` ✅。注意本项目只发 `max_tokens`，若目标模型要求 `max_completion_tokens`，需改适配器（本次不改）。

### 1.4 阿里云百炼 DashScope（通义千问，OpenAI 兼容模式）

- **官方文档**：OpenAI 兼容 <https://www.alibabacloud.com/help/zh/model-studio/compatibility-of-openai-with-dashscope>；DashScope 原生 <https://help.aliyun.com/zh/model-studio/qwen-api-via-dashscope>；模型列表 <https://help.aliyun.com/zh/model-studio/models>；错误码 <https://help.aliyun.com/zh/model-studio/error-code>。
- **鉴权**：`Authorization: Bearer $DASHSCOPE_API_KEY`（Key 形如 `sk-…`）。**Key 与地域强绑定**：用某地域 base_url 必须用同地域创建的 Key，跨地域返回 **401 `invalid_api_key` / "Incorrect API key provided"**（文档「重要」块原文）。

### 2.0 先选对 backend：`openai-images` 还是 `generic-http`

| backend | 何时用 | 硬约束 |
|---|---|---|
| `openai-images` | 目标厂商是 **OpenAI 兼容的 images 端点**（`/v1/images/generations`、`/v1/images/edits`） | 请求体**由代码写死**为 `{model, prompt, n:1, size:"<宽>x<高>"}`；带参考图时自动改走 **multipart edits**（字段 `model,prompt,n,size,image`）。**你只能改 baseUrl / apiKey / model / 两个路径**，改不了字段结构 |
| `generic-http` | 其他所有厂商（火山 Seedream、万相 Wanx、自建接口等） | `bodyTemplate` 渲染后**必须是合法 JSON**；异步任务要靠 `pollUrl`+`pollStatusPath`；**task_id 只会从这 4 个路径里找**：`data.task_id` / `task_id` / `data.id` / `id` |

> ⚠️ **第 3 条是本项目最容易被忽视的坑**：如果厂商把任务号放在别的路径（例如万相异步是 `output.task_id`、部分厂商是 `result.taskId`），**本项目根本取不到 task_id，于是不会轮询**，最后会报「响应里找不到图片字段」。遇到这种情况，优先换该厂商的**同步端点**，或接受「需要改代码」这个结论（本次不改）。

- **鉴权**：OpenAI 官方为 `Authorization: Bearer <OPENAI_API_KEY>`；Azure OpenAI 侧则为 `api-key: <key>` 头（或 Entra token），**两者不同，别混用**。
- **base_url 与端点**：`https://api.openai.com` + `POST /v1/images/generations`（文生图，JSON）、`POST /v1/images/edits`（参考图编辑，`multipart/form-data`）。**同步返回**。
- **请求字段（Azure 官方参考原文）**

| 字段 | 取值 / 说明 |
|---|---|
| `model` | 如 `gpt-image-1` |
| `prompt` | 提示词 |
| `size` | **`gpt-image-1` 系列只接受 `1024x1024`、`1536x1024`（横）、`1024x1536`（竖）、`auto`**；**`gpt-image-2` / `2.5` 系列支持任意 `宽x高`：宽高都要能被 16 整除、宽高比 ∈ [1:3, 3:1]、最大 `3840x2160`**；`dall-e-2` 才是 256/512/1024 方形，`dall-e-3` 用 1024x1024 / 1792x1024 / 1024x1792 |
| `n` | 1~10，默认 1 |
| `quality` | `standard` / `low` / `medium` / `high` / `auto` |
| `background` | `transparent` / `opaque` / `auto`（仅 gpt-image-1；transparent 需输出格式支持透明，即 png 或 webp） |
| `output_format` | 仅 gpt-image-1 系列；`png` / `jpeg` / `webp` |
| `output_compression` | 0~100，仅 webp/jpeg，默认 100 |
| `response_format` | `url` / `b64_json` —— **官方原文：该参数仅 dall-e-2 支持，`gpt-image-1` 系列始终返回 base64**；`url` 形式的链接**仅 60 分钟有效** |
| edits 专有 | `image`（**必填**，单张或数组）、`mask`（可选），请求体是 **multipart/form-data** |

- **响应**：`data[0].b64_json`（gpt-image-1 恒为 base64）或 `data[0].url`（dall-e 系，60 分钟过期）。本项目 `src/image.js` 会依次尝试 `b64_json` / `b64` / `image_base64` / `url`，**都能取到**。
- **🔴 本项目接 `gpt-image-1` 的隐藏坑（务必先改配置再测）**：`openaiImages()` 发的是 `size: "${width}x${height}"`，而宽高来自 `image.defaultRatio` 经 `RATIO_SIZE` 表映射：

  | 项目 ratio | 项目实际发出的 size | `gpt-image-1` 是否接受 |
  |---|---|---|
  | `1:1` | `1024x1024` | ✅ |
  | `3:2` | `1536x1024` | ✅ |
  | `2:3` | `1024x1536` | ✅ |
  | `3:4`（**项目默认**） | `1024x1365` | ❌ 400 |
  | `16:9` / `9:16` / `21:9` / `4:3` | `1536x864` / `864x1536` / `1792x768` / `1365x1024` | ❌ 400 |

  → **接 `gpt-image-1` / `gpt-image-1.5` 时必须把 `image.defaultRatio` 设为 `1:1`、`3:2` 或 `2:3` 之一**（或改用 `generic-http` 自己控 size）。这是配置能解决的，不用改代码。
  → 若用 **`gpt-image-2` / `gpt-image-2.5-*`**：因为支持「16 的倍数 + 比例 [1:3,3:1]」的任意尺寸，`16:9`（1536x864）、`9:16`（864x1536）、`21:9`（1792x768）**都合法**（各值都能被 16 整除）；**但项目的 `3:4 → 1024x1365` 仍然非法（1365 不是 16 的倍数）**，`defaultRatio` 依旧要改成 `2:3`。
- **模型 ID（规范枚举，2026-09 快照）**：`gpt-image-1.5`（**edits 端点的默认模型**）、`gpt-image-2`、`gpt-image-2-2026-04-21`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-sunburst-2026-09-08`、`gpt-image-2.5-flare`、`gpt-image-2.5-flare-2026-09-08`、`gpt-image-1`、`gpt-image-1-mini`、`dall-e-2`、`dall-e-3`；edits 端点另有 `chatgpt-image-latest`。编辑端点 `image` 支持**数组、最多 16 张**（GPT image 要求 png/webp/jpg，每张 <50MB）。**各模型的具体能力/上下限未逐一确证**（模型页 403）。
- **本项目配置（`openai-images`）**

```json
{
  "image": {
    "backend": "openai-images",
    "defaultRatio": "2:3",
    "defaultWidth": 1024, "defaultHeight": 1536,
    "openai": { "baseUrl": "https://api.openai.com", "apiKey": "sk-...", "model": "gpt-image-1",
                "generatePath": "/v1/images/generations", "editPath": "/v1/images/edits" }
  }
}
```

  - 参考图（演员定妆图/关键帧参考）会自动走 `edits`：`src/image.js` 检测到 `refImage` 文件存在即切换，并把 `negative` 拼到 prompt 末尾（`prompt\n\nAvoid: <negative>`），因为 **images 端点没有独立的 negative 字段**。
  - `response_format` 只在该 model 名含 `dall-e` 时才发（见 `src/image.js`），对 `gpt-image-1` 不发，符合官方口径。

### 2.2 火山方舟 Seedream（豆包图像，Ark）

- **官方文档**：图片生成 API <https://www.volcengine.com/docs/82379/1541523>（**本次已用官方文档接口 `https://www.volcengine.com/api/doc/getDocDetail?DocumentID=1541523&LibID=82379&lang=zh` 抓取正文核证**）；Base URL 及鉴权 <https://www.volcengine.com/docs/82379/1298459>；模型列表 <https://www.volcengine.com/docs/82379/1330310>；模型价格 <https://www.volcengine.com/docs/82379/1544106>；错误码 <https://www.volcengine.com/docs/82379/1299023>。国际版同族文档：<https://docs.byteplus.com/en/docs/modelark/image-generation-api>（base_url `https://ark.ap-southeast.bytepluses.com/api/v3`）。
- **鉴权**：`Authorization: Bearer $ARK_API_KEY`（API Key 管理页获取长效 Key）+ `Content-Type: application/json`；也支持 AK/SK 签名（那种方式 `model` 要填 Endpoint ID）。
- **base_url 与端点**：`POST https://ark.cn-beijing.volces.com/api/v3/images/generations` —— **同步返回**（也支持 `"stream": true` 流式输出，仅部分模型）。
- **请求示例（官方 curl，精简）**

```bash
curl https://ark.cn-beijing.volces.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "doubao-seedream-5-0-pro-260628",
    "prompt": "赛博朋克风格的雨夜街头，霓虹灯反射在积水上，电影感",
    "image": "https://.../ref.png",
    "size": "2K",
    "response_format": "url",
    "watermark": false,
    "sequential_image_generation": "disabled"
  }'
```

- **字段与取值范围（官方原文）**

| 字段 | 取值 |
|---|---|
| `model` | `doubao-seedream-5-0-pro-260628`（图层拆分+单图生成）、`doubao-seedream-5-0-flash-260915`、`doubao-seedream-5-0-260128` / `doubao-seedream-5-0-lite-260128`、`doubao-seedream-4-5-251128`（即将下线）、`doubao-seedream-4-0-250828`（即将下线）；官方教程 curl 用的是 `doubao-seedream-5-0-lite-260128`。**注意：官方字段表里没有 `n`、没有 `seed`、没有 `negative_prompt`**（出图张数由 `sequential_image_generation` 决定），塞这些字段会返回 400 `InvalidParameter.UnsupportedParameter` |
| `prompt` | 所有模型支持**中英文**；5.0 pro/flash 另支持俄/阿/菲/泰/土/韩/马来/西/葡/印尼/法/德/越/日。**建议中文 ≤300 字、英文 ≤600 词** |
| `image` | **string 或 string[]**（参考图/图生图）；支持 **URL** 或 **Base64**，base64 必须形如 `data:image/png;base64,<...>`（**格式名小写**） |
| `size` | **5.0 pro / flash**：方式 1 给档位 `1K`/`1.5K`/`2K`（默认 **2K**，1.5K 与 1K 同价）；方式 2 给 `宽x高`，**总像素 ∈ [921600, 4624220]、宽高比 ∈ [1/16, 16]**。**5.0 lite**：档位 `2K`/`3K`/`4K` 或像素（默认 `2048x2048`，总像素 ∈ [3686400, 16777216]） |
| `response_format` | 默认 **`url`**（**链接 24 小时内有效**）｜`b64_json` |
| `watermark` | **默认 `true`！**（右下角「AI 生成」水印）→ **要无水印必须显式传 `false`** |
| `sequential_image_generation` | `auto` / `disabled`（组图，默认 disabled）；配套 `sequential_image_generation_options.max_images` ∈ **[1,15]**，且「**输入参考图数量 + 生成数量 ≤ 15**」 |
| `output_format` | `png` / `jpeg`（响应里的 `data.output_format`） |
| `stream` | 默认 false（5.0 lite / 4.5 / 4.0 支持） |
| `optimize_prompt_options.mode` | `standard`（默认）/ `fast`（5.0 flash/lite/4.5 不支持 fast） |

- **响应**：`model`、`created`、`data[]`（每张含 `url` 或 `b64_json`、`output_format`），**`data.error.{code,message}` 为单图错误**（组图时某张因审核失败不影响其它张，但内部 500 会中断后续）；用量 `usage.generated_images`（**成功张数**）、`usage.total_tokens`。**结果链接 24 小时有效**。
- **模型 ID（官方「模型列表」原文，2026-09 快照）**：`doubao-seedream-5-0-pro-260628`、`doubao-seedream-5-0-flash-260915`、`doubao-seedream-5-0-lite-260128`（与 `doubao-seedream-5-0-260128` 并列标注「即将下线」）、`doubao-seedream-4-5-251128`（即将下线）、`doubao-seedream-4-0-250828`（即将下线）。
- **计费（官方「模型价格」原文，人民币）**：口径 = **按成功输出的图片张数 × 分辨率档位计价，另加输入图张数费用**；审核未通过不计费。`doubao-seedream-5-0-pro`：单图 ≤261 万像素 **0.30 元/张**、>261 万像素 **0.60 元/张**（图层拆分 0.15/0.30）；`5-0-flash` 0.12；`5-0-lite` 0.22；`4-5` 0.25；`4-0` 0.20。输入图：**首张免费，第 2 张起 0.02 元/张**（除 pro 外多为免费）。限流：**最大 IPM 500 张/分钟**（所有 Seedream 图像模型）。
- **坑与限制**
  1. **`watermark` 默认 true**：不显式传 `false` 就会拿到带「AI 生成」水印的定妆卡/关键帧（成片里会很难看）。
  2. **官方字段表里没有 `n` / `seed` / `negative_prompt`**：塞这些字段会 400（`InvalidParameter` / `InvalidParameter.UnsupportedParameter`）。**这一点直接决定本项目模板里不能放 `n` 与 `seed`** —— 而 `generic-http` 的示例模板默认是带这些的，务必按 2.0 节的建议精简。
  3. `size` 两种方式**不可混用**；给像素时**总像素与宽高比两个约束要同时满足**（官方举例：`512x512` 无效、`2048x1024` 有效）。**且各模型下限不同**：
     - `5.0 pro` / `5.0 flash`：总像素 ∈ [921,600, 4,624,220]，宽高比 [1/16,16]；
     - `5.0 lite` / `4.5`：总像素 ∈ [**3,686,400**, 16,777,216]（默认 `2048x2048`）；
     - `4.0`：总像素 ∈ [921,600, 16,777,216]。
  4. `output_format` **默认 `jpeg`**（可选 `png`），`response_format` 默认 `url`（**24 小时过期**）。
  5. 参考图数量：`5.0 pro/flash` 最多 10 张，`5.0 lite/4.5/4.0` 最多 14 张；base64 **必须带 `data:image/<小写格式>;base64,` 前缀**。
  6. 提示词过长会「信息分散、模型忽略细节」——官方给的字数建议不是硬限制但值得遵守。
- **本项目适配映射（`generic-http`）**

```json
{
  "image": {
    "backend": "generic-http",
    "generic": {
      "url": "https://ark.cn-beijing.volces.com/api/v3/images/generations",
      "method": "POST",
      "headers": "{\"Content-Type\":\"application/json\",\"Authorization\":\"Bearer {{apiKey}}\"}",
      "bodyTemplate": "{\"model\":\"{{model}}\",\"prompt\":\"{{prompt}}\",\"image\":\"{{refImage}}\",\"size\":\"{{width}}x{{height}}\",\"response_format\":\"url\",\"watermark\":false}",
      "responseImagePath": "data.0.url",
      "apiKey": "<ARK_API_KEY>",
      "model": "doubao-seedream-5-0-pro-260628",
      "refImageField": "image",
      "refImageFormat": "dataurl"
    }
  }
}
```

  - `refImageFormat` **必须是 `dataurl`**（Seedream 要求 `data:image/png;base64,` 前缀；默认 `base64` 是裸串）。
  - `refImageField: "image"` 让参考图落到 `image` 字段（**不填参考图时该字段渲染成 `""`**；若实测报「空图片」错误，可把参考图相关字段挪到单独的模板里用）。
  - `size` 用 `{{width}}x{{height}}` 时：**只有 `5.0 pro` / `5.0 flash` 能直接吃项目默认尺寸**（`1024x1536` = 1,572,864 像素、`1536x864` = 1,327,104 像素，均 ≥ 下限 921,600 且宽高比合法）→ 这两档**不必改 `defaultRatio`**（与 `gpt-image-1` 相反）。但 **`5.0 lite` / `4.5` 的下限是 3,686,400 像素，项目默认尺寸全部不合法** → 这两档必须把 `defaultWidth/defaultHeight` 提到 ≥369 万像素（如 `1680x2240`），或干脆把 `size` 写死成档位 `"2K"`（模型自己选宽高，官方给了映射参考表）。
  - **官方字段表无 `n`/`seed`/`negative_prompt`** → 上面的模板已经把它们去掉了，不要"照抄" 2.0 节的通用示例再叠上去。
  - 若想要**组图**（一次出多张关联图，适合「定妆图多视角」）：把 `sequential_image_generation` 设为 `"auto"` 并把 `sequential_image_generation_options.max_images` 写进模板 —— 但本项目的 `responseImagePath` 只能取**一张**（`data.0.url`），多图需要业务侧处理。
  - 无需轮询（同步接口），`pollUrl` 留空即可。

### 2.3 阿里云百炼 通义万相 Wanx（DashScope）

```bash
curl --location 'https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation' \
  --header 'Content-Type: application/json' \
  --header "Authorization: Bearer $DASHSCOPE_API_KEY" \
  --data '{
    "model": "wan2.6-t2i",
    "input": { "messages": [ { "role": "user", "content": [ { "text": "一间有着精致窗户的花店，漂亮的木质门，摆放着花朵" } ] } ] },

  }'
```

- **字段与取值范围（官方原文）**
  - 通用：`input.messages`（**仅支持单轮、单个 text**，多传报错）；`parameters.n` ∈ **1~4（默认 4！按张计费，测试务必设 1）**；`parameters.size` 格式是 **`宽*高`（星号！）**，**默认 `1280*1280`**；`seed` ∈ [0, 2147483647]；`negative_prompt` ≤ 500 字；`prompt_extend`（默认 true，开启会多耗 3~4 秒，且改写的提示词可能触发版权审核 → 报 `IPInfringementSuspect` / `DataInspectionFailed`，此时可关掉）；`watermark`（默认 false，true 时右下角「AI 生成」）。

  - **wan2.2 及以下**：宽高各自在 [512, 1440] 像素之间（**单边上限 1400**）—— 约束口径与 2.5/2.6 完全不同。

- **模型 ID（官方文档真实出现）**：
  - **新版/推荐**：`wan2.7-image-pro`、`wan2.7-image`、`wan2.6-image`、`wan2.6-t2i`、`wan2.5-t2i-preview`
  - 旧版：`wan2.2-t2i-flash`、`wan2.2-t2i-plus`、`wanx2.1-t2i-turbo`、`wanx2.1-t2i-plus`、`wanx2.0-t2i-turbo`
  - 千问系（同文档提及）：`qwen-image-3.0-pro`、`qwen-image-plus`、`qwen-image`
- **计费（官方原文 + 官方模型页）**：口径是「**按成功生成的图像张数计费；模型调用失败或处理错误不产生任何费用**」，`n` 直接影响费用（费用 = 单价 × 张数）。实例价：**`wan2.7-image` 0.2 元/张（华北 2 北京）**、0.224826 元/张（新加坡）、0.027504 元/张（东京）。限流：`wan2.7-image` **RPM 300**（东京另加 TPM 1,000,000）。**其余模型的逐项单价未逐条确证 → 需以官方模型页为准**。
- **坑与限制**
  1. **`n` 默认 4**：不显式传 `n: 1` 就会一次扣 4 张的钱。
  2. **size 是 `宽*高`（星号）不是 `宽x高`**，且 2.5/2.6 有**总像素下限 [1280×1280 = 1,638,400]** —— 本项目默认尺寸（`1024x1536` = 1,572,864、`1536x864` = 1,327,104）**全部达不到下限**，直接发会被拒；`21:9` 的 `1792x768` 也不合法。→ **要么在模板里写死官方推荐尺寸，要么改用 wan2.2 及以下（单边 [512,1440] 口径，项目默认尺寸基本都合法）**。
  3. **wan2.7 的两个额外坑**：① `size` 走档位（`1K`/`2K` 默认/`4K`）时，**「没有图片输入」会输出正方形**（官方原文「当没有图片输入时：输出为正方形」）→ **竖屏漫剧必须用显式像素方式**；② 组图开关字段叫 `enable_sequential`（关组图时 `n` ∈ 1~4 默认 1，开组图时 ∈ 1~12 默认 12——**又是一个"默认值会多花钱"的地方**）。
  4. 结果 URL **24 小时过期**（本仓库拿到即下载落盘，无风险）；`prompt_extend` 可能引入版权内容触发审核失败。
- **本项目适配映射（推荐走 wan2.6 同步端点）**

```json
{
  "image": {
    "backend": "generic-http",
    "generic": {
      "url": "https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation",
      "method": "POST",
      "headers": "{\"Content-Type\":\"application/json\",\"Authorization\":\"Bearer {{apiKey}}\"}",
      "bodyTemplate": "{\"model\":\"{{model}}\",\"input\":{\"messages\":[{\"role\":\"user\",\"content\":[{\"text\":\"{{prompt}}\"}]}]},\"parameters\":{\"size\":\"1104*1472\",\"n\":1,\"negative_prompt\":\"{{negative}}\",\"watermark\":false,\"prompt_extend\":true}}",
      "responseImagePath": "output.choices.0.message.content.0.image",
      "apiKey": "<DASHSCOPE_API_KEY>",
      "model": "wan2.6-t2i",
      "refImageField": "image",
      "refImageFormat": "dataurl"
    }
  }
}
```

  - **`size` 必须写死**（上面的 `1104*1472` 是官方 3:4 推荐值）；想让尺寸跟画幅走，就得改代码或换成 wan2.2 系列（那种口径下 `{{width}}*{{height}}` 才有意义）。
  - **为什么不用旧版异步端点**：旧协议把任务号放在 **`output.task_id`**，而本项目的 task_id 只从 `data.task_id` / `task_id` / `data.id` / `id` 里找 → **取不到 → 不会轮询 → 报「找不到图片字段」**。用 wan2.6 同步端点可以完全绕开这个限制。
  - 若你确实必须用旧版异步（例如只有 wan2.1 额度）：需要 `headers` 加 `"X-DashScope-Async":"enable"`、`pollUrl` 填 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/tasks/{{taskId}}`、`pollStatusPath` 填 `output.task_status`、`pollSuccessValues` 填 `SUCCEEDED`、`responseImagePath` 填 `output.results.0.url` —— 但**仍会卡在 task_id 探测不到**，属于已知的适配器能力边界。

### 2.4 Google Gemini 图像生成（Nano Banana 系）

⚠️ **核证限制（重要）**：`ai.google.dev`、`cloud.google.com`、`docs.cloud.google.com`、`generativelanguage.googleapis.com` 从本机**全部超时或被阻断**，**官方文档页正文未能抓取**。下面的字段来自 **Google 官方机器可读规范（Discovery）** `https://generativelanguage.googleapis.com/$discovery/rest?version=v1beta`（`revision 20260928`，经代理取得）与 **Google 官方 SDK `google-genai`**（PyPI 官方包，含 `types.py` / `_api_client.py` 源码与 README 示例）。凡是**只能靠文档页确认**的项，一律标注「未查到」。

- **官方文档入口**（URL 由搜索命中，正文未抓取）：图像生成指南 <https://ai.google.dev/gemini-api/docs/image-generation>；模型页 <https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-image>；定价 <https://ai.google.dev/gemini-api/docs/pricing>。
- **鉴权**：Header **`x-goog-api-key: <API_KEY>`**（官方 SDK `_api_client.py` 原文 `self._http_options.headers['x-goog-api-key'] = self.api_key`）；另有 OAuth（Discovery 含 `scopes`）；`?key=` 查询参数形式**未能从文档页确证**。Key 在 Google AI Studio <https://aistudio.google.com/apikey>。
- **base_url 与端点（同步）**：`https://generativelanguage.googleapis.com/`，API 版本 **`v1beta`**；`POST /v1beta/models/{model}:generateContent`（Discovery：`"path": "v1beta/{+model}:generateContent"`，`httpMethod: POST`）。**图生图/编辑走同一个端点**，参考图作为 `parts[].inlineData` 与文本一起放进 `contents`。**不是** OpenAI 的 `/images/generations` 形态，所以 **`openai-images` 后端完全不适用**。
- **关键字段（逐条来自 Discovery 规范）**：
  - `generationConfig.responseModalities`：数组，枚举 `MODALITY_UNSPECIFIED`/`TEXT`/`IMAGE`/`AUDIO` —— **要出图必须含 `IMAGE`**（空数组等价于只请求文本）。
  - `generationConfig.imageConfig`：`aspectRatio`（支持 `1:1`/`1:4`/`4:1`/`1:8`/`8:1`/`2:3`/`3:2`/`3:4`/`4:3`/`4:5`/`5:4`/`9:16`/`16:9`/`21:9`）、`imageSize`（`512`/`1K`/`2K`/`4K`，默认 `1K`）、`personGeneration`（`ALLOW_ALL`/`ALLOW_ADULT`/`ALLOW_NONE`）等。
    ⚠️ **其他三家都是像素 `宽x高`，只有 Gemini 是「比例字符串 + 档位」** → 项目里的 `{{width}}x{{height}}` 不能直接塞进来；`aspectRatio` 要硬编码（`{{ratio}}` 渲染出来是 `1024:1365` 这种**像素比**，不是合法宽高比）。
  - **没有** `size:"1024x1024"`、**没有** `n`（要数量用 `candidateCount`）、**没有** `negative_prompt`、**没有** `seed`。
  - 输入图：`Part.inlineData` → `Blob{mimeType, data}`（**纯 base64，不带 `data:` 前缀**）；支持 png/jpeg/webp/heic/heif/gif/avif；大文件走 `fileData`（Files API）。
- **请求示例**

```bash
curl -X POST "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-image:generateContent" \
  -H "Content-Type: application/json" -H "x-goog-api-key: $GEMINI_API_KEY" \
  -d '{"contents":[{"role":"user","parts":[
        {"text":"一辆红色跑车在雨夜霓虹街道上，电影感"},
        {"inlineData":{"mimeType":"image/png","data":"<base64 无前缀>"}}]}],
      "generationConfig":{"responseModalities":["IMAGE"],
        "imageConfig":{"aspectRatio":"9:16","imageSize":"2K"}}}'
```

- **响应**：结果在 **`candidates.0.content.parts.0.inlineData.data`**（裸 base64）；被安全策略拦截时**没有 candidates**，只返回 `promptFeedback.blockReason`；用量 `usageMetadata.{promptTokenCount, candidatesTokenCount, totalTokenCount}`。建议取「第一个含 `inlineData` 的 part」而不是死取 `parts.0`（同时请求 TEXT 时会混排）。
- **模型 ID**：**未能从官方文档页确证完整列表**（模型页不可达）。官方 SDK 源码/测试里确证出现的有 **`gemini-2.5-flash-image`**（即社区所称 Nano Banana）与 **`gemini-3.1-flash-image`**；`nano-banana-pro-preview` 亦出现在 SDK 内部类型中。**其余以官方控制台为准。**
- **计费**：**未查到**（定价页不可达）。可确证的是按 token 计费（响应含 `usageMetadata`）。搜索命中的 Google Cloud 定价摘录（**二手转述，未直连验证**）提到「输入图每张 560 token、输出图 1K/2K 约 1120 token」——**仅供参考，不要当成 Gemini Developer API 的准数**。
- **本项目适配映射（`generic-http`）**

```json
{
  "image": {
    "backend": "generic-http",
    "generic": {
      "url": "https://generativelanguage.googleapis.com/v1beta/models/{{model}}:generateContent",
      "method": "POST",
      "headers": "{\"Content-Type\":\"application/json\",\"x-goog-api-key\":\"{{apiKey}}\"}",
      "bodyTemplate": "{\"contents\":[{\"role\":\"user\",\"parts\":[{\"text\":\"{{prompt}}\"}]}],\"generationConfig\":{\"responseModalities\":[\"IMAGE\"],\"imageConfig\":{\"aspectRatio\":\"3:4\",\"imageSize\":\"2K\"}}}",
      "responseImagePath": "candidates.0.content.parts.0.inlineData.data",
      "apiKey": "<GEMINI_API_KEY>",
      "model": "gemini-2.5-flash-image",
      "refImageField": "inlineData",
      "refImageFormat": "base64"
    }
  }
}
```

  - 带参考图时把 `parts` 换成 `[{"text":"{{prompt}}"},{"inlineData":{"mimeType":"image/png","data":"{{refImage}}"}}]`。
  - 同步接口，`pollUrl` 留空；返回裸 base64 会被 `saveImagePayload` 正常落盘。
  - ⚠️ **现实障碍**：该端点在**国内网络下不可达**（本次实测本机全部超时），要接必须有可直连 Google 的出口。**建议：先不要接 Gemini 图像** —— 火山 Seedream 与万相 Wanx 在中文提示词、参考图、计费透明度上都更容易验证；Gemini 更适合做文字/多模态理解（见第五节）。

### 2.5 通用 HTTP 自建接口（本项目最灵活的通道）

适用场景：自建 SD/Flux 服务、公司内部网关、任何「不是 OpenAI 形态、文档又写得清楚」的厂商。**没有厂商文档可引用**，这里写的是「怎么填本项目的字段」：

1. **先在设置页用向导**（设置 → 出图后端 → `generic-http`）：
   - 「📋 粘贴 curl 自动填表」：把厂商文档里的 curl 整段粘进去，会自动得到 `url` / `method` / `headers` / `bodyTemplate`（Key → `{{apiKey}}`，提示词/尺寸/种子 → 占位符）；
   - 「🔎 试发一次并推荐字段」：用当前模板真实发一次（**会花钱**，提示词是 `connectivity probe`），把原始响应显示出来并**推荐响应字段路径**，点一下即可填入 `responseImagePath`。
2. **同步接口的最小配置**
```json
{
  "image": {
    "backend": "generic-http",
    "generic": {
      "url": "https://your-endpoint/v1/images/generations",
      "method": "POST",
      "headers": "{\"Content-Type\":\"application/json\",\"Authorization\":\"Bearer {{apiKey}}\"}",
      "bodyTemplate": "{\"model\":\"{{model}}\",\"prompt\":\"{{prompt}}\",\"negative_prompt\":\"{{negative}}\",\"width\":{{width}},\"height\":{{height}},\"seed\":{{seed}},\"n\":1}",
      "responseImagePath": "data.0.b64_json",
      "apiKey": "<KEY>",
      "model": "<MODEL_ID>",
      "refImageField": "image",
      "refImageFormat": "base64"
    }
  }
}
```

3. **异步任务接口**额外填三项（缺一不可）：`pollUrl`（含 `{{taskId}}`）、`pollStatusPath`（状态字段的点号路径）、`pollSuccessValues`（逗号分隔的成功值）。**注意 task_id 只能从 `data.task_id` / `task_id` / `data.id` / `id` 四个路径取到**（见 2.0 的警告）。
4. 参考图：`refImageField`（字段名，默认 `image`）+ `refImageFormat`（`base64` 裸串 / `dataurl` 带 `data:image/png;base64,` 前缀）。**一定要按厂商文档选对**——很多厂商（火山、Google 系）要求带前缀。
5. 自建 ComfyUI 出图不要走这条，直接 `image.backend: "comfyui"`（填 `url`、`workflowPath`、`map`、`refImageNode`），它自带 `/upload/image` 上传与 `/history` 轮询，见第 3.2 节。

### 2.6 四家出图厂商「同一后端、只换模板」对照表

| 厂商 | `url` | `bodyTemplate` 关键差异 | `responseImagePath` | 需要轮询? |
|---|---|---|---|---|
| Ark Seedream | `https://ark.cn-beijing.volces.com/api/v3/images/generations` | `size` 用 `{{width}}x{{height}}`；`watermark:false`；**不能有 `n`/`seed`** | `data.0.url` | 否 |
| 万相 wan2.6/2.7 | `…/api/v1/services/aigc/multimodal-generation/generation` | 结构是 `input.messages` + `parameters`；`size` 用 **`{{width}}*{{height}}`（星号）** 且要满足总像素口径 | `output.choices.0.message.content.0.image` | 否 |
| 万相 ≤2.5（旧协议） | `…/api/v1/services/aigc/text2image/image-synthesis` | `input.prompt` + `parameters`，**必须加 `X-DashScope-Async: enable`** | `output.results.0.url` | **是**（task_id 在 `output.task_id` → 本项目取不到，见 2.0） |
| Google Gemini | `…/v1beta/models/{{model}}:generateContent` | `contents[].parts[]` + `generationConfig.responseModalities:["IMAGE"]`；尺寸用 `imageConfig.aspectRatio` 比例字符串 | `candidates.0.content.parts.0.inlineData.data` | 否 |

> 通用陷阱：**模板里写 `"image":"{{refImage}}"` 时，纯文生图会渲染成 `"image":""`**，多数厂商会判参数错误（Seedream 尤其可能报 `InvalidImageURL.EmptyURL`）→ 文生图与图生图**各留一份配置**，或按画布上有没有参考图连线来切。

```bash
curl https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "doubao-seedance-2-5-260628",
    "content": [
      {"type": "text", "text": "女孩抱着狐狸，镜头缓缓拉出，可以听到风声"},
      {"type": "image_url", "image_url": {"url": "https://.../first.png"}, "role": "first_frame"},
      {"type": "image_url", "image_url": {"url": "https://.../last.png"},  "role": "last_frame"}
    ],
    "ratio": "adaptive",
    "duration": 5,
    "watermark": true
  }'
```

- **首尾帧（本项目最关心的一点，官方原文口径）**：
  - **不是独立字段**，而是 `content` 数组里两个 `image_url` 对象：首帧 `role: "first_frame"`、尾帧 `role: "last_frame"`（**`role` 是必填的**）。
  - 支持**首尾帧**的模型：`Seedance 2.5`、`Seedance 2.0 系列`、`Seedance 1.0 pro`；**`Seedance 1.0 pro fast` 不支持首尾帧（只能首帧）**。
  - **互斥约束**：图生视频-首帧、图生视频-首尾帧、全模态参考生视频是**三种互斥场景，不可混用**；首尾帧图宽高比不一致时**以首帧为准，尾帧自动居中裁剪**。
  - `Seedance 2.5` 在首尾帧任务下 `ratio` **只能用 `adaptive`**。
  - 官方推荐用 `return_last_frame: true` 取回尾帧图（jpeg、与视频同像素、无水印），作为下一段的首帧 —— 这正好对应本项目的「视频续写」链路。
- **请求体常用字段**

| 字段 | 类型 / 默认 | 要点 |
|---|---|---|
| `model` | string 必选 | 模型 ID，或 Endpoint ID |
| `content[]` | 数组 必选 | 元素类型 `text` / `image_url` / `video_url` / `audio_url` / `draft_task` |
| `content[].image_url.url` | string 必选 | 支持**公网 URL**、**Base64 data URL**（必须 `data:image/<小写格式>;base64,...`）、素材 ID `asset://<ASSET_ID>` |
| `content[].role` | string | 图片：`first_frame` / `last_frame`；视频：`reference_video` |
| `resolution` | string | 各模型支持子集：2.5 支持 480p/720p/1080p（默认 720p）；2.0 系列额外支持 4k；2.0 fast/mini 仅 480p/720p |
| `ratio` | string | `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive` |
| `duration` | integer | 1.0 pro：默认 5，范围 [2,12]；2.0 系列：默认 5，[4,15] 或 -1；2.5：默认 -1，[4,30] 或 -1（-1 = 智能指定） |
| `frames` | integer | [29, 289] 且满足 `25+4n`；与 `duration` 二选一，**frames 优先** |
| `seed` | integer 默认 -1 | [-1, 2147483647]（1.0 pro / pro fast） |
| `watermark` | boolean 默认 false | true 时右下角显示「AI 生成」 |
| `camera_fixed` | boolean 默认 false | 固定镜头；参考图场景不支持 |
| `generate_audio` | boolean 默认 true | 2.5 / 2.0 系列的有声视频（输出恒为单声道） |
| `return_last_frame` | boolean 默认 false | 查询结果里多返回 `content.last_frame_url` |
| `callback_url` | string | Webhook 回调，回调体结构与查询接口一致 |
| `priority` | integer 默认 0 | [0,9]，仅同 Endpoint 内插队（2.5 / 2.0 系列） |
| `execution_expires_after` | integer 默认 172800 | [3600, 259200] 秒，超时任务变 `expired` |

- **响应示例（查询任务，精简）**

```json
{
  "id": "cgt-2025****",
  "model": "doubao-seedance-2-5-260628",
  "status": "succeeded",
  "content": { "video_url": "https://.../xxxx.mp4", "last_frame_url": "https://.../xxxx.jpeg" },
  "usage": { "completion_tokens": 123456, "total_tokens": 123456 },
  "created_at": 1710000000, "updated_at": 1710000060,
  "seed": 11, "resolution": "720p", "ratio": "16:9", "duration": 5, "framespersecond": 24,
  "error": null
}
```

  - 任务 id 字段：**`id`**（创建与查询同名）；状态枚举：`queued` / `running` / `cancelled` / `succeeded` / `failed`，另有超时态 `expired`。
  - **结果视频在 `content.video_url`**；尾帧在 `content.last_frame_url`（仅 `return_last_frame:true` 时）。失败时 `error` 为 `{code, message}` 对象，成功为 `null`。
  - 用量看 `usage.completion_tokens`（视频模型不计输入 token，故 `total_tokens = completion_tokens`）。
  - **有效期**：视频 URL（含尾帧 URL）**24 小时过期**；Seedance 2.5 产物 URL **下载次数上限 100 次**；**任务记录只保留 7 天**。→ 必须拿到即下载落盘。
- **图片与请求体硬限制（官方原文）**：格式 jpeg/png/webp/bmp/tiff/gif（2.0 系列及以上额外支持 heic/heif）；宽高比（宽/高）∈ **[0.4, 2.5]**；边长 ∈ **[300, 6000] px**；**单图 < 30 MB、请求体 ≤ 64 MB**，官方明确「大文件请勿使用 Base64 编码」；图片数量：首帧 1 张、首尾帧 2 张、2.5 全模态参考 1~30 张、2.0 系列 1~9 张。视频输入 mp4/mov，单个 ≤ 200 MB。
- **模型 ID（官方模型列表原文）**

| Model ID | 官方备注 |
|---|---|
| `doubao-seedance-2-5-260628` | Seedance 2.5：默认 ratio=adaptive、720p（480p/720p/1080p）、duration [4,30] 或 -1、支持首尾帧与有声视频 |
| `doubao-seedance-2-0-260128` | Seedance 2.0：480p/720p/1080p/4k、[4,15] 或 -1、支持首尾帧 |
| `doubao-seedance-2-0-fast-260128` / `doubao-seedance-2-0-mini-260615` | 480p/720p，限时折扣（企业用户） |
| `doubao-seedance-1-0-pro-250528` | **官方标注「即将下线」**；480p/720p/1080p、[2,12]、支持首帧与首尾帧 |
| `doubao-seedance-1-0-pro-fast-251015` | **官方标注「即将下线」**；**仅首帧**，不支持首尾帧 |

- **计费（按 token，不按秒）**：官方原文「视频价格 = token 单价 × token 用量」；token 用量估算公式为 `(输入视频时长 + 输出视频时长) × 输出宽 × 输出高 × 输出帧率 / 1024`，精确值以 `usage.completion_tokens` 为准；**仅对成功生成的视频计费，审核失败不收费**；输入含视频时有「最低 token 用量」限制。限时优惠（官方原文，2026-08-07 14:00 ~ 10-07 14:00 UTC+8，仅企业用户）：Seedance 2.0 mini 480p/720p 打 4 折（720p 最低约 0.2 元/秒），2.0 fast 打 7.5 折（720p 最低约 0.6 元/秒）。**各分辨率的具体 token 单价表未从文档确证 → 未查到，需以官方控制台「模型价格」页与价格计算器为准**。
- **开通门槛**：开通 Seedance 2.5 / 2.0 系列需满足任一条件 —— 账户余额 > 200 元、购买 200 元档及以上节省计划、或已有可用资源包余量。
- **坑与限制**
  1. **URL 24h 过期 / 2.5 限 100 次下载 / 任务记录仅 7 天**：拿到 `content.video_url` 立刻下载（本项目 `genericVideo` 正是拿到即下载，符合要求）。
  2. **视频不支持 base64**（只支持 URL 或素材 ID）；图片支持 base64 但**必须带 `data:image/png;base64,` 前缀**。
  3. **不支持直接上传含真人人脸的参考图/视频**（Seedance 2.5 / 2.0 系列），相关错误码见下。
  4. 常见错误码：`InputImageSensitiveContentDetected.PrivacyInformation` / `InputVideoSensitiveContentDetected.PrivacyInformation` / `OutputVideoSensitiveContentDetected(.PolicyViolation)` / `InputTextRiskDetection`（风险识别，多为 400）；`AuthenticationError`(401)、`ModelNotOpen`(404)、`InvalidEndpointOrModel.NotFound`(404)、`InvalidParameter.*`(400)、`MissingParameter`(400)、`PayloadTooLarge`/`RequestBodyTooLarge`(413)、`InvalidImageURL.EmptyURL`(400)、`InvalidParameter.TaskTypeConstraint`/`TaskTypeMismatch`（2.5 任务类型判定不一致，**异步**报错）；429 家族：`AccountRateLimitExceeded`、`ModelAccountRpmRateLimitExceeded`、`ModelAccountTpmRateLimitExceeded`、`ServerOverloaded`、`RequestBurstTooFast`、`InflightBatchsizeExceeded`（充值可解锁更大并发）、`QuotaExceeded`（排队任务数超限）。
  5. 危险默认值：`duration: -1`（智能指定）会让**实际时长与计费不可预期**；官方说明其返回值是「实际总帧数 / 24 向下取整」，本项目做成本核算时应显式给整数秒。
- **本项目适配映射（Ark）**
  - **backend 选 `generic-http`**（`placeholder` / `comfyui-h3` 都不适用）。
  - 可直接粘贴的 config 片段（首帧 + 尾帧，720p / 16:9 / 5s）：

```json
{
  "video": {
    "backend": "generic-http",
    "generic": {
      "url": "https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks",
      "method": "POST",
      "headers": "{\"Content-Type\":\"application/json\",\"Authorization\":\"Bearer {{apiKey}}\"}",
      "bodyTemplate": "{\"model\":\"{{model}}\",\"content\":[{\"type\":\"text\",\"text\":\"{{prompt}}\"},{\"type\":\"image_url\",\"image_url\":{\"url\":\"{{firstImage}}\"},\"role\":\"first_frame\"},{\"type\":\"image_url\",\"image_url\":{\"url\":\"{{lastImage}}\"},\"role\":\"last_frame\"}],\"resolution\":\"720p\",\"ratio\":\"16:9\",\"duration\":{{duration}},\"seed\":{{seed}},\"watermark\":false}",
      "responseVideoPath": "content.video_url",
      "apiKey": "<ARK_API_KEY>",
      "model": "doubao-seedance-2-0-260128",
      "refImageFormat": "dataurl",
      "pollUrl": "https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks/{{taskId}}",
      "pollStatusPath": "status",
      "pollSuccessValues": "succeeded",
      "pollIntervalMs": 10000,
      "pollMaxTimes": 180
    }
  }
}
```

  - 逐条对应关系说明：
    1. `refImageFormat` **必须为 `dataurl`**（Ark 的 base64 需要 `data:image/png;base64,` 前缀，默认 `base64` 裸串会报 `InvalidImageURL`）。
    2. `task_id` 探测顺序是 `data.task_id → task_id → data.id → id`，Ark 创建响应正好是顶层 `id`，**命中**。
    3. **Ark 没有 `width` / `height` 参数**，只有 `ratio` + `resolution`；而本项目的模板占位符里**没有 `{{ratio}}`**（见 `src/video.js` 的 vars 列表），所以 `ratio`/`resolution` 必须在 `bodyTemplate` 里**写死**，默认模板里的 `{{width}}/{{height}}` 会造成 400。
    4. `{{refImage}}` 与 `{{firstImage}}` 在 `src/video.js` 里是**同一个值**，模板里只能用其中一个（两个都写会变成 3 张图 → 400）。
    5. 尾帧是「双向坑」：模板里有 `{{lastImage}}` 但本次没传尾帧 → 渲染出 `"url":""` → Ark 报 `InvalidImageURL.EmptyURL`；反之传了尾帧而模板没有 `{{lastImage}}` → 本仓库会直接报错。**建议固定用首尾帧模板，并保证画布上总是接尾帧**。
    6. `pollSuccessValues` 只留 `succeeded`；注意 `expired` **不会**被本仓库的 `/fail|error|cancel/i` 失败判定命中，会一直轮询到超时 —— 建议把 `pollMaxTimes` 按实际耗时收紧。
    7. `duration` 占位符是「不带引号的数字」，符合 Ark integer 要求；但要注意各模型档位不同（1.0 pro 只接受 [2,12]、2.0 系列 [4,15]、2.5 [4,30]），本项目 `video.maxShotSeconds` 默认 12，接 2.0 系列时记得对齐。

### 3.2 ComfyUI 原生 HTTP API

> 本项目已有完整实现（`src/comfy.js` + `video.comfy` 配置 + 内置两套 H3 工作流），本节写清官方接口口径与本仓库的字段映射，便于换实例/换工作流时对照。

- **官方文档**
  - Server Routes（HTTP + WS 路由总表）：<https://docs.comfy.org/development/comfyui-server/comms_routes>
  - Server Messages（WebSocket 消息类型）：<https://docs.comfy.org/development/comfyui-server/comms_messages>
  - API Examples（Method 1/2/3）：<https://docs.comfy.org/development/comfyui-server/api-examples>
  - Workflow JSON 规范（前端 schema）：<https://docs.comfy.org/specs/workflow_json>
  - 官方脚本示例：<https://raw.githubusercontent.com/comfyanonymous/ComfyUI/master/script_examples/basic_api_example.py>、<https://raw.githubusercontent.com/comfyanonymous/ComfyUI/master/script_examples/websockets_api_example.py>
  - 路由实现（权威）：<https://raw.githubusercontent.com/comfyanonymous/ComfyUI/master/server.py>
- **鉴权**：**原生自托管默认无鉴权**（没有 API Key、没有必须的 Header）；`--listen 0.0.0.0` 即对网络开放。官方只提到「含付费 Partner Nodes 的工作流可在 payload 的 `extra_data` 里带 Comfy 平台 key」（`{"prompt": {...}, "extra_data": {"api_key_comfy_org": "comfyui-..."}}`，key 在 platform.comfy.org 生成）。云实例（如本项目实测用的 x-gpu 容器）多由网关加 token 或直接给带签名的域名 —— **具体以你的实例为准**。
- **base_url**：默认 `http://127.0.0.1:8188`。⚠️ 官方 `server.py` 会把**所有路由同时挂到 `/api` 前缀下**，即 `/prompt` 与 `/api/prompt` 等价。
- **核心端点（官方路由表原文 + 本仓库实际使用）**

| 端点 | 方法 | 用途 |
|---|---|---|
| `/prompt` | POST | 提交工作流，返回 `prompt_id` 或 `error` + `node_errors` |
| `/history`、`/history/{prompt_id}` | GET | 取执行结果（含 `outputs` 与 `status`） |
| `/view` | GET | 取回产物字节流（`filename` + `subfolder` + `type`） |
| `/upload/image` | POST | 上传输入图（multipart，字段固定为 `image`） |
| `/object_info`、`/object_info/{node_class}` | GET | 取全部/单个节点定义（用于提交前校验节点与必填项） |
| `/queue` | GET/POST | 查看队列 / 清空或删除待执行任务 |
| `/interrupt` | POST | 中断当前执行（带 `{"prompt_id":...}` 则定向中断） |
| `/free` | POST | 卸载模型释放显存 |
| `/system_stats` | GET | 探活：系统信息、`comfyui_version`、设备与显存 |
| `/ws` | WebSocket | 实时进度（`status` / `execution_start` / `executing` / `executed` / `progress` / `execution_error` / `execution_success` …） |

- **`POST /prompt` 请求与响应**

```json
// 请求
{ "prompt": { "144": {"class_type": "PrimitiveStringMultiline", "inputs": {"value": "夜色中的档案馆走廊…"}},
              "152": {"class_type": "KSampler", "inputs": {"seed": 123, "steps": 4, "latent_image": ["131", 0]}} },
  "client_id": "任意 uuid" }
// 成功
{ "prompt_id": "<uuid>", "number": 3, "node_errors": {} }
// 校验失败（HTTP 400）
{ "error": {"type": "missing_node_type", "message": "...", "details": "..."}, "node_errors": {...} }
```

  - **最常见的坑：HTTP 200 不等于会出片** —— 只要还有可执行的输出节点，服务端就会入队并返回 200，同时把校验失败的节点放进 `node_errors`。**必须同时检查 `node_errors` 与后续 `/history` 的 `status`**。
  - 常见校验错误 `type`：`missing_node_type`（节点未安装，**云实例节点版本与前端 bundle 不一致时最常见**）、`required_input_missing`（必填输入没给，典型是忘了给 LoadImage 的 `image`）、`prompt_no_outputs`、`prompt_outputs_failed_validation`、`bad_linked_input`、`return_type_mismatch`、`dependency_cycle`、`value_not_in_list`（枚举越界）、`value_smaller_than_min` / `value_bigger_than_max`、`invalid_prompt_id`（自定义 `prompt_id` 不是规范 UUID）。
- **`GET /history/{prompt_id}` 响应结构**

```json
{ "<prompt_id>": {
    "outputs": { "<node_id>": { "images": [{"filename":"video_00001.mp4","subfolder":"video","type":"output"}], "animated": [true] } },
    "status": { "status_str": "success", "completed": true, "messages": [] } } }
```

  - **外层是「以 prompt_id 为 key 的字典」**，取产物要走 `entry.outputs`。
  - **视频落在哪个键**：官方视频保存节点（`SaveVideo` / `SaveWEBM`）走 `PreviewVideo` 输出，产物与图片一样放在 `outputs[node]["images"]` 并附带 `animated` 标记；**第三方视频节点（如 VHS_VideoCombine）惯用 `gifs` 键**。本仓库的读取顺序是 `videos || gifs || images`，两种都能命中。
  - 本项目实测（MiniMax H3 云实例）：视频确实落在 `outputs.<节点>.images[]`，文件名形如 `MiniMax_H3_<时间戳>_<hash>_00001_.mp4`，`type=output`、`subfolder=video`。
- **`GET /view`**：参数 `filename`（必填，缺失 404）、`subfolder`、`type`（`output` | `input` | `temp`，**默认 output**）、`preview`、`channel`。文件名不得以 `/` 开头或含 `..`（否则 400）。
- **`POST /upload/image`**：multipart 字段 `image`（必填）+ `overwrite`（`"true"`/`"1"` 才覆盖，否则重名自动改成 `name (1).ext`）+ `type`（默认 input）+ `subfolder`；返回 `{"name","subfolder","type"}`，把 `name` 填进工作流 `LoadImage` 的 `inputs.image`。
- **`GET /object_info`**：返回全部节点定义（体积随安装节点数增长，**具体体积官方未给数值 → 只能实测**；本仓库有 5 分钟缓存）；`/object_info/{node_class}` 只返回单个节点；**未知节点名返回 `{}` 且 HTTP 200**（不是 404）。推荐用法：提交前用它核对每个 `class_type` 是否存在、必填输入名、枚举取值与模型清单。
- **API 格式工作流 vs 前端导出格式（关键）**：能提交给 `/prompt` 的是 **API 格式** —— `{"<节点id>": {"class_type": "...", "inputs": {...}}}`，节点 id 为字符串数字键，连线写成 `["<上游节点id>", <输出下标>]`。官方脚本注释原文：「File → Export (API) in the interface」。前端 `File → Save` 导出的工作流（顶层 `nodes[]` + `links[]` + `widgets_values`）**不能直接提交**，会得到 `missing_node_type` 之类的校验失败。
- **本项目适配映射（`video.comfy`）**

```json
{
  "video": {
    "backend": "comfyui-h3",
    "comfy": {
      "url": "https://<你的实例域名>/",
      "workflowPath": "",
      "preferKeyframe": true,
      "videoNode": "131",
      "model": "minimax-h3",
      "useTurbo": true,
      "turboLora": "minimax_h3_fl2v_lightx2v_turbo_4step_v0.1_comfy.safetensors",
      "turboSteps": 4,
      "megapixels": 0.4,
      "preflight": true,
      "pollMs": 3000,
      "timeoutMs": 900000,
      "map": "{\"positive\":\"144.value\",\"duration\":\"133.value\",\"seed\":\"152.seed\",\"aspectRatio\":\"115.aspect_ratio\",\"megapixels\":\"115.megapixels\",\"firstFrame\":\"131.image\",\"lastImageNode\":\"\",\"lora\":\"151.lora_01\",\"steps\":\"152.steps\",\"promptOptimize\":\"150.switch\"}"
    }
  }
}
```

  - `map` 的键语义（值为 `<节点id>.<inputs字段名>`）：`positive` 提示词、`duration` 时长、`seed` 种子、`aspectRatio` 比例、`megapixels` 分辨率当量、`firstFrame` 首帧图、**`lastImageNode` 尾帧图（留空 = 不支持尾帧）**、`lora` 加速 LoRA、`steps` 步数、`promptOptimize`（**留空或显式关掉**，否则提示词会外发给第三方 LLM）。
  - **尾帧**：ComfyUI 本身没有「首尾帧参数」，实现方式是**上传两张图、分别写进两个 LoadImage 节点的 `inputs.image`**。因此要在 H3 工作流里真正做首尾帧，必须先在 `map.lastImageNode` 填上尾帧节点（如 `"132.image"`），否则本仓库会**明确报错**而不是静默丢帧。
  - `preflight: true` 会在提交前拉 `/object_info` 校验节点类型、必填项与模型清单 —— **这是云实例上最常见的 400 原因（`missing_node_type`）的第一道防线**，建议保持开启。
  - `useTurbo` + `turboLora` + `turboSteps`：本项目实测同一实例 20 步约 120s/条，turbo LoRA 4 步约 45s/条（2.7×）。`megapixels` 0.4 ≈ 864×480。
  - 提交后按 `pollMs`（默认 3000）轮询 `/history/{prompt_id}`，超时由 `timeoutMs`（默认 900000）控制；中断走 `POST /interrupt`。

```bash
curl -X POST -H "Authorization: Token {your_api_key}" -H "Content-Type: application/json" -d '
{ "model":"viduq3-pro",
  "images":["https://.../startend2video-1.jpeg","https://.../startend2video-2.jpeg"],
  "prompt":"The camera zooms in on the bird, ...",
  "duration":5, "seed":0, "resolution":"1080p", "audio":true, "off_peak":false }' \
 https://api.vidu.cn/ent/v2/start-end2video
```

  - **首尾帧的写法就是 `images` 数组：第一张 = 首帧，第二张 = 尾帧**（没有 `first_frame`/`last_frame` 这种命名）。
  - 约束：首/尾帧分辨率之比需在 **0.8~1.25**；图片比例需 < 1:4 或 4:1；png/jpeg/webp；≤50MB；**请求体 ≤20MB**；支持**图片 Base64 或 URL**，base64 需带 `data:image/png;base64,` 前缀。
  - 其他字段：`prompt`（接口文档 ≤5000 字符、FAQ 说约 1500 → **保守按 1500 设计**）、`duration`、`seed`、`resolution`、`movement_amplitude` ∈ `auto|small|medium|large`、`audio`、`off_peak`（错峰，**48 小时内生成，未完成自动取消并返还积分**）、`callback_url`。
  - **`img2video` 只支持 1 张图**（即只有首帧），首尾帧必须用 `start-end2video`。
- **模型 ID（文档真实出现）**：`viduq3-turbo`、`viduq3-pro`、`viduq3-pro-fast`、`viduq2-pro-fast`、`viduq2-pro`、`viduq2-turbo`、`viduq1`、`viduq1-classic`、`vidu2.0`。
- **响应**：提交返回 `task_id`（根字段）；查询 `state` ∈ `created|queueing|processing|success|failed`，结果在 **`creations[0].url`**（**24 小时有效期**），失败看 `err_code`（如 `TaskPromptPolicyViolation`、`CreditInsufficient`、`QuotaExceeded`…）。
- **计费（积分制，1 积分 = ¥0.03125）**：`viduq3-pro` 1080p **24 积分/秒**（错峰 12）、720p 20（错峰 10）；`viduq3-turbo` 1080p 13（错峰 7）、720p 12（错峰 6）。**生成失败不计积分（含审核拒绝）**。并发：500 元套餐 **≤5 并发**（无 QPS 概念）。
- **本项目适配映射（五家里最干净的一家）**

```json
{
  "video": {
    "backend": "generic-http",
    "generic": {
      "url": "https://api.vidu.cn/ent/v2/start-end2video",
      "method": "POST",
      "headers": "{\"Authorization\":\"Token {{apiKey}}\",\"Content-Type\":\"application/json\"}",
      "bodyTemplate": "{\"model\":\"viduq3-turbo\",\"images\":[\"{{refImage}}\",\"{{lastImage}}\"],\"prompt\":\"{{prompt}}\",\"duration\":5,\"resolution\":\"720p\",\"movement_amplitude\":\"auto\",\"off_peak\":false}",
      "refImageFormat": "dataurl",
      "apiKey": "<VIDU_API_KEY>",
      "model": "viduq3-turbo",
      "pollUrl": "https://api.vidu.cn/ent/v2/tasks/{{taskId}}/creations",
      "pollStatusPath": "state",
      "pollSuccessValues": "success",
      "responseVideoPath": "creations.0.url",
      "pollIntervalMs": 5000,
      "pollMaxTimes": 120
    }
  }
}
```

  - **成功值是 `success`**（不是 `succeeded`，别混）；失败值 `failed` 会被本仓库的 `/fail|error|cancel/i` 判定捕获 ✅。
  - `refImageFormat: dataurl` 最合适（Vidu 明确要求 `data:image/...;base64,` 形式），但注意**请求体 ≤20MB**，大图建议改用公网 URL。
  - 只要首帧时改用 `…/ent/v2/img2video` 并把 `images` 改成单元素数组，**同时删掉 `{{lastImage}}`**。

#### 3.3.6 五家共性坑（针对本仓库 `generic-http` 适配器）

1. **`duration` / `resolution` 常是枚举受限值**（Runway `veo3.1` 只收 4/6/8、Kling 2.5 Turbo 只收 5/10、Luma 必须是 `"5s"` 字符串）→ **写死在 `bodyTemplate`**，不要用 `{{duration}}`。
2. **轮询成功后 `data` 会被替换成轮询响应**，所以 `pollStatusPath` 与 `responseVideoPath` 都是**相对轮询响应根**的路径（不是提交响应）。
3. **`{{lastImage}}` 是「单向开关」**：模板里出现它，本仓库就认为你要尾帧；不接尾帧时若不换模板，会渲染出空字符串 → 多数厂商直接判参数非法 → **建议准备「首帧版」「首尾帧版」两套配置**（画布连线也要对应）。
4. **`refImageFormat` 要按厂商选**：MiniMax(v2)、Runway、Vidu 明确接受 Data URL（用 `dataurl`）；Kling 文档只写「url 或 base64」（用 `base64` 更稳）；**Luma 官方规范只声明 `url`**（能否 base64 未确证）。
5. **取片 URL 都有有效期**（MiniMax v1 1 小时、Runway 24~48 小时、Vidu 24 小时、Kling 30 天但防盗链）→ 本仓库「拿到即下载落盘」的逻辑正好适配，不要在前端缓存厂商直链。
6. **失败也可能计费**：Runway 明确「内容审核失败照样计费，反复触发可能封号」；MiniMax 与 Vidu 则明确审核失败不计费。接 Runway 时要在提示词侧更谨慎。

## 四、TTS（配音）

> **先看这条总缺口**：本项目 `tts.generic` 的 `bodyTemplate` 只有 **5 个占位符** —— `{{text}} {{voice}} {{model}} {{apiKey}} {{speed}}`，而且渲染结果**必须是合法 JSON**。因此：
> - 所有厂商的**音频格式参数**（Azure `X-Microsoft-OutputFormat`、火山 `encoding`、阿里 `input.format`、ElevenLabs `output_format`）**都无法从 `tts.format` 传下去** → 只能写死在 headers/body/url 里；
> - **语种 / 情感 / 方言 / 指令类参数**（火山 `emotion`+`explicit_language`、阿里 `instruction`+`language_hints`、ElevenLabs `language_code`）**全部传不进去**；
> - **动态唯一 ID**（火山 `reqid`）与**路径 / query 参数**（ElevenLabs 的 `voice_id`、`output_format`）是当前模板的**结构性盲区**。
> 这些不是配置问题，是**适配器能力边界**——要突破需改 `src/tts.js`（本次不改，只写清）。

### 4.1 OpenAI TTS（本项目 `openai` 后端，开箱可用）

- **官方文档**：`POST /v1/audio/speech` 参考 <https://platform.openai.com/docs/api-reference/audio/createSpeech>。
  ⚠️ **核证限制**：该域名对本机 curl 全部 403（Cloudflare），本节端点与字段取自 **OpenAI 官方 OpenAPI 规范仓库** <https://github.com/openai/openai-openapi>（`servers: https://api.openai.com/v1`，operationId `createSpeech`，schema `CreateSpeechRequest`）。**价格与中文语种清单未确证 → 未查到，需以官方定价页/控制台为准**。
- **鉴权**：`Authorization: Bearer $OPENAI_API_KEY`；Key 在 platform.openai.com 的 API keys 页创建。
- **base_url 与端点**：`https://api.openai.com/v1` + `/audio/speech` → `POST https://api.openai.com/v1/audio/speech`（无地域差异）。
- **请求体**（`additionalProperties: false`，**多传字段直接报错**）：

| 字段 | 必填 | 取值（规范原文） |
|---|---|---|
| `model` | ✅ | `tts-1`、`tts-1-hd`、`gpt-4o-mini-tts`、`gpt-4o-mini-tts-2025-12-15` |
| `input` | ✅ | 文本，**maxLength 4096 字符** |
| `voice` | ✅ | `alloy, ash, ballad, coral, echo, fable, onyx, nova, sage, shimmer, verse, marin, cedar`，或自定义 `{"id":"voice_1234"}` |
| `instructions` | ✖ | 语气控制，maxLength 4096；**不适用于 `tts-1` / `tts-1-hd`** |
| `response_format` | ✖ | `mp3`(默认)、`opus`、`aac`、`flac`、`wav`、`pcm` |
| `speed` | ✖ | **0.25 ~ 4.0**，默认 1 |
| `stream_format` | ✖ | `sse` / `audio`(默认)；`sse` 不支持 `tts-1`/`tts-1-hd` |

- **响应**：`200` 即**二进制音频流**（content-type 为 `audio/mpeg`、`audio/aac`、`audio/wav`、`application/octet-stream` 等）；错误码 `400`（参数/格式/音色非法）、`401`（key 缺失或吊销）、`403`（组织策略拦截）、`429`（限流）、`500`、`503`。**没有 SSML 支持**。
- **本项目映射（`tts.backend = "openai"`，零改动可用）**

```json
{
  "tts": {
    "backend": "openai",
    "retries": 3, "retryBaseMs": 800, "voice": "alloy", "model": "gpt-4o-mini-tts",
    "speed": 1, "format": "mp3",
    "openai": { "baseUrl": "https://api.openai.com", "apiKey": "sk-...",
                "path": "/v1/audio/speech", "model": "gpt-4o-mini-tts", "voice": "alloy" }
  }
}
```

  可传：`input`(整句台词)、`voice`、`model`、`speed`、`response_format`(=`tts.format`)。**传不了**：`instructions`（`gpt-4o-mini-tts` 最大的卖点是「用自然语言控制语气」，本项目 `src/tts.js` 的 openai 分支 body 是固定 5 字段 → **用不了**，需改代码）。长台词超 4096 字符会 400，需业务侧切句。

### 4.2 Azure AI Speech（当前仓库**无法直接对接**，需改代码）

- **官方文档**：REST 参考 <https://learn.microsoft.com/zh-cn/azure/ai-services/speech-service/rest-text-to-speech>；语言/音色支持 <https://learn.microsoft.com/zh-cn/azure/ai-services/speech-service/language-support?tabs=tts>；配额与限制 <https://learn.microsoft.com/zh-cn/azure/ai-services/speech-service/speech-services-quotas-and-limits>；定价 <https://azure.microsoft.com/en-us/pricing/details/cognitive-services/speech-services/>。
- **鉴权**（二选一）：`Ocp-Apim-Subscription-Key: <资源密钥>`，或 `Authorization: Bearer <access_token>`（token 由 `POST https://<region>.api.cognitive.microsoft.com/sts/v1.0/issueToken` 换取，**有效期 10 分钟**）。⚠️ 官方提示：**Bearer token 只在签发它的端点上有效**，跨主机用会 401。Key 在 Azure 门户 Speech 资源 →「密钥和终结点」。
- **base_url 与端点**：`POST https://{region}.tts.speech.microsoft.com/cognitiveservices/v1`（如 `eastasia`、`southeastasia`、`japaneast`、`eastus`、`westus2`）；自定义语音部署走 `https://{region}.voice.speech.microsoft.com/cognitiveservices/v1?deploymentId=...`；语音列表 `GET https://<资源名>.cognitiveservices.azure.com/tts/cognitiveservices/voices/list`（**区域域名形式的 voices/list 未在文档确证 → 以官方为准**）。
- **请求头（官方表）**：`Content-Type: application/ssml+xml`（必需）、`X-Microsoft-OutputFormat`（必需）、`User-Agent`（必需，**长度 < 255 字符**），加上鉴权头。**请求体是 SSML**（XML，不是 JSON），例如：

```xml
<speak version='1.0' xml:lang='zh-CN'><voice xml:lang='zh-CN' name='zh-CN-XiaoxiaoNeural'>我家的后面有一个很大的花园。</voice></speak>
```

- **响应**：`200` 直接是音频二进制（无 JSON 包装）；错误 `400`（缺参/header 过长）、`401`（key/token 无效或地域错）、`415`（Content-Type 不是 ssml+xml）、`429`、`502`、`503`。
- **中文音色（语言支持页）**：zh-CN / zh-HK / zh-TW 共 **39 个**，含 `zh-CN-XiaoxiaoNeural`、`zh-CN-YunxiNeural`、`zh-CN-YunyangNeural`、`zh-CN-YunjianNeural`、方言音色 `zh-CN-XiaoxiaoDialectsNeural` 与 8 个 `*MultilingualNeural` 多语种音色；`StyleList` 支持 narration-relaxed / cheerful / angry / sad / chat 等风格。
- **计费（官方定价页内嵌数据，us-east 值）**：标准 Neural **$15 / 100 万字符**；Neural HD **$22 / 100 万字符**；专业自定义语音 **$24 / 100 万字符**；免费层 F0 **每月 50 万字符**。
- **限制与坑**：**单请求音频最长 10 分钟**（超出被截断）；SSML 中 `<voice>` + `<audio>` 总数 ≤ 50；实时 TTS 事务数 F0 20/分钟、S0 默认 30 TPS。官方明确：**多数 429 不是配额问题**，而是该 region 内该音色的后端容量受限，「增加配额无法解决」，建议换音色原生 region 或热门音色。
- **本项目映射：❌ 现有两个后端都接不了，必须改 `src/tts.js`**：
  - `openai` 后端：端点与鉴权形态都不对，排除。
  - `generic-http` 后端：**结构性冲突** —— 它要求 `bodyTemplate` 渲染后是**合法 JSON**，而 Azure 要求 body 是 `application/ssml+xml` 的 **XML 原文**；把 SSML 塞进 JSON 模板会带上引号、Content-Type 也不对，必然失败。
  - 而且 `voice` 必须写进 SSML 的 `<voice name>`、`speed` 在 SSML 里是 `<prosody rate="+10%">`、音频格式在 **header** 里（`X-Microsoft-OutputFormat`，这个倒可以放 headers 模板）。
  - **落地路径**：新增一个「raw body + binary 响应」的通道（约 20 行改动），或新增 `backend: "azure-speech"`；region、`X-Microsoft-OutputFormat`、voice 名建议写死。

### 4.3 火山引擎语音技术（豆包语音 / 语音合成）

- **官方文档**：V1 HTTP 非流式（大模型）<https://www.volcengine.com/docs/6561/1257584>；V1 小模型 <https://www.volcengine.com/docs/6561/79820>；**参数与错误码全表 <https://www.volcengine.com/docs/6561/79823>**；V3 单向流式 <https://www.volcengine.com/docs/6561/2528925> 与完整参数 <https://www.volcengine.com/docs/6561/1598757>；鉴权方法 <https://www.volcengine.com/docs/6561/1105162>；计费 <https://www.volcengine.com/docs/6561/1359370>；音色列表 <https://www.volcengine.com/docs/6561/1257544>。
- **鉴权（三套并存，按控制台版本选）**：
  1. **新版 + V3（推荐）**：`X-Api-Key: <API Key>` + **`X-Api-Resource-Id`**（`seed-tts-2.0` / `seed-tts-1.0` / `seed-tts-1.0-concurr`，**决定模型版本与计费商品**）+ `X-Api-Request-Id`。
  2. **旧版 + V3**：`X-Api-App-Id` + `X-Api-Access-Key` + `X-Api-Resource-Id`（**双要素**）。
  3. **V1 老接口**：`Authorization: Bearer;{token}` —— **注意是分号 `;` 不是空格**（官方明确警告）；body 里还要带 `app.appid` / `app.cluster`。
- **base_url 与端点**：V1 非流式 `POST https://openspeech.bytedance.com/api/v1/tts`（**本项目最合用**）；V3 单向流式 `POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`（SSE 版加 `/sse`）；WebSocket `wss://openspeech.bytedance.com/api/v3/tts/unidirectional/stream`。
- **请求示例（V1 非流式）**

```bash
curl -X POST "https://openspeech.bytedance.com/api/v1/tts" \
  -H "Authorization: Bearer;YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "app":     {"appid":"123456789","token":"fake_token","cluster":"volcano_tts"},
    "user":    {"uid":"video-factory"},
    "audio":   {"voice_type":"zh_female_vv_uranus_bigtts","encoding":"mp3","rate":24000,"speed_ratio":1.0},
    "request": {"reqid":"<每次唯一的 UUID>","text":"字节跳动语音合成","text_type":"plain","operation":"query"}
  }'
```

  字段（官方表）：`audio.voice_type` 必填；`encoding` ∈ `wav|pcm|ogg_opus|mp3`（默认 pcm，**wav 不支持流式**）；`rate` ∈ 8000/16000/24000；`speed_ratio` ∈ [0.1, 2]（小模型 [0.2, 3]）；`volume_ratio` ∈ [0.5, 2]；`pitch_ratio` ∈ [0.1, 3]；`emotion` + `enable_emotion` + `emotion_scale`；`explicit_language` ∈ `crosslingual|zh-cn|en|ja|es-mx|id|pt-br`；`text_type` ∈ `plain|ssml`；HTTP 下 `operation` 只能 `query`。
- **响应（V1 是 JSON + base64，不是 URL）**：`{"reqid":"...","code":3000,"message":"Success","data":"<base64 音频>","addition":{"duration":"1960"}}`；V3 是逐块 base64 的流，需自行按顺序拼接。
- **错误码（V1 官方表）**：`3001` 无效请求、`3003` **并发超限**、`3005` 服务忙、`3006` 同 reqid 重复请求、`3010` **文本长度超限**、`3011` 无效文本、`3030` 处理超时、`3050` 音色不存在。V3：`40402003 TTSExceededTextLimit`、`45000000 speaker permission denied`。
- **音色与模型 ID（官方音色列表）**：豆包语音合成 2.0（`*_uranus_bigtts`）如 `zh_female_vv_uranus_bigtts`、`zh_female_xiaohe_uranus_bigtts`、`zh_male_m191_uranus_bigtts`、`zh_male_taocheng_uranus_bigtts`；旧音色如 `BV700_streaming`。V3 模型版本由 `X-Api-Resource-Id` 决定。
- **计费（官方计费页，元）**：**豆包语音合成模型 2.0 后付费 3 元/万字符**（资源包 2.8 元/万字符起）；大模型语音合成 1.0 后付费 **5 元/万字符**；声音复刻 2.0 3 元/万字符、大模型声音复刻 8 元/万字符；计费口径为**合成字符数**（1 汉字 = 1 字符，标点/空格/回车各 1，**SSML 标签也计费**）；正式版**默认 10 并发**，增购 **100 元/并发/月**；免费额度各 **20000 字符（半年有效）**。
- **中文支持**：原生中文主力，含 8 种方言音色与 30+ 语种识别。
- **坑与限制**：**V1 文本上限 1024 字节（UTF-8），官方建议 < 300 字符**，超限报 `3010`；**`request.reqid` 每次必须唯一**（重复报 `3006`）；**V1 不支持 2.0 音色**（要用 V3）；音频是 base64 需自行解码；音色需在控制台下单（含 0 元免费音色）否则 `45000000`。
- **本项目映射（`generic-http` + V1 非流式）**

```json
{
  "tts": {
    "backend": "generic-http",
    "retries": 2, "retryBaseMs": 1200, "voice": "zh_female_vv_uranus_bigtts",
    "model": "seed-tts-1.1", "format": "mp3",
    "generic": {
      "url": "https://openspeech.bytedance.com/api/v1/tts",
      "method": "POST",
      "headers": "{\"Authorization\":\"Bearer;{{apiKey}}\",\"Content-Type\":\"application/json\"}",
      "bodyTemplate": "{\"app\":{\"appid\":\"YOUR_APPID\",\"token\":\"fake_token\",\"cluster\":\"volcano_tts\"},\"user\":{\"uid\":\"video-factory\"},\"audio\":{\"voice_type\":\"{{voice}}\",\"encoding\":\"mp3\",\"rate\":24000,\"speed_ratio\":{{speed}}},\"request\":{\"reqid\":\"00000000-0000-0000-0000-000000000000\",\"text\":\"{{text}}\",\"text_type\":\"plain\",\"operation\":\"query\"}}",
      "responseType": "json",
      "responseAudioPath": "data"
    }
  }
}
```

  - 可传：`text`、`voice`(→`audio.voice_type`)、`speed`(→`speed_ratio`)、`apiKey`(→`Bearer;` 头)。
  - **必须写死**：`appid`、`cluster`、`uid`、`encoding`(=格式)、`rate`、`text_type`、`operation`。
  - **两个硬伤**：① `reqid` 无法动态生成（固定值有 `3006` 风险，建议后续在适配器里随机化）；② 1024 字节上限 → 本仓库整句直送，长台词必报 `3010`，需业务侧切句。
  - V3 不可用：响应是分片流，本仓库无法拼接。

### 4.5 ElevenLabs

- **官方文档**：Create speech <https://elevenlabs.io/docs/api-reference/text-to-speech/convert>；模型清单 <https://elevenlabs.io/docs/models>；API 定价 <https://elevenlabs.io/pricing/api>。
- **鉴权**：**`xi-api-key: <API key>`**（注意不是 `Authorization: Bearer`）；Key 在账户设置 → API Keys。

- **请求示例**

```bash
curl -X POST "https://api.elevenlabs.io/v1/text-to-speech/JBFqnCBsd6RMkjVDRZzb?output_format=mp3_44100_128" \
  -H "xi-api-key: $ELEVENLABS_API_KEY" -H "Content-Type: application/json" \
  -d '{"text":"今夜的风很大。","model_id":"eleven_multilingual_v2"}'
```

  - `output_format` 取值形如 `mp3_44100_128`（默认）、`mp3_22050_32`、`pcm_24000`、`wav_44100`、`opus_48000_64` 等（**192kbps mp3 需 Creator 档以上；44.1kHz 的 PCM/WAV 需 Pro 档以上**）。
  - body：`text`（必填）、`model_id`（默认 `eleven_multilingual_v2`）、`language_code`（**multilingual_v2 不支持该参数**）、`voice_settings{stability, similarity_boost, style, use_speaker_boost, speed}`、`seed`、`previous_text`/`next_text`、`previous_request_ids`/`next_request_ids`（≤3，用于长文连贯）。
- **响应**：`200` 是**二进制音频文件**（无 JSON 包装）；`422` 才是 JSON 校验错误 `{"detail":[...]}`。
- **模型 ID（官方模型表）**：`eleven_v4`、`eleven_v4_turbo`、`eleven_v3`、`eleven_v3_conversational`、`eleven_multilingual_v2`（默认）、`eleven_flash_v2_5`、`eleven_flash_v2`。
- **单请求字符上限（官方模型页）**：`eleven_multilingual_v2` **10,000**、`eleven_v3` **5,000**、`eleven_flash_v2_5` **40,000**、`eleven_v4` **10,000**。
- **计费**：API 按 1K 字符计价 —— TTS v4 **$0.08/1K 字符**（促销 $0.022）、v4 Turbo / v3 Conversational / Flash **$0.04**、v3 **$0.08**、v2 Multilingual **$0.08**；订阅制按 credits（**1 credit ≈ 1 字符**）。
- **中文支持**：`eleven_multilingual_v2` 官方语言表**明确包含 `zh`**（共 29 种语言）；`eleven_flash_v2_5` = v2 全部语言 + hu/no/vi。**要确定性中文支持请用 `eleven_multilingual_v2`**（v3/v4 只标称 70+/90+ 语言，未逐项列中文）。
- **本项目映射（`generic-http` + `responseType: binary`）**

```json
{
  "tts": {
    "backend": "generic-http",
    "retries": 3, "retryBaseMs": 1000, "voice": "JBFqnCBsd6RMkjVDRZzb",
    "model": "eleven_multilingual_v2", "format": "mp3",
    "generic": {
      "url": "https://api.elevenlabs.io/v1/text-to-speech/JBFqnCBsd6RMkjVDRZzb?output_format=mp3_44100_128",
      "method": "POST",
      "headers": "{\"xi-api-key\":\"{{apiKey}}\",\"Content-Type\":\"application/json\"}",
      "bodyTemplate": "{\"text\":\"{{text}}\",\"model_id\":\"{{model}}\"}",
      "responseType": "binary"
    }
  }
}
```

  - 🔴 **`voice_id` 只能写死在 `url` 里**：它是**路径参数**，`{{voice}}` 只能注入 headers/bodyTemplate，**换音色 = 改 config**。
  - ⚠️ `output_format` 是 query 参数，同样没有 `{{format}}` 占位符 → 写死在 url。
  - `responseType: "binary"` 会被适配器直接落盘（且响应 content-type 为 `audio/mpeg`，也满足「以 audio/ 开头即按二进制落盘」的兜底）。

### 4.6 五家横向对照

| 厂商 | 推荐 backend | 关键阻塞点 | 响应形态 |
|---|---|---|---|
| OpenAI | **`openai`（零改动）** | `instructions` 传不了；`input` ≤ 4096 字符需切句 | 二进制 |
| Azure Speech | **❌ 当前无法对接**（需改代码加 SSML/raw-body 通道） | body 必须是 SSML XML，与本仓库「bodyTemplate 必须渲染为合法 JSON」结构性冲突 | 二进制 |

## 五、视觉理解（可选：画面自检 / 一致性评分）

### 5.0 先看现状：本项目今天的「画面质检」是怎么做的

- `src/qc.js`：黑帧、静音、响度、时长不符、缺镜等**基于 ffmpeg 与文件属性**的检查；
- `src/consistency.js`：跨镜角色一致性用 **8×8 灰度平均哈希（aHash）的汉明距离**打分（按角色分组、取多数位中位哈希为基准、离群阈值默认 0.34）——**文件里已诚实写明口径**：「**不做人脸识别**，能抓住画风飘/明暗飘/构图飘，抓不住『同一画风但换了张脸』；接上真实出图后端后，把本文件的哈希换成 embedding 即可，调用方接口不变」。
- 角色字典里已经有 `qcVision`（kind = `vision`），内置三套方案分别配的是 `openai / gpt-4o-mini`（省钱、均衡）与 `openai / gpt-4o`（高质量）。
- **关键代码事实（决定「要不要改代码」，务必看）**：`src/llm.js` 的 `chat()` 里有这一句 —— `if (Array.isArray(opts.messages)) messages.push(...opts.messages)`，它是**原样透传**、不校验 `content` 类型的。所以：
  - ✅ **OpenAI / 阿里百炼兼容模式 / 火山方舟 Ark 三家，只要调用方自己把 `messages[].content` 传成内容块数组（含 `image_url`），就能零改造跑多模态**（这三家的端点拼接、`Authorization: Bearer`、`max_tokens`、`stream:false`、`response_format:{type:'json_object'}` 与本项目现状全部对得上）。
  - ⚠️ 但**当前没有任何调用方这么传**（`qc.js` / `consistency.js` 都不调用 LLM），所以「落地质检」仍需要**新增一个调用点**（新函数或新 API），只是**不必改 `llm.js` 本身**。
  - ⚠️ 用 `chatJSON()` 时有个真实的小坑：解析失败后的重试分支是 `chat({ ...opts, prompt: \`${opts.prompt}\n\n上一次输出不是合法 JSON…\` })` —— 如果你**只传 `messages` 不传 `prompt`**，重试会往最后追加一条内容为「`undefined`\n\n上一次输出不是合法 JSON…」的 user 文本消息（图片本身在 `messages` 里不会丢）。→ **多模态质检建议直接用 `chat()` + `parseJSONLoose()`，或记得同时传 `prompt`**。
  - ❌ **Gemini 必须新写调用分支**：`endpoint()` 会把 `https://generativelanguage.googleapis.com` 拼成 `…/v1/chat/completions`（错的），鉴权头固定 `authorization: Bearer`（Gemini 要 `x-goog-api-key`），请求体固定 `{model, messages, max_tokens}`（Gemini 要 `contents` + `generationConfig`），响应解析取 `data.choices[0].message.content`（Gemini 在 `candidates[0].content.parts[0].text`）——**四处都不兼容**。 **→ 已由 V-101 落地，见 5.8（本节其余判断仍成立）**

### 5.1 DeepSeek（`deepseek-flash`，官方支持图片输入 —— 与现有 Key 同源，最省事）

- **官方文档**：图像理解 <https://api-docs.deepseek.com/zh-cn/guides/vision/>；模型与价格 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing>（**本次已抓取正文核证**）。
- **鉴权**：`Authorization: Bearer $DEEPSEEK_API_KEY`（与文本同一把 Key）。
- **base_url 与端点**：`https://api.deepseek.com/chat/completions`（同步）；也支持 Anthropic 兼容 `/anthropic/messages` 与 Responses API。
- **图片怎么传（三种，官方原文）**：
  1. **Base64 内联**：`content` 为块数组，图片块 `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,<...>"}}`；
  2. **外部 URL**：`{"type":"image_url","image_url":{"url":"https://..."}}`（URL ≤ 8192 字符、≤32 MiB、**需 60 秒内可下载**）；
  3. **Files API**：先上传再用 `{"type":"file","file_id":"file-api-xxxx"}` 引用（单图上限提高到 64 MiB）。
- **请求示例（官方 curl）**

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" -H "Authorization: Bearer <Key>" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":[
        {"type":"text","text":"这张关键帧里人物是否变形？只输出 JSON：{\"ok\":true|false,\"reason\":\"\"}"},
        {"type":"image_url","image_url":{"url":"data:image/jpeg;base64,<BASE64>"}}]}]}'
```

- **限制（官方原文）**：支持 JPEG/PNG/GIF/WebP（**按文件实际内容判断**，不看扩展名/声明 MIME）；请求体 ≤ **48 MiB**；单图 ≤ 32 MiB（base64/URL）、≤ 64 MiB（Files API file_id）；**单请求最多 600 张图**；**单边最长 8192 px**（一次请求含 ≥15 张图时降为 4096 px）；**图片只能出现在 user 消息里**（system/assistant 带图返回 400）；`detail` 支持 `low`（缩到 512×512，省 token）/`high`（= `original`）/`original`/`auto`（当前等价 original）。
- **计费**：图片按尺寸折算 token 与文本一同计费，**每张图 token 有上限 1024**（小于约 544×544 会被放大、更大的会被缩到约 1300×1300 当量），官方提供「Token 与用量计算」页面的图片 token 计算器。
- **本项目接入建议**：**这是最划算的质检升级路径**（同一把 Key、同一 baseUrl、单价低、中文输出好，且**只要调用方传 `messages` 就能跑，不用改 `llm.js`**）。配置侧：

```json
{ "provider": "deepseek", "baseUrl": "https://api.deepseek.com/chat/completions", "model": "deepseek-flash" }
```

  并在 `models.roles.qcVision` 里写 `{ "provider": "deepseek", "model": "deepseek-flash", "temperature": 0.2 }`（注意：角色层当前只影响「设置页/接口展示与校验」，真正调用仍走全局 `llm` 段，见 6.0）。

### 5.2 阿里云百炼 通义千问 VL（Qwen-VL，OpenAI 兼容）

- **官方文档**：OpenAI Vision 接口兼容 <https://www.alibabacloud.com/help/zh/model-studio/qwen-vl-compatible-with-openai>（**本次已抓取正文核证**，`.md` 后缀可取 Markdown）。
- **鉴权**：`Authorization: Bearer $DASHSCOPE_API_KEY`（**Key 与地域绑定**，跨地域 401）。
- **base_url 与端点**：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`（旧域名 `https://dashscope.aliyuncs.com/compatible-mode/v1` 仍可用）→ `POST /chat/completions`；也可走 DashScope 原生 `…/api/v1/services/aigc/multimodal-generation/generation`。
- **模型 ID（文档真实出现）**：`qwen3-vl-plus`、`qwen-vl-plus`、`qwen-vl-max`。
- **图片怎么传**：OpenAI 兼容格式 —— `messages[].content` 为数组，图片块 `{"type":"image_url","image_url":{"url":"..."}}`（支持 URL 与 base64 data URL）。

- **中文 OCR（本项目的字幕/文字校验首选这家）**：官方文档有专门的「文字识别与信息抽取」能力说明（识别图中文字/公式、抽取票据表单信息、支持格式化输出），并有 `qwenvl html` / `qwenvl markdown` 文档解析提示词（Qwen3-VL 起支持 Markdown）。
- **本项目适配**：与 DeepSeek 一样，**只要调用方传 `messages` 数组就能跑，不用改 `llm.js`**。配置：

```json
{ "provider": "openai", "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1", "model": "qwen3-vl-plus" }
```

  官方建议：**非 Agent 通用对话场景不设 System Message**，把角色设定与输出格式要求写进 user 的 text 块（本项目 `chat({system})` 会插一条字符串 system 消息，质检场景建议改用 `messages` 自己拼）。

### 5.3 火山方舟 豆包视觉（Doubao，Ark）

- **官方文档**：对话（Chat）API <https://www.volcengine.com/docs/82379/1494384>（**本次已用官方文档接口抓取正文核证**）；Base URL 及鉴权 <https://www.volcengine.com/docs/82379/1298459>；「控制图片理解的精细度」见该文档内链接页。

### 5.4 OpenAI GPT-4o / GPT-5.x 视觉（本项目**改造最省**的一家）

- **鉴权**：`Authorization: Bearer $OPENAI_API_KEY`（规范 `securitySchemes.ApiKeyAuth`）。
- **base_url 与端点（规范 `servers`）**：`https://api.openai.com/v1`；`POST /chat/completions`（`createChatCompletion`）、`POST /responses`（`createResponse`）、`POST /responses/input_tokens`（**本地估 token，可先算钱**）。
- **图片传法**（规范逐字段确证）

```json
{ "model": "gpt-4o",
  "messages": [{ "role": "user", "content": [
    { "type": "image_url",
      "image_url": { "url": "https://… 或 data:image/jpeg;base64,<...>", "detail": "auto" } },
    { "type": "text", "text": "比较这两帧的人物一致性，输出 JSON 评分" } ] }] }
```

  - `type` 固定 `image_url`；`image_url.url` 官方描述原文「Either a URL of the image or the base64 encoded image data」→ **base64 要写成 data URL**；`detail` ∈ **`auto` / `low` / `high`**。

- **响应**：Chat → `choices[0].message.content`；Responses → `output[]` 中 `type:"output_text"` 项，文本在 `content[].text`。用量 `usage.prompt_tokens`/`completion_tokens`/`total_tokens`，图像 token 在明细里单列（规范示例有 `input_tokens_details:{"text_tokens":10,"image_tokens":40}`）。

- **结构化输出**：`response_format:{type:'json_object'}` 或 `{type:'json_schema', json_schema:{name, strict, schema}}`（`strict:true` 只支持 JSON Schema 子集；`json_object` 必须在提示词里明确要求输出 JSON）。
- **本项目适配**：**唯一「几乎零改造」能跑视觉的一家** —— `provider: "openai"` + `baseUrl: "https://api.openai.com"` 会被拼成 `https://api.openai.com/v1/chat/completions` ✅，鉴权 ✅，`response_format:{type:'json_object'}` ✅；只要调用方传多模态 `messages` 即可。

## 六、按专业角色的推荐搭配

### 6.0 先认清本项目的两条「角色层」事实（很重要，避免配了不生效）

1. **角色字典是真实的、可查的**：`src/model-registry.js` 定义了 **12 个角色**，并提供 `GET /api/settings/models` 返回每个角色「现在用什么模型、来自哪一层、还缺什么 Key」，还内置三套搭配方案（`省钱 / 均衡 / 高质量`）与校验函数。
   - 角色 id：`outline`（小说大纲）、`chapter`（章节写作）、`script`（剧本）、`storyboard`（分镜/提示词）、`promptOpt`（提示词优化）、`brief`（需求解析）、`keyframe`（关键帧出图）、`refImage`（参考图/定妆图）、`firstLast`（首尾帧图）、`video`（镜头视频）、`tts`（配音）、`qcVision`（画面质检）。
   - 优先级：角色显式设置 > 激活的搭配方案 > 该 kind 的既有分段默认（`llm` / `image` / `video` / `tts` 段）> 内置默认。
2. **但真实调用链目前走的是全局分段**：`src/llm.js` 取 `cfg.llm`（可被单次请求的 `provider/baseUrl/model` 覆盖，见 `src/modules/novel.js` 传入 `opts.provider`），出图/视频/配音分别取 `image.backend` / `video.backend` / `tts.backend`。因此下表是**搭配建议**：落地时要么改全局分段，要么在调用处显式指定，别指望只改 `models.roles` 就全链路生效。
3. **提供方白名单只有 9 个 id**（`PROVIDERS`）：`mock`、`placeholder`、`none`、`deepseek`、`openai`、`openai-images`、`generic-http`、`comfyui`、`comfyui-h3`。**通义千问 / 火山方舟 / 智谱 / Kimi / 硅基流动没有内置 provider id**，两条落地路径：
   - 文本类：选 `provider: "openai"`（OpenAI 兼容）+ 覆盖 `baseUrl` 指向该厂商的兼容端点；
   - 出图/视频/配音：选 `generic-http`，按第二、三、四节的模板填写。
   - 若想新增独立 provider id，需要改代码（本次不改）。

### 6.2 三套「可落地」的组合（按预算档）
