# 模块2 · 小说工坊 使用说明

> 100 种题材 → 角色规模（≤200）→ 总字数（≤1000 万）→ 结构化大纲 → 带上下文逐章写作 → 阅读/编辑/导出。

## 一、快速开始

1. 启动服务：`cd ai-video-factory && node server.js`（默认 http://127.0.0.1:8788/）。
2. 顶部进入「📖 小说工坊」。
3. 左侧「＋ 新建」→ 向导四步：
   1. **题材与参数**：题材（100 种，可按分类筛选 + 关键词搜索）、标题、基调、叙事视角、角色规模上限（≤200）、总字数（≤1000 万，含短/中/长/超长快捷档）、章节字数（1000~3000，滑块可调）、季/卷数；
   2. **定义演员**：点「载入演员表」勾选模块1 `actors` 里的演员（`C-0001` 形式），也可添加自定义角色（name/role/gender/age/desc，ID 自动分配 `CX-0001`）；两者合计 **不得超过角色规模，硬上限 200**；
   3. **故事框架介绍**：长文本直接写进输入框（越具体，大纲越贴合）；也可以点右侧「✨ AI 自动填写」让模型生成结构化框架、1 个主标题 + 2 个备选标题和推荐新角色，先预览再确认；
   4. **参考范本**（可选）：上传 txt/md/json，走 `POST /api/upload`，路径写入 `ref_doc_path`、原名写入 `ref_doc_name`，生成大纲时会把正文（前 12000 字）注入提示词。
4. 「创建项目」→ 进入工作区，点 **① 生成章节大纲**。
5. 大纲满意后点 **② 写作下一章** / **批量写作…**（下一章 / 指定范围 / 全部未写，可勾选强制重写）。
6. 「章节」标签页阅读、手动编辑保存、单章重写；「导出」标签页下载 TXT / Markdown / JSON。
7. 手动保存正文时，若字数不在 2500-3500 字范围，章节状态会显示「不足」或「超长」并给出中文提示；点「重写」可按目标范围重新生成。

### 一键流程（简化生成方式）

新建页与工作区顶部都有一排「一键流程」按钮，每步都会先保存当前表单，再进入下一步：

1. **① 一键加入参数角色**：若标题/题材为空，先调用「AI 头脑风暴创意题材规划」自动补全题材、基调、视角、角色规模与完整故事框架；保存后打开「故事框架 AI 自动填写」预览，确认即写入框架并创建/复用演员矩阵角色卡（不生图、不收费）。角色自由模式开启时，数量与风格全由 AI 按剧情规划。
2. **② 一键生成大纲**：按整条故事线逐章规划章首/章末与上下文衔接，并补齐全部非章节分节，进入后台队列（支持进度与取消）。
3. **③ 一键生成章节**：从第 1 章到最后一章逐章生成 2500-3500 字章节大纲（覆盖已有大纲，不动正文）。
4. **④ 一键写作**：对全部未写章节逐章写作 2500-3500 字正文，进入后台队列。

> 「一键生成大纲」在整份 JSON 生成失败时会自动切换到后台稳健模式；「③ 一键生成章节」要求已有大纲。

### AI 头脑风暴创意题材规划 / 题材写作技能提示词

题材区是「3 选 1」：① 选择系统题材 ② 题材生成器 ③ AI 头脑风暴。三者互斥，也可以关闭系统题材做自由创作。

- **① 选择系统题材**：100 种系统题材，可按分类筛选 / 关键词搜索；点「收起题材列表」折叠网格，点「关闭系统题材（不按 100 种写）」进入自由创作（`genre=custom-free`，不套用任何系统题材）。选定后点「📐 写作技能提示词」查看该题材专属的 7 模块写法参考，或点「查看 AI 题材创意引擎」。
- **② 题材生成器**：弹窗里选「世界背景 × 主角设定 × 核心冲突 × 叙事节奏 × 目标受众 × 基调」，可填题材名与关键词，点「生成题材」得到一个自定义题材（含定位、关键词、世界规则、循环危机、终极谜团、主角公式、爆款钩子、续集发动机、完整 7 模块框架与写作技能提示词）。规则组合生成，**不联网、不消耗额度**，与 AI 方案互补。
- **🕘 题材生成历史**：题材生成器与 AI 头脑风暴每次生成都会自动归档（同一题材只保留一条，重复生成覆盖更新），点「历史题材（N）」可查看：名称/分类/来源/使用次数/关键词/定位，支持「应用到表单」「删除」「清空历史」。历史存服务端表 `genre_generator_history`，重开页面仍在。
- **③ AI 头脑风暴创意题材规划**：让 AI 从 100 种题材里挑一个最易出爆款、可无限发展续集的题材，给出推荐基调、视角、角色规模、季数、标题、标题描述和完整 7 模块故事框架，预览确认后一次性写入表单。
- 自定义题材（生成器 / 头脑风暴）会写入 `novel_ai_settings.custom_genre` 与 `genre_mode`，小说 `genre` 保存为 `custom-xxxx`；框架 / 大纲 / 正文仍按该自定义题材名生成。
- 2026-10 起的接口：`GET /api/novels/ai/genre-skill-prompt`（系统题材确定性生成）、`GET /api/novels/ai/genre-generator-options` + `POST /api/novels/ai/generate-genre`（题材生成器）、`POST /api/novels/ai/brainstorm-genre`（AI 头脑风暴，真实 LLM 质量增强，mock 走离线模板）。

### 标题、题材、基调与自动化选项

- 基调提供 100 种组合预设，从题材推荐、情绪强度和叙事节奏自动生成候选。
- 标题输入框新增「标题描述」，用于补充标题意象、主角和核心冲突。
- 「AI 自动规划题材」会根据标题和标题描述，从 100 种题材中选择最匹配的题材并回填分类。
- 叙事视角可开启「AI 自动规划视角」，生成框架时返回推荐 POV 并自动回填。
- 角色规模可开启「AI 自动规划规模」，按剧情规模给出建议角色数量。
- 「无创意限制」按钮会取消用户手动设定，自动使用系统安全上限 200，并把角色数量交给剧情与角色自由模式规划。

### 角色自由模式（默认开启，位于「参数与角色」）

- 「参数与角色」栏内默认勾选「角色自由模式」；开启后「最多按剧情新增」输入框会隐藏，角色数量与风格全由 AI 按剧情规划（系统硬上限仍为 200）。关闭自由模式后才显示手动上限。
- 开启「角色自由模式」后会同时**收起「定义演员」整块**（演员表引用 + 自定义角色），避免和 AI 自动规划冲突；需要手动指定时点该栏右上「仍要手动定义演员与角色」临时展开，再点一次收起。
- AI 会结合故事大纲、章节章首章末、整条故事线和现有角色缺口，发现剧情必须新增的角色。
- 每个角色包含外观、性格、服装、背景、首次出场、剧情作用和故事线作用等详细描述。
- 角色会创建或复用演员矩阵 `C-xxxx`，并写入 `novel:<小说ID>` 标签、绑定到当前小说 `actor_ids`，形成本小说专属归档。
- 开启自由模式后，AI 生成大纲、自动规划生成或一键全部重写章节大纲时会自动触发一次角色缺口检查。
- mock 模式只显示规划说明，不自动创建角色卡。

### AI 设置与任务稳定性

- 小说级 AI 配置写入 `novel_ai_settings`，旧 `novels.meta` 会在首次访问时自动迁移。
- 角色创建后写入 `novel_character_links`，记录来源、剧情作用、首次出场和故事线作用。
- 一键全部重写章节大纲、稳健大纲生成和角色剧情补齐改为后台任务，支持进度、取消和失败记录。
- 费用预检会返回预计章节数、角色数和 LLM 调用次数。

### 故事框架 AI 自动填写

- **入口**：创建/编辑表单的「故事框架介绍」右侧「✨ AI 自动填写」；每次点击调用 1 次 LLM，「重新生成」会再调用 1 次。
- **依据**：题材、基调、叙事视角、总字数、单章字数、季数、角色规模、已选演员矩阵角色、自定义角色，以及上传的参考范本（前 12000 字）。
- **100 题材创意引擎**：每个题材都会自动生成独立的世界风格、世界规则、循环危机、终极谜团、主角公式、开局钩子、爆款钩子、爽点循环和续集发动机。题材栏的「查看 AI 题材创意引擎」可直接检查。
- **产出**：
  - 固定 7 模块创作骨架：世界观体系 / 人物矩阵 / 主线分段规划 / 支线储备库 / 基调主题与受众 / 叙事节奏与反转 / 伏笔管控。
  - 每个模块自动包含世界风格、世界规则、开放区域、循环危机、终极谜团、主角特别之处、成长代价、三层反派、分季锁坑、开局与结局闭环。
  - 季数和主线阶段根据小说总字数自动缩放：短篇保持单季闭环，中长篇逐季扩展，长篇和超长篇预留持续新地图与终极谜团。
  - 1 个主标题 + 2 个备选标题，单个不超过 20 字。
  - 最多 8 个按剧情推荐的新角色，含定位、性别、年龄、外观、性格、服装、背景、剧情作用。
- **确认行为**：
  - 标题和故事框架直接覆盖当前表单（已有内容也会覆盖；确认前会先弹预览）。
  - 勾选的新角色会创建演员矩阵正式角色卡（`C-xxxx`），同名角色自动复用，不重复建卡。
  - **不会自动生成定妆图**，不产生出图费用；需要定妆图时到演员矩阵手动触发。
  - 角色总数仍受当前 `cast_size` 和 200 硬上限约束，超限会中文拒绝。
- **离线模式**：LLM provider 为 `mock` 时只生成带「【离线占位】」标记的框架和标题，不创建角色卡，避免污染角色库。

## 二、两步生成分别做什么

### ① 生成章节大纲（一次性结构化 JSON）

用 `chatJSON` 生成，按 `总字数 ÷ 章节字数` 推导章节数（**单次上限 200 章**，超出会提示分卷/分批继续），并按批次调用模型（默认每批 20 章，首批同时产出总纲），避免单次输出过长被截断。产出字段：

| 字段 | 内容 |
|---|---|
| `logline` | 一句话故事 |
| `framework` | 故事框架逻辑：核心冲突、主角目标、对立力量、三幕、主题、结局走向 |
| `worldview` | 世界观/力量体系/禁忌 |
| `volumes` | 卷（季）结构：起止章、卷目标、卷高潮 |
| `chapters` | 全篇章节走向：标题、起因→推进→结果摘要、关键事件、开场钩子、**章末钩子**、人物ID、地点ID、视角、关联伏笔 |
| `timeline` | **宏大时间线**：故事内时间、事件、对应章节、对后续影响 |
| `locations` | **地点档案**：`L-0001` 编号、名称、类型、环境要点、首次出现章、归属 |
| `characters` | **人物 ID 出场规划**：`C-xxxx`/`CX-xxxx`、定位、出场章、人物弧光、作用、关系 |
| `foreshadow` | **伏笔表**：埋设章 → 回收章、内容、回收方式、状态 |
| `reversals` | 反转清单：章节、类型、内容、影响 |
| `beats` | **节奏卡点**：爽点/虐点 + 强度 1~10（前端画成曲线条） |
| `hooks` | 钩子银行：每章章末钩子 |
| `loops` | **跨季章节时间回路**：闭环/闪回/预叙、from→to 章、呼应关系 |
| `logic` | 全篇逻辑关系与因果链：因 → 果、关系、说明 |

结果写入 `novel_outlines.payload`（JSON 字符串）与 `raw`（模型原文），并同步生成 `novel_chapters` 骨架行（title/summary/hook/cliffhanger/characters/locations，`status='outline'`）。
**已写完（status=done）的章节正文永远不会被重新生成的大纲覆盖。**

- **按指令优化**：`POST /api/novels/:id/outline/optimize`，用中文写清改什么（例：前三章节奏加快、反派提前到第 5 章、伏笔 F-01 提前到第 8 章回收），产出新版本；只改内容不删章。
- **续规划章节（分卷/分批继续）**：`POST /api/novels/:id/outline` 带 `{chapterFrom: N, chapterCount: M}`，或前端大纲面板的「⤵ 续规划章节」按钮。保留第 1~N-1 章既有大纲与全部正文，从第 N 章往后继续规划（单次最多 200 章），新产出的日期/地点/伏笔/时间线/回路会合并进同一份大纲并产出新版本。1000 万字推导出的上千章就是靠它一批批补齐。
- **生成时的额外要求**：`POST /api/novels/:id/outline` 的 `instruction` 字段同样会以最高优先级注入提示词，并记录在 `meta.instruction`。
- **指定章节规划**：每章大纲必须同时规划 `start_state`（章首承接）、`end_state`（章末落点）、`handoff_in/out`（上下章交接）、`storyline_anchor`（整条故事线锚点），不能只写章节开头。
- **一键全部重写**：章节区点「一键全部重写」，按每批 20 章从第 1 章重写到最后一章，并强制校验前后章状态衔接和故事线闭环。

### ② 根据大纲写成完整章节小说

逐章生成，每章都带完整上下文（`src/modules/novel.js` 的 `chapterContext()` / `renderChapterContext()`）：

1. 全书框架（logline + 框架 + 世界观 + 作者框架介绍 + 本卷结构）；
2. 该章大纲（走向、关键事件、开场钩子、**章末必须落在的钩子**、情绪卡点、本章反转）；
3. 前 2~3 章的摘要 + **结尾 500 字原文**（不得矛盾、不得重复叙述）；
4. 相关人物档案（姓名/定位/性别年龄/性格背景/弧光/作用/关系）与地点档案（L 编号）；
5. **未回收伏笔清单**（埋设章 ≤ 本章且未回收）+ 本章必须回收的伏笔；
6. **已发生事件时间线**（本章之前的全部条目）+ 因果链参考 + 跨季时间回路；
7. 下一章预告（本章结尾要留接口）。

生成走 `enqueue({type:'novel'})` 异步任务，前端用 `ctx.watchJob` 轮询进度（进度条 + 已写/总数 + 取消）。字数用 `countWords()` 统计：低于目标 80% 时**在同一次生成里**追加一次「续写补足」调用（只续一次，不会无限重试）；模型未产出或接口报错会把该章标记 `status='error'` 并记录中文原因，任务继续写后面的章。

## 三、HTTP 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/novels` | 项目列表（含已写章数/总字数/进度），并返回 LLM 状态 |
| POST | `/api/novels` | 创建（校验 cast_size ≤200、target_words ≤1000 万、chapter_words ∈[1000,3000]） |
| GET | `/api/novels/:id` | 详情：小说 + 最新大纲 + 章节列表（**不含正文**）+ 统计 + 演员/角色 + 范本预览 |
| GET | `/api/novels/:id/assets` | 全量资产 ID 索引：人物 `C-xxxx` / 环境 `L-xxxx` / 物品 `P-xxxx` |
| GET/PUT | `/api/novels/:id/characters/free-mode` | 读取或保存角色自由模式、数量上限和风格策略 |
| POST | `/api/novels/:id/characters/free-mode/plan` | 只规划剧情缺口角色，不写库 |
| POST | `/api/novels/:id/characters/free-mode/auto` | 自动发现并归档角色到当前小说 |
| PUT | `/api/novels/:id` | 更新参数（同样校验，越界拒绝且不写入） |
| DELETE | `/api/novels/:id` | 删除，并连带删除其大纲与章节 |
| GET | `/api/novels/:id/outline` | 最新大纲（含 13 个分节、版本历史、章节骨架） |
| POST | `/api/novels/:id/outline` | 生成大纲 `{instruction?, refText?, chapterCount?, chapterFrom?, saveVersion?, batchSize?}`；`chapterFrom>1` 为续规划模式 |
| POST | `/api/novels/:id/outline/optimize` | 按用户指令优化大纲 `{instruction}` |
| POST | `/api/novels/:id/chapters/generate` | 批量写作 `{from?,to?,count?,mode?:'next'\|'range'\|'all',force?}` → `{jobId,total,idxs}` |
| POST | `/api/novels/:id/chapters/:idx/generate` | 单章重写 → `{jobId,total}` |
| GET | `/api/novels/:id/chapters/:idx` | 读取单章（含正文） |
| PUT | `/api/novels/:id/chapters/:idx` | 手动保存正文/标题/摘要（按 countWords 重新统计） |
| DELETE | `/api/novels/:id/chapters/:idx` | 删除章节 |
| GET | `/api/novels/:id/export?format=txt\|md\|json` | 导出；带 `download=1` 时直接以附件输出 |
| POST | `/api/novels/:id/actors` | 更新演员绑定 `{actorIds:[], customActors:[]}` |
| POST | `/api/novels/ai/framework` | 故事框架 AI 自动填写：生成框架/标题/角色提案，只生成不写库 |
| GET | `/api/novels/ai/genre-blueprints` | 返回 100 种题材的创意引擎；带 `genre=<id>` 时查询单个题材 |
| GET | `/api/novels/ai/creative-options` | 返回 100 种基调、题材数量和自动化能力开关 |
| POST | `/api/novels/ai/plan-genre` | 根据标题和标题描述自动从 100 种题材中规划题材 |
| GET/PUT | `/api/novels/:id/creative-options` | 读取或保存标题描述、AI 自动视角、AI 自动角色规模和无创意限制设置 |
| GET/PUT | `/api/novels/:id/ai-settings` | 小说级 AI 配置权威接口 |

| GET | `/api/novels/:id/estimate?action=outline\|characters\|chapter-write` | LLM 调用与任务规模预估 |
| POST | `/api/novels/:id/outline/ai/rewrite-all` | 后台一键重写全部章节大纲 |
| POST | `/api/novels/:id/outline/ai/robust-job` | 后台稳健生成完整大纲 |

| GET | `/api/novels/options` | 题材(100)/分类/视角/基调/上限/大纲分节字典（前端兜底用） |

> 大纲与正文提示词默认注入全量资产 ID 索引，并按「故事大纲 > 正文内容承接 > 头尾逻辑与故事线闭环」排序。故事大纲页增加「头尾逻辑与故事线」分节，用于写清开篇逻辑、因果链、重大转折、结局逻辑、头尾闭环和最终画面。

`POST /api/novels/:id/outline` 与优化接口是**同步**调用（按批次数次 LLM 调用）；章节写作是**异步任务**，用 `GET /api/jobs/:id` 轮询（或 `ctx.watchJob`）。

## 四、LLM 未配置 / 失败怎么办

- 界面顶部与工作区会显示黄色提示条；错误弹窗给出两条路径：
  1. 「设置」页 → LLM → provider `deepseek` + API Key（或 `~/.dsh/.credentials.yaml` 的 `DEEPSEEK_API_KEY`）；
  2. 「设置」页 → LLM → provider **`mock`（离线模板）**：不联网、不消耗额度，产出结构、ID 规则、伏笔表等字段与真实生成完全一致的占位内容，用于先把「大纲 → 章节 → 导出」流程跑通。
- 也支持任何 OpenAI 兼容服务：设置页把 `baseUrl` 指到本地服务（如 `http://127.0.0.1:11434/v1`）并填模型名即可。
- 所有 LLM 调用都包了 `try/catch`：失败会返回明确中文错误、章节标记为 `error`，不会让服务崩溃。

## 五、自测

```bash
node tests/test-novel.js                 # mock 全链路（默认跳过真实 LLM；设置 SKIP_REAL_LLM=1 更明确）
node tests/test-novel-ai.js              # 故事框架 AI 自动填写自测（mock + 角色卡 + 上限 + HTTP）
```

- 独立 DB 和数据目录：默认写入系统临时目录，测试结束自动清理。
- 覆盖：参数越界拒绝、题材/上限字典、大纲生成（mock 全链路 + instruction + 200 章上限 + 分批 + 续规划合并）、大纲优化、真实 `chatJSON` 调用、章节 job 写作与续写、章节 CRUD、参考范本上传与回读、演员绑定上限、导出（txt/md/json + 附件下载）、404 分支、前端视图渲染冒烟（DOM 桩，13 个分节 / 阅读器 / 编辑器 / 导出面板 / 创建向导）、故事框架 AI 自动填写（mock 生成 / 角色卡创建复用 / 上限校验 / HTTP 接口）以及真实前端 API 层（`web/lib/api.js` 的 upload/readText/watchJob）。

## 六、实现要点与已知限制

- 单次规划上限 200 章、每批 20 章：1000 万字（≈10000 章）需要多次「续规划章节」逐步补齐（每次 200 章，约 50 次）。
- 超长篇真实写作成本很高：每章 1~2 次 LLM 调用，200 章以上建议分批跑并在夜间执行。
- 模型可能超出目标字数（实测目标 1000 字可写出 1600+ 字）：只在**不足**时补写，不会截断正文（截断会破坏文气）。
- 大纲是「一份 JSON」：模型偶尔漏字段时用占位/空值兜底并在 `meta.warnings` 里给出中文提示，可点「重新生成」或「按指令优化」补全。
- 前端不 import 任何 `web/lib/*`，只用契约里的 `ctx`（`api/meta/toast/confirm/modal/watchJob/go`），样式类名统一 `nv-` 前缀并自行注入 `<style id="nv-style">`。
