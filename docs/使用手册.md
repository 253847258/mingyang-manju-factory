## 0. 启动

```bash
cd ai-video-factory
./start.sh                      # 推荐：带单实例守卫（检测到已有实例会拒绝启动并给出精确 kill 命令）
node server.js                  # 直接启动（无守卫，自己保证只有一个实例）
```

> **单实例守卫（本轮 P0）**：`./start.sh` 会先探测「端口占用者 PID」与「已存在的 `node server.js` PID」，**有实例就直接拒绝启动**，并逐个打印 `kill <PID>` 的精确命令（卡死才用 `kill -9 <PID>`）。脚本自身**绝不 `kill`/`pkill` 任何进程**，处置权交给你。确实要并存（不推荐，两份内存配置缓存会互相覆盖 → 配置漂移）用 `bash start.sh --force`，它会打印风险提示。出处：`start.sh:7-10`、`:51-62`、`:16-18`。
控制台会打印：

```
界面： http://127.0.0.1:8788/
LLM ： deepseek / deepseek-chat （Key 已配置）
出图： placeholder （就绪）
模块： 模块1 演员宫格 ✅ ｜ 模块2 小说 ✅ ｜ 模块3 剧本 ✅
```

浏览器打开该地址即可。右上角三个状态徽章（🤖 LLM / 🖼 出图 / 📊 计数）随时反映后端状态。

**首次使用建议**
1. `./scripts/verify-all.sh` —— 全量自检（**35 个阶段**；**第 9 波**实测 **35/35 阶段全部通过、断言合计 3519、失败 0、退出码 0**（合计不是固定值），末行 `✅ 全部自检通过`。**口径：阶段数固定为 35；单阶段断言数与其合计数随代码演进，一律以 `./scripts/verify-all.sh` 的输出为准** —— 每阶段结尾都打印 `=== 结果：N 通过 / 0 失败 ===`，运行标签是 `N/35`），全部用临时库与离线假实例，不动你的数据、不花模型钱（仅模块 3 的 2 次真实 LLM 小调用用于验证连通性）。
2. `node scripts/seed-demo.js` —— 写入 10 位演示演员 + 宫格排布 + 定妆图，用于快速熟悉界面。
   - 想一次看全四个模块跑通：`node scripts/simulate-all.js` —— 用临时库离线跑完「演员档案/定妆图 → 无限画布与关系线 → 小说大纲与章节 → 剧本分集与分镜 → 关键帧/视频/整集成片 → 画布资产桥」，逐项断言并产出 `docs/全模块功能模拟测试报告.md`（含落库/落盘/ffprobe 证据），不花模型钱、不动你的数据。
3. 打开「⚙️ 设置」配好 LLM 与出图后端。

## 1. 模块一：明星演员矩阵

### 1.1 界面构成

- **左栏「演员阵容」**：搜索框（姓名/ID/标签）、画风筛选、演员列表；点选高亮，双击打开档案，右键弹出该演员的生成清单。
- **中间「宫格矩阵画布」**：每个格子 = 一位演员的卡位，显示定妆主图（无图时显示渐变占位 + 首字）、演员 ID、姓名、角色类型、画风徽章、素材数量。
- **顶部工具条**：新建演员 / 自动排布宫格 / 切换「宫格 ⇄ 自由」/ 列数 / 格宽 / 缩放 / 复位 / 批量生成 / 刷新。
- **右侧「明星档案」抽屉**：双击格子或右键「打开明星档案」打开。

### 1.2 无限画布（完整操作清单）

画布是**无限画布**：世界坐标没有边界，缩放 5%～800%，可在任意方向无限延伸；每个画布独立保存自己的缩放/平移/背景设置，刷新或切换画布后原样恢复。

| 操作 | 效果 |
|---|---|
| 左键点击卡片 | 选中（单选） |
| **空白处左键拖拽** | **框选**（橡皮筋）；Shift/Ctrl 追加框选 |
| Ctrl / Cmd / Shift + 点击 | 加选/取消；多选时卡片显示 **1…n 顺序角标**（双人同框、批量生成按此顺序） |
| 拖拽卡片（宫格模式） | 与目标**换位**（一次批量请求落库） |
| 拖拽卡片（自由模式） | 任意摆放 + **网格吸附 + 对齐参考线** |
| 方向键 ←→↑↓ | 宫格=换位；自由=微调（Shift 大步 40px） |
| **滚轮 / 触控板捏合** | 缩放（**以光标为中心**，5%～800%） |
| **空格 + 拖动 / 中键 / Alt + 拖动 / 触控板双指** | 平移 |
| **双击空白** | **在光标处新建演员**（卡位直接落在该位置，自动进入自由模式） |
| 双击卡片 | 打开明星档案 |
| 右键卡片 | 生成清单 + AI 补全 + 复制副本 + **🔗 连线到…** + **🔗 管理连线** + 锁定卡位 + 移到最前 + 删除 |
| 右键空白 | **📍 在此处新建演员** + 排布 + 全选/取消 + 批量生成 + 视图 + **导出 PNG** + 新建画布 |
| **F** / **0** / **Ctrl+2** / **Home** | 适应窗口 / 复位 100% / **缩放到选中** / 回到原点 |
| **Ctrl+A** / **Esc** / **Enter** / **Del** / **Ctrl+D** / **Ctrl+L** | 全选 / 取消 / 打开档案 / 删除 / 复制副本 / 显隐连线 |

**视图控件**
- **左下缩放条**：`− 65% ＋ ⤢ ▣`（缩放、点击百分比复位、适应窗口、缩放到选中）
- **右下小地图**：实时缩略图 + 当前视口矩形，**点击或拖拽即可跳转**；工具栏可开关
- **顶部 HUD**：缩放百分比 · 模式 · 卡片总数（超出视野显示"视野内 n"）· 已选数 · 关系连线数 · **LOD 级别**
- **工具栏**：新建演员 · 画布选择器 · 新建画布 · 排布（宫格/画风/角色/种族）· 列数 · 格宽 · 模式 · 吸附 · **背景（点阵/网格/纯色 + 网格 20/40/80）** · 小地图开关 · 连线开关 · 缩放 · 导出 PNG · 批量生成

**多选工具条**（选中 ≥2 张时出现在底部中央）：左/水平居中/右对齐 · 顶/垂直居中/底对齐 · **横向等距分布 / 纵向等距分布**（自由模式，立即落库）。

**关系连线**：右键卡片 →「🔗 连线到…」选择目标 + 关系标签（对手戏/亲属/敌对/师徒/恋人/同盟/上下级/宿敌，也可自定义）→ 画布上以贝塞尔曲线 + 标签呈现，选中相关演员时高亮；「🔗 管理该演员的连线」可逐条删除。连线只用于关系可视化，不影响出图与剧本数据。

**LOD 分级渲染**：缩放 < 22% 只画色块与姓名（不加载图片）、22%~50% 画图与徽章、> 50% 全信息 —— 200 位演员在无限画布上依然顺滑；配合视口裁剪，只渲染可视区域。

**节点类型（五类）+ 左右端口连线**

| 类型 | 创建方式 | 内容 |
|---|---|---|
| 🎭 演员卡 | 演员表 / 拖入 | 定妆主图、ID·角色·身高、素材数 |
| 🏞 环境节点 | 工具栏 `🏞 环境` / 右键空白 | 标题、时间、天气/氛围、描述、标签、**参考图矩阵** |
| 🗝 物品节点 | 工具栏 `🗝 物品` / 右键空白 | 标题、分类、持有者、描述、标签、**参考图矩阵** |
| 🖼 参考图节点 | 工具栏 `🖼 参考图` / 右键空白 | 多张参考图（1–4 列矩阵）、标签、说明 |
| 📝 便签 | 工具栏 `📝 便签` / 右键空白 | 多行文字、6 色 |

- **参考图矩阵**：工具栏 `🧩 参考图矩阵`（或右键空白）→ 一次选择多张图 → 自动生成 N 个参考图节点、按矩阵排布并**自动成组**，可整组拖动/收起。
- **给任意节点挂参考图**：右键节点 → `📎 上传参考图（可多选）`，第一张自动为主参考；编辑面板里可查看缩略图矩阵、移除单张。
- **左右端口连线（核心）**：每个节点左右各有一个端口（选中/悬停时高亮）——
  - **拖拽**：从右端口（蓝）拖到目标节点松手 → 弹出关系标签面板（参考/出现在/持有/使用/饰演/对手戏/敌对/同盟/场景切换/道具来源 + 自定义）→ 一键建线；
  - **点两次**：单击端口进入「起点已选」（Esc 取消），再点目标节点即可建线；
  - **数量不限**：任意两个节点之间都可连，同方向多条、双向、环状都可以（实测一次建 20+ 条无压力，HUD 实时显示 `🔗 n`）。
- **关系线操作**：右键线条可**修改标签 / 反转方向 / 删除**；节点右键 `🧹 清理该节点的全部连线`；删除节点会级联清理其连线。
- 连线会记录**出线侧/入线侧**（right/left），渲染为贝塞尔曲线 + 箭头 + 标签，选中相关节点时整条线高亮。

**画布组合出图（连线即约束）**

把画布当成生成控制台：**演员卡 × 环境节点 × 物品节点 × 参考图节点** 可一键合成出图。

1. 在画布上选中参与出图的节点（点选 / Ctrl 多选 / 选中分组）；
2. 工具栏 **`⚡ 组合出图`**（或演员卡右键「与选中的环境/物品组合出图…」、资产节点右键「与选中演员组合出图」）；
3. 面板里选类型（全身定妆 / 脸部特写 / 多角色同框 / 姿态 / 自由构图）、比例、张数、种子、补充正负向词，可开关 **「带上连线关联的节点」**；面板底部**实时预览**合成后的英文正负向词与参与节点摘要；
4. 点「🚀 开始生成」→ 结果**同时**写入演员素材库（`kind=compose`，可在档案里设为主图）并挂到参与的环境/物品节点（节点内以矩阵缩略图展示最新 12 张）。

- **提示词合成规则**：风格头（取演员/默认画风）→ 镜头模板 + **人物锚点**（`subjectFragment`，多演员会拼成 group shot）→ `in {环境：时间/天气/标题/描述/标签}` → `with {物品：标题/分类/描述/标签}` → 参考图节点信息 → 补充词 → 质量尾 → 风格尾；负向词 = 风格负面 + 通用负面 + 补充。
- **参考生图**：若参与节点里带有参考图（参考图节点或环境/物品节点挂的图，取第一张为主参考），会自动作为参考图提交（面板会标注「使用参考图：xxx」）。
- **环境/物品节点单独出图**：右键节点 →「🎨 生成概念图（文生图）」，结果同样挂到节点内。

**画布资产桥（画布 → 剧本 → 分镜 → 关键帧）**

把画布上设计好的**环境 / 物品 / 参考图**变成生产链上的权威设定：

1. **绑定**：剧本工厂 → 右侧「🎨 绑定画布资产」→ 选择画布 → 绑定（可随时解绑）。绑定快照存进该剧本，不随画布后续改动而变（想更新就重新绑定一次）。
2. **分镜增强**：生成分镜时——
   - 画布环境与小说地点**同名即合并**（保留原地点 ID，如 `L-0001 雾港码头` 会带上画布设定的英文令牌）；
   - 每镜提示词自动附加 `canvas set: late night, dense fog, harbor pier, wooden pier`（令牌级去重，纯英文）；
   - 动作/台词提到画布道具名（如「停摆怀表」）时，自动附加该道具英文令牌；
   - 每镜的 `refs.canvas` 记录命中的环境节点、道具节点与**可用参考图**。
3. **关键帧参考生图**：制作台渲染关键帧时，若镜头有 `refs.canvas.refImages`，会自动把它作为**参考图**提交（结果记录的 `meta.canvasRef` 可查）。可在设置页或 `config.json` 里用 `image.useCanvasRefs=false` 关闭。
4. **资产清单导出**：`GET /api/canvas/:id/export-assets?format=md|csv|json`（带 `&download=1` 直接下载），产出环境/物品/参考图/关系线/演员出场的完整清单，供美术与制作参考。

**节点（卡片）能力**
- **单卡缩放**：选中卡片后拖右下角蓝色手柄即可改单张尺寸（落库）；「📐 统一尺寸」把选中卡片统一成当前格宽。
- **层级**：`]` 置于顶层 / `[` 置于底层（右键菜单也有 上移/下移一层），绘制与命中原生按 z 排序。
- **便签节点**：工具栏 `📝 便签`（或右键空白 →「在此处新建便签」）新建便签，双击编辑文字、6 种颜色、可拖动/缩放/删除；便签可 `Ctrl+C` / `Ctrl+V` 复制粘贴到视野内。
- **演员卡是画布唯一节点**：`Ctrl+C` 会提示改用 `Ctrl+D`（生成新演员「副本」），避免误解为可以重复摆同一张卡。

**分组框（Frame）**
- **成组**：选中若干卡片 → 工具栏 `🗂 成组`（或 `Ctrl+G`、右键「组成分组」）→ 自动生成贴合包围盒的分组框。
- **整体操作**：拖标题栏整组移动（组内卡片同步位移并落库）；拖边框改大小；点标题栏选中；双击标题栏重命名。
- **右键菜单**：重命名 / 收起·展开 / 换颜色 / 选中组内全部 / 把当前选中项加入或移出本组 / 贴合内容大小 / **解散分组（保留卡片）** / 解散并删除组内卡位。
- **收起**：折叠成一条标题栏，组内卡片不再绘制与命中（画布清爽）；展开即恢复。
- **自动分组**：`🎨 画风组` / `🎭 角色组` / `🧬 种族组` 一键按字段生成真实分组框（同时完成宫格排布）。

**画布 → 业务联动（选角中枢）**
- **拖拽放置**：把左侧演员列表的条目直接**拖到画布上**即可放置卡片；**拖进某个分组框内自动归入该分组**（落点会被约束在框内）。
- **拖拽归组**：在画布上把卡片拖到分组框范围内松手，也会自动加入该分组。
- **分组批量出图**：右键分组 →「🎬 为组内演员批量生成定妆图」→ 全身主图 / 脸部特写 / 全部 12 表情 / 多角度全身，或自定义参数（一次提交组内全部演员）。
- **分组加入小说选角**：右键分组 →「📖 把组内演员加入小说选角…」→ 选择小说 → 组内演员自动并入该小说的演员表（演员卡右键也有同样入口）；超角色规模时会给出中文提示。
- **复制组内演员 ID 清单** / **清空组内成员（保留分组框）**。

**撤销 / 重做**
- `Ctrl+Z` 撤销、`Ctrl+Shift+Z`（或 `Ctrl+Y`）重做，最多 40 步；覆盖拖动、对齐、分布、排布、成组、便签、层级、统一尺寸、删除等画布操作（不涉及演员档案与出图）。
- 实现方式：每次操作前对「**该画布全部卡位** + 分组 + 便签」拍快照（含被筛选/折叠隐藏的卡片，避免恢复时丢卡片），撤销时通过 `POST /api/canvas/restore` 原子恢复；HUD 上的 `↶ n` 显示可撤销步数。

**多画布（语义明确）**
- **主画布 `CV-MAIN`**：常驻显示全部演员（宫格预览），`showAll = true`。
- **新建画布**：是**独立空间，默认从空开始**（`showAll = false`）——空态会给出「⊕ 放入全部演员」按钮，也可双击空白在光标处新建、或拖入卡片。
- 工具栏 `⊕ 放入全部`（把演员表全部放入本画布，宫格）与 `⌀ 清空本画布`（只删卡位与连线，**不动演员/素材/小说/剧本**）。
- 每张画布的排布、缩放、平移、背景、连线各自独立保存；主画布不可删除。

**导出**：`🖼 导出图`（工具栏）与右键菜单「导出 PNG 阵容图」是同一功能，把当前画布（含分组标题、风格色条、姓名/ID/角色/身高、素材数）渲染成 2 倍像素 PNG 下载。

**一致性自检**：`python3 tests/canvas-audit.py` —— 134 项自动化审计（**会先备份主画布、跑完自动还原，可在正式实例上安全运行**），逐条核验本节声明的每一项能力（缩放边界/光标锚定/平移四种入口/LOD 阈值/小地图/框选与顺序角标/对齐与分布/连线增删显隐/视图持久化/背景与网格/多画布语义/分组框全生命周期/便签节点/节点缩放与层级/撤销重做不丢数据/文档与实现是否一致），并交叉校验"同一功能不同入口结果一致"。

### 1.2.1 可执行节点图（画布即工作流）

无限画布不仅能摆放素材，还能直接当**生产流水线**用：节点有类型化端口、连线能表达顺序、整图先出计划、人工审批后才执行。全部操作都在画布上完成。

**第一步：把节点连成图**

- 每个节点左右两侧有**带类型的端口**（按类型配色、放大后显示端口名）：演员/环境/物品/参考图输出 `image`/`ref`；关键帧（出图）节点接收 `in`/`ref1..3`、输出 `image`；视频节点接收 `first`（首帧）/`last`/`ref1..2`、输出 `clip`；成片时间线节点接收 `clip1..clip24`、输出 `film`。
- 把线**拖到目标节点的端口上**（而不是节点空白处）就建立「数据流边」，会自动带上端口名与槽位序号；拖到节点空白处仍是原来的**语义关系线**（对手戏/出现在/持有…），两者可以共存。
- 不兼容的连接会被当场拦住并给中文原因（例如「不允许 text → first 的连接」）；服务端会再校验一次。

**也可以完全手工搭图**：工具栏 `➕ 流程节点` 直接创建「🖼 关键帧（出图）」「🎬 视频片段」「📝 文本」「🎬 成片时间线」「📦 交付终点」；右键某个视频片段还有 `↻ 生成续写片段`——它会在右边建一个新的视频节点并自动把上一段的 `clip` 接到它的 `first`，执行时自动取上一段尾帧作为首帧（视频续写）。

**第二步：铺开一集分镜（可选但最省事）**

工具栏 `🎞 铺开分集` → 选剧本 + 分集 → 「🎞 铺开到画布」：系统按镜头建出「关键帧（出图）→ 首帧 → 视频片段」三件套，并按 `clip1..clipN` 接到「成片时间线」节点。**只排版，不生成任何东西**；一集超过 24 镜会自动分成多个成片节点。

**第三步：执行计划（dry-run）+ 人工审批**

工具栏 `🧭 执行计划` → 弹出计划：将执行哪些节点、可跳过哪些（含跳过原因）、预估调用次数（出图/视频分列）、成本级（L/M/H）、环形依赖提示。要真正开跑需三步：

1. 点 `✅ 批准计划`（不想跑点 `⛔ 拒绝`，不会产生任何调用）；
2. 把**只打印在运行服务终端**（`./start.sh` 那个窗口，形如 `[gate] 计划 PL-xxxx 待人工确认，确认码：123456`）的 6 位确认码填进输入框；
3. 点 `▶ 执行（需确认码）`。服务端在执行前会**再比对一次计划**——期间画布被改过就拒绝执行。

> 这道闸门是为「100 集批量生产」防烧钱设计的：Agent（见下）只能提交计划，拿不到确认码，因此**无法自己开始花钱**。

**第四步：看结果与增量重跑**

- 执行中每个节点显示 `running / done / error`，关键帧与视频节点直接显示产出的画面/片段，成片节点显示「片段 N 段 · 已产出」。
- 右键视频节点 `▶ 生成 / 重跑该片段`、右键成片节点 `🎬 立即成片（按 clip1..N 顺序）` 或 `👁 预览拼接顺序（dry-run）`（先看每段的端口、时长、台词、文件，确认顺序无误再跑）。
- **输入指纹**保证不浪费钱：提示词/参数/上游产物没变就自动跳过；只有变化或显式覆盖才重跑。

**首尾帧过渡与视频续写**

视频节点有两个画面输入端口：`first`（首帧）与 `last`（尾帧）。

- **首尾帧过渡**：两帧都接上（例如一张开场图 + 一张收尾图）→ 成片在这一镜内从首帧过渡到尾帧。本地 `placeholder` 后端用「首帧运镜 → 尾帧」的交叉溶解如实表达，并在执行记录里标注 `raw.lastFrame=xfade`；云端 H3 需要在「设置 → 视频 → 字段映射」里给 `lastImageNode` 填上工作流里负责尾帧的 `LoadImage` 节点 id；通用 HTTP 后端则需在请求体模板里带 `{{lastImage}}` 占位符。**没准备就明确报中文错**，不会静默把尾帧丢掉。
- **视频续写**：把**上一段的 `clip` 端口接到下一段的 `first` 端口** → 执行时自动用 ffmpeg 抽出上一段的**尾帧**作为下一段的首帧，画面自然延续（节点上会显示「↻ 续写（首帧取自上游片段尾帧）」）。这条链可以一直往下接，等于把无数个 3~5 秒片段串成一段连续长镜。
- 注意：只给尾帧、不给首帧的镜头会**诚实失败**（视频不能凭空生成）——请给它一个首帧，或用 `clip → first` 的续写接法。

**自动补尾帧（只给首帧也能做首尾帧过渡）**

- 右键片段 →「⌛ 自动补尾帧」：按**本镜提示词 + 收尾定格语义**（`final frame, settled composition, end of shot`）新建一张尾帧出图节点，落在片段正上方，并自动接好 `image → last`。之后点「执行计划」：先出这张尾帧图，再把它作为首尾帧过渡的尾帧送进视频后端。
- 另外三个入口（同一实现）：HTTP `POST /api/canvas/auto-last`、画布内 Claw 指令「给镜 1 补尾帧」（可带镜号）、MCP 工具 `canvas_auto_last_frame`。
- **只建图不生成**：不发起任何出图/视频调用，尾帧图同样走「执行计划 → 人工批准 + 确认码」；重复补会被中文拒绝（提示该片段已有尾帧），非视频节点、没有提示词的片段也会被拒绝并说明原因。
- 执行前的**首尾帧自检**：尾帧图不存在 → 直接中文报错（不让后端先扣一次钱再报天书错误）；首尾帧是同一张图 → 告警「这一镜不会有任何运动」；只连首帧 → 结果里提示可以去补尾帧。

- **运动量量化**：首尾帧不是同一张图也可能「几乎一样」。执行前会把两帧缩成 32×32 灰度算平均绝对差：差异 ≤1% 判「基本没有运动」、<4% 判「变化很轻微」，告警里直接带百分比（执行记录里是 `firstLast.distance/level/verdict`）。全部在本地用 ffmpeg 算，不花钱、不连外网。

**队列自动暂停（预算/额度软着陆）**

- 设了「本月金额上限」后，如果某一批付费调用会让本月金额**突破上限**，系统不会硬跑，而是**暂停队列**：
  - **已在跑的任务跑完**（不打断进行中的工作），**排队中的任务留在队列里**（不失败、不丢进度、不丢已产出的产物）；
  - 暂停状态**落库**，重启服务也依然暂停（避免「重启一下就把闸门绕过去」）；
  - 原因写得很直白：「本月金额将达 44 CNY，超过月度上限 20（已用 0）。已排队任务已暂停（未丢失），可提高上限或清零台账后点『恢复队列』继续。」
- **顶栏横幅**：一旦暂停，任何页面顶部都会出现「⏸ 队列已暂停 · 点击恢复」，点一下即可恢复（恢复后排队任务自动继续，不用重新提交）。
- **流水线行为**：暂停期间 `runPipeline` 会停在 `queue_paused` 并说明原因，**不推进任何阶段**；重跑付费阶段返回 `blocked + paused`（不创建计划、不花钱）。
- 暂停与恢复都会出现在**决策时间线**里（系统自动 / 人类决定），谁在什么时候按下的暂停一目了然。
- 命令行 / Agent：`GET /api/queue/state`、`POST /api/queue/pause`、`POST /api/queue/resume`。

**决策时间线（制片 Agent 页 → 🧭 决策时间线）**

- 自动化制片最怕黑箱：片子出来了，却说不清「哪一步是 Agent 自己做的、哪一步是人类批准的、钱花在哪一次批准之后」。这张卡片把**已落库的事实**按时间摊开。
- 每行 = 一条事件：时间、图标、**行动者徽标**（`人类决定` / `Agent` / `系统`）、事件标题、细节。行动者只有三类，含义写在卡片底部：
  - `human` —— 人类决定：批准执行计划、驳回/确认码错误、取消任务、保存画布快照；
  - `agent` —— Agent 或 MCP 发起：生成执行计划（dry-run，不花钱）、未批准就尝试执行（被拒、零调用）；
  - `system` —— 系统自动：阶段开始/完成/失败、等待人工批准、计划过期、画布改动导致计划作废、节点与任务失败。
- 顶部汇总一句话：「30 条事件（人类决定 5 · Agent 发起 5 · 系统自动 20），批准放行 2 次、被拒/作废 2 次、阶段失败 0 次」——**一眼看清自动化与人工介入的比例**。
- 时间线**只摊开事实、不推断、不美化**（连「未批准就尝试执行 → 被拒绝」这种失败尝试也照实列出）。
- 命令行 / Agent：`GET /api/studio/timeline?productionId=` 或 `?canvasId=&limit=`、MCP `studio_timeline`。

**画布快照与回滚（画布工具栏 → 📸 快照）**

- 画布是这套系统的唯一工作现场，一次误清空或一次「重铺」就能把几十分钟的手工布局冲掉（撤销栈跨刷新就没了）。所以整张画布可以像版本一样管理：点「📸 快照」→ 填名称/备注 → 「📸 保存当前画布」，卡位 / 分组 / 连线 / 视图一起存下来。
- **回滚前先看差异**：点某张快照的「🔍 差异」，会告诉你「当前比快照多 1 个卡位；1 个卡位被移动/改尺寸；连线少 1 条」——不是只比数量，而是把新增/消失/移动/内容变化/连线增删分开算。
- **回滚是可逆的**：点「↩ 回滚」时，系统会先把**当前现场**自动存成一张 `自动` 快照，所以回错了还能再回滚回来（列表里能看到「回滚前自动快照 · …」）。
- **破坏性操作自动留档**：清空画布、铺开分集之前会自动保存一张 `自动` 快照（清空接口的返回里带 `autoSnapshot`），界面上也能看到。
- 回滚会把**类型化端口与 `slot`** 一起还原（否则一次还原就把数据流边退化成普通关系线）；单画布最多保留 40 张，超出时先淘汰最旧的自动快照，人工快照最后才动。
- Claw 指令也认：「保存快照」「存个档」→ 直接存；「回滚到上一个快照」「退回」→ 回滚到最近的人工快照并说明已自动留档。Agent 侧有三个 MCP 工具：`canvas_snapshot_save` / `canvas_snapshots`（可带 `diff_id` 看差异）/ `canvas_snapshot_restore`。

**多平台版本（制作台 → 📱 多平台版本）**

- 一次成片要发多个平台时，画幅/分辨率/安全区都不一样。点「📱 多平台版本」先出**规划**：
  - 平台规格：抖音/视频号 `1080x1920（9:16）`、小红书 `1080x1440（3:4）`、B站/YouTube `1920x1080（16:9）`、方屏 `1080x1080（1:1）`；
  - **裁切损失**：竖屏转横屏按「铺满裁切」会丢约 **68%** 画面 —— 这种情况会直接建议改用「模糊补边」保留完整构图；
  - **字幕安全区**：字幕底边距按目标高度换算后与平台安全区比对（抖音底部有 UI 遮挡，安全区按 22% 高算），不足就提示「按平台单独封装并调大 MarginV」；
  - **响度口径**：各平台对应到 `流媒体（-14 LUFS）`，与成片包装里的响度归一联动。
- 三种补边方式：`铺满裁切`（画面最满）、`模糊补边`（保留完整画面，两侧放大模糊填充）、`黑边补`（最保守）。
- 点「📱 生成这些版本」→ 走任务队列（可看进度、可取消），产物落在成片同目录，文件名带平台与分辨率；**全程本地 ffmpeg，零成本**。
- 想固化下来：设置 `variants.targets`（例如 `['douyin','bilibili']`）后，**交付包会自动生成并带上 `variants/`**，`manifest.json` 里记录每个平台版本的裁切损失。
- 命令行 / Agent：`GET /api/render/variants`（规划）、`POST /api/render/variants`（生成）、MCP `render_variants`。

**响度归一（成片包装 → 响度归一）**

- 交付给平台/广播前，响度是硬指标：太轻用户要调音量，太响会被平台自动降音量（动态被压平）。
- 在「🎁 成片包装」里选口径：`EBU R128（-23 LUFS，欧洲广播）`、`ATSC A/85（-24 LKFS，北美广播）`、`流媒体（-14 LUFS，对标 YouTube/抖音）`、`播客（-16 LUFS）`，或 `不处理`（默认，保持原样）。
- 封装时用 **两遍法** loudnorm：先量一遍拿到实际响度/真峰/动态，再按实测值**线性**归一 —— 单遍动态压缩会把动态压平，两遍才既达标又保真。执行记录里能看到「-51.8 → -23.01 LUFS」这样的前后对照。
- 「📈 测一下当前成片响度」只测量不改文件：给出 `I`（整体响度）/`LRA`（动态范围）/`Peak`（真峰），并按当前口径告诉你**是否达标、偏离多少 LU、真峰有没有超上限**。
- **静音轨不误判**：成片本来就没启用配音/BGM 时（静音轨），响度目标不适用，提示会说明原因而不是判不达标。质检报告里的响度项同样按口径判定，静音轨降级为提示。
- 命令行 / Agent：`GET /api/render/loudness?scriptId=&code=&target=`、MCP `render_loudness`。

**专业后期导出（制作台 → ⤓ 时间线 XML/OTIO、⤓ 字幕 VTT/TTML）**

- **时间线三格式**：同一份镜头序列导出 `EDL（CMX3600）`、`FCP7 XML（xmeml v4）`、`OTIO（OpenTimelineIO）`。三者与「界面顺序 = 成片顺序」**同源同一份数据**，所以在画布上拖缩略图调序后，三种导出会一起变；Premiere / DaVinci / FCP7 直接导入 XML，管线/审片系统读 OTIO，老流程吃 EDL。
- **字幕三规范**：`SRT`（平台通用）、`WebVTT`（网页 / HLS）、`TTML`（广播 / 流媒体流程，带 region 与安全区 origin/extent）。
- **字幕排版规范校验**（SRT/VTT/TTML 共用同一份口径）：单行字数（默认 ≤18 字）、行数（≤2）、**语速 CPS**（≤21 字/秒）、单条停留（0.8~8s）、重叠、**安全区**（按画面高度与成片 `MarginV` 换算，例如 1280p 需 ≥154px 才不压底边）。质检报告里有独立的「字幕规范」检查项，交付包的 `manifest.json` 记录逐集结论。
- 按钮点开即列出三种格式的内容规模与逐条建议，并可一键下载；命令行/Agent 侧用 `GET /api/render/timeline?format=otio`、`GET /api/render/subtitles?format=vtt`、MCP `render_interchange`。

**工作流能力匹配（制作台 → 🧩 能力匹配）**

- 点「🧩 能力匹配」：把**实例真正具备的能力**（比例、单镜时长上限、是否接受首帧/尾帧、turbo LoRA、配音后端、计价方式）与**这一集的要求**（镜数、最长镜、总时长、比例、有没有台词、画布上是否接了 `last`/`dub`）逐项对表。
- 三级结论：**⛔ block**（跑不通，例如实例 503 / 未配地址）会给出替代方案（先用 placeholder 把流程跑通）；**⚠️ warn**（能跑但要降级）给可执行建议，例如「有镜头 9s 超过单条上限 2s → 用右键「↻ 生成续写片段」把长镜拆成两条」「实例缺 turbo LoRA → 按 120s/条，本集 30 条约 60 分钟，建议先跑前 5 镜确认画质」；**✅ ok** 才说明真的匹配。
- 一次都没匹配到需求时（没给集号、画布上也没视频节点）会**明说「这次没比什么」**，不会给一个空洞的 ✅。
- 这是**纯判断**：不发请求、不改配置、不花钱；Agent 侧可直接调 MCP 工具 `render_backend_fit`。制片 Agent 计划页也会自动带一张卡片（有降级/跑不通时才出现）。

**计费口径与对账（设置 → 计费口径 / 制片 Agent → 🧾 对账）**

- 口径二选一：**按次**（每次调用一口价）或 **按秒**（`秒数 × 单价 × 分辨率阶梯`，阶梯如 `720p ×1 / 1080p ×1.5`，在设置页按 `720:1，1080:1.5` 的写法填）。没配 `billing` 时自动回落到「预算单价（按次）」，老配置不受影响。
- 制片估算跟着口径走，并给出**换口径对比**：同一集「按次 6 元 vs 按秒 31 元」一目了然。
- **对账按真实产出**统计：只数落库且 `done` 的关键帧/视频条数与时长（提交了但失败的不算）。制片 Agent 卡片与一页纸报告的「三之二、计费口径与对账」都有**逐项差额表**（关键帧 12→1 张、视频 12→1 条、时长 36→4s、金额 −8.88 CNY）。
- 单价没填时：结论是「未配置单价」，**金额差额返回 null**（只对账条数与秒数），绝不把「没填单价」显示成「免费」。
- 命令行 / Agent：`GET /api/studio/productions/:id/reconcile`、MCP `studio_reconcile`。

**逐镜缩略轨与拖拽调序（成片节点内）**

- 成片（时间线）节点底部会画出**每个片段的缩略图**（服务端用 ffmpeg 抽一帧，按「源文件路径 + mtime + size」缓存到 `data/thumbs/`，`GET /api/render/thumb?path=…&size=160`），格子上的小数字就是**拼接序号**。
- **直接拖动缩略图即可改顺序**：拖到哪就拼到哪，松手后写回端口 `clip1..N`（保证端口唯一）与 `slot 0..N-1`，节点上会提示「已调序：1.片段C 2.片段A 3.片段B（成片会按这个顺序拼接）」。
- 顺序的**唯一口径**和「👁 预览拼接顺序」的 dry-run 完全一致；少给几条、混入别的连线、拿片段节点当时间线调序，都会被中文拒绝并说明原因。单节点最多 24 段（超了请用「铺开分集」的分块成片）。
- 缩放到 22% 以下（LOD 简）时不画缩略轨，缩略图也不会去请求，避免大画布卡顿。

**跨镜角色一致性（制作台 → 🧬 跨镜一致性）**

- 同一个角色的所有关键帧应该「看起来是一路人」。点「🧬 跨镜一致性」：按分镜里的角色分组，算每张关键帧的 8×8 感知哈希与组内基准（多数位中位哈希）的距离，把明显飘掉的镜头列出来，并告诉你**只重跑哪几镜**就够（不必整集重出）。
- 判定线 = `max(阈值, min(0.5, 中位数+3×MAD))`：用中位数/MAD 这种抗离群统计量，避免「4 张里 1 张异色反而把自己的判定线抬高到永远不报」；`阈值` 可在 `GET /api/render/consistency?threshold=` 里调，界面上用默认 0.34。
- **口径诚实**：这是**代理指标**（整体观感：明暗/构图/色调/画风），**不做人脸识别** —— 抓得住「画风飘」，抓不住「同画风换脸」。本地占位后端产出的 SVG 无法解码，会被如实计入「未纳入评分」，接入真实出图后自动纳入。
- 同时，整集质检（`🔍 成片质检`）里也会带一条「跨镜一致性」检查项，离群时是 ⚠️ 告警，报告 Markdown 里同样有；Agent 侧可直接调 MCP 工具 `render_consistency_score`（只读、不花钱）。

**多轨时间线（画面叠轨 / 画中画 / 字幕轨）**

成片时间线节点除了按 `clip1..clip24` 排好主轨（V1），还能再接三种轨道：

- **画面叠加轨 `ov1..ov4`**：由「🖼️ 叠加层」节点提供，三种模式 ——
  - **画中画**：按「宽度占主画面比例」缩到指定角落（右下/左下/右上/左上/居中），适合小窗解说、监控画面；
  - **全屏叠加**：铺满画面，适合片头标题、转场、全屏贴纸；
  - **水印**：整片常驻的小角标（可半透明）。
  每个叠加层可设**出现/消失时间窗**（秒，留空=从片头/到片尾）、宽度占比、不透明度、淡入淡出秒数；画面默认取接入它的上游片段，也可以在节点里**直接上传一张图片/视频**。
- **字幕轨 `sub`**：由「💬 字幕轨」节点提供 —— 可**上传现成 .srt**（时间码原样沿用）、**手工写时间码行**，或把文本节点接到它的 `text` 端口；并可选**烧录进画面**或**软字幕轨**（播放器可开关）。想精细控制字幕时机时，用它替代「按台词自动生成」。
- 合成由成片节点的执行一次完成（一次 ffmpeg，不逐轨重编码，成片时长不变）。右键叠加层/字幕轨节点可编辑参数或单点重跑；没产出、文件缺失、端口重复都会**明确报中文错**，不会静默少一条轨。

**音频闭环（让画布产出的成片有声音）**

工具栏 `🔊 音频` 新建音频节点，三种模式：

- `🔊 配音（TTS 合成）`：填台词（或接一个文本/便签节点，或绑定镜头自动取台词）→ 执行后产出配音文件；
- `🎧 已有音频`：上传一段音频（配音 / 音效）直接引用；
- `🎵 背景乐`：上传音乐，作为整片背景乐。

接线方式：把音频节点的 `audio` 端口拉到某镜**视频节点的 `dub` 端口** = 这一镜就用这段配音（不再走 TTS 合成）；拉到**成片节点的 `bgm` 端口** = 整片背景乐，混音时会**自动压低人声以外的音乐（ducking）**。成片音轨模式完全由画布决定：配音 + 背景乐 → 混音；只有背景乐 → 纯音乐；都没有 → 静音轨（台词仍以字幕呈现）——每条决定都会写进成片报告的 `audioPlan`。

> 提示：配音走的是设置里的「配音后端」（TTS），按其「台词 + 音色」缓存，重复执行不重复付费；没配 TTS 后端时，配音节点会明确报「需要配置 TTS 后端」，而不是静默产出一条无声的片子。

**给 Agent 用（MCP）**

```bash
node scripts/mcp.js --catalog          # 看 41 个工具（只读 / 计划 / 执行 / 改画布）
node scripts/mcp.js                    # 以 stdio MCP 暴露给任意 Agent 客户端
node scripts/mcp.js --http --port 8799 # 或起独立 HTTP 审批服务
```

Agent 侧可读画布与资产、生成 dry-run 计划、改画布结构与连线；**执行（`canvas_run` / `canvas_run_node`）必须由人批准并输入确认码**，每次审批与尝试都会写进审计表（谁在何时批/拒了什么）。界面上另有 `GET /api/mcp/tools` 可查看工具目录。

### 1.3 明星档案（每人一个独立 ID）

ID 由系统分配：`C-0001`、`C-0002`…（创建后固定不变，小说模块与剧本模块靠它引用角色）。

档案抽屉包含：

1. **一键生成**：各镜头类型快捷键 + 「生成主人物定妆图」/「脸部多角度全套」/「全部 12 表情」/「自定义提示词生成」。
2. **素材库**：按镜头类型分页签浏览全部生成结果；点击一张图 → 设为**主图**（宫格封面 + 参考生图基准）；右键图片 → 大图查看 / 复制提示词 / 删除。
3. **基础档案**：姓名、别名、性别、年龄、种族、身高、体重、体型、肤色、角色类型。
4. **外形细节**：发型、发色、瞳色、五官特征、服饰、配饰（英文标签效果最好，如 `black trench coat, leather gloves`）。
5. **人设**：性格、背景故事、音色、标签；**「🧠 AI 补全人物描述」** 会根据姓名与已有信息自动补出性格/背景/服饰/五官/音色/标签。
6. **画风与出图参数**：10 种画风、8 种比例、宽高、默认 seed / CFG / 步数 / 采样器、附加锚点词（受保护片段，可放专属 LoRA 触发词）、**上传参考图**。
7. **提示词**：可编辑的英文正向 / 负向词；「🎨 一键优化提示词」调用 LLM 重写（保留人物锚点与风格包，写回档案）；「📄 复制引擎拼装词」直接拿拼装结果。
8. **记录**：创建/更新时间与素材数量。

**生成参数面板**：选类型 → 勾选变体 → 画风覆盖 → 每变体张数 / 比例 / seed / CFG / 步数（🎲 一键随机）→ 补充正向词 / 负向词 / 场景氛围 → 勾选「参考生图」（默认在有主图时开启，用于跨图一致性）→ 面板底部**实时预览**最终英文正负向词与出图张数。

提交后右下角出现进度卡片（`生成中 3/12`），完成后自动刷新宫格封面与素材库。

### 1.5 提示词是怎么拼出来的（理解后可精准调优）

```
风格头(风格包) → 人物锚点(性别/年龄/种族/身高/体型/肤色/发型/瞳色/五官/服饰/配饰)
→ 镜头模板(景别/构图/表情/姿态标记) → 场景/补充词 → 质量尾 → 风格尾
负面词 = 风格专属负面 + 通用负面(手部/解剖/水印…) + 你的补充负面
```

人物锚点是**受保护片段**：所有镜头类型、所有批次都会原样保留，这是跨图一致性的第一道锁；第二道锁是「参考生图」（以主图/参考图为基准）；第三道锁是角色专属锚点词（`ext_prompt`，可挂 LoRA 触发词）。

## 2. 模块二：小说工坊

完整说明见 `docs/模块2-使用说明.md`。

操作顺序：**① 参数与题材 → ② 定义演员与角色 → ③ 上传故事框架范本（可选）→ ④ 生成章节大纲 → ⑤ 批量撰写章节 → ⑥ 阅读 / 编辑 / 导出**。

- **③ 参考范本**：上传任意 TXT/MD 框架文档，生成大纲时自动注入（超长自动截断并中文提示）。
- **④ 章节大纲**（13 个分节可视化）：一句话故事、故事框架与核心冲突、世界观、卷/季结构、章节大纲与走向、宏大时间线、地点档案 `L-0001`、人物 ID 出场规划、伏笔表（埋设→回收）、反转清单、节奏卡点、钩子银行、跨季章节时间回路、全篇逻辑因果链。
  - 「优化大纲」：用中文指令重写（如「节奏加快，第 3 章提前揭露内鬼」），产出新版本。
  - 「续规划」：超长篇分卷继续（单次 ≤200 章，每批 20 章；1000 万字约需 10 次续规划）。
- **⑤ 批量撰写**：可选「续写下一批」/指定章节区间/全书；逐章带上下文（全书框架 + 本章大纲 + 前情摘要 + 人物地点 + 未回收伏笔 + 事件时间线），字数不足自动续写一次；右下角实时进度。
- **⑥ 章节**：阅读器、手动编辑保存、单章重写（不满意直接重生成）、删除；导出 TXT / MD / JSON（可下载附件）。

## 4. 模块四：制作台（分镜 → 关键帧 → 视频 → 整集成片）

完整说明见 `docs/模块4-使用说明.md`。

操作顺序：**① 选剧本与剧集 → ② 渲染关键帧 → ③ 生成视频 → ④ 合成整集 → ⑤ 播放/下载**。

- **① 选剧集**：左栏列出所有剧本与剧集，徽章显示 `33镜 · 🖼12/33 · 🎬3/33`（镜头数 / 已出关键帧 / 已出视频）。
- **② 渲染关键帧**：把该集（或勾选的）镜头送去**当前出图后端**出图 —— 提示词直接用模块 3 分镜里的英文正/负向词，尺寸按剧本形态自动选（竖屏漫剧 720×1280 / 横屏 16:9 / 电影 21:9）。默认**跳过已有**关键帧，可「重做（覆盖）」。
- **③ 生成视频**：每镜生成一段 mp4。
  - 本地后端（默认）：ffmpeg 按该镜的**运镜**（推/拉/摇/移/跟/升降/环绕/手持晃动/变焦/甩镜/希区柯克变焦）把关键帧做成 h264 视频，时长 = 分镜时长。
  - 云端后端：**ComfyUI + MiniMax H3**（内置两套官方工作流，填实例地址即可用）：该镜**有关键帧就自动用首帧驱动**（先把关键帧上传作首帧，画面与关键帧一致），没有关键帧或实例不支持首帧则走文生视频；自动挂 turbo LoRA 4 步（≈45s/条，基础 20 步 ≈120s/条）；产物**自带音频**。占位出图产出的 SVG 关键帧会自动用 ffmpeg(librsvg) 光栅化成 PNG 再上传。也可选任意厂商视频 API（请求体模板 + 响应字段路径 + 异步轮询）。
  - **云端 H3 的前置校验**：提交前会拉一次 `/object_info` 校验节点类型/必填项/模型清单（云实例的节点版本常和前端导出的工作流不一致，这是最常见的 400 原因），并把会把提示词外发第三方 LLM 的「提示词优化」节点强制关掉；超时会自动 `/interrupt` 释放实例，不留僵尸任务。
  - **省算力技巧**：只给 `H`/`M` 成本级的镜头上视频（工具栏可按成本级筛选批量提交），`L` 级保持静帧+运镜。
- **④ 合成整集**：把该集所有镜头视频按分镜顺序 ffmpeg 拼接成一个整集 mp4；缺哪个镜头会在结果里提示。
- **⑤ 成片包装与整季流水线**：
  - **成片包装**：字幕（烧录 / 软字幕轨 / 关闭，可预览 SRT）、音轨（静音 / AI 配音 TTS / 上传 BGM）、淡入淡出；`保存为默认` 后每次封装都按该配置。
  - **整季流水线**：勾选剧集与阶段（分集规划 / 生成分镜 / 渲染关键帧 / 生成视频 / 封装成片）→ 看工作量与耗时预估 → 一键跑完整季 → 弹出逐集生产报告（镜数 / 关键帧 / 视频 / 成片时长与体积 / 警告）。
  - **省算力**：流水线里可只给成本级 H/M 的镜头上视频，或先用「离线试跑」（分镜走规则、不调用模型）验证编排。
- **⑥ 成片**：底部成片列表可直接播放/下载整集，也可 **🗑 删除**（记录 + mp4 一起清）；同一集多次封装不会互相覆盖。工具条 `🧹 清理中间产物` 可回收封装过程中的临时文件（服务启动时也会自动清理）。单镜视频、关键帧同样能单独下载或删除重做。
- **导出**：制作台可直接导出该集 CSV/JSON（分镜 + 提示词 + 状态），交给外部剪辑或继续投喂视频流水线。

> 提示：本地运镜成片只是"占位成片"，用来验证编排与时长；接上云端视频模型后同一套分镜直接产出真实 AI 视频，无需改动上游任何数据。

## 4.5 自动化制片 Agent（一句话到成片）

「🎬 制片 Agent」页把模块 1~4 串成一条流水线。用法：

1. 在上方输入**一句话需求**（例如「拍一部三集的雾港悬疑短剧，竖屏，每集六十秒，6 个角色，日系赛璐璐画风」）。高级参数可留空——留空就用需求里解析出的值，也可以手动覆盖：题材、画风、比例、集数、每集秒数、角色数、要写的章节数。
2. 勾选「离线试跑」可完全不花钱、不连外网地演示整条流水线（LLM 走规则模板、出图/视频走本地占位后端）。
3. 点「🧭 生成生产计划」→ 页面给出解析结果、**十个阶段的清单**（标出哪两个阶段要花钱）与**调用次数/金额估算**。
4. 点「▶ 开始执行（免费阶段）」→ 依次完成：建演员 → 小说与大纲 → 剧本与分镜 → 画布铺开。**这些阶段不会产生任何出图/视频费用**。
5. 流水线会在**关键帧出图**前停下，弹出人工审核面板：显示待执行节点数、可跳过项、成本级。此时：
   - 点「✅ 批准计划」；
   - 把**运行服务终端**上打印的 6 位确认码（`[gate] 计划 PL-xxxx 待人工确认，确认码：123456`）填进输入框；
   - 点「▶ 继续执行」→ 关键帧开始渲染（这一步真实出图后端会计费）。
   - 视频生成阶段同样需要一次批准。
6. 之后「整集成片 / 成片质检 / 交付包」会自动完成。在产物区可以预览成片、看逐集质检结论、**📦 下载交付包**（zip 含成片/字幕/分镜表/素材/EDL/报告/质检）。
7. 任何阶段失败：展开该阶段看中文错误 → 修好后点「↻ 重跑该阶段」；已完成的阶段不会重复执行（想强制重跑用同一个按钮的 `force`）。

> 提示：整条流水线也可以在命令行/Agent 侧驱动 —— `node scripts/mcp.js --catalog` 里能看到 `studio_create / studio_status / studio_run / studio_run_stage / studio_resume` 五个工具；**放行付费阶段同样需要人类给出的确认码**。

## 5. 常见问题

**Q：生成的人物图都一样（灰底卡片）？**
A：当前出图后端是 `placeholder`（本地占位）。到「设置 → 出图后端」选择 `generic-http` 并填入厂商接口即可切换真实出图，历史记录仍保留。

**Q：提示「未配置 LLM API Key」？**
A：设置页填 Key，或把 Key 放到环境变量 `DEEPSEEK_API_KEY`，或写入 `~/.dsh/.credentials.yaml`（本机会自动读取）；也可把 provider 切到 `mock` 先跑通流程。

**Q：长篇小说生成中断/很慢？**
A：长篇写作是逐章多次调用，属正常；单章 2000 字约 20–60 秒（取决于模型）。中断后可从任意章节继续「批量写作」。

**Q：我的数据在哪里？**
A：全部在 `data/`（`factory.db` 数据库、`images/` 定妆图与关键帧、`videos/` 镜头视频与整集成片、`uploads/` 上传的参考文档与技能文档）。设置页可一键导出全量 JSON 备份。

**Q：制作台出片报「未找到 ffmpeg」？**
A：本地运镜成片需要系统 ffmpeg（`ffmpeg -version` 可验证）。没有 ffmpeg 时请改用云端视频后端（ComfyUI-H3 / 通用 HTTP），或在设置里切换。

**Q：提交任务后我重启了服务，任务一直显示"进行中"怎么办？**
A：不会了 —— 服务启动时会自动把上次进程遗留的 `running/queued` 任务标记为「服务重启导致任务中断」，你重新提交即可；已完成的关键帧/视频/成片都会保留。重跑前可点制作台的 `🧹 清理中间产物` 回收残留临时文件。

**Q：拿到厂商的出图/视频/配音接口后，怎么最快接进来？**
A：不用手抄文档，两步就够（设置 → 出图/视频/配音 → 通用 HTTP 模板）：
1. 点「📋 粘贴 curl 自动填表」——把厂商文档里的 curl 命令整段粘进去，点「解析并填入」：URL、方法、请求头、请求体模板会自动生成；API Key 会替换成 `{{apiKey}}`（不落明文），提示词/负向词/宽高/种子/模型会自动换成 `{{prompt}}/{{negative}}/{{width}}/{{height}}/{{seed}}/{{model}}` 占位符，参考图字段会指向 `{{refImage}}`。
2. 点「🔎 试发一次并推荐字段」——用当前模板真发一次最小请求，弹窗里会显示 HTTP 状态、耗时、content-type、原始响应片段，并**自动推荐「响应图片/视频/音频字段路径」**（例如 `data.images.0.url`、`output.b64`），点一条即可填入；若厂商是异步任务式（只返回 `task_id`），会提示你去填「轮询 URL / 状态字段」。试发用的是草稿配置，**不点保存就不会写进配置**。
3. 想先看看效果可点「🧪 测试出图 / 试渲染 2 秒」，成功后即可在模块 1/4 批量出图、出片。

**Q：真实厂商接口老是失败（429 / 5xx / 网络抖动 / 额度不足），会不会整集都失败？**
A：不会。出图/视频/配音都内建了**自动退避重试**（默认 2 次，可在设置里改「失败重试次数」）：只对「限流 429 / 5xx / 网络异常」重试，且指数退避；**鉴权失败、额度不足、内容审核、字段路径不对一律不重试**（避免白白重试付费接口）。失败信息现在自带中文归类，例如 `[触发限流（429）] 出图接口 429: …（已尝试 3 次）`，任务卡片上直接能看到原因。

**Q：要发到海外平台，字幕和多语言物料怎么出？**
A：制作台工具栏点「🌐 出海物料」：
- **目标语言**：英/日/韩/西/葡/泰/越/印尼 可多选（也可在 `设置 → 数据与备份` 外的配置里用 `publish.languages` 固定下来）；
- **多语言字幕**：按台词逐条翻译，**时间码与条数严格不变**（这是硬约束，翻译错一条不会把整片时间轴搞乱）；模型不可用或漏条时**逐条保留原文并告警**，不会产出坏字幕；相同内容按哈希缓存，重复生成不再调用模型；
- **封面帧**：默认取成片时长的 12% 处（可在配置里用 `publish.coverAt` 指定秒数），按剧集比例输出（竖屏漫剧 1080x1920）；没有成片时用第一镜关键帧兜底；
- **发布元数据**：3 个标题备选、60~120 字简介、6~8 个话题标签、一句引流钩子，并附目标语言要点；模型失败时走规则兜底（用剧名/集名/logline/钩子/悬念拼），不影响出物料。
生成结果落盘在 `data/publish/<集号>/`，并**随「📦 导出交付包」一起打包**（`publish/` 目录，含 `*_publish.md` 可直接贴给运营）。

**Q：配音怎么按角色分？台词比镜头长怎么办？**
A：先在「🎭 明星演员矩阵 → 演员档案 → 音色」给每个角色填音色（例如 `zh-male-deep` / `zh-female-soft`，填厂商文档里的 voice 值），然后在「🎁 成片包装」把音轨设为**配音（TTS）**或**配音+背景乐**：
- **按角色配音**：每镜会根据台词推断说话人，取该角色的音色合成；推断不出时用镜头演员表里第一位有音色的角色；都没填则用默认音色并在报告里告警提示补配置。
- **时长自适应**：合成后自动比对镜头时长 —— 超出会先加速（上限可在 `设置 → 成片` 的 `ttsMaxSpeed` 调，默认 1.25x），加速后仍超长才截断，并在报告与任务日志里明确写出截断秒数；短于镜头时长不处理（后面自然是静音）。
- **合成缓存**：相同「台词 + 音色 + 语速」会复用 `data/audio/cache` 里的音频，**重复封装同一集不会再重复请求厂商**（关掉缓存在设置里把 `ttsCache` 设为 false）。
- **配音 + 背景乐**：BGM 循环铺满整集，并在有人声时自动压低 BGM（侧链压缩避让），结束后淡出。
- 封装产物的 `meta.audio` 里带完整配音报告（每句音色来源/音频时长/镜头时长/适配动作/缓存命中），制作台成片卡片与本集看板都能看到。

**Q：交付前怎么确认成片没问题（黑帧/静音/时长对不上）？**
A：制作台工具栏点「🔍 成片质检」，它用 ffmpeg **真检测**（不是抽查截图）：
- **黑帧**（`blackdetect`）：单段 ≥1s 或占比 >30% 判告警，给出时间区间；
- **静音**（`silencedetect`）：静音总时长超过 1s 或占片长 25% 判告警；
- **响度**（`ebur128`）：整体响度过低（< −30 LUFS）或峰值过高（> −0.1 dBTP）判告警；
- **流与规格**：缺视频/音频流、编码不是 h264、分辨率与镜头不一致；
- **时长口径**：成片时长与「各镜视频时长之和」差 >0.5s 或 5% 判告警（漏镜、时长被改都会命中）；
- **分镜与失败**：还差几个镜头没视频、失败镜头按「可重试 / 需先处理」归类。

结论分三级：❌ 有错误（交付级问题，如某镜没有视频）/ ⚠️ 有告警（质量隐患）/ ✅ 通过；报告可下载 Markdown，并会自动打进「📦 导出交付包」的 `qc/` 目录。质检要跑 ffmpeg（成片 100 秒约几秒），因此**交付清单预览默认不跑质检**，打包时才逐集执行。

**Q：跑了半天，怎么知道进度、哪里慢、为什么失败？**
A：制作台工具栏点「📊 生产看板」，一次给出六类信息：
- **进度**：集数 / 镜头数 / 关键帧·视频·成片的完成百分比；
- **任务**（近 7 天）：按类型（关键帧/视频/合成/流水线/组合出图…）统计成功数与成功率、平均耗时、P95、最长耗时、最近一条错误；
- **渲染**：关键帧与视频各自的成功数/失败数/成功率、平均延迟（取每次生成的实测耗时），并按后端拆分（例如 `comfyui-h3(120/124)`）；
- **失败原因 Top**：按错误归类聚合（限流 / 5xx / 网络 / 鉴权 / 额度 / 审核 …），带中文标签、次数、受影响镜头数与原文样例 —— 直接告诉你该改配置还是该重试；
- **产出趋势**：近 7 天每日成功出图/出片条形图（失败单独计数），以及「计费渲染数」（非占位后端才计）；
- **吞吐与 ETA**：近 1 小时出片速度 + 剩余镜头数 → 估算还需多久（样本不足时会明确说明）。

**Q：做好了一集，怎么交付给平台或剪辑？**
A：制作台工具栏点「📦 导出交付包」→ 弹窗先给你**交付清单**（集数 / 镜头数 / 关键帧 / 视频 / 成片时长 / 打包体积 / 缺失项 / 失败镜头），确认后点「生成并下载 ZIP」。包内结构：
```
final/        整集成片 mp4（按分镜顺序 + 字幕/音轨/淡入淡出包装）
subtitles/    每集 SRT 字幕（可直接给平台做软字幕）
storyboard/   每集分镜表 CSV / JSON（含英文正负向提示词、种子、后端、采用版本标记 → 可复现同一版）
timeline/     EDL 时间线（Premiere / DaVinci / Final Cut 直接导入）
assets/       每镜关键帧与镜头视频原文件（便于二次剪辑；可在弹窗里取消勾选以减小体积）
report.md     生产报告（本月用量与金额、逐集明细、失败镜头归类与原因）
manifest.json 交付清单（文件列表、缺失项、失败镜头）
```
缺成片或有关键帧/视频缺失时**不会报错**，会写进清单与报告让平台方知道；脚本调用可直接 `GET /api/render/deliver?scriptId=SC-0001&code=S01E001`。

**Q：同一镜生成了好几版，怎么挑一版用？**
A：制作台每张镜头卡片上有「🎞 版本 N/M」按钮（有多版本时会高亮，已采用会显示 ★）：点开是**版本对比弹窗** —— 关键帧直接看图（点击放大）、视频可播放，每版标注版本号 / 后端 / seed / 时间 / 时长，失败的版本显示错误原因。
- 点「★ 设为采用」即锁定该版本（同一镜同类型互斥，只保留一个采用版）；
- **整集成片与看板都会使用采用版本**（已用 ffprobe 断言：采用 2s 与 6s 两个版本合成出的成片时长相差正好 4 秒）；
- 「取消采用」回退到「最近一次成功」；弹窗底部还有「🖼 再生成一版关键帧 / 🎬 再生成一版视频」方便继续比对。

**Q：怎么防止误操作把 API 额度烧光 / 盘被写满？**
A：设置 →「💾 数据与备份 → 预算与存储保护」：
- 填「单张图/单条视频/配音每千字」单价 → 本月金额按真实用量自动累计（单价填 0 则只记用量）；
- 设「本月上限 monthlyCap」→ 超过后**直接拒绝**新的出图/出片/流水线任务并给中文原因；
- 设「单次确认阈值 confirmOver」→ 单次预估超过该值时，制作台会先弹确认框（显示预估金额、本月已用、完成后占比），确认后才开跑；
- 设「磁盘告警/上限 warnGB / maxGB」→ 超告警在设置页与「💰 预算与磁盘」弹窗提示，**超上限直接拒绝提交新任务**（先点「🧹 清理中间产物」或删旧集产物）。占用分项里现在**单列 `cache`** —— 参考图栅格化缓存 `data/cache/refs/` 此前没被算进磁盘总量，属**漏算**，C-101 已纠正并计入；现网 `totalMB` 247.3 → 248.9。想看看「缓存占了多大、清掉能省多少」用只读接口 `GET /api/render/cache`（**只看不删**，返回 `{ok,dir,exists,files,bytes,freedMB,dryRun:true,note}`）；真要清用 `POST /api/render/cleanup` 带 `{cache:true}`（不传 `cache` 时行为与以前**逐字段一致**），想先看数不删就带 `{dryRun:true}`。**重启后实测生效**（PID 3218408）：`GET /api/render/cache` 返回 `files:6 / bytes:1704190 / freedMB:1.6`，`/api/guard/status` 的 `disk.parts` 已含 `cache`（1.6MB）；界面侧**已接（H-101）**：设置页「数据与备份 / 磁盘保护」里有 `#cache-row`（缓存分项）、`#cache-scan`（🔍 查看可清理量，只读）与 `#cache-clean`（🧹 清理缓存，**二次确认**，文案写明「不影响成片/关键帧/定妆图」）。（新增路由必须重启实例才生效 —— 重启前先查 `GET /api/jobs` 有没有在跑。）
- 用量统计错了可以点「♻ 清零本月用量」（只清统计，不删任何产物）。

**Q：一集里有几个镜头失败了，要逐个重跑吗？**
A：不用。制作台工具栏点「♻ 重试失败镜头」（括号里是失败数）：它会先**按错误归类**再决定 —— 限流 429 / 5xx / 网络类会自动重新提交（仍然走退避重试与预算闸门）；鉴权失败 / 额度不足 / 内容审核 / 字段路径错误这类**重试也不会成功**的，会列成清单（镜头号 + 中文原因）让你先改配置或换 Key，避免白烧额度。单个镜头卡片上也有「重试」按钮。

**Q：云端视频实例探测失败（HTTP 503 / 未配置）？**
A：云端 ComfyUI 容器是**临时实例**，地址失效很常见。到「设置 → 视频 → ComfyUI 实例地址」填入可用地址（**工作流路径留空即用内置 H3 模板，不必自己准备 JSON**），点「📡 探测后端」。探测会一次给全结论：显卡与显存、节点校验是否通过（缺哪个节点类型）、模型清单是否齐全（缺哪个权重文件）、是否支持首帧输入、turbo LoRA 是否可用。若返回 503：平台通常提示「实例正在启动」，等 1~2 分钟再探测；长时间 503 说明容器已释放，需要向平台要新地址。

**Q：H3 报「工作流与实例不匹配 / missing_node_type / required_input_missing」？**
A：这是云实例的节点版本与前端导出的工作流不一致导致的（例如前端用 `ttN text` 传提示词，而实例只有 `PrimitiveStringMultiline`）。本工厂内置的两套模板已按可用实例的 schema 适配过；如果你用自己的工作流 JSON，按报错里的节点 id 与字段名对照 `/object_info/<节点名>` 改一处即可。预检通过后才会提交，所以不会白跑一次 400。

**Q：换了端口/机器后演员 ID 会变吗？**
A：不会。ID 存在数据库里，与端口无关；迁移时整体拷贝 `data/` 目录或走 JSON 导出/导入即可。

### 6.1 真实模型接入

**界面路径**：设置页 `http://127.0.0.1:8788/#/settings`。接模型只需要 4 张卡片：🤖 文本生成（LLM）、🖼 出图后端、🎞 视频后端、🔊 配音后端；每张卡都有「保存」与「探测/测试」按钮（探测用当前已保存配置真发一次最小请求，测试出图/试听会真实计费）。

**火山方舟：数据面只认 API Key，AK/SK 只能打控制面**

- 数据面（推理、模型列表）：`base_url = https://ark.cn-beijing.volces.com/api/v3`（国际站 `https://ark.ap-southeast.bytepluses.com/api/v3`），鉴权头固定 `Authorization: Bearer <ARK_API_KEY>`。
- **拿 AK/SK 调 `/api/v3/*` 会直接回 `403 UnsuportAuthentication`** —— AK/SK（或 STS）只被**控制面** `open.volcengineapi.com` 接受（火山 V4 签名），两套鉴权体系完全不同。
- 其它易错点：Key 必须在控制台创建、不能自己拼接；头名只认 `Authorization: Bearer`（`x-api-key` 会被当成未鉴权）；**KeyID 不要拼进 Bearer**；API Key 与站点绑定，北京与新加坡不可混用。
- 官方文档：<https://docs.volcengine.com/docs/82379/1298459?lang=zh> ｜ <https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-auth/references/auth-modes.md> ｜ 控制面签名示例 <https://docs.volcengine.com/docs/ark/start-endpoint-api?lang=zh>
- 自检：

```bash
export ARK_API_KEY='<ARK_API_KEY>'
curl -sS https://ark.cn-beijing.volces.com/api/v3/models -H "Authorization: Bearer $ARK_API_KEY" | head -c 300
```

**常见错误码速查**（「归类」列是任务卡片/日志里显示的中文标签，来自 `src/retry.js`）

| 厂商原文 | 归类 | 自动重试 | 处置 |
|---|---|---|---|
| `AuthenticationError: The API key format is incorrect.`（401） | 鉴权失败 | 否 | 去控制台**完整重新复制** Secret；确认没把 KeyID 当 Key、没加多余前缀、站点匹配 |
| `AccountOverdueError`（403 欠费） | ⚠️ 也显示「鉴权失败」 | 否 | 看账单并充值 |
| `AccessDenied`（403 无模型权限） | ⚠️ 也显示「鉴权失败」 | 否 | 到控制台**开通该模型/服务**，或换有权限的 Key |
| `UnsuportAuthentication`（403，AK/SK 打数据面） | 鉴权失败 | 否 | 改用 ARK API Key，别用 AK/SK 调 `/api/v3` |
| `model_not_found` / `No available channel for model ...`（若 503） | ⚠️ 服务端错误 → **会白白重试** | 是 | 直接改模型名/换通道，别等重试 |
| `Arrearage`（账户欠费） | ⚠️ 未命中内置关键词，按状态码归类 | 视状态码 | 以厂商原文为准，去充值 |
| `insufficient_balance_error`（402 余额不足） | 额度/余额不足 | 否 | 充值或换 Key |
| `3001 requested resource not granted`（火山语音） | 鉴权失败（未授权） | 否 | 控制台**开通语音合成资源**，核对 appid / accessToken / voice_type 配套 |

> **注意（容易误判）**：归类规则是**先匹配 401/403 数字、再看文本关键词**，所以「403 欠费」与「403 无权限」都会显示成**「鉴权失败（Key 无效或未授权）」**。看到这个标签别直接断定 Key 写错，一定展开厂商原文区分 `format incorrect` / 欠费 / 无权限。
>
> **注意（会白花钱）**：聚合/中转服务把「模型不存在」包成 503 时会被判成可重试的服务端错误，**会多试 2 次**；遇到 `model_not_found` 请立刻改模型名。
>
> **自动重试口径**：只重试 **限流 429 / 5xx / 网络异常**；鉴权失败、额度不足、内容审核、字段路径错误一律不重试；**超时默认也不重试**（生成类接口可能已在厂商侧跑完并计费）。次数在设置页「失败重试次数」。

### 6.2 按专业角色配置模型

**12 个角色**（设置页 🧠 模型矩阵按类别分 5 组展示）：

| 角色 | 类别 | 管什么 |
|---|---|---|
| 小说大纲 / 章节写作 / 剧本 / 分镜、提示词 / 提示词优化 / 需求解析 | 文本（llm） | 大纲分卷、章节正文、剧本台词、逐镜分镜、提示词改写、一句话需求 → 结构化参数 |
| 关键帧出图 / 参考图、定妆图 / 首尾帧图 | 图像（image） | 分镜关键帧、定妆与角色一致性、i2v 的首尾帧锚点 |
| 镜头视频 | 视频（video） | 图生视频为主 |
| 配音 | 语音（tts） | 按角色音色配音 |
| 画面质检 | 多模态（vision） | 读图判断穿帮/变形并打分 |

**每个角色现在真的驱动了哪一步（如实说明）**：文本类 6 个角色**已真驱动**流水线调用点（需求解析只驱动 provider，模型名仅记录）；**关键帧/参考图/首尾帧/镜头视频/配音/画面质检这 6 个角色目前只具备「解析 + 设置 + 校验」能力** —— 真正的出图/出视频由画布节点按 `image` / `video` 分段后端执行，质检走本地 ffmpeg，配音调用点未接线。

**四级优先级**（逐字段独立判定，界面「来源说明」列就是后端实际判定结果，不是界面猜测）：

```
角色显式设置（config.models.roles.<角色>）
  > 激活的搭配方案（config.models.profiles[<方案>].<角色>）
    > 该类别既有分段默认（llm / image / video / tts 段）
      > 内置默认（角色推荐值 + 提供方默认地址）
```

- **空串 = 未设置**：把某字段清空等于「清除」，会自动回落下一层。
- `provider` / `model` / `baseUrl` / `temperature` 四个字段**各自独立**向下找，所以可能出现「provider 来自角色、地址来自提供方默认」。
- 「来源说明」列**第一行**是短标签：`角色显式设置` / `方案：<名>` / `全局段默认` / `提供方默认地址` / `内置默认`；**第二行**是后端原文（含配置路径），例如 `既有分段默认（llm 段的全局默认）`。旁边的「密钥状态」列只显示掩码结论（如「已配置 Key（来源：llm.apiKey）」），**任何位置都不显示明文 Key**。

**三套内置方案**（每套覆盖全部 12 个角色；按钮上显示覆盖度，悬停看「为什么这么配」）：

| 角色组 | 省钱 | 均衡 | 高质量 |
|---|---|---|---|
| 大纲 / 章节 | deepseek-chat | deepseek-chat | deepseek-reasoner |
| 剧本 / 分镜 / 提示词优化 | deepseek-chat | deepseek-chat | gpt-4o |
| 需求解析 | deepseek-chat | deepseek-chat | deepseek-chat |
| 关键帧 / 参考图 / 首尾帧 | 自建 ComfyUI | gpt-image-1（商用） | gpt-image-1（最高画质档） |
| 镜头视频 | 自建 ComfyUI H3（开 turbo） | 同左 | 同左（关 turbo 换画质，在 video.comfy 段调） |
| 配音 | tts-1 | tts-1 | tts-1-hd |
| 画面质检 | gpt-4o-mini | gpt-4o-mini | gpt-4o |

- 点方案按钮 = 只写激活方案；点「取消方案（回落分段默认）」= 取消激活。
- ⚠️ **已被「角色显式设置」过的角色仍优先用角色值**，切方案不会静默清空它们。

**校验结论怎么用**：设置页同时给「保存前本地预检」与「后端校验结论」两段。

- **error（有 error 就不该保存）**：激活的方案不存在 / 角色未指定提供方 / 提供方未登记 / 提供方不支持该类别（kind 不匹配）/ 缺 Key 或接口地址。
- **warn（提醒，不阻塞）**：需要显式模型名却留空（会回落提供方默认）/ 配音后端为 `none`（成片是静音轨 + 字幕）。
- 有 error 时**保存按钮被禁用**；后端 `PUT /api/settings` 还有一道白名单校验（未知角色、未登记提供方、温度越界、地址非 `http(s)` 等），**非法请求整体不落盘**。
- provider 与 model **成对写入**：只改 model 也会把该行当前 provider 一起写进角色层，避免跨层错配。

### 6.3 图生图（参考图出图）

**什么时候会自动走图生图**

- 通用 HTTP 后端：**有参考图**（该镜的画布参考图 `shot.refs.canvas.refImages[0]`，且 `image.useCanvasRefs` 不为 `false`、文件确实存在）**且配了图生图模板**（`image.generic.refBodyTemplate` 非空）→ 用图生图模板；否则回落请求体模板。
- OpenAI 图像后端：有参考图自动走 `POST /images/edits`，不需要额外配置。
- ComfyUI 后端：参考图先上传到实例、再填进「参考图节点 `nodeId.field`」指定的节点，成功后才算图生图。

**怎么配**：设置 → 🖼 出图后端 → 通用 HTTP → **「图生图模板（有参考图时用；留空=仍用上面那套）」**。留空即老行为（两路共用一套模板）。

**为什么要分两套**：模板里写 `"image":"{{refImage}}"` 时，纯文生图会渲染成 `"image":""`，多数厂商判参数非法（火山方舟 Seedream 报 `InvalidImageURL.EmptyURL`）；适配器还会兜底把空的参考图键**直接删掉**，不发空串。

**`usedTemplate` 落库位置**：数据库 `shot_renders` 表的 **`meta` 列**，由出图结果归一后写入（归一 5 个键）：

| meta 键 | 含义 |
|---|---|
| `usedTemplate` | `i2i`（带参考图走图生图）/ `t2i`（纯文生图；占位后端也归一成 t2i） |
| `usedTemplateRaw` | 后端原始标记（与契约不一致时才出现，如 `placeholder`） |
| `templateSource` | 实际用的模板/端点：`refBodyTemplate` / `bodyTemplate` / `openai.editPath` / `comfy.refImageNode=<节点>` |
| `refImageSent` | 参考图**是否真的随本次请求发出**（占位后端恒 false） |
| `refImagePresent` | 本次调用**是否有可用参考图**（区分「没带」与「带了没发出去」） |

`meta` 是**浅合并**落库：本次覆盖同名键、保留更早写入方留下的其它键，并加 `metaMergedFrom=<上一条 id>` 标出来源；上面 5 个诊断键恒由本次出图结果覆盖，不会继承陈旧值。

**怎么确认「这张到底是不是图生图」**（只读命令）：

```bash
cd /home/linsheng/Desktop/ai-video-factory
node --input-type=module -e "
import {all} from './src/db.js';
const rows = all(\"SELECT id, shot_id, file_path, created_at, meta FROM shot_renders WHERE kind='keyframe' ORDER BY created_at DESC LIMIT 10\");
for (const r of rows) console.log(r.created_at, r.shot_id, (r.file_path||'').split('/').pop(), r.meta);
"
```

判读：`usedTemplate=i2i` **且** `refImageSent=true` → 真走了图生图；`i2i` 但 `refImageSent=false` → 带了参考图却没发出去；`t2i` 且 `refImagePresent=true` → 带了参考图但走了文生图（多半没配图生图模板）。想同时确认「用的是哪套模板」看 `templateSource`。

> **注意（口径差异）**：`usedTemplate` 只回答「本次有没有参考图」，不回答「用的是哪套模板」——带了参考图但没配图生图模板时会回落到请求体模板，而 `usedTemplate` 仍是 `i2i`、`templateSource` 才是 `bodyTemplate`。**两个键一起看才准确。**
>
> **注意**：适配器返回里的中文 `notes`（例如「未配置 refBodyTemplate → 仍用单模板发送」）**不会落库**，事后从库里查不到。
>
> **注意**：修复前写入的历史记录 `meta` 里永远缺少这些键，追溯时请按时间分段看（`grep` 一下就能发现同镜相邻两条键集合不同）。

### 6.4 时间线导入 / 导出

**导出（EDL / FCP7 XML / OTIO）**：制作台工具条「⤓ 时间线 XML/OTIO」→ 弹窗先逐格式试跑并给结论（如「✅ edl：33 段 · 帧率 25 · 6263 字符」），每个格式一个下载按钮。命令行等价：

```bash
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=edl&download=1'    # EDL（CMX3600）
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=fcp7&download=1'   # FCP7 XML（xmeml，扩展名 .xml）
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=otio&download=1'   # OTIO（OpenTimelineIO JSON）
```

- 三者**同源**：clips 都来自同一次「某集镜头看板」，这份看板也正是**成片拼接**与交付包用的同一份数据 → **界面顺序 = 成片顺序 = 导出顺序**。
- 帧率取 `config.video.fps`（默认 25）；这一集还没有镜头视频时接口给中文错误「这一集还没有镜头视频，无法导出时间线」。
- 交付包里也自带一份 EDL（`timeline/` 目录）。

**导入（FCP7 XML / OTIO → 接入到画布成片节点）**：制作台工具条「⤓ 导入时间线」→ 弹窗里按顺序做四件事：① 选**画布**；② 选该画布上的**成片（时间线）节点**（没有就先到画布放一个）；③ 选**格式**（自动识别 / FCP7 XML / OTIO）；④ 把导出的文本**粘贴**进去或**选文件**（`.xml`/`.otio`/`.json`，上限 5MB，文件只在浏览器里读取、不上传）。然后点「🔍 预览计划」——这是 **dry-run：不写库、不发起任何生成请求**，计划里逐行给 `clip1…clipN（slot N）← 哪段素材 · 命中哪个画布视频节点 · 时长`，并列出「画布上没有对应视频节点的片段」「按文件名（而非完整路径）匹配的片段」等中文告警；确认无误后再点「⤓ 应用（写画布连线）」。

- **零付费**：导入只做「文本解析 + 画布连线读写」，**不调用任何出图/视频/配音后端，也不新建任何节点**。
- **要么整批写入、要么一段不写**：只要有片段在画布上找不到对应视频节点，就直接中文拒绝，**绝不伪造节点**；重复执行**不会重复建线**（已存在的连线会被复用）。
- **前提**：导入必须落到画布上**已存在的成片时间线节点**，且片段要能对上画布上**已有的视频节点**（按产物文件名匹配）→ 正确顺序是「先在画布上把这一集镜头跑出来 → 再导入时间线接成片」，不是「先导入再出片」。
- **两个限制**：单个成片节点最多接 **24 段**（更多请先在画布建好后续成片节点再分次导入）；画布上有多个同名视频节点时该段会被判为「对不上」，需要你先理清素材。
- 命令行等价：`POST /api/render/timeline-import`，body 形如 `{"canvasId":"CV-MAIN","timelineNodeId":"<节点 id>","format":"auto","content":"<XML 或 JSON 文本>","apply":false}`（`content` 也可换成 `path` 指向 `data/` 下已有文件；`apply:true` 才真正写连线）。

解析层（`src/interchange-import.js`，纯计算：不读库、不写库、不发请求）已实现 `parseFcp7Xml` / `parseOtio` / `detectInterchange` / `parseInterchange` / `clipsToTimelinePlan`；格式只按内容嗅探（SRT、HTML、坏 JSON 一律返回 null，不瞎猜格式）。离线自验：`node tests/test-interchange-import.js`。

> **注意（本轮并发变更）**：「导入时间线」是本轮由另一条并行线**新增并接通**的能力（路由 + 界面同时落地）。若你手上的版本更早，可能还只有导出、没有「⤓ 导入时间线」按钮。

### 6.5 字幕与响度

**字幕导出**：制作台「字幕导出」，或命令行：

```bash
curl -OJ 'http://127.0.0.1:8788/api/render/subtitles?scriptId=SC-0001&code=S01E001&format=ttml&download=1'   # srt / vtt / ttml
```

弹窗里同时给「字幕规范」校验结论（单行字数 / 行数 / 每秒字符数 CPS / 最短最长停留 / 重叠 / 空行 / 安全区）。

**TTML 逐条位置 / 对齐怎么配**

- 位置（纵向 → `tts:displayAlign`）：`bottom`/`after` → 底部；`top`/`before` → 顶部；`middle` → 垂直居中。
- 对齐（横向 → `tts:textAlign`）：`center`（默认）/ `left` / `right`。
- 写法可以是 `'top'`、`'left'`、`'top-left'`、`'bottom center'`、数组，或对象 `{position:'top', align:'left'}`。
- 逐条优先级：**默认 → 该条的 `cue.align` / `cue.position` → `perCueAlign` 覆盖（按轴覆盖）**。
- `perCueAlign` 四种形态：函数 `(cue, i) => 'top'` / 字符串（整篇同一条）/ 数组（按 0 基序号）/ 对象或 `Map`（出现与某条 `cue.index` 匹配的键就按 index 取，否则按 0 基序号）。
- 输出：每条位置不同会**各自生成一个 `<region>`**；多 region 时每个 `<p>` 带 `region` 属性，单 region 时 `region` 写在 `<body>` 上。region 的 `origin`/`extent` 由安全区百分比换算（默认 上 10 / 下 15 / 左 5 / 右 5）。
- 兼容性：默认参数下输出与改动前**逐字符一致**。

> **注意（能力已实现，但界面/接口还没接）**：逐条位置/对齐**只能由代码或 Agent 侧调用**。HTTP 导出与交付包都固定用默认参数（实测本机导出的 TTML 只有 1 个 region，挂在 `<body>` 上），没有配置项与界面入口；另外 SRT 解析出的 cue 不含 `align`/`position` 字段，只在你自己构造 cue 对象时才有意义。要真正下发逐条位置，请在代码里调 `toTtml(cues, { defaultAlign, perCueAlign })`（或用 `toTtmlDetailed` 拿 warnings/regions/alignments）。

**响度口径与两遍法**

| 口径 | 目标响度 | 真峰上限 |
|---|---|---|
| 不处理（默认） | — | — |
| EBU R128（欧洲广播） | -23 LUFS | -1 dBTP |
| ATSC A/85（北美广播） | -24 LKFS | -2 dBTP |
| 流媒体（YouTube/抖音等） | -14 LUFS | -1 dBTP |
| 播客 / 有声 | -16 LUFS | -1 dBTP |

- 在制作台「🎁 成片包装」的响度 chips 里选（配置项 `finish.loudness`，默认不处理）；同面板「📈 测一下当前成片响度」可**只测量不改文件**。
- 实现是 ffmpeg `loudnorm` **两遍法**：第一遍测量实测响度，第二遍按实测值**线性归一**（单遍动态压缩会压掉动态范围，所以不用）。归一结果写进成片 meta；失败**不阻断成片**，只写中文原因。
- 需要本机 ffmpeg（零成本、零网络）。

### 6.7 常见问题排查

**Q：配置改了但没生效？**
A：分两种情况 —— ① **通过设置页保存的**：立即生效；② **直接手改 `config/config.json` 的**：**必须重启服务**（服务进程有配置内存缓存，只有首次才读盘）。**代码改动同理**：新加的接口/界面在旧进程上不存在也必须重启（本次实测到：新加的 `POST /api/render/timeline-import` 在未重启的进程上返回 `404 Not Found`）。重启（精确 PID，**禁止 `pkill`**）：

```bash
ss -ltnp | grep 8788                  # ① 找到占用 8788 的 PID（唯一权威来源；没有 ss 用 lsof -i :8788）
kill <PID>                            # ② 只结束这一个（等 1~2 秒；仍不退再 kill -9 <PID>）
cd /home/linsheng/Desktop/ai-video-factory && setsid ./start.sh    # ③ 独立会话重新拉起
sleep 1; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8788/   # ④ 期望 200
```

> **为什么禁用 `pkill`**：这台机器上不止一个 node 进程（DSH 的 Web GUI 也是 node），`pkill` 会连带杀掉无关进程。永远按 PID 精确处理。

**Q：为什么绝对不能同时跑两个 server 实例？**
A：**本会话真实踩过。** 两个实例各持一份**独立的内存配置缓存**，而磁盘只有一份 `config/config.json`：A 保存后，B 再保存一次就会**用它的旧内存把 A 刚写的值覆盖回去**（表现为「设置页保存了却被打回」「两个页面看到不同配置」）；同时两个实例还会抢同一个 SQLite 库与 `data/` 目录。自检：

```bash
ss -ltnp | grep 8788                             # 8788 上应该只有一行
ps -eo pid,lstart,cmd | grep "[n]ode server.js"  # 看一共有几个 server 进程
tr '\0' '\n' < /proc/<PID>/environ | grep -E '^(PORT|FACTORY_DB|FACTORY_CONFIG)'   # 看每个进程用的是哪份库/配置
```

判据：**看它用的是不是同一份 `config/config.json`** —— 同一份 = 危险的双实例（先精确 kill 掉多余那个再动配置）；若某个进程带 `FACTORY_DB`/`FACTORY_CONFIG` 指向 `/tmp/...` 并且监听另一个端口（例如验收脚本的 8901），那是**正常的临时隔离实例**，读写的是自己的临时库，可以安全共存。

**Q：全量自检里画布审计报 `/tmp/refs` 找不到？**
A：**不用手工建夹具**。`tests/canvas-audit.py` 启动时会调用同目录的 `tests/make-audit-refs.py` **幂等生成** `/tmp/refs/ref1..3.png`（640×480；已存在且合法就跳过、不改 mtime；ffmpeg 不可用时回落标准库手写 PNG，所以离线裸跑也能有夹具）。目录可用环境变量 `AUDIT_REFS_DIR` 覆盖；也可单独准备：

```bash
cd /home/linsheng/Desktop/ai-video-factory
python3 tests/make-audit-refs.py          # 默认 /tmp/refs、3 张；加 --force 强制重新生成
```

早期版本硬编码该目录却无人创建，干净机器上会中断整个审计；**现在已自愈**（`tests/make-audit-refs.py` 是该夹具的唯一真源）。

**Q：看到「鉴权失败」就一定是 Key 写错了吗？**
A：不一定，但**能靠标签排除的情况比以前多了**（本轮 P0 修正）。现在的判定顺序是 **`quota`（额度/欠费）→ `model`（模型不可用）→ `auth`（鉴权）→ 限流/审核/超时/网络/字段/配置/5xx/4xx**，而且**文本关键词先判、状态码只在文本判不出来时才兜底**（`src/retry.js:25-43`、`:54-62`）。所以：① **403 的欠费**（`Arrearage` / `AccountOverdueError`）现在归 **「额度/欠费（需充值或提额，不自动重试）」**，不再冒充鉴权失败；② **403 的无权限**（`AccessDenied`，文案里没有额度/模型关键词）仍归 **「鉴权失败」**。看到「鉴权失败」还是别急着换 Key，先展开厂商原文区分「Key 形态不对（`format incorrect`）/ 无权限」两种；看到「额度/欠费」就直接去充值或提额，看到「模型不可用」就去核对模型名/开通状态（这两类都**不会自动重试**，别干等）。

**Q：为什么图生图没生效？**
A：按顺序查四件事 —— ① `image.useCanvasRefs` 是否被设成 `false`（设成 false 会整体禁用画布参考图）；② 该镜有没有画布参考图、文件是否还在磁盘上；③ 出图后端是通用 HTTP 时，**「图生图模板」是否为空**（空就退回单模板）；④ 事后查 `shot_renders.meta` 的 `usedTemplate` / `templateSource` / `refImageSent` 三键，确认到底有没有发出去。
   - **本轮补充（双模板口径）**：设置页出图预设第 4 项已改成**两套模板** —— 请求体模板 `bodyTemplate` 是**文生图**（不含 `image` 键），图生图模板 `refBodyTemplate` 是**图生图**（含 `image`/`strength`），与后端 `src/image.js#pickImageBodyTemplate` 同口径（`web/views/settings.js:422-462`、`src/image.js:411-417`）。**老配置注意**：早期预设把 i2i 模板写进了 `bodyTemplate`（文生图时会把空的 `"image":""` 发给厂商被判参数非法，如方舟 Seedream 报 `InvalidImageURL.EmptyURL`），请到设置页**重套一次该预设**或把含 `image`/`strength` 的那套手工挪到「图生图模板」输入框（`web/views/settings.js:504`）、说明在 `:518`。

### 6.8 视觉质检：多模态真实读图（本轮新增）

跨镜一致性的旧判据是「8×8 灰度 aHash 代理指标」，抓画风/明暗/构图漂移可以，**抓不住「同一画风但换了张脸 / 手部畸形 / 穿模 / 糊字」**。本轮新增**多模态真读图**作为第二道判据，两者**并存**（`src/vision-qc.js:1-20`）。

- **怎么开**：给「画面质检」角色（`qcVision`）配一个支持视觉的提供方 + 模型（如 `deepseek-flash` / `gpt-4o-mini` / `qwen3-vl-plus`）+ 接口地址 + Key（角色配置见 6.2；该模块**自身不发任何请求**，必须由调用方注入 `runVision`，例如 `qcEpisode({scriptId, code}, { vision: (req) => chat(req) })`，见 `src/vision-qc.js` 的 `visionAvailable()`，`:207-305`）。
- **整集质检里的新检查项**：`consistency-vision`（`src/qc.js:162`、`:164`、`:247-267`）：
  - 没配多模态后端 / 没注入调用器 → **`info`**，文案「未配置多模态质检后端，使用代理指标」，并在 detail 里明示「不会发起任何多模态请求」；
  - 注入了且后端可用 → 有离群镜头 **`warn`**（附真实评分与建议重跑的镜头）、无离群 **`ok`**；
  - 没拿到有效评分 → **`info`**（如实说明原因，**绝不假装通过**）。
- **离群判定口径**：组内 ≤2 张只用**绝对阈值**（默认 0.6）；**≥3 张**要求**「低于阈值」且「低于 中位数-3×MAD」**同时成立才算离群，这样「整组都偏低」不会被误报成「某一镜离群」，而是给出整组复核提示（`src/vision-qc.js:1050-1085`、`:673-674`、`:19-20`）。
- **aHash 代理指标的边界**：它是**代理指标**、永远可用（本地 ffmpeg、零成本、零网络），但**不做人脸识别**，也判断不了手部畸形/穿模/糊字；真实判据只在「配好后端 + 注入 `runVision`」时才生效（`src/vision-qc.js:4-6`）。
- **费用闸门是软的**：默认最多 48 次多模态调用、每组最多 12 对（`src/vision-qc.js:35-36`），超了只记警告；调大前先算账。
- **自检**：`tests/test-vision-qc.js` 已登记为全量自检 **31/35 阶段**；**V-101（Gemini 视觉质检接入）交付时 97 项**（`strategist/runs/V-101.json`：55 → 97，+42），随后 **M-101（登记 `google`）再 +13 → 本轮单跑实测 110 项通过 / 0 失败**。Gemini 协议形状与限制见 `docs/模型对接参考.md` §5.8。

### 6.12 墙钟非单调加固（E-101，本轮新增）

**你为什么要关心它**：这台机器的系统墙钟**不是单调的** —— 它会周期性回拨/前拨约 12.4 秒（E-101 后的独立复测：65 秒 / 259 次采样里 >50ms 的跳变 **19 次**，最大回拨与前拨均 **12449ms**，`strategist/runs/VERIFY-35.json#clock_skew_replication`）。后果很直白：

- 「**取最新的一条**」如果按 `created_at` 排序，回拨后**后写入的行反而带着更早的时间戳** → 界面/接口会取到**别的任务写的旧行**（这就是上一轮那个「偶发失败」的物理成因）；
- 「**耗时**」如果按 `Date.now()` 相减，回拨时会算成**负数** → 看板/报告/对账里出现负数耗时（早前自检产物里真的出现过 `"ms": -12349`）。

**现在怎么修的（对你可见的行为变化）**：

1. **取值判序**：`src/**` 里 71 处「按 `created_at` 判序」的 SQL 全部改为按**插入序 `rowid`**（`ORDER BY rowid DESC` = 「最后插入的那一条」，与墙钟完全无关）。这些表都没有 `AUTOINCREMENT`，删行复用 rowid 时 SQLite 仍保证新行 rowid 严格大于现存所有行，所以等价。口径写在 `src/db.js:22-44`。
2. **耗时**：同进程调用耗时改用单调钟（`performance.now()`，`src/util.js:26-42` 的 `monoNow()` / `elapsedMsSince()` / `clampMs()`），**永不为负**；`jobs.created_at → finished_at` 这类**跨进程/跨重启**的墙钟差值无法用单调钟，只能钳到 ≥0 并在代码里注明受跳变影响（如 `src/stats.js:60-66` 的任务耗时）。
3. **防回流**：新增静态护栏测试，扫描 `src/**` 断言「没有任何 SQL 再按 `created_at` 判序」「没有任何 `Date.now()` 相减当耗时」（白名单只留真按时间语义的调度/日期窗口）。
4. **对使用者的影响**：**不需要你做任何事**，行为更稳定了；只是如果你自己在写 SQL/脚本取值，请也按 `rowid`（或显式主键）判序，别再用 `created_at`。
5. **自检**：新套件 `tests/test-clock-skew.js`（38 项）已登记为全量自检的 **35/35 阶段**。它的「改前必失败」证据：把 `src` 拷到影子目录 `/tmp/e101-pre/src` 跑同一测试得到 **9 通过 / 25 失败**（原始输出 `/tmp/e101-pre/run-before.txt`）。细节与逐文件行号见 `strategist/runs/E-101.json`。

**计数口径（本轮实测，取代旧值）**：全量自检 `./scripts/verify-all.sh` = **35 个阶段**、**3519 项断言（第 9 波实测值，不是固定值 —— 一律以脚本输出为准）**、**失败 0**、退出码 0，末行 `✅ 全部自检通过`（原始日志 `strategist/runs/logs/verify-all-154126.log`，留痕 `strategist/runs/VERIFY-40.json`）；**阶段数固定为 35，单阶段断言数一律以脚本输出为准**。`scripts/accept-schedules.sh` = **14 项 `ok()` 断言**（`grep -cE '^\s*ok "'` → 14）。零付费证据（**第 8 波**）：跑前跑后 `app_config['usage:monthly']` 均为 `{"2026-09":{"images":63,"videos":0,"ttsChars":0}}`（63 里有 2 张是用户界面操作；第 7 波当时是 5），`config/config.json` md5 跑前跑后同为 `1b945be03bb4333e1093128482603934`。
