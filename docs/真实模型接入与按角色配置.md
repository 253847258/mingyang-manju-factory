## 1. 真实模型接入

### 1.1 去哪儿配（唯一入口）

```
http://127.0.0.1:8788/#/settings
```

设置页是 hash 路由（`web/app.js:11` 定义 `settings` 模块、`web/app.js:68` 写 `location.hash = \`#/${mod.id}\``），所以 `#/settings` 就是「设置」。

设置页从上到下共 7 张卡片，接模型只需要这 4 张：

| 卡片 | 代码位置 | 后端可选值 | 关键字段 |
|---|---|---|---|
| 🤖 文本生成（LLM） | `web/views/settings.js:74-109` | `deepseek` / `openai` / `mock` | `baseUrl`、`model`、`apiKey`、`maxTokens`（长文建议 ≥ 8000） |
| 🖼 出图后端 | `web/views/settings.js:417-578` | `placeholder` / `generic-http` / `openai-images` / `comfyui` | 见 1.3 |
| 🎞 视频后端（制作台） | `web/views/settings.js:579-692` | `placeholder` / `comfyui-h3` / `generic-http` | 见 1.3 |
| 🔊 配音后端（TTS） | `web/views/settings.js:693-790` | `none` / `openai` / `generic-http` | 见 1.3 |

每张卡底部都有三个按钮：**保存**（`PUT /api/settings`）、**探测/测试**（📡 探测 / 🧪 测试出图 / 🔊 试听一句）。探测用当前**已保存**的配置真发一次最小请求，结论是中文的；测试出图/试听会真的调一次厂商接口（真实后端会计费，用 1 张/1 句的量）。

### 1.2 最快路径：粘贴厂商文档里的 curl

不想逐字段抄文档，就用内置的**厂商接入向导**（出图 / 视频 / 配音三张卡共用，`web/views/settings.js:791-855`）：

1. 点「📋 粘贴 curl 自动填表」→ 把厂商文档里的 curl 命令整段粘进去 → 点「解析并填入」。
   - 后端接口 `POST /api/settings/parse-curl`（`src/routes/meta.js:286`），支持 `-X / -H / -d / -F / -u` 等写法。
   - 它会自动拆出 `url / method / headers / bodyTemplate`，把 Key 换成 `{{apiKey}}`、提示词/尺寸/种子换成 `{{prompt}}/{{width}}/{{height}}/{{seed}}`（`src/vendor.js:129-138`）。
2. 点「🔎 试发一次并推荐字段」→ 用**草稿**配置真发一次最小请求，弹窗给出 HTTP 状态、耗时、content-type、原始响应片段，并**推荐「响应图片/视频/音频字段路径」**（例如 `data.images.0.url`），点一条即填入。
   - 后端接口 `POST /api/settings/probe-vendor`（`src/routes/meta.js:292`）：草稿配置只在内存里合并，**不点保存就不会写进配置**。
   - 若厂商只返回 `task_id`（异步任务式），它会提示你去填「轮询 URL / 轮询状态字段」。
3. 回到卡片点「保存」，再点「🧪 测试出图 / 试渲染 / 🔊 试听一句」确认端到端通了。

### 1.3 四类后端分别怎么填

**出图（🖼）**

- `generic-http`（推荐，能接任意厂商协议）：接口 URL、方法、API Key、模型名 `{{model}}`、**请求头（JSON，支持 `{{apiKey}}`）**（`:451`）、请求体模板（`:452`）、**图生图模板**（`:453`）、响应图片字段路径、参考图字段名、参考图格式（`base64` / `dataurl`）、轮询 URL、轮询状态字段、轮询间隔、最大轮询次数、成功状态值（`web/views/settings.js:478-508`）。
  - 请求体模板可用变量：`{{prompt}} {{negative}} {{width}} {{height}} {{seed}} {{model}} {{apiKey}} {{refImage}} {{ratio}}`。
  - 卡片顶部有 5 个预设按钮（OpenAI 兼容 / 返回 URL 型 / 异步任务型 / 参考生图…）可一键填模板（`web/views/settings.js:422-462`）。
- `openai-images`：`base_url`、模型、生成路径、**参考生图路径(edits)**（有参考图时自动走 `/images/edits`，`src/image.js:287-290`）。
- `comfyui`：ComfyUI 地址、工作流 JSON（API 格式）路径、参考图节点 `nodeId.field`、超时、节点映射 JSON。

**视频（🎞）**

- `generic-http`：视频接口 URL、方法、API Key、模型名、响应视频字段路径、参考图格式、轮询 URL/状态字段、请求体模板（变量含 `{{duration}} {{move}} {{refImage}}`）（`web/views/settings.js:566-582`）。
- `comfyui-h3`：实例地址、工作流 JSON 路径（**留空即用内置 H3 模板**）、视频节点 id、模型名（记录用）、是否用首帧驱动（i2v）、turbo LoRA 开关/步数、分辨率 megapixels、轮询与超时、节点映射 JSON。提交前会用 `/object_info` 预检节点与模型清单（`web/views/settings.js:542-565`）。
- `placeholder`：本地 ffmpeg 运镜成片，用来零成本跑通闭环。

**配音（🔊）**

- `openai`（OpenAI 兼容 `/v1/audio/speech`）：`base_url`、接口路径、模型（`tts-1` / `gpt-4o-mini-tts`）、音色 voice、API Key。
- `generic-http`：TTS 接口 URL、方法、API Key、模型、响应类型（`binary` / `b64` / `url`）、音频字段路径、请求体模板（变量 `{{text}} {{voice}} {{model}} {{apiKey}} {{speed}}`）（`web/views/settings.js:664-676`）。
- 卡片上还有全局的「默认音色 / 语速 / 失败重试次数」。
- `none`：不出声，成片是静音音轨 + 字幕。

**文本（🤖）**：`provider` 选 `deepseek` / `openai`，填 `baseUrl` / `model` / `apiKey`；没有 Key 时先把 `provider` 切 `mock` 跑通全流程（`web/views/settings.js:102-106`）。

### 1.4 鉴权差异表（各家官方口径 ↔ 本项目怎么落地）

官方口径汇总自 `docs/模型对接参考.md` 的「速查表」（`docs/模型对接参考.md:32-60`），适配器实现见 `src/image.js:381-393`（`applyAuthHeader`）与 `src/video.js:10`/`:293`（复用同一实现）。

| 厂商 / 接口 | 官方鉴权头 | 本项目怎么配 |
|---|---|---|
| 火山方舟 Ark（LLM / Seedream / Seedance） | `Authorization: Bearer <ARK_API_KEY>` | 默认口径就会自动补（模板没给 Authorization 时补 `Bearer <key>`） |
| 阿里百炼 DashScope（通义千问 / 通义万相） | `Authorization: Bearer <sk-...>`；旧版异步端点在请求头加 `X-DashScope-Async: enable` | 同上；异步头写进「请求头（JSON）」 |
| DeepSeek / OpenAI / Kimi / GLM / 硅基流动 | `Authorization: Bearer <key>` | `llm` 段直接填 Key 即可 |
| 生数 Vidu | **`Authorization: Token <key>`（不是 Bearer）** | 在「请求头（JSON）」写 `{"Authorization":"Token {{apiKey}}"}` |
| 火山语音 V1 | **`Authorization: Bearer;{token}`（是分号，不是空格）** | 在 `tts.generic.headers` 里手写（见下方注意） |
| ElevenLabs | **`xi-api-key: <key>`（头名不是 Authorization）** | 在 `tts.generic.headers` 里手写 `{"xi-api-key":"{{apiKey}}"}` |
| Runway | `Authorization: Bearer <key>` + **每个请求必带 `X-Runway-Version: 2024-11-06`** | 版本头照抄进视频侧「请求头（JSON）」（模板 headers 会原样透传） |
| Google Gemini | **`x-goog-api-key: <key>`（非 Bearer）** | 只能用高级字段 `authHeader`（见下方注意） |

**为什么模板里自己写头就够了**：`applyAuthHeader` 只有在配置了 `authHeader` 时才改写头；没配置时只在「模板里没有 Authorization」的情况下补一个 `Authorization: Bearer <key>`（`src/image.js:392-398`）。也就是说**模板 headers 里你写什么就发什么**，不会被覆盖。

> `authHeader` / `authPrefix` 这两个高级字段**只在 `src/image.js`（`applyAuthHeader`）和 `src/video.js`（复用）里被读取**，而：
> - `src/config.js` 的默认配置里**没有**这两个字段（`grep -n auth src/config.js` 无命中）；
> ~~- `PUT /api/settings` 的白名单里**也没有**它们（出图 `src/routes/meta.js:92`、视频 `:120` 的字段列表）→ 设置页保存时会被静默忽略；~~

### 1.5 火山方舟（Ark）：数据面只认 API Key，AK/SK 只能打控制面

这是最容易踩错的一处，结论有官方出处（核证记录见 `strategist/runs/ARK-AUTH-RESOLVE.json`）：

- 官方文档链接：
  - Base URL 及鉴权（方舟官方文档）<https://docs.volcengine.com/docs/82379/1298459?lang=zh>
  - 同上的控制台镜像入口 <https://console.volcengine.com/ark/region:cn-beijing/docs/ark/base-url-and-authentication?lang=zh>
  - 火山引擎官方仓库 `ark-cli` 的鉴权模式说明（明确区分控制面/数据面）<https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-auth/references/auth-modes.md>
  - 控制面 OpenAPI（AK/SK + 火山 V4 签名）示例 <https://docs.volcengine.com/docs/ark/start-endpoint-api?lang=zh>
- **数据面**（推理、模型列表）：`base_url = https://ark.cn-beijing.volces.com/api/v3`（国际站 `https://ark.ap-southeast.bytepluses.com/api/v3`），鉴权头固定 `Authorization: Bearer <ARK_API_KEY>`。
- **AK/SK 不能用于推理**：拿 AK/SK 去调 `/api/v3/*`，数据面直接回 `403 UnsuportAuthentication`；AK/SK（或 STS）只被**控制面** `open.volcengine.com` 接受（走火山 V4 签名，与数据面是两套完全不同的鉴权体系）。
- 其它易错点：API Key 必须在控制台创建、不能自己拼接；头名只认 `Authorization: Bearer`（`x-api-key` / `api-key` 会被当成未鉴权）；**KeyID 不要拼进 Bearer**；API Key 与站点绑定，北京与新加坡**不可混用**。

自检（把 Key 放环境变量，避免落到命令历史和明文文件里）：

```bash
export ARK_API_KEY='<ARK_API_KEY>'
curl -sS https://ark.cn-beijing.volces.com/api/v3/models -H "Authorization: Bearer $ARK_API_KEY" | head -c 300
```

返回模型列表就是通了；返回 401 / 403 见下表处置。

### 1.6 常见错误码速查

「内置归类」一列来自 `src/retry.js:6-65`（`ERROR_KINDS` + `RULES` + 状态码兜底），实测样例来自 `strategist/runs/REAL-BACKEND.json`、`strategist/runs/ARK-AUTH-RESOLVE.json` 与 `strategist/runs/ARK-LIVE2.json`。**下表每一行的归类都在本轮用 `classifyError(err)` 逐条复算过**（不是从旧版本抄的），带 ★ 的行是**本轮 P0 修复后与以前不同**的口径。

| 厂商原文（HTTP） | 内置中文归类 | 会自动重试吗 | 你该做什么 |
|---|---|---|---|
| `AuthenticationError: The API key format is incorrect.`（401） | 鉴权失败（Key 无效或未授权） | 否 | 换 Key：到厂商控制台**完整重新复制** Secret（KeyID 无法复原 Secret）；确认没把 KeyID 当 Key、没多加前缀；确认 Key 与站点/区域匹配 |
| `AccountOverdueError`（403 欠费） | ★ **额度/欠费（需充值或提额，不自动重试）**（`src/retry.js:28` 命中 `accountoverdue`） | 否 | 去厂商控制台看账单并充值。**以前**它被显示成「鉴权失败」，会把人引去换 Key —— 这就是注意 1 要修的事 |
| `AccessDenied`（403，无模型权限） | 鉴权失败（Key 无效或未授权）—— 即使 403 已改由文本关键词优先，**这一条文本里没有额度/模型关键词，仍归 auth** | 否 | 到控制台**开通该模型/服务**，或换一把有权限的 Key |
| `UnsuportAuthentication`（403，AK/SK 打数据面） | 鉴权失败 | 否 | 别用 AK/SK 调 `/api/v3`，改用 ARK API Key（见 1.5 与 1.7） |
| `model_not_found` / `No available channel for model ...`（503） | ★ **模型不可用（请检查模型名/开通状态，不自动重试）**（`src/retry.js:33`；规则位置在 `server` 之前，因此 503 不会再被判成 5xx） | **否**（以前是「是」→ 白重试 2 次、白花钱） | 直接改模型名或换通道，别等重试 |
| `Arrearage`（403 账户欠费） | ★ **额度/欠费（需充值或提额，不自动重试）**（`src/retry.js:28` 已收录 `arrearage`） | 否 | 以厂商返回原文为准（这就是欠费），去充值 |
| `insufficient_balance_error`（402 余额不足） | 额度/欠费（需充值或提额，不自动重试）；另外**状态码 `402` 的兜底分支也是 quota**（`src/retry.js:59`） | 否 | 充值或换 Key |
| `3001 requested resource not granted`（403，火山语音） | ★ **额度/欠费（需充值或提额，不自动重试）**（命中 `resource not granted`） | 否 | 到控制台**开通语音合成资源**，并核对该资源下的 appid / accessToken / voice_type 是配套的一组。**以前**归「鉴权失败」，会误导成「再换一把 Key」 |
| `SetLimitExceeded`（429，方舟账号额度用尽 / 安全体验模式） | 触发限流（429）→ **会重试**（文本未命中 quota 关键词，按 429 归 `rate`；`src/retry.js:35`） | **是** | ⚠️ 这条是「会重试但重试也修不好」的典型：账号侧额度已用尽，重试必然同样失败。请按 1.7 去关「安全体验模式」/提额 |

任务卡片与日志里看到的文案形如 `[触发限流（429）] 出图接口 429: …（已尝试 3 次）`（`src/retry.js:104-107`、`:118-124`），中括号里就是归类。

**自动重试的口径**：只重试 **限流 429 / 5xx / 网络异常** 三类（`src/retry.js:85` 的 `DEFAULT_RETRY_KINDS = ['rate','server','network']`，对外唯一口径 `RETRY_KINDS` 见 `src/retry.js:90`）。**鉴权失败、额度不足、模型不可用、内容审核、字段路径不对一律不重试**（`quota` / `auth` / `model` 三类被注释明确写成「永不重试」的红线，见 `src/retry.js:88-90`）；另外**超时默认也不重试**——因为生成类接口很可能已经在厂商侧跑完并计费，重试等于重复付费。重试次数在设置页「失败重试次数」（`image.retries` / `video.retries` / `tts.retries`，默认 2）。

> **注意 1（本轮已修正，不要再按旧版理解）**：规则数组的**判定顺序**现在是 **`quota` → `model` → `auth` → `rate` → `moderation` → `timeout` → `network` → `format` → `config` → `server` → `client`**（`src/retry.js:25-43`，数组顺序即优先级，命中即 `break` 见 `:53`），而且**文本关键词先判、状态码数字只在文本判不出来时才兜底**（`src/retry.js:54-62`）。所以：① 403 的**欠费**（`Arrearage` / `AccountOverdueError`）现在归 **quota**，不再显示成「鉴权失败」；② 403 的**无权限**（`AccessDenied`，文案里没有额度/模型词）仍归 **auth**。结论：看到「鉴权失败」还是**不能直接断定 Key 写错**，要展开厂商原文区分 `format incorrect`（Key 形态不对）/ 无权限两种，处置不同。

> **注意 2（本轮已修，别再照着旧版防坑）**：「模型不存在 / 未开通 / 已下线」现在归 **model（不重试）**，不会再被当 5xx 白重试。**红线**：新增关键词一律**锚定在 `model` / `endpoint` 前缀或完整短语**上，**裸 `not found` / 裸 `invalid` 刻意不收** —— 否则 `404 Not Found`（资源不存在）和 `InvalidParameter.*`（参数校验失败）都会被误判成「模型不可用」（`src/retry.js:29-33`；关键词清单与逐条确证见 `strategist/runs/RETRY-MODELWORDS.json`，回归在 `tests/test-guard.js`，本轮由 41 条扩到 **52 条**）。

### 2.3 四级优先级：谁盖住谁

优先级（**逐字段独立判定**，出处 `src/model-registry.js:457-591`；设置页也写了同一句 `web/views/settings.js:403`）：

```
① 角色显式设置  config.models.roles.<角色>
② 激活的搭配方案 config.models.profiles[activeProfile].<角色>
③ 该 kind 的既有分段默认  llm / image / video / tts 段
④ 内置默认（角色推荐值 + 提供方默认地址）
```

要点：

- **空串 = 未设置**（`src/model-registry.js:320` 的 `isSet`）：把某字段写成空串等于「清除」，会自动回落到下一层；被清空的角色条目是惰性的，不影响解析。
- `provider` / `model` / `baseUrl` / `temperature` **四个字段各自独立**向下找，所以完全可能出现「provider 来自角色、baseUrl 来自提供方默认」的组合。
- `baseUrl` 只在「提供方与分段一致」时才复用分段地址（`src/model-registry.js:501-509`），否则用提供方内置地址。
- 图像/视频/语音类角色的 `temperature` 恒为 `null`（不适用）。

### 2.4 界面上的「来源」列怎么读

设置 → 🧠 模型矩阵，每一行是「角色 / 当前生效（provider / model）/ **来源说明** / 密钥状态 / 改为」。表头定义见 `web/views/settings.js:338-341`。

「来源说明」是**两行**（`web/views/settings.js:263-269`，标签映射 `:148`）：

- 第一行是短标签，取自后端 `resolved[].sourceLevel`：
  | sourceLevel | 界面短标签 |
  |---|---|
  | `role` | 角色显式设置 |
  | `profile` | 方案：<方案名>（例如「方案：均衡」；未激活时显示「方案：(未激活)」） |
  | `kind` | 全局段默认 |
  | `provider` | 提供方默认地址 |

  - `既有分段默认（llm 段的全局默认）`
  - `角色显式设置（config.models.roles.outline）`
  - 三个字段来自不同层时会逐字段列出，如 `provider←角色显式设置；model←全局段默认；baseUrl←提供方默认地址；temperature←内置默认`。

### 2.6 校验结论怎么用

校验函数 `validateModels`（`src/model-registry.js:593-767`），设置页把结论分两段展示（`web/views/settings.js:366-383` 后端结论、`:402-409` 说明）。

**error（阻塞，有 error 就不该保存）**：

1. 激活的搭配方案不存在（`activeProfile` 指向一个不存在的方案）；
2. 角色未指定模型提供方；
3. 提供方**未登记**（不在 `PROVIDERS` 字典里）；
4. 提供方**不支持该角色的类别**（kind 不匹配，例如把 `openai-images` 配给 `video` 角色）；
5. 角色「还不能跑」：缺 Key 或（对 ComfyUI/通用 HTTP 类）缺接口地址。

**warn（提醒，不阻塞）**：

1. 该提供方需要显式模型名但模型名留空（`needsModel && !model`）→ 会回落提供方默认；
2. 角色的提供方是 `none`（配音未启用）→ 成片是静音音轨 + 字幕。

判定与保存的关系：

- 后端 `ok = errors === 0`（`:592`）。
- **界面预检**（`web/views/settings.js:208-233`）：未登记提供方 / kind 不匹配 / 需要显式模型名却留空 → 列出中文原因并**禁用「💾 保存模型矩阵」按钮**；没有改动时也禁用（避免空写配置）。
- **后端 PUT 还有一道白名单**：`sanitizeModelsPatch`（`src/model-registry.js:769-820`，路由在 `src/routes/meta.js:214-215`）—— 未知角色、未登记提供方、`temperature` 越界（必须 0~2）、`baseUrl` 非 `http(s)://`、`baseUrl>500` / `model>200` 字、方案名 >32 字等一律报中文错，**非法请求整体不落盘**。
- provider 与 model 是**成对写入**的：只改 model 也会把该行当前 provider 一起写进角色层，避免「provider 来自方案、model 来自角色」的跨层错配（`:272-285`）。
- 保存后 `PUT /api/settings` 会把 Provider/Model 写进 `config.models.roles`；写成空串的条目是惰性的（等同未设置）。**PUT 只能写值、没有「删除键」语义**。

## 3. 图生图（参考图出图）

### 3.1 什么时候会自动走图生图

三条链路各有自己的判定，共同点是「**本次带没带参考图**」：

**出图后端 = 通用 HTTP（`generic-http`）**

- 参考图来源：该镜的画布参考图 `shot.refs.canvas.refImages[0]`，由 `resolveShotCanvasRef` 解析成绝对路径（`src/modules/render.js:212-223`）。前置条件是 **`image.useCanvasRefs` 不为 `false`**，且该文件确实存在于磁盘。
- 有参考图 **且** 配了图生图模板（`image.generic.refBodyTemplate` 非空）→ 用 `refBodyTemplate`；否则回落 `bodyTemplate`（`src/image.js:411-417` 的 `pickImageBodyTemplate`）。
- 所以「自动走 i2i」的完整条件：`image.useCanvasRefs ≠ false` **且** 该镜有画布参考图 **且** 文件存在 **且** `image.generic.refBodyTemplate` 已配置。

**出图后端 = OpenAI 图像（`openai-images`）**：有参考图走 `POST /images/edits`（图生图），否则 `/images/generations`（`src/image.js:287-290`）。**不需要**配额外模板。

**出图后端 = ComfyUI**：参考图先 `POST /upload/image` 上传、再填进 `image.comfy.refImageNode` 指定的节点；上传并填入成功后才标记为图生图（`src/image.js:545-599`）。

怎么配图生图模板（通用 HTTP）：**设置 → 🖼 出图后端 → 通用 HTTP → 「图生图模板（有参考图时用；留空=仍用上面那套）」**（`web/views/settings.js:504`，卡片里的说明在 `:518`）。留空就是老行为（文生图/图生图都用同一套模板）。

**为什么必须分两套模板**：模板里写 `"image":"{{refImage}}"` 时，**纯文生图会渲染成 `"image":""`**，多数厂商判参数非法（火山方舟 Seedream 会报 `InvalidImageURL.EmptyURL`，`src/image.js:402-408`）。为此适配器还会做一次兜底：渲染后把**空的参考图键直接删掉**，而不是发空串（`pruneEmptyRefKeys`，`src/image.js:310`、调用点 `:465`，覆盖 `image/images/refImage/init_image/first_frame_image/last_frame_image/image_url` 等各家字段名，含嵌套对象）。

**真机验证结论**（`strategist/runs/REFIMG-I2I.json`，2 张真机调用共 ¥0.4）：

- 带画布参考图那张：请求体出现 `input.messages.0.content.1.image = "data:image/png;base64,..."`，`usedTemplate='i2i'`；
- 纯文生图那张：请求体**不含任何 image 键**，`usedTemplate='t2i'`。

### 3.2 `usedTemplate` 落在哪里

出图结果里的「模板标记」会被归一成 5 个键，写进数据库 `shot_renders` 表的 **`meta` 列（JSON）**：

- 归一函数：`imageMetaFromResult`（`src/modules/render.js:148`）
- 落库点：关键帧阶段的 `insertShotRender`（`src/modules/render.js:308-317`）

| meta 里的键 | 含义 |
|---|---|
| `usedTemplate` | `i2i`（带参考图走图生图模板/端点）/ `t2i`（纯文生图；**占位后端与未知后端也归一成 t2i**） |
| `usedTemplateRaw` | 后端原始标记（与库里契约不一致时才出现，例如 `placeholder`） |
| `templateSource` | 实际用的模板/端点键：`refBodyTemplate` / `bodyTemplate` / `openai.editPath` / `comfy.refImageNode=<节点>` / `placeholder` |
| `refImageSent` | 参考图是否**真的随本次请求发出**（占位后端恒 `false`） |
| `refImagePresent` | 本次调用**是否有可用参考图** → 用来区分「没带参考图」和「带了但没发出去」 |

同一条 meta 里通常还有 `canvasRef`（用了哪张画布参考图）与 `canvasScene`（画布场景名）。

**meta 是浅合并落库**的（`src/modules/render.js:120-128`、`:170-177`）：本次 patch 覆盖同名键，**更早写入方留下的其它键保留**；合并时还会加一个 `metaMergedFrom=<上一条记录 id>` 标出来源。代价是新行可能带上一条行的陈旧描述字段（如 `motion`/`backend`/`seed`），但上面 5 个诊断键**恒由本次出图结果覆盖**，不会继承陈旧值。


判读：

**历史行不会回填**：修复模板标记落库之前写入的记录，`meta` 里**永远缺少**这些键（实测 02:54 那条就缺）。追溯时请按「修复时间点」分段看，不要以为「缺键 = 没走图生图」。

## 4. 时间线导入 / 导出

### 4.1 导出：EDL / FCP7 XML / OTIO

**界面路径**：制作台 → 工具条「⤓ 时间线 XML/OTIO」（`web/views/render.js:613` 导出按钮、`:614` 导入按钮；导出是直链下载、**没有弹窗**，导入弹窗是 `openTimelineImport()` 在 `:1530` 起）。

弹窗会先逐个格式试跑一遍并给结论，例如：

```
✅ edl：33 段 · 帧率 25 · 6263 字符
✅ xml：33 段 · 帧率 25 · 36568 字符
✅ otio：33 段 · 帧率 25 · 50004 字符

三种格式与「成片拼接顺序」同源同一份数据（界面顺序 = 成片顺序 = 导出顺序）。
```

然后每个格式一个下载按钮：`⬇ EDL（CMX3600）` / `⬇ FCP7 XML（xmeml）` / `⬇ OTIO（OpenTimelineIO）`。

**命令行等价（可复制）**：

```bash
# EDL（CMX3600）—— Premiere / DaVinci / Final Cut 都能导入
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=edl&download=1'
# FCP7 XML（xmeml）—— 下载文件名的扩展名是 .xml
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=fcp7&download=1'
# OTIO（OpenTimelineIO JSON）
curl -OJ 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=otio&download=1'
# 不下载、只看结论（format/fps/clipCount/content）
curl -s 'http://127.0.0.1:8788/api/render/timeline?scriptId=SC-0001&code=S01E001&format=otio' | head -c 300
```

- `scriptId` / `code` 从界面 URL 或制作台选集处拿；`SC-0001` / `S01E001` 是本机演示数据里的一集。
- 这一集还没有镜头视频时，接口返回中文错误「这一集还没有镜头视频，无法导出时间线」（`src/routes/render.js:301`）。
- 帧率取 `config.video.fps`（默认 25，`src/routes/render.js:294`）。

**「三者同源」是怎么保证的**：三个格式都用**同一份 clips**，clips 来自同一次 `getEpisodeBoard(scriptId, code)` 的镜头序列（`clips = board.shots.filter(s => s.video)`，`src/routes/render.js:285-316`）；这份 board 同时也是**成片拼接**与交付包用的同一份数据（`src/deliver.js:229`、`src/qc.js:167`、`src/publish.js:145` 都调 `getEpisodeBoard`）。所以「界面顺序 = 成片顺序 = 导出顺序」不是口号，而是同一数据源的三个出口。

交付包里也自带一份 EDL（`timeline/` 目录，`docs/使用手册.md` 的交付包结构一节）。

### 4.2 导入：FCP7 XML / OTIO → 接入到画布成片节点（dry-run → 应用）

**界面路径**：制作台工具条「⤓ 导入时间线」（`web/views/render.js:614`，与导出按钮相邻）→ 弹窗「⤓ 导入时间线（FCP7 XML / OTIO → 接入成片节点）」（`web/views/render.js:1530` 起，`openTimelineImport()`）。

**操作步骤**（每一步都在同一个弹窗里）：

1. **选画布**：下拉列出所有画布（`GET /api/canvas/list`），默认选 `CV-MAIN`。
2. **选成片节点**：下拉只列该画布上 `kind='timeline'` 的节点（`GET /api/canvas?id=…`）。该画布还没有成片时间线节点时，弹窗会直接提示你先去画布放一个（或用「铺开分集」生成）。
3. **选格式**：`自动识别（按内容）` / `FCP7 XML（xmeml v4）` / `OTIO（Timeline.1）`。
4. **给内容**：把 Premiere / Final Cut / DaVinci 导出的文本**粘贴**进文本框，或**选择文件**（`.xml` / `.otio` / `.json`，上限 5MB；文件只在浏览器里读取、**不会上传**）。
5. 点「🔍 预览计划」→ 这是 **dry-run**：**不写库、不发起任何生成请求**。计划里逐行给 `clip1…clipN（slot N）← 哪段素材 · 命中哪个画布视频节点 · 时长 · recordIn`，并列出「画布上没有对应视频节点的片段」「按文件名（而非完整路径）匹配的片段」等中文告警。
6. 计划可用时，点「⤓ 应用（写画布连线）」→ 按 `clip1..N` 端口 + slot 把片段接到所选成片节点。

**命令行等价**：

```bash
# ① dry-run（默认）：只回接入计划，不写任何连线
curl -s -X POST http://127.0.0.1:8788/api/render/timeline-import \
  -H 'content-type: application/json' \
  -d '{"canvasId":"CV-MAIN","timelineNodeId":"<成片节点 id>","format":"auto","content":"<FCP7 XML 或 OTIO JSON 文本>","apply":false}' | python3 -m json.tool | head -60

# ② 确认无误后真正接线（apply:true）
curl -s -X POST http://127.0.0.1:8788/api/render/timeline-import \
  -H 'content-type: application/json' \
  -d '{"canvasId":"CV-MAIN","timelineNodeId":"<成片节点 id>","format":"auto","path":"data/xxx/S01E001.xml","apply":true}' | python3 -m json.tool | head -40
```

`content` 与 `path` 二选一：`path` 只能指向 **`data/` 目录下已有**的 `.xml` / `.otio` 文件（越界路径会被拒绝）；两者都给时以 `content` 为准。

**语义要点（按当前代码，逐条可核对）**：

- **零付费**：全程只做「文本解析 + 画布连线读写」，**不调用任何出图 / 视频 / 配音后端，也不新建任何节点**（dry-run 的中文说明与「未新建任何节点」的落款分别在 `src/routes/render.js:447`、`:490`）。
- **默认 dry-run**：`apply` 不为 `true` 时只返回计划，`note` 里明确写「没有写入任何连线、也没有发起任何生成请求」（`src/routes/render.js:447`）。
- **要么整批写入、要么一段不写**：只要有片段在画布上找不到对应视频节点，就直接中文拒绝（`applied:false`），**绝不伪造节点**（`src/routes/render.js:462-466`）。
- **重复执行不会重复建线**：同 `from_node → to_node → to_port` 已存在的连线会被**复用**而不是重建（返回值里区分 `created` / `reused`，查重逻辑在 `src/routes/render.js:468-475`）。
- **端口上限 24 段/成片节点**：超过时接口拒绝，并提示「需要分块、每 24 段一次」，请先在画布上建好后续成片节点再分次导入（`src/routes/render.js:457`，上限常量 `src/interchange-import.js:625` 的 `DEFAULT_MAX_PORTS = 24`）。
- **片段怎么对上节点**：先按**完整路径**匹配（节点的 `data.lastFile` 或最近一次成功的节点产物 `canvas_node_runs.file_path`），再退回**唯一同名文件**匹配（按文件名匹配会给出「请核对是不是同一个素材」的告警）；画布上有多个同名节点时视为缺失（`src/routes/render.js:415`）。
- **拼接顺序**：由 `clip1..N` 端口决定，与界面顺序、导出顺序同源；应用成功后返回 `order`（只读预览，`src/routes/render.js:487-491`）。
- **格式与目标校验**：`format` 只接受 `auto` / `fcp7` / `otio`（`:245-247`）；画布必须存在、节点必须存在且 `kind='timeline'`（`:284-289`）；格式无法识别时给中文 400 + 重新导出建议（`:294-299`）。
- **返回值脱敏**：返回的 clips 里 `file` 只给**文件名**（不回完整路径），另有 `hasFile` 区分「没素材」与「有素材」（`src/routes/render.js:429`）。

**解析层能力**（`src/interchange-import.js`，纯计算：不读库、不写库、不发请求）：

| 函数 | 作用 |
|---|---|
| `parseFcp7Xml(xml)` | 解析 FCP7 XML（xmeml）：取 clipitem 的名称/时长/起止/文件路径；未闭合 XML、空序列、坏输入一律给中文原因而不是抛栈（`src/interchange-import.js:224`） |

| `detectInterchange(text)` | 按内容嗅探格式，只认 `fcp7` / `otio`；SRT、HTML、空串、坏 JSON 一律返回 `null`（**不瞎猜格式**，`:589`） |
| `parseInterchange(text, {format})` | 上面两步的组合入口（`:613`） |
| `clipsToTimelinePlan(clips, opts)` | 把 clips 转成「怎么把这些片段接到成片/时间线节点」的**计划**（端口/slot/chunks/warnings，仍不写库，`:634`） |

### 5.2 TTML 的逐条位置 / 对齐怎么配

位置（纵向，映射到 `tts:displayAlign`）与对齐（横向，映射到 `tts:textAlign`）是分开的（`src/subtitles.js:70-83`）：

| 你写的值 | 效果 |
|---|---|
| `bottom` / `after` | 画面底部（`displayAlign=after`，region id 仍是 `bottom`） |
| `top` / `before` | 画面顶部（`displayAlign=before`，region id 是 `top`） |
| `middle` | 垂直居中（`displayAlign=center`） |
| `center` / `left` / `right` | 横向对齐；`center` 是默认值，region 上**不写** `tts:textAlign`（继承 `<style xml:id="default">`） |

支持的写法（`parseAlignSpec`，`src/subtitles.js:94-131`）：`'top'`、`'left'`、`'top-left'`、`'bottom center'`、数组、或对象 `{position:'top', align:'left'}`。

**逐条优先级**（`src/subtitles.js:210-221`）：

```
默认（defaultAlign） → 该条的 cue.align / cue.position 字段 → perCueAlign 覆盖（按轴覆盖）
```

`perCueAlign` 支持四种形态（`src/subtitles.js:138-166`）：

| 形态 | 含义 |
|---|---|
| 函数 `(cue, i) => 'top'` | 逐条回调（回调里抛错不会拖垮整篇字幕，只跳过该条） |
| 字符串 `'top'` | 整篇统一 |
| 数组 `['top', 'bottom', …]` | 按 **0 基序号**取 |
| 对象 / `Map` `{3:'top'}` | 只要出现与某条 `cue.index` 匹配的键，就**一律按 `cue.index` 取**；否则按 0 基序号取 |

输出结构：

- 每条位置不同会**各自生成一个 `<region>`**；**多 region 时**每个 `<p>` 带 `region="…"` 属性，**单 region 时** `region` 写在 `<body>` 上（`src/subtitles.js:235-242`）。
- region id：默认对齐时就是位置名（`bottom`/`top`/`middle`），非默认对齐时是「位置-对齐」（如 `top-left`）；`origin` / `extent` 由安全区百分比换算，默认安全区 `top:10, bottom:15, left:5, right:5`（`src/subtitles.js:168-183`）。
- **兼容性**：默认参数（不传 `defaultAlign`、没有任何逐条对齐）下，输出与改动前**逐字符一致**（`src/subtitles.js:76-77`）。

> **注意（能力已实现，但界面/接口还没接）**：逐条位置/对齐目前**只能由代码或 Agent 侧调用**，没有配置项、也没有界面入口——
> - HTTP 导出固定用默认参数：`/api/render/subtitles` 调的是 `toTtml(cues, { lang:'zh', title:code })`（`src/routes/render.js:520`），交付包同样只传 `lang`/`title`（`src/deliver.js:285`）；
> - 实测本机导出的 TTML **只有 1 个 region**（`<region xml:id="bottom" tts:origin="5% 85%" tts:extent="90% 75%" tts:displayAlign="after"/>`，region 挂在 `<body>` 上）；
> - 另外 `parseSrt` 产出的 cue 只有 `index/start/end/duration/lines/text/chars`（`src/subtitles.js:36-39`），**不含 `align`/`position`** → `cue.align` / `cue.position` 只在你自己构造 cue 对象时才有意义。

1. 第一遍：`ffmpeg loudnorm=print_format=json` 测出 `input_i / input_tp / input_lra / input_thresh / target_offset`（`measureForNormalize`，`:39-57`）；

## 7. 常见问题排查

### Q1：配置改了但没生效？

**先判断你是怎么改的**：

- **通过设置页保存的** → 立即生效（`saveConfig` 会同步更新内存缓存，`src/config.js:225`）。
- **直接手改 `config/config.json` 的** → **必须重启服务**。原因：`loadConfig` 有内存缓存，只有首次（或显式 `reload:true`）才读盘，之后一律返回缓存（`src/config.js:214-222`）。所以手改文件后不重启，服务用的还是旧配置。

> **代码改动同理**：新加的接口/界面在**旧进程上不存在**，也必须重启才生效。本次实测就撞到过这一条 —— 并行线新加的 `POST /api/render/timeline-import` 在未重启的进程上返回 `404 Not Found`，重启后才可用。

**重启（精确 PID，禁止 `pkill`）**：

```bash
# ① 找到占用 8788 的那个 PID —— 这是唯一权威来源
ss -ltnp | grep 8788          # 没有 ss 就用：lsof -i :8788

# ② 只结束这一个进程（start.sh 用 exec 拉起，PID 就是 node 服务进程本身）
kill <PID>                    # 等 1~2 秒确认它退了；仍不退再 kill -9 <PID>

# ③ 用独立会话重新拉起（必须在仓库目录下）
cd /home/linsheng/Desktop/ai-video-factory && setsid ./start.sh

# ④ 验证起来了
sleep 1; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8788/   # 期望 200
```

> **为什么禁用 `pkill` / `pkill -f node`**：这台机器上**不止一个 node 进程**（例如 DSH 的 Web GUI 也是 node）。`pkill` 按名字匹配会**连带杀掉无关进程**，包括你以为在后台的服务和正在跑的任务。永远按 PID 精确处理。

### Q2：为什么绝对不能同时跑两个 server 实例？

**本会话真实踩过这个坑**（当时并存过两个 `node server.js` 进程，记录在 `strategist/runs/ROLE-WIRING.json` 的 risks）。机制：

1. **双份内存配置缓存**：`loadConfig` 的缓存是**进程内**的（`src/config.js:214`），而磁盘上只有**一份** `config/config.json`。A 实例点保存 → 把它的整份内存写盘；B 实例再保存一次 → **用它的旧内存把 A 刚写的值覆盖回去**。表现就是「设置页明明保存成功了，过一会儿又变回去」或「两个页面看到的配置不一样」。
2. **抢同一份数据**：两个实例还会同时操作同一个 SQLite 库与 `data/` 目录，任务状态/队列状态互相打架。

**自检（同一个端口 / 同一份配置只应有一个实例）**：

```bash
ss -ltnp | grep 8788                             # 期望只有一行（8788 上的那个）
ps -eo pid,lstart,cmd | grep "[n]ode server.js"  # 看一共有几个 server 进程
# 对每个进程确认它用的是哪份库/配置（临时隔离实例是正常的，见下方说明）：
#   tr '\0' '\n' < /proc/<PID>/environ | grep -E '^(PORT|FACTORY_DB|FACTORY_CONFIG|FACTORY_DATA_DIR)'
```

**怎么判断是「危险的双实例」还是「正常的临时隔离实例」**：

- ❌ **危险**：两个进程都指向 **同一份** `config/config.json` 与 `data/factory.db`（通常都没有 `FACTORY_*` 环境变量，端口不同或第二个因端口占用而失败）→ 这就是双份内存缓存互相覆盖 + 抢同一个库的场景，**先精确 kill 掉多余的那个再动配置**。
- ✅ **正常**：临时实例自己带 `FACTORY_DB` / `FACTORY_CONFIG` / `FACTORY_DATA_DIR`（都指向 `/tmp/...`）并监听另一个端口（例如验收脚本用的 8901、或别的验证用 8899）—— 它读写的是自己的临时库与临时配置，**不碰你的真实配置**，可以安全共存。

> 判据一句话：**看它用的是不是同一份 `config/config.json`**。同一份 → 危险；指向 `/tmp/...` 的临时配置 → 正常。

**改配置时的正确顺序**：确保只有一个实例在跑 → 改配置/重启 → 验证（设置页或 `curl /api/settings/models`、`/api/guard/status`）。

### Q3：全量自检里画布审计报 `/tmp/refs` 找不到？

### Q4：看到「鉴权失败」就一定是 Key 写错了吗？

**不一定**。分类规则是「先匹配 401/403 数字、再看文本关键词」，所以 **403 的欠费（`AccountOverdueError`）和无权限（`AccessDenied`）也会显示成「鉴权失败（Key 无效或未授权）」**。请展开厂商返回原文区分三种情况（详见 1.6 的注意 1）。

1. `image.useCanvasRefs` 是不是被设成了 `false`（设成 false 会**整体禁用**画布参考图，`src/modules/render.js:215`）；
2. 该镜有没有画布参考图（`shot.refs.canvas.refImages[0]`），文件是否真的还在磁盘上；
3. 出图后端是 `generic-http` 时，`image.generic.refBodyTemplate`（图生图模板）**是否为空** —— 空就退回单模板；

### 8.1 额度/模型类错误不再误判、不再白重试，且给中文告知

- 错误字典新增两类**永不重试**的错误：`quota`（额度/欠费）与 `model`（模型不可用）（`src/retry.js:10`、`:13`）。
- 判定顺序（数组顺序即优先级，命中即 `break`）为 **`quota` → `model` → `auth` → `rate` → `moderation` → `timeout` → `network` → `format` → `config` → `server` → `client`**（`src/retry.js:25-43`、`:53`）。`quota` 必须排在 `auth`/`server` 之前，否则厂商包在 403/500 里的欠费会被吃成「鉴权失败」或「可重试的 5xx」（`src/retry.js:26-27`）。
- `model` 规则**锚定在 `model`/`endpoint` 前缀或完整短语**上，**裸 `not found` / 裸 `invalid` 刻意不收**，避免把 404 资源不存在、`InvalidParameter.*` 参数校验失败误判成模型不可用（`src/retry.js:29-33`）。
- 「可重试清单」是唯一口径 `RETRY_KINDS`，**只含 `rate` / `server` / `network`**（`src/retry.js:85`、`:90`）。
- 中文告知：界面上看到的是 `ERROR_KINDS` 里的 `label`；抛错时 `withRetry` 会把归类与尝试次数拼进 message（`src/retry.js:104-107`、`:118-124`）。实测文案形如 `⛔ 未自动降级：模型不可用（请检查模型名/开通状态，不自动重试）。`（`/tmp/v-35-final.log` 阶段 27/35 的断言输出，见 `strategist/runs/RETRY-MODELWORDS.json`）。

**它解决什么**：跨镜一致性的旧判据是「8×8 灰度 aHash 代理指标」，只能抓画风/明暗/构图漂移，抓不住「同一画风但换了张脸 / 手部畸形 / 穿模 / 糊字」。本轮新增多模态真读图作为**第二道判据**，与代理指标**共存**（`src/vision-qc.js:1-20`）。

**整集质检的接入（新增检查项 `consistency-vision`）**：`qcEpisode({scriptId, code}, { vision, cfg, question, threshold, maxPairs, role })` 在代理指标之后追加真实画面质检（`src/qc.js:162`、`:164`、`:247-258`）。分级规则：

| 情形 | 级别 | 文案/细节 |
|---|---|---|
| 没有可用多模态后端，或调用方未注入 `runVision` | `info` | 「未配置多模态质检后端，使用代理指标」，`detail` 里明示「本次未注入多模态调用器（`qcEpisode` 第二参数 `{ vision }`），因此不会发起任何多模态请求」（`src/qc.js:267`，detail 拼装在 `:259-266`） |
| 注入了 `runVision` 且后端可用、**有离群镜头** | `warn` | 附真实评分与建议重跑的镜头（`src/qc.js:308-312`） |
| 注入且可用、**无离群** | `ok` | 「真实画面质检：N 组两两比较（M 对），最低分 X，未发现离群镜头」（`src/qc.js:314-317`） |
| 注入但**没拿到有效评分** | `info` | 如实说明原因（例如所有调用都失败），**绝不假装通过**（`src/qc.js:305`；原因文案来自 `src/vision-qc.js:1111-1116`） |
| 整段抛异常 | `info` | 「真实画面质检未能执行（已降级为代理指标）」（`src/qc.js:320-322`） |

**离群判定口径**（`src/vision-qc.js:1050-1085`，方法串 `NEG_RE`/`POS_RE` 见 `:673-674`）：

- 组内评分先算**中位数** `median` 与 **MAD**（绝对中位差），相对线 `relativeCut = max(0.15, median - 3×MAD)`（`:1056-1061`）。
- **≤2 张**一组（只有两两一对）：只用**绝对阈值**（`score < threshold`，默认 0.6）（`:1063-1069` 的 `values.length >= 3 ? … : absolute` 分支）。
- **≥3 张**一组：要求**「低于绝对阈值」且「低于 `中位数-3×MAD`」**两个条件同时成立才算离群（`sc.outlier = absolute && relative`，`:1063-1069`）。
- 这样设计的理由：「整组都偏低」不会被误报成「某一镜离群」，而是给出**整组复核**的提示（`groupLow` / `shareHint`，`:1079-1084`；`src/vision-qc.js:19-20`）。
- 用户显式传入的 `threshold` 是**权威口径**（`:925`）。

**aHash 代理指标的边界（务必理解，别当成等价物）**：

- aHash 是**代理指标**，永远可用（本地 ffmpeg、零成本、零网络），但它**不做人脸识别**，也识别不了手部畸形/穿模/糊字这类语义问题。
- 真实判据只在「① 配好支持视觉的后端 + ② 调用方注入 `runVision`」时才生效（`src/vision-qc.js` 的 `visionAvailable()`，`:207-305`）。
- 两者**并存**：真实质检跳过时，代理指标的结果与既有结论**不受影响**（`src/qc.js:247-249` 的分级注释）。

## 15. 墙钟非单调加固（E-101）

**背景（环境事实，不是本项目缺陷）**：本机墙钟**非单调**。E-101 落地后的独立复测（`strategist/runs/VERIFY-35.json#clock_skew_replication`）：`Date.now()` 对照 `process.hrtime.bigint()`（单调钟）每 250ms 采样一次、共 **65s / 259 次**，其中 **>50ms 的跳变 19 次**，**最大回拨与前拨均为 12449ms**（≈ 每 3.4s 一次，非偶发）。早期的同法采样与行级铁证见 `strategist/runs/FLAKE-FIX.json`。代码注释里也写着这层口径（`src/db.js:22-44`、`src/util.js:11-23`）；注释里的频率原先写的是「每 ~20 秒出现一次」，与本轮 250ms 采样测得的「≈ 每 3.4s 一次」不一致，**已按本轮独立复测改正**（口径一律以 `VERIFY-35.json#clock_skew_replication` 为准）。

它造成的两类缺陷，本轮已在 `src/**` 系统性修掉（29 个文件）：

| 缺陷 | 成因 | 修法 | 出处 |
|---|---|---|---|
| ①「取最新一行」取错行 | 全部 `created_at` 都是 `nowISO()` 写下的**墙钟字符串**，回拨后「程序序更晚写的行」可能带**更早**的时间戳，于是 `ORDER BY created_at DESC LIMIT 1` 会取到别的任务写的行 | **`src/**` 里 71 处按 `created_at` 判序的 SQL 全部改为按插入序 `rowid`**。依据：这些表**都没有 `AUTOINCREMENT`**，插入时 `rowid = max(rowid) + 1`；即使删行导致 rowid 被复用，SQLite 仍保证新行 `rowid` **严格大于现存所有行**（复用只发生在「被删出的空洞 < 当前 max」上）⇒ `ORDER BY rowid DESC` 恰好等价「按插入序倒序」，**与墙钟无关**。多表 JOIN 时 rowid 有歧义，必须写 `别名.rowid` | 口径与用法写在 `src/db.js:22-44`（导出 `ORDER_INSERT_DESC` / `ORDER_INSERT_ASC`）；逐文件行号清单见 `strategist/runs/E-101.json#files_with_lines` |
| ②耗时被记成负数 | `Date.now() - t0` 在回拨时是负数，污染看板 / 报告 / 对账（早前自检产物里真的出现过 `"ms": -12349`） | **同进程**耗时改用单调钟：`src/util.js` 新增 `monoNow()`（`performance.now()`）、`elapsedMsSince(t0, clock)`（单调差值、下限钳 0、**可注入时钟**便于测试）、`clampMs(v)`（NaN/Infinity/负 → 0）。**跨进程 / 跨重启**的墙钟差值（`jobs.created_at → finished_at` 等落库字符串）**无法**用单调钟，只能钳到 ≥0 并注明受跳变影响 | 实现与选型边界：`src/util.js:26-42`；跨进程钳 0 的三处：`src/stats.js:60-66`（任务耗时排除负样本）、`src/studio.js`（制片报告阶段耗时）、`src/schedules.js:1105-1111`（调度延迟 —— 这里必须继续用墙钟，因为「迟到几分钟」是**真时间语义**） |

**静态护栏（防回流）**：`tests/test-clock-skew.js` 会扫描 `src/**`，断言 (a) 没有任何 SQL 再按 `created_at` 判序、(b) 没有任何「`Date.now()` 相减当耗时」（**白名单**只有真按时间语义的用法：`src/stats.js` 的日期窗口算术、`src/schedules.js` 的 `next_run_at`/调度延迟等）。

## 16. 参考图类型：按真实文件类型发送 + SVG 自动栅格化

**现场故障（2026-09-30 实测，用户报「生成图片被拒绝」）**：演员页「批量定妆」勾选带参考图（`useRef`）后 **6 张全失败**，厂商原文（`jobs.result` 里逐条不同 request_id、同一原因）：

```
400 InvalidParameter: Cannot determine file type for
http://ds-restful-api-bj-prod.oss-cn-beijing.aliyuncs.com/restful/data-uri/…/…?Expires=…&Signature=…
```

**根因**：占位后端的定妆图是 **SVG**（`src/image.js#placeholderImage` 返回 `mime: 'image/svg+xml'`，全库 442 张历史定妆图都是 `.svg`），而 `useRef` 取的参考图正是演员的 `cover_image`（`src/modules/actors.js:147`：`actor.ref_image || actor.cover_image`）。通用出图**把 data URL 硬编码成 `data:image/png;base64,…`**（不管真实类型），于是「声明 PNG、内容 SVG」；百炼受理后把 data URI 转存到自己的 OSS，再取文件类型时判定失败 → 400。视频侧的 `{{refImage}}`/`{{lastImage}}`（`src/video.js` 的 `b64Of`）是同一处硬编码，首帧/尾帧遇 SVG 会同样栽。

**修法**（`src/util.js` 新增三件套，出图与视频统一走它）：
- `sniffImageMime(buf)` —— **按文件头魔数**判真实类型（PNG `89 50 4E 47` / JPEG `FF D8 FF` / WebP `RIFF….WEBP` / GIF / SVG 文本），**不看扩展名、也不信调用方声明**；
- `readImageForVendor(abs)` —— 光栅类型（png/jpg/webp）按真实类型直接发；**SVG 先本机 ffmpeg（librsvg）栅格化成 PNG**（按内容哈希缓存，同一张图只转一次）；魔数认不出的（如误把 mp4 当参考图、文件损坏）**不猜也不丢**：按扩展名如实声明类型照发，并在 notes 写明「厂商可能拒绝」；
- data URL 一律 `data:${真实 mime};base64,…`；`{{refImage}}` 渲染为空时仍走既有的删键逻辑（不发空串）。

**为什么不做「静默降级为文生图」**（这条是有意为之，别改）：参考图用不上时**静默换成本批语义**会让用户拿到一批「看起来正常、但没有按参考图约束」的图，比直接失败更难发现；视频侧本来就有「不静默丢尾帧」的红线（`src/video.js`：模板缺 `{{lastImage}}` 直接报错）。因此：SVG 栅格化失败 → 抛中文错误（出图 `ImageError` / 视频 `VideoError`，逐镜失败不影响同批其他镜头）；魔数认不出 → 照发 + notes 摊开风险。

**可追溯（不必翻服务端日志，也是本轮的「验证纪律」赖以成立的东西）**：出图返回值新增 `refImageMime` / `refImageRasterized`（`src/image.js` 的 `genericHttp`、`src/video.js` 的 `b64Of`）；归一函数 `imageMetaFromResult`（`src/modules/render.js:148-166`）记 `usedTemplate / templateSource / refImageSent / refImagePresent`。
> **补写的一处白名单漏洞**：`imageMetaFromResult` 原先只挑固定几个键，`refImageMime` / `refImageRasterized` **会被它吃掉**（出图返回里有、库里却没有）。已在 `src/modules/render.js:163-164` 补写：只在出图适配器确实返回这两个字段时才落库，占位/其他后端不加噪音。
> **定妆图侧**（`src/modules/actors.js` 的 `insertActorImage` 调用处 `:170-181`）：除 `refImageUsed / refImage`（`:172`）外，本轮又补了「**勾了 `useRef` 却没有可用参考图**」的如实标注 —— meta 记 `refImageRequested: true` + 中文 `refImageNote`（`:174-179`），结果项里记 `refNote`（`:191`），避免用户看到「成功」就以为参考图生效了（实际是纯文生图）。
