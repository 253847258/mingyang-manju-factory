### P0-2 时钟回拨问题仍在产品代码里

位置：`src/edit-timeline.js:150/152/156/414/449`

仍有按 `created_at DESC` 决定“最新”的查询：

- 成片视频选择
- 关键帧选择
- 成片版本列表
- 审片意见列表

本机存在墙钟回拨，可能取错最新行或造成列表乱序。这是真实产品问题，不是测试误报。

处理建议：

- “最新记录”统一改 `rowid DESC`
- 版本类保留 `version_no DESC`，再用 `rowid DESC` 做稳定兜底
- 不得把 `created_at` 作为唯一排序依据

### P0-3 小说工坊四步页面引入测试回归

位置：`web/views/novel-pipeline.js:183/191`

新页面直接调用 `window.localStorage`，Node DOM 冒烟环境没有 `window`，导致 `test-novel.js` 的 UI 测试从 `mount()` 起连锁失败。

同时，测试仍断言旧按钮“写作下一章”，而当前默认流程已经改成“四步生产线”，测试预期也需要同步更新。

处理建议：

- 访问浏览器存储前加 `typeof window !== 'undefined'`
- 更新 `test-novel.js` 的 UI 断言到新四步流程
- 不删除旧流程兼容入口

### P0-4 外部模型仍是单点

证据：

- 火山当前模型返回 `SetLimitExceeded`
- 账号处于 Safe Experience Mode
- 试过 9 个备用模型 ID，全部返回 404 / 未开通

### P2-2 两个失败属于测试本身问题

#### 画布九宫格

`tests/test-canvas-sheets.js:52` 写死 Windows 路径：

```text
C:/Users/Administrator/.../ffmpeg.exe
```

macOS 会走 JS 兜底，所以断言 `engine === 'ffmpeg'` 失败。产品拼图功能本身成功，失败的是测试不可移植。

#### 时间线感知哈希

`tests/test-timeline.js:887-924` 用纯红色和纯蓝色色块测 aHash。纯色图没有纹理，aHash 位图可以完全相同，因此“异色必须距离拉满”的断言不成立。

建议使用带纹理、形状或明暗结构的测试图，而不是纯色块。

### P2-3 测试会改写已跟踪报告文件

运行全量测试后，`scripts/simulate-all.js` 会改写：

- `docs/全模块功能模拟测试报告.md`
- `docs/全模块功能模拟测试报告.json`

这会造成“只读检查也污染 Git 工作区”。建议测试输出写到临时目录，或只在显式 `--update-report` 时更新正式报告。
