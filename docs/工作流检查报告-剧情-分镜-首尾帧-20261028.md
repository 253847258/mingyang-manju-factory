## 一、结论速览

| 领域 | 评分 | 一句话 |
|---|---|---|
| 剧情结构 | **B-** | 单集有 logline/钩子/悬念（100%），但**180/180 集全是草稿**，闸门不硬拦 |
| 分镜提示词 | **B** | 298 镜全部有正/负向提示词，英文为主、含镜头语言；但**ID 泄漏、镜头时长/景别失衡** |
| 首尾帧 | **C** | 功能做全了（自动补尾帧/尾帧落库/后端映射），但**实际使用率 0/298**，且缺一致性校验 |
| 资产层（V2 核心） | **D** | 只有演员是一等公民；**无 asset_version / snapshot / lineage** |
| 闸门与编排 | **D** | 审核状态机有，但 `reviewGate` **只告警不阻断** |

**一句话**：零件齐、工序通，但**没有闸门、没有资产快照、没有血缘**——这正是 V2 要补的三件事。

---

## 二、V2 方案要点（参考）

- 三层：**资产层**（角色/场景/道具/服装 + 版本 + 快照）→ **工序层**（九站）→ **编排层**（闸门/队列/预算/留痕）。
- 三闸门：**① 剧本锁定 ② 前三镜锚定 ③ 成片定版**；其余全自动。
- 两条硬约束：**版本只增不改**、**集级快照隔离**。
- 血缘六项：模型与版本、seed、完整提示词、参考图哈希、关键参数、生成时间。
- 交付契约：单集 60–90 秒、**8–12 镜**、单镜 3–6 秒、台词 ≤30 字。

## 三、剧情检查

### 做得好

- **180 集全部有** `logline`、`hook`（集末钩子）、`cliffhanger`（悬念）——覆盖率 100%。
- 小说大纲层很扎实：10 卷结构、23 条因果链、22 条长线回环、20 条伏笔（含回收章）、19 项时间线。
- 剧本模块已有审核状态机（draft → review → approved → locked）。

### 问题（按严重度）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **闸门一是假的** | `script-review.js` 注释与实现均为「只告警，不硬阻断」；`reviewGate` 返回 `ok:true` 只带 pending | 没审的剧本也能一路拍到成片 |
| 2 | **180/180 集全是 draft** | `SELECT review_status,COUNT(*) FROM script_episodes` → draft 180 | 实际生产中从未走过审核闸门 |
| 3 | **单集镜头数严重超标** | EP-0001/0002 各 33 镜，EP-0003/0004 各 24 镜；V2 要求 8–12 镜 | 单集 120 秒，超出 60–90 秒目标；成本与返工面翻倍 |
| 4 | **缺集级节拍图** | 有集钩子，但没有「每集三幕/节拍/情绪曲线」结构化字段 | 剧情节奏靠模型自由发挥，无法验收 |
| 5 | **无集级资产快照** | 改一个角色会影响所有集 | 第 3 集和第 1 集人物不一致，无法隔离 |

### 建议

1. **把闸门一改成硬阻断**：未 approved 的集，制作台直接拒绝提交（可留 `--force` 但写审计）。
2. **加集级节拍表**：每集 3–5 个节拍（钩子/冲突/反转/悬念），作为拆镜输入。
3. **镜头数/时长契约**：默认 8–12 镜、单镜 3–6 秒；超限给出中文警告并要求确认。
4. **集级快照**：开拍时冻结角色/场景/道具/服装版本。

## 四、分镜提示词检查

### 做得好

- **298/298 镜都有正向和负向提示词**（空值 0）。
- **265 镜纯英文**（模型友好），无纯中文提示词。
- 提示词包含镜头语言：`cinematic photorealistic, film still, arri alexa 35mm, shallow depth of field` + 角色外形 + 景别。
- 负向词齐全（anime/cartoon/cgi plastic/over-smoothed skin 等）。

### 问题

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **角色/地点 ID 泄漏进提示词** | 7 镜提示词含 `(C-xxxx)/(L-xxxx)` | 模型会把编号当文字画进画面（此前正文已出现同类问题） |
| 2 | **中英混排 33 镜** | 265 纯英 / 33 混排 / 0 纯中 | 英文模型对混排理解不稳，画风容易漂 |
| 3 | **景别失衡** | 远景 82（28%）、大特写 75（25%）、中景 66、全景 23… | 大特写过多、远景偏多，缺少叙事中景，节奏容易碎 |
| 4 | **时长越界** | 平均 4.63s，但 45 镜 >6s、6 镜 >10s，最长 20s | 超出 V2 的 3–6s 契约；长镜更贵、更易穿帮 |
| 5 | **台词超长** | 35 镜有台词，最长 45 字，3 镜 >30 字 | 单镜读不完，字幕会被迫加速 |
| 6 | **缺提示词血缘** | 没有逐镜记录 seed / 参考图哈希 / 模型版本 | 好镜头无法复现，坏镜头无法定位原因 |

### 建议

1. **提示词清洗器**：提交出图前统一剥离 `(C-/L-/CX-)` 编号、压缩中英混排、补全负向词。
2. **提示词 linter**：检查长度、CJK 比例、景别/时长/台词字数，超限阻断或警告。
3. **景别配额**：按集设定 远/中/近/特 的配比（如 2:4:3:1），拆镜时校验。
4. **血缘落库**：每镜记录模型、seed、完整提示词、参考图哈希、参数。

## 五、首尾帧检查

### 做得好

- 功能链完整：
  - `shots.tail_image` 一镜一尾帧，落库可还原；
  - 画布右键「⌛ 自动补尾帧」→ `createLastFrameNode` → `image → last` 连线；
  - HTTP `/api/canvas/auto-last`、Claw 指令、MCP 工具四个入口；
  - 本地 placeholder 用 `xfade` 表达首尾过渡；
  - ComfyUI 通过 `lastImageNode` 映射尾帧节点；
  - 通用 HTTP 通过 `{{lastImage}}` 占位符；
  - 只给尾帧不给首帧会「诚实失败」，不静默丢帧。

### 问题

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **实际使用率为 0** | `SUM(tail_image<>'')` → **0 / 298** | 功能做了但没人用，成片仍是「单帧运镜」 |
| 2 | **自动补尾帧未进主流水线** | 只在画布右键/指令触发，制作台批量出视频不会自动补 | 批量生产时默认没有首尾帧 |
| 3 | **Kling 模板尾帧字段为空会 400** | 预设里固定带 `"last_frame":{"url":"{{lastImage}}"}`；无尾帧时为空串 | 没设尾帧的镜头直接失败（与 Seedance 同类问题） |
| 4 | **缺首尾帧一致性校验** | 只有 pHash 跨镜抽检，没有「首帧 vs 尾帧」的人脸/服装/色调对比 | 首尾过渡可能出现「换人/换衣服」 |
| 5 | **真人首帧被视频审核拒绝** | Seedance `PrivacyInformation`（本次实测） | 写实人物首帧无法走 Seedance |
| 6 | **尾帧未进血缘** | 尾帧路径不在 take/lineage 结构里 | 无法复现「这一版首尾帧是怎么来的」 |

### 建议

1. **默认策略**：视频后端支持首尾帧时，每镜自动补尾帧（可开关），不支持的镜头明确降级为首帧驱动。
2. **双模板**：视频请求体模板支持「有尾帧/无尾帧」两套（与出图的双模板一致），避免空字段 400。
3. **首尾一致性 QC**：对首帧与尾帧做人脸/服装标签/色调三项比对，低于阈值重出尾帧。
4. **尾帧进入血缘**：`take/lineage` 记录首帧、尾帧、seed、提示词、参考图哈希。
5. **真人策略**：写实真人首帧走 Kling/Runway/Luma；Seedance 只用于动漫化/风格化。

## 六、跨模块 / 资产层对照（V2 差距）

| V2 要求 | 现状 | 差距 |
|---|---|---|
| 角色/场景/道具/服装 四类一等实体 | 只有演员是一等公民；场景/道具/服装散落在画布与提示词 | **缺三类实体与版本** |
| asset_version 只增不改 | 无 | 改动会覆盖，无法回到旧版 |
| snapshot 集级冻结 | 无 | 改角色会污染已完成集 |
| take / lineage 血缘 | 有 shot_renders 多版本，但缺 seed/参考图哈希/参数 | 复现能力不足 |
| cost_ledger 每笔记账 | 图片/视频有部分计量；LLM token 不计 | 成本不可控 |
| gate_log 闸门签字 | 有审核字段，但闸门不阻断、无签字记录 | 无法追责 |
| 生产订单 project → episode → shot | 模块各自为政 | 缺统一状态机 |

### P0（先做，直接影响能不能量产）

5. 集级资产快照（角色/场景/道具/服装）

7. 提示词血缘落库（seed/参考图哈希/模型版本）
8. 自动补尾帧进主流水线

### P2（规模化）

9. 生产订单与看板
10. cost_ledger / gate_log 完整化

## 九、一句话总结

**剧情的"钩子"有了，"闸门"没有；分镜的"提示词"有了，"纪律"没有；首尾帧的"功能"有了，"使用"没有。**
