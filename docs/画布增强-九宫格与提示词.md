# 画布增强：九宫格 / 描述自动改进 / 一致性闸门 / 专业提示词

> 本轮在模块 1（明星演员矩阵 · 画布）上做加法：修掉占位出图的 SVG 断链，新增人物/环境九宫格、
> 描述自动改进、一致性标红与一键重跑、专业级提示词体检与专业化。**旧接口与字段全部保持不变。**

---

## 1. 出图底座：占位后端改为 PNG

- 现状问题：占位（placeholder）后端原本输出 **SVG**，而 `src/video.js` 只接受栅格图
  （`/\.(png|jpe?g|webp|bmp|gif|tiff?)$/i`），导致「离线模式 → 本地运镜出片」「九宫格拼图」都会断链。
- 改法：新增明文 `src/pngd.js`（纯 Node，`zlib` + CRC32 的 PNG 编码器 + 简化占位图渲染 + 纯 JS 拼图），
  并把 `src/image.js` 的 `placeholderImage` 改为输出 **`.png`**（返回结构不变：`filePath/absPath/mime/backend/model/seed/...`）。
- 效果：`tests/test-graph.js` 从 12 项失败降到 **0 失败**（199 通过）；离线全链路出片与拼图可用。

> 接了真实出图后端（`generic-http` / `comfyui` / `openai-images`）时不受影响——它们本来就出 PNG。

## 2. 人物九宫格 / 环境九宫格

**产物**：9 张独立 PNG + 1 张自动合成的 **3×3 设定表**。

### 人物（固定专业设定表）

| # | 格子 | 复用变体 |
|---|---|---|
| 1 | 定妆主图 | `full/keyart` |
| 2-4 | 正面 / 侧面 / 背面全身 | `angle/front|left|back` |
| 5-7 | 平静 / 微笑 / 愤怒 | `expression/neutral|smile|angry` |
| 8 | 服饰细节 | `costume/embroidery` |
| 9 | 手部特写 | `gesture/open-palm` |

### 环境（视角 × 时段）

3 视角（全景 / 中景 / 特写）× 3 时段（白天 / 黄昏 / 夜晚）= 9 格，
拼 `scene` 节点的 `desc / timeOfDay / weather / tags` + 画风包。

### 流程与落库

1. `planSheet` 出 9 格任务（提示词复用 `prompts.js#buildPrompt` 与 `data/styles.js` 风格包，不写库）。
2. 生成前过 `preflightBatch` 成本闸门（队列暂停或预算超额时给中文原因）。
3. 逐格出图 → 每格落一条 `actor_images`（`kind='sheet-<cell>'`）。
4. `composeSheet` 拼 3×3：优先自带 ffmpeg（`scale`+`pad`+`xstack`），不可用时用 `pngd` 纯 JS 兜底。
5. **人物默认把设定表设为该角色主参考图**（`actor_images.kind='sheet'` + `setPrimaryImage` → 写 `actors.ref_image`）。
   环境则写入节点 `data.refImages[0]`。
6. 元数据写 `actors.meta.sheets[]` / `canvas_nodes.data.sheets[]`（**不新增数据表**）。

### 接口

- `POST /api/canvas/sheets/plan` `{kind:'character'|'environment', actorId|nodeId, styleId?}` → 9 格计划 + 成本结论
- `POST /api/canvas/sheets/generate` `{...同上, confirm:true, sync?:true}` → `{jobId}` 或同步结果
- `POST /api/canvas/sheets/compose` `{files[9], cols:3, cell, gap}` → 手动拼图
- `GET  /api/canvas/sheets?actorId=|nodeId=` → 历史九宫格

### 界面

画布工具条新增 **🔲 九宫格**：选类型（人物 / 环境）→ 选目标 → 「预览 9 格」→「生成九宫格」。

## 3. 描述自动改进（预览后确认）

- 角色：复用 `prompts.js#optimizePrompt(mode='describe')`，补 `personality / background / costume / hair / face / voice / tags`。
- 环境 / 物品：新增 LLM 补 `desc / timeOfDay / weather / mood / palette / cameraNotes / tags`。
- **离线可用**：mock 或没有 Key 时自动回退到确定性规则（按角色定位 / 画风 / 时段生成可用描述），并标注 `source=rule`。
- 流程：`preview` 只算不写库（返回 `token`）→ `apply` 才落库（返回 `undoToken`）→ `undo` 回滚。
- 落库统一走 `updateActor` / `updateAsset`，口径与演员编辑器一致。

### 接口

- `POST /api/describe/preview` `{scope:'actor'|'asset', id}`
- `POST /api/describe/apply` `{token}`
- `POST /api/describe/undo` `{token}`

## 4. 一致性闸门（标红 + 一键重跑，不阻断出片）

- 现有 `consistency.js#scoreConsistency` 是**按镜头渲染记录**打分的，吃不了任意图片；
  因此 `src/canvas-consistency.js` 用同一套方法（8×8 灰度 aHash + 组内离群，判定线 `max(阈值, 中位数+3×MAD)`）
  在明文里实现一份，直接对**演员图片 / 节点 refImages**打分。
- 解码**优先用 sharp**（可选依赖，装了就能读 PNG/JPEG/WebP），没装时回退到纯 JS PNG 解码器。
- 阈值默认 `0.34`；只告警、标红，不阻断出片。
- 一键重跑：对低分节点重出主图，写一条 `actor_images`（`variant='rerun'`）；**锁定节点跳过**；队列暂停或预算超额时给中文原因。

### 接口

- `GET  /api/canvas/consistency?canvasId=` → `{nodes, low, summary}`
- `POST /api/canvas/consistency/rerun` `{canvasId, confirm?}`

## 5. 专业级提示词（含剧本分镜）

- 新增 `src/prompt-quality.js`：
  - `PRO_STYLE_TAILS`（10 个画风的镜头/光位/色彩/胶片质量尾）、`PRO_NEGATIVES`（按画风负向库）。
  - `promptDiagnose`：重复 token、中英混排、缺人物锚点/镜头构图/焦段/光影/质量尾/负向词、超长、缺画风专业尾。
  - `promptRepair`：确定性修复（去重 → 踢中文 → 补镜头/光影/质量尾与负向）——**幂等**、不调 LLM、不花钱。
  - `professionalizePrompt`：LLM 出 POS/NEG 预览；mock/失败时自动回退到 `promptRepair`。
- 覆盖三处：演员 `prompt_pos/neg`、环境/物品节点 `data.prompt|negative`、剧本镜头 `shots.prompt_pos/neg`。

### 接口

- `POST /api/prompt/diagnose` `{scope:'actor'|'asset'|'shot'|'text', id|text, styleId?}`
- `POST /api/prompt/professionalize` `{scope, id|text, styleId?, apply?, confirm?}`
- `POST /api/scripts/:id/prompt-professionalize` `{episode?}`（剧本工厂「专业化提示词」按钮，跳过锁定镜头）

## 7. 已知限制

1. **一致性解码**：装了 `sharp` 时支持 PNG/JPEG/WebP；没装时纯 JS 只支持八位 PNG（其它格式跳过且不报错）。
2. **一致性是代理指标**：8×8 aHash 只判「明显离群」，不做人脸识别；纯色/极简图哈希会退化，属预期。
3. **九宫格同步生成**：真实后端下 9 张图可能较久；界面提供同步/后台两种方式。
4. **队列暂停时的付费动作**：`preflightBatch` 读到 `jobs:paused` 时会拦住后台任务（不往暂停队列塞任务）；
   而**同步的用户动作**（九宫格 `sync:true`、一致性重跑）会先要求人工确认，确认后立即执行、不进队列；
   预算/存储类阻断始终硬拒绝。
5. **拼图尺寸**：tile = cell + 2×gap，输出为 `3×(cell+2×gap)` 的正方形；ffmpeg 与纯 JS 两条路径尺寸一致。

## 8. 与制作台的闭环（两条成片线收敛）

职责划分：**制作台 = 批量自动出片；画布 = 资产精修（角色/环境/九宫格/一致性）；剧本工厂 = 审核/改词/配平。**

- 制作台侧边分集列表直接显示**审核状态**（草稿 / 待审 / 已通过 / 已锁定），未通过时加 `⚠ 未审核` 标；
  点开剧本还有「✍ 去剧本工厂审核本剧」。
- 制作台顶栏加「✍ 去剧本工厂」「🎭 去画布精修」两个入口。
- 画布工具栏加「🎞 去制作台」；剧本工厂导出区加「🎞 去制作台」。
- 画布时间线仍用「🎞 铺开分集」导入剧本分镜，画布负责精修与二次导出。

> 关于早前记的“`timeline-order` 需要 nodeId 的 400”：复核后确认**不是缺陷**——界面调用时始终带 `node_id`
> （`timelineOrderDialog(hit.id)`），只有手工不带参数请求才会 400。已按现状保留。
