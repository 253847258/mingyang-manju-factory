# 全模块功能模拟发现的问题与修复

> 来源：`node scripts/simulate-all.js`（全模块端到端模拟）与 `./scripts/verify-all.sh` 的逐项断言。
> 原则：模拟脚本只做「真实调用 + 断言」，发现的问题全部回到产品代码里修，并把复现路径固化成回归用例。

## 一、英文正向提示词混入中文（模块1）

**现象**：`POST /api/actors/:id/prompt` 返回的 `positive`（英文正向提示词）里夹着中文片段。

- `angle`（多角度全身）全部 5 个变体：`正面 / 背面 / 左侧 / 右侧 / 四分之三` —— 该分类只写了 `variantLabels`（中文标签），漏了 `variantTokens`（英文令牌），拼装时回退成了中文标签。
- `group/duo`：同上（`双人同框`）。
- 另外 `buildPrompt` 会把「性格的气质 / 背景：… / 多角色同框…」以及**自由文本字段**（如中文服饰「黑色风衣」）直接拼进英文正向，SD / Flux 一类的英文编码器遇到中文会明显降质。

**影响**：出图质量下降，且与「英文正向 + 负向」的产品定义不符（模块3 的分镜提示词一直是纯英文，两者不一致）。

**修复**（`src/data/dictionaries.js`、`src/prompts.js`）：

1. 给 `angle` / `group` 补 `variantTokens`；
2. 中文补充位不再进英文 `positive`，改为随返回值提供 `positive_zh`（中文版提示词，供中文模型或界面展示）；
3. 新增 `stripCjk()`：把英文正向里无法翻译的中文片段剔除，并记录在 `cjkDropped`（不静默丢失，调用方可提示用「一键优化」翻译）；
4. `group` 分类改为写入英文同框约束 `multiple characters in one frame, each keeping consistent appearance`。

**回归**：`tests/test-actors.js` 新增「全部变体英文正向零中文残留 / positive_zh 齐备 / 中文服饰被剔除并记录」3 项（63 个变体全覆盖）。

## 二、剧本正文早于画布绑定 → 画布设定永远进不了分镜（模块1↔模块3）

**现象**：先写剧本正文（离线规则或 LLM），**之后**才把画布绑到剧本，再生成分镜时，所有镜头的 `prompt_pos` 都不带 `canvas set:` 令牌，`refs.canvas` 也是空的 —— 画布上的环境/物品/参考图白绑了。

**根因**：`fallbackEpisodeScript` 生成场次时需要地点表才能给场次分配 `location_id`；但剧本正文是更早生成的，存下来的 `episode.scenes` 里 `location_id` 全是空，分镜阶段直接复用了这份「没有地点归属」的场次，于是画布环境匹配不上。

**修复**（`src/modules/script.js`）：分镜阶段若发现「已有场次全部没有 location_id，而地点表非空」，就用合并了画布环境的地点表重新推导一次场次，并在 `warnings` 里中文说明原因。

**回归**：`tests/test-bridge.js` 新增 2 项（场次无地点归属时重推后仍带 `canvas set:` 令牌、`location_id` 指向画布节点）。

## 三、数据目录在项目之外时，路径「越界」直接把接口打成 500

**现象**：把 `FACTORY_DATA_DIR` 指到项目目录之外（文档里支持的用法）后：

- `GET /api/upload/text?path=…` 回读上传的参考范本 → `500 非法路径：越界访问被拒绝`；
- `GET /api/scripts/:id` 读取技能文档存在性 → 抛错，导致**模块3 的分集规划 / 单集剧本 / 分镜 / 导出全线 500**；
- 小说参考范本读取同样受影响。

**根因**：上传文件保存在 `DATA_DIR` 下，而路径按「相对 ROOT」存储；当 `DATA_DIR` 在 ROOT 之外时，路径形如 `../../…`，`safeJoin(ROOT, rel)` 会**抛异常**（而不是返回不存在），于是「只读检查」变成了接口级 500。

**修复**：统一改用 `resolveAsset()`（同时支持 ROOT 相对 / DATA_DIR 相对 / 绝对路径，越界时返回 `null` 不抛错），并新增 `assetExists()` 包装 —— 涉及 `src/routes/meta.js`、`src/modules/script.js`、`src/modules/novel.js`。

**回归**：`scripts/simulate-all.js` 刻意把临时数据目录放在项目目录之外，因此每次模拟都会覆盖这条路径（参考范本上传回读、技能文档绑定与读取、分镜与导出）。

## 四、参考图矩阵的 JSON 调用无法指定画布与排布（模块1）

**现象**：`POST /api/canvas/ref-matrix` 用 JSON `{ files:[{name,path}] }` 调用时，`canvas_id / x / y / cols / cell / groupName / tags` 全被忽略（只认 multipart 提交里的 `meta` 字段），节点只能落在默认画布与默认坐标。

**修复**（`src/routes/actors.js`）：multipart 的 `meta` 与 JSON 顶层参数都接受，multipart 优先，保持前端调用不变。

**回归**：`scripts/simulate-all.js` 的「参考图矩阵」步骤用 JSON 调用并断言 3 个 `refimg` 节点 + 自动成组。

## 五、附带修复（与模拟同一轮）

- **探测失败看不到原因**：`/api/video-backend/probe` 失败时返回 `ok:false`，被前端 api 层当成请求失败，界面只显示「请求失败（HTTP 200）」，把详细中文原因吞掉了。现在探测接口 HTTP 层恒成功、可用性放 `ready` 字段，设置页与制作台都能显示完整结论（例如「实例返回 HTTP 503（平台提示实例正在启动，稍后重试）」）。
- **缩放下限**：后端只存视图状态不做钳制（前端限制 5%~800%）属于既有约定，模拟脚本按该约定断言「原样存回」，避免误判为缺陷。

## 六、UI 模拟（`tests/ui-simulate.py`，5 个页面 148 项）发现的问题

### 6.1 平移状态泄漏（严重，`web/views/actors.js`）

**现象**：在演员矩阵画布上用 Alt/空格拖拽平移一次之后，**松开鼠标、不再按任何键，只移动鼠标就仍在平移画布**；此时空白框选只会选中起点下方那张卡，卡片/便签拖拽、右下角缩放、端口连线全部失效，必须切走再切回模块才恢复。

**根因**：`let panning = null` 只在 `mousedown` 里赋值，全文件没有任何 `panning = null`（`mouseup` 只处理连线与拖拽落库），于是 `mousemove` 的 `if (panning) {...; return; }` 一直成立。更隐蔽的是：它让**原有审计里的「中键拖动可平移」断言假通过** —— 中键本来无效，但上一个平移状态没复位，鼠标一动 panX 就变了。

**修复**：平移状态改挂在 `S.panning` 上（可被 `window.__acDebug()` 观测），`mouseup` 与 `window.blur` 都复位并不再泄漏；同时在 `__acDebug` 里暴露 `panning`，让自动化能直接断言。

### 6.2 中键拖拽平移无效（同一文件）

**现象**：画布提示语写着「空格 / 中键 / 双指拖动平移」，但中键按住拖动时画布不动（`panX/panY` 恒为 0）。

**根因**：`mousedown` 中 `if (ev.button === 0 && panMode) {...}` 只处理左键，紧接着 `if (ev.button !== 0) return;` 把中键(button=1)提前 return 掉了。

**修复**：`panMode && (ev.button === 0 || ev.button === 1)` 都能起手平移。

**回归**：`tests/ui-simulate.py` 新增 3 项（中键可平移 / 松手后平移复位 / 平移后仍可正常选中卡片），`tests/canvas-audit.py` 新增 1 项（松开鼠标后平移状态已复位），并把「中键拖动可平移」保留为硬断言。

### 6.3 连带修掉的测试侧问题

- `tests/canvas-audit.py` 的成功还原分支会提前 `return`，导致自建的「审计临时画布」从不删除、每次审计攒一个空的临时画布 → 抽出 `drop_temp_canvas()` 在两条清理路径上都执行（现已验证审计后只剩主画布）。

## 七、适配器链路的离线验证与顺手改进

**背景**：真实出图/视频/配音仍要自备厂商接口（这也是交付时唯一的外部阻塞项）。为了让你拿到 key 之后一次成功，新增 `tests/test-adapters.js`（49 项）：用一个**假厂商服务端**把三条适配器链路全部跑通。

- **出图 generic-http**：模板变量（`{{prompt}}/{{negative}}/{{width}}/{{height}}/{{seed}}/{{ratio}}/{{kind}}/{{model}}`）、`headers` 模板（Bearer + 自定义头）、`responseImagePath`（b64 / URL 两种）、参考图 `base64|dataurl` 与自定义字段名、异步 `{{taskId}}` 轮询成功路径；异常路径逐条断言中文报错：轮询超时、任务 failed（带厂商原因）、HTTP 500（带厂商原文）、非 JSON 响应、响应缺字段（点名 `data.0.b64_json` 之类路径）、`bodyTemplate` 渲染后非法 JSON。
- **出图 openai-images**：`/v1/images/generations`（Bearer + size + dall-e 自动 `response_format=b64_json`）、参考图自动切 `/v1/images/edits`（multipart，负向词合并成 `Avoid:` 段）、URL 形式响应落盘、缺 Key 时中文引导且不发请求。
- **视频 generic-http**：`duration/width/height/seed` 注入、关键帧 base64 回填、产物落盘并被 `ffprobe` 识别为 mp4、响应缺字段时点名路径。
- **配音 openai / generic-http**：二进制、b64、URL、`responseType=binary` 四种取回方式、字段缺失报错、空台词与未启用后端的中文引导。
- **顺手改进**：轮询型任务在 `raw.taskId` 里保留任务号（原来轮询后 `data` 被覆盖，返回体里就看不到任务号了，排查厂商问题很不方便）——`src/image.js` 与 `src/video.js` 同步修好并加了断言。

> 用法：拿到厂商文档后，把请求体照抄进「设置 → 出图/视频 → 通用 HTTP 模板」，把返回里的图片/视频字段路径填进 `responseImagePath/responseVideoPath`，先在「🔌 测试连接 / 🧪 测试出图」点一次；链路本身已被 49 项断言覆盖，剩下的只可能是厂商参数差异。

## 八、生产化加固：自动重试 + 错误归类 + 厂商接入向导（本轮）

前面把「协议链路」验证完了，这一轮补的是真实厂商 API 上线后必然遇到的另一半问题：**阶段性失败**与**陌生协议配置成本**。

### 8.1 自动退避重试与错误归类（`src/retry.js`）

- **归类**：`classifyError()` 把错误分成 11 类（限流 / 5xx / 网络 / 超时 / 鉴权 / 额度 / 内容审核 / 参数 / 字段路径 / 本地配置 / 未知），每类带中文说明与「是否可重试」。判定优先级为**文本原因 > 状态码兜底**——因为不少厂商用 HTTP 500 包着「额度不足」这类业务错误，只看状态码会误判成可重试而白白重试。
- **重试**：`withRetry()` 指数退避（默认 2 次、基数 800ms、带抖动），**只重试限流/5xx/网络**；超时默认不重试（生成类接口超时可能已在服务端跑完并计费），鉴权/额度/审核/字段错误一律不重试。次数与退避基数在设置页可改（出图/视频/配音各一项）。
- **落地范围**：出图（generic-http / openai-images / comfyui）、视频（generic-http）、配音（openai / generic-http）、ComfyUI `/prompt` 提交。
- **可读性**：失败的文案自带归类与尝试次数，例如 `[触发限流（429）] 出图接口 429: rate limit（已尝试 3 次）`，任务卡片无需再翻日志。

### 8.2 厂商接入向导（`src/vendor.js` + 设置页）

- **`parseCurl()`**：把厂商文档里的 curl 直接解析成模板配置。支持 `-X/-H/-d/--data-raw/-F/-u/--url` 与引号、续行；`Authorization`/`x-api-key` 等密钥头一律替换成 `Bearer {{apiKey}}`（不落明文）；请求体按字段名智能替换占位符——`negative_prompt` 优先于 `prompt` 判定（否则会被 prompt 规则抢走），数值字段输出**不带引号**的 `{{width}}`（实现上用 JSON 安全哨兵占位再还原，避免 `JSON.stringify` 把占位符加引号导致模板非法）；未识别的部分原样保留并给出中文提示。
- **`suggestFields()`**：在未知结构的响应 JSON 里递归找「最像图片/视频/音频」的字符串，按 base64 特征、data URL、媒体扩展名、字段名、文件头特征打分排序，给出 `data.images.0.url` 这样的路径。
- **`probeVendor()`**：用当前（或草稿）模板真发一次最小请求，返回状态码、耗时、content-type、原始响应片段与推荐字段；响应直接是二进制媒体时提示「无需字段路径」；失败时返回归类而不是抛异常。**草稿试发不落库**，界面可以「先验证再保存」。
- **界面**：出图/视频/配音三张通用模板卡都加了「📋 粘贴 curl 自动填表」与「🔎 试发一次并推荐字段」，推荐字段点一下即填入。

### 8.3 本轮测试

`tests/test-adapters.js` 从 49 项扩到 **80 项**（新增重试与归类 10 项、向导 21 项）；`tests/ui-simulate.py` 从 148 项扩到 **153 项**（含「向导演示不污染正式配置」的还原断言）（三张卡的重试输入、向导按钮、curl 弹窗解析回填）。模拟中另有一处**测试自身**的坑顺手修掉：UI 模拟最初把示例厂商 URL 保存进了正式配置，现已改为保存前清空示例值。

## 九、生产守护：预算 / 磁盘 / 失败重试（本轮）

### 9.1 用量台账与预算闸门（`src/guard.js`）

- **记账**：只有真实后端（generic-http / openai-images / comfyui / 云端视频 / TTS）成功生成时才记一笔，占位出图与本地 ffmpeg 运镜不计费；台账按月分桶写在 `app_config`。
- **换算**：按配置单价（图/视频/配音千字）折算本月金额，币种可配；单价填 0 就只记用量不算金额。
- **闸门**：`preflightBatch()` 在关键帧/视频/流水线提交前统一检查 —— 超「本月上限」**直接拒绝**并给中文原因（含已用/本次/合计）；超「单次确认阈值」返回 `needConfirm`，由前端弹确认后带 `confirm:true` 再提交；磁盘超上限一并拒绝。
- **界面**：设置「数据与备份」新增预算与存储保护（9 个参数 + 用量/金额/磁盘实时展示 + 一键清零本月用量）；制作台工具栏新增「💰 预算与磁盘」。

### 9.2 磁盘保护

`diskUsage()` 分项统计 `images / videos / audio / finish / uploads / tmp / work / database`，给出告警与上限判定；`cleanupIntermediates()` 之外再补一层「超上限拒绝新任务」的硬闸门，避免百集长跑把盘写满。

### 9.3 失败镜头一键重试

`retryFailedRenders()` 把 `status='error'` 的渲染按**最新一条/镜头/类型**去重后分类：

- 可重试（限流 429 / 5xx / 网络 / 超时）→ 自动按集重新提交（仍走退避重试与预算闸门）；
- 不可重试（鉴权 / 额度 / 内容审核 / 字段路径 / 配置）→ 返回清单（镜头号 + 中文归类 + 原文），提示「重试不会成功，请先修配置」，避免白烧额度。

界面在制作台工具栏给出「♻ 重试失败镜头（N）」，弹窗同时显示已提交数与需人工处理的清单。

### 9.4 本轮修掉的一个真问题

**预算闸门在「覆盖重做」时形同虚设**：`estimateRender` 统计的是「缺失的关键帧/视频数」，而 `overwrite:true` 时实际会重跑全部镜头 —— 首次测试就抓到「已有全部关键帧时提交覆盖重做，预估金额为 0，闸门不拦」。现改为按**实际会跑的镜头数**估算（`shotIds` 数量，或覆盖时该集镜头总数），并补了对应断言。

### 9.5 测试

新增 `tests/test-guard.js`（33 项：台账/换算/闸门三态/磁盘 warn 与 blocked 分离/失败归类/API 端到端含假厂商 500×2 后成功、401 不重试、needConfirm→confirm、用量记账与清零），`tests/ui-simulate.py` 增至 159 项（工具栏两个新按钮与两个弹窗、设置页预算字段）。`./scripts/verify-all.sh` 扩到 13 个阶段、**869 项断言**。

## 十、镜头版本管理（多版本对比 + 人工采用）

**缺口**：同一镜反复重做（手动重渲、失败重试、换种子/换后端）会在 `shot_renders` 里累积多条记录，但看板只显示「最近一次成功」，既看不到历史版本、也无法挑选；更关键的是**整集成片拼接用的也是「最近一次」**——重做一版不满意就再也回不到上一版。

**实现**（`shot_renders.picked` 列走 `addMissingColumns` 迁移，零破坏）：

- `listShotVersions(shotId, kind)`：按新→旧返回全部版本（含失败记录），带 `version` 序号、`isLatest`、`picked` 标记；
- `pickRender(id)`：采用某版本（同一镜同类型互斥，先清后置），失败版本拒绝采用并给中文错误；`unpickRender(shotId, kind)` 取消采用回退到「最近一次成功」；
- `bestRender(shotId, kind)`：**采用优先，其次最近成功** —— 看板的 `keyframe`/`video` 槽位与 `clipsForEpisode()`（整集拼接）统一走它；
- 接口：`GET /api/render/shots/:shotId/versions?kind=`、`POST /api/render/renders/:id/pick`、`POST /api/render/shots/:shotId/unpick`；
- 界面：镜头卡片「🎞 版本 N/M」（多版本高亮、已采用显示 ★）→ 对比弹窗（关键帧可看图放大、视频可播放、每版显示后端/seed/时间/时长，失败版本显示原因）+「★ 设为采用 / 取消采用 / 删除该版本」+「再生成一版关键帧/视频」。

**验证**（`tests/test-render.js` 56 → 70 项，`tests/ui-simulate.py` 159 → 162 项）：

- 版本列表顺序/序号/latest 标记、采用后互斥、看板槽位切换、关键帧采用不影响视频；
- **成片确实用采用版本**：给同一镜造 2 秒与 6 秒两个视频版本，分别采用后各合成一次，**成片时长相差 4 秒**（ffprobe 实测）；
- 采用不存在的记录 / 采用失败版本 → 中文错误。

**本轮修掉的测试侧问题**（都是「测试自己不可靠」，产品行为正确）：

1. 版本断言最初依赖前面用例的耗时（用 `now` 当插入时间戳），导致版本排序判断偶发失败 → 改为**未来时间戳**精确控制顺序；
2. 成片时长断言最初写死「+3 秒」，但该集只有部分镜头有视频 → 改为**两版本对比**（更严谨且不依赖数据集）；
3. UI 模拟的「LLM 测试连接」断言等待条件写成了「不再显示未测试」，会把「测试中…」当成终态 → 改为**等出现 ✓/✗**，并在 90s 未返回时降级为提示（外网延迟不该把整轮自检判失败）；
4. 「成片用采用版本」这条断言一开始靠 `films[0]` 取产物，而多集/多次合成时列表按 `created_at DESC` 排序、同秒创建可能取错记录（全量自检里偶发失败：两次都读到同一条 5.0s 成片）→ 改为**用合成任务返回的 `filmId` 精确定位**，并补了「两次合成产出两条不同记录」的断言（连跑两次稳定）。
5. 教训记录：`tests/ui-simulate.py` 与 `tests/canvas-audit.py` **不能并发跑**（审计会临时清空主画布再还原，并发会把中间态误判为数据被改动）——本次误并发一次，已确认最终状态完好（15 卡位 / 8 分组 / 5 连线）。

## 十一、满配规模验证（200 演员 / 单集 200 镜 / 100 集 / 200 章）

**动机**：产品文档把上限写成「角色 ≤200、单集 ≤200 镜、单季 100 集、单次规划 200 章」，但此前所有测试都在 10 演员 / 33 镜的小数据上跑过 —— 上限只是纸面承诺。

**做法**：抽出可复用的种子脚本 `scripts/seed-scale.js`（按上限一次写入 200 演员 / 200 卡位 / 200 连线 / 100 集 / 20000 镜 / 200 章 / 300 任务），两处复用：

- `tests/test-scale.js`（24 项）：后端接口在满配下的**耗时预算 + 正确性**。实测 19 个接口合计约 **1.4s**，最慢「整季工作量预估」（100 集 × 200 镜 = 20000 镜扫描）约 **0.7s**；演员列表 59ms、画布 200 卡位 12ms、单集看板（200 镜 + 300 渲染记录）约 100ms、全量备份导出（2 万镜）365ms；并断言关键表索引存在、无 5xx。
- `tests/ui-scale.py`（21 项）：**独立临时实例 + 浏览器**验证满配前端。首屏可用耗时：演员矩阵 200 卡位 **1.4s**、小说 200 章 **0.88s**、剧本 100 集 **0.64s**（打开详情 0.77s）、制作台 200 镜看板 **1.6s**；满配下缩放进入 LOD2、适应窗口 0.9s、看板全选 200 镜 1.5s 且计数正确、章节可点读；无 JS 错误。

**过程中的两次「假问题」**（值得记录，因为都是测试自身的坑）：

1. **计时用了 wall clock**：`Date.now()` / `time.time()` 被系统时钟调整（NTP）影响，出现过 `-7148ms`、`-2750ms` 这种负耗时，而负数会让「在预算内」的断言无条件通过 —— 两处都改成**单调时钟**（`performance.now()` / `time.monotonic()`）并夹紧到 ≥0。
2. **首屏计时口径错了两次**：先是把固定等待时间当成加载耗时（所有页面都「3512ms」），后又把只在详情页出现的元素当列表页标记（`.sc-input` 在未选中剧本时不存在 → 误报「剧本页 20.8s」）。改成「等到该模块关键元素出现」并用列表页真实存在的标记后，才拿到可信数字。

## 十二、一键交付包（ZIP / 字幕 / 分镜表 / EDL / 生产报告）

**缺口**：做完一集之后没有任何「交付物」出口 —— 成片、字幕、分镜表、提示词、用量报告散落在 `data/` 与各个页面里，要交给平台或剪辑得手工凑。

**实现**（`src/deliver.js`）：

- **零依赖 ZIP**：Node 没有内置 zip，而项目坚持不引第三方包 → 自实现（`deflateRawSync` + CRC32 表 + 本地/中央目录 + EOCD），压缩后才更小就 deflate，否则原样存储，UTF-8 文件名标记。
- **交付内容**：`final/` 成片、`subtitles/` SRT、`storyboard/` CSV+JSON（含英文正负向提示词、种子、后端、**采用版本标记**）、`timeline/` EDL（CMX3600，按 fps 精确到帧）、`assets/` 每镜关键帧与片段原文件（可关）、`report.md`（用量与金额、逐集明细、失败镜头归类）、`manifest.json`、`README.txt`（含缺失项说明）。
- **工程上的取舍**：缺成片/缺关键帧/有失败镜头时**不报错**，而是写进清单与报告 —— 交付方需要知道缺什么，而不是被一个 500 挡住。
- **接口**：`GET /api/render/deliver/manifest`（清单，供界面预览）、`GET /api/render/deliver`（zip 下载，`assets=0` 可只给清单类文件）；界面在制作台工具栏「📦 导出交付包」。

**验证**（新增 `tests/test-deliver.js`，32 项）：

- **ZIP 由 Python `zipfile` 独立校验**（不信自家实现）：CRC 参考值 `0xCBF43926`、`testzip()` 无坏条目、UTF-8 文件名与目录、中文内容无损、可压缩内容确实变小、空条目也合法；
- **EDL**：帧率标记、时间码逐条验算（3s → `00:00:03:00`、2.5s → `00:00:02:13` 帧数四舍五入）、clip 名与动作/台词注释、镜序连续；
- **内容完整性**：CSV 行数 = 镜头数 + 表头、JSON 含提示词/后端/采用标记、字幕只含带台词镜、报告含逐集明细与用量金额、manifest 汇总与库内一致、素材条目数正确；
- **边界**：未合成成片 → 列入缺失而非报错；有失败镜头 → 归类写入清单与报告；`assets=0` 体积变小；不存在的剧本/剧集 → 中文错误（接口 200 + `ok:false` 或 400）。

界面另有 3 项 UI 断言（工具栏按钮、清单弹窗内容与体积、下载入口），`tests/ui-simulate.py` 增至 165 项。

## 十三、生产看板（可观测性）与三处口径修正

**动机**：100 集无人值守跑起来后，最缺的是「现在到哪了、为什么慢、为什么失败」。任务表、渲染表、用量台账里其实都有数据，但没有聚合。

**实现**（`src/stats.js` + `GET /api/render/stats` + 制作台「📊 生产看板」）：

- **进度**：集/镜头/关键帧/视频/成片完成百分比；
- **任务**：按类型聚合总数、成功/失败/取消、成功率、平均耗时、P95、最长耗时、最近错误；
- **渲染**：关键帧/视频的成功率与平均延迟（取每次生成实测 `meta.elapsedMs`），按后端拆分；
- **失败原因 Top**：按错误归类（限流/5xx/网络/鉴权/额度/审核…）聚合次数、受影响镜头数与原文样例；
- **产出趋势**：近 N 天每日成功出图/出片 + 失败数 + 计费渲染数；
- **吞吐与 ETA**：近 1 小时出片速度 → 剩余镜头估算剩余小时数；
- 同时给出一段**中文摘要文本**（`statsSummary`），界面与接口共用，避免前后端各写一套口径。

**测试驱动出的三处口径问题**（都是我自己聚合写错，测试期望先暴露）：

1. **任务平均耗时被排队任务拉低**：原先只看 `created_at/finished_at` 是否存在，而排队/运行中的任务两个字段都可能被写成同一时刻 → 0ms 混进均值（60/60/30/20 算成 34s）。改为**只统计已结束（done/error/canceled）**的任务。
2. **「产出趋势」把失败也算成产出**：失败记录会灌水成出图量。改为趋势只统计 `status='done'`，失败单独一列 `failed`。
3. **「计费渲染数」把失败请求也算成计费**：失败的请求一般不计费。改为**成功且非占位后端**才计入。

**顺带的一致性修复**：LLM 调用的失败此前没有接错误归类（界面上只会看到 `LLM 调用失败：fetch failed`）。现在 `src/llm.js` 的失败路径也走 `tagError()`，界面能直接看到 `[网络异常（连接失败/被重置）]`，与出图/视频/配音保持一致（新增 2 项断言：连不上时归类为 network、原文保留）。

**测试**：新增 `tests/test-stats.js`（29 项：空库、进度、任务耗时/成功率/P95、渲染成功率与后端拆分、错误 Top、趋势分桶与计费口径、吞吐与 ETA、摘要六段），`tests/ui-simulate.py` 增至 167 项，`./scripts/verify-all.sh` 扩到 **17 个阶段、1000 项断言**。

## 十四、成片质检（QC）与「快慢分离」

**动机**：平台退片最常见的原因是「中间有黑帧」「音轨断掉」「时长对不上」，而这些不该靠肉眼在时间轴上找。

**实现**（`src/qc.js` + `GET /api/render/qc` + 制作台「🔍 成片质检」）：用 **ffmpeg 真检测**（不是抽帧看图）：

| 检查 | 方法 | 判级 |
|---|---|---|
| 黑帧 | `blackdetect=d=0.4` | 单段 ≥1s 或占比 >30% → 告警 |
| 静音 | `silencedetect=n=-35dB:d=0.8` | 总时长 >1s 或 >片长 25% → 告警 |
| 响度 | `ebur128`（I/LRA/Peak） | I < −30 LUFS 或 Peak > −0.1 dBTP → 告警 |
| 流/规格 | `ffprobe` | 缺视频流 → 错误；缺音频流按角色区分；编码非 h264 / 分辨率不符 → 告警 |
| 时长口径 | 成片 vs「各镜视频时长之和」 | 差 >0.5s 或 5% → 告警（漏镜、时长被改都会命中） |
| 分镜覆盖/失败镜头 | 看板 + 错误归类 | 缺镜视频 → 错误；失败镜头按可重试/需人工处理归类 |

**顺手修掉的两处口径/体验问题**：

1. **镜头片段「没有音轨」被判成告警**：本地运镜产出的中间片段本来就没有音轨，逐条告警会淹没有效信息。改为按角色区分 —— **成片没有音轨才是告警**（交付要求），**片段没有音轨只记提示**。改完后同一集的告警从 12 条降到 2 条，剩下的正好是真问题。
2. **质检拖慢了交付清单**：`buildDelivery` 内联质检后，清单接口在 33 镜一集上从 0.03s 变成 6.8s，整季 100 集会更夸张。改为**快慢分离**：清单预览默认不跑质检（`qc=0`，返回 `verdict: 'deferred'`），**打包时才逐集质检**（zip 内带 `qc/*.md` 与 `qc/*.json`，清单里单列 `qc` 结论字段，界面弹窗也注明时机）。

**其它**：质检结论不混进「缺失项」（语义不同）→ `manifest.qc` 独立字段 + `README.txt` 里的「质检结论」段；`buildDelivery` 因内联质检改为 async，交付包测试同步适配。

**测试**：新增 `tests/test-qc.js`（33 项）：用 ffmpeg 现造「好片 / 中间黑帧 / 前段静音 / 无音轨 / 时长不符」五种样本，逐条验证**检出有效**（不是空跑），再加整集聚合、摘要/Markdown、交付包内置报告；`tests/ui-simulate.py` 增至 169 项（质检按钮与弹窗，等待改为轮询最多 60s）。`./scripts/verify-all.sh` 扩到 **18 个阶段、1035 项断言**。

## 十五、配音链路（按角色音色 / 时长自适应 / 缓存 / 避让混音）

**缺口**（都是真实生产会踩的）：整集只用一个音色（演员档案里的 `voice` 字段从来没被用过）、台词超出镜头时长会糊到下一镜或被 `-t` 截断、每次重新封装都重新合成一遍（重复付费）、配音与背景乐不能同时存在。

**实现**（`src/dub.js` + `src/finish.js`）：

- **按角色选音色**：`voiceForShot()` 依次尝试「指定说话人的演员档案音色 → 镜头演员表里第一位有音色的角色 → 默认音色」，并记录来源（`actor` / `actor-first` / `fallback` / `episode-default`）便于提示补配置；
- **时长自适应**：`fitAudioToShot()` 用 ffprobe 读实际音频时长，超出镜头时长先 `atempo` 加速（≤`ttsMaxSpeed`，默认 1.25x；因为 atempo 单次支持 0.5~2.0，1.25x 内一次足够），加速后仍超长才截断并告警；不足则不动；
- **合成缓存**：`synthesizeCached()` 按「文本+音色+语速+格式」哈希缓存到 `data/audio/cache`，重复封装零请求（实测第二次封装 `cacheHits=2 / requests=0`）；
- **配音 + 背景乐避让**：新增音轨模式 `tts_bgm` → `applyAudio(mode:'mix')`：人声按时间点铺开并混成总线，总线 `asplit` 成两路，一路进最终混音、一路做 `sidechaincompress` 键控去压低循环 BGM；
- **配音报告**：封装结果 `meta.audio.ttsReport` 里逐句给出音色来源、音频时长、镜头时长、适配动作（`ok/speedup/trim`）、是否命中缓存、以及告警（超长截断、未配音色、合成失败）。

**本轮修掉的三个实现级 bug（都是测试先抓到的）**：

1. `voiceForShot` 里 `cast.find(...) || get(DB)` 短路 —— cast 条目没有 `voice` 字段时直接返回它，导致**数据库查询永不执行、所有角色退化成默认音色**；改为「音色一律以演员档案为准，cast 只当名字来源」。
2. 混音滤镜用了 **`split`（视频滤镜）**，音频必须用 `asplit` → ffmpeg `Error parsing filterchain`；改对后还发现同一标签不能被消费两次，于是把「人声总线」再 `asplit` 一次（一路混音、一路键控），并删掉多余的 per-clip split（否则 `Filter asplit has an unconnected output`）。
3. `ttsStatus()` 对 `backend='none'` 返回「就绪」（因为成片走静音轨是正常路径），但**配音场景下它意味着不可用** → `dubEpisode` 改为 `ready && backend !== 'none'` 才算可配音，否则明确回报「未启用配音后端」。

**测试**：新增 `tests/test-dub.js`（32 项，用**假 TTS 厂商**按台词里标注的秒数返回音频，从而确定性地验时长适配）：音色选择 5 项、缓存 4 项、时长自适应 4 项、整集配音与时间轴 7 项、未就绪/失败 2 项、混音 4 项、整集封装串链 4 项；`tests/ui-simulate.py` 增至 170 项（「配音+背景乐」选项）。`./scripts/verify-all.sh` 扩到 **19 个阶段、1071 项断言**。

## 十六、出海物料（多语言字幕 / 封面 / 发布元数据）

**动机**：漫剧的实际变现路径是分发到平台（含海外），而平台侧要的是「标题 + 简介 + 话题 + 封面 + 对应语言的字幕」。此前交付包里只有中文 SRT 与成片。

**实现**（`src/i18n.js` + `src/publish.js` + `GET /api/render/publish/options|POST /api/render/publish` + 制作台「🌐 出海物料」）：

- **多语言字幕**：自实现 SRT 解析/重建（毫秒级时间码），逐批（默认 30 条）交给 LLM 翻译，**强制校验条数与时间码不变**；缺条或整批失败 → **逐条保留原文并给出中文告警**；结果按「内容+语言+provider」哈希缓存到 `data/subtitles/i18n/`，同时留一份 `<集号>.<语言>.srt` 可读路径；

- **交付集成**：交付包新增 `publish/` 目录（`*_publish.md|json`、`<集号>.zh.srt`、配置了语言时的多语言 SRT、`*_cover.jpg`），清单里汇总 `publish: [{code, languages, cover, metadata}]`。清单预览默认走**规则版元数据**（不花模型钱），多语言字幕按配置的语言生成。

**测试**：新增 `tests/test-publish.js`（31 项）：SRT 解析往返无损、忽略无时间码碎片、翻译后**时间码逐条一致**、多行文本保持、缓存命中、换语言独立缓存、未知语言报错、模型不可用回退原文且时间码不变、多语言批量跳过未知语言、封面 1080x1920 且为合法 JPEG、无成片时中文错误、整套物料文件落盘与 Markdown 结构、不选语言时只出中文、关元数据生成走规则、交付包内置 publish/ 与清单汇总。`tests/ui-simulate.py` 增至 172 项（出海物料按钮与语言多选弹窗）。`./scripts/verify-all.sh` 扩到 **20 个阶段、1104 项断言**（当时值）。

## 十七、线上试跑发现的问题：静音轨被质检误报

**场景**：在运行中的实例上跑了一遍完整链路（新演员 → 定妆图 → 新画布组合出图 → 新剧本 → 17 镜分镜 → 关键帧 → 视频 → 整集成片 → 质检 → 出海物料 → 交付包）。质检结论是 `warn`，两条告警：

- 「静音偏多：1 段合计 60.01s」
- 「整体响度过低（-70 LUFS，低于 -30）」

**判断**：这集封装时用的是**静音轨**（`audio: 'silent'`，还未接 TTS/BGM）——整轨静音与 −70 LUFS 是**设计如此**，不是质量问题。质检把「预期的静音轨」当成了缺陷，属于误报；长跑 100 集会刷出上百条无意义告警。

**修复**（`src/qc.js`）：`qcFile()` 增加 `silentTrack` 语义，`qcEpisode()` 从成片 `meta.audio.mode` 读出音轨模式并传入：

- 若为静音轨且静音占比 ≥95% → `silence` 与 `loudness` 降为**提示**（并写明「成片使用静音轨：未启用配音/BGM，静音与响度检查不适用」）；
- 其它模式（tts / bgm / mix）保持原有告警逻辑。

修完后同一集结论从 `warn（2 告警）` 变成 **`pass`（0 告警 / 22 提示 / 45 通过）**。

**顺带**：无台词剧集在生成多语言字幕时会静默跳过 —— 现在会明确回报「本集没有台词（无字幕可翻译），已跳过多语言字幕生成」。

**回归**：`tests/test-qc.js` 增至 35 项（静音轨成片：静音与响度降为提示；同一文件按普通音轨评估时**仍会告警**，证明该开关真正生效）、`tests/test-publish.js` 增至 32 项（无台词剧集跳过多语言字幕并说明）。总断言 **1106**（当时值；P2–P5 落地后为 **24 阶段 / 1664 项**，见第十八节）。

## 十八、画布可执行节点图（P2–P5）集成期发现的 10 个问题

把画布从「素材墙」升级为「可执行节点图」（类型化端口 → DAG 执行 → 人类审核闸门 → 成片时间线）时，逐步施工 + 交叉验证挖出了一批**只在真实集成场景才会暴露**的问题。以下每条都附「症状 → 根因 → 修复 → 回归断言」。

### 18.1 任务取消后终态被覆写（`src/jobs.js`）

- **症状**：点「取消」后任务先变 `canceled`，随后又自己变回 `done / 100%`（或 `error`），用户以为取消没生效。
- **根因**：`cancelJob()` 先把状态置为 `canceled`，但 `pump()` 里 handler 的 promise 结算时会**无条件**写 `status:'done'` 或 `'error'`，把取消状态覆盖掉；另外 `canceled` 这个 Set 只在 `cancelJob` 里追加、从不清理，长跑会一直涨。
- **修复**：结算前先判 `isCanceled(id) || getJob(id).status === 'canceled'`，命中就写回 `canceled`（附「已完成的部分产物保留」）；`finally` 里 `canceled.delete(id)` 释放内存。
- **回归**：新增 `tests/test-jobs.js`（35 项）——含「取消后状态仍为 canceled」「进度未被拉到 100%」「result 未被写入」「isCanceled 归 false」。

### 18.2 备份/还原/撤销把数据流边退化成普通关系线（`src/modules/actors.js`）

- **症状**：给画布连线加了 `from_port`/`to_port`/`slot` 后，一次「备份→还原」或一次 Ctrl+Z，端口与槽位全部消失，成片顺序随之失去依据（**静默错片**风险）。
- **根因**：`restoreCanvas()` 还原连线时的 INSERT 列清单还是旧的 11 列，没带新增的三列。
- **修复**：还原时一并写回 `from_port`/`to_port`/`slot`；审计的备份/还原快照也补上这三个键。
- **回归**：`tests/canvas-audit.py` 的「刷新后类型化边与槽位编号不丢」「带端口边必然两端都有端口」。

### 18.3 语义关系线被当成执行依赖 → 整张画布报「环形依赖」（P2 × P3 集成缺陷）

- **症状**：在真实主画布（12 位演员 + 环境/物品节点 + 5 条「对手戏/出现在/持有」关系线）上点「执行计划」，直接报 **「画布存在环形依赖，无法执行：沈砚、雾港码头、停摆怀表」**——而这张图上根本没有需要执行的节点。
- **根因**：`planGraph()` 把**所有**连线都喂给拓扑排序，且排序集合包含不可执行的素材节点；语义关系线是「互相参考」的双向关系，必然成环。
- **修复**：新增 `isFlowLink()` ——**只有数据流边参与排序与成环判定**：带 `from_port`/`to_port` 的连线一定是数据流边；不带端口的连线仅当**目标节点可执行**时才算数据流边。`runGraph()` 的重排使用同一判据。
- **回归**：`tests/test-graph.js` 182 项全绿（含环检测用例）；`tests/test-timeline.js` 里含「语义连线不阻塞计划」。

### 18.4 成片子步骤覆盖任务级进度（`src/timeline.js`）

- **症状**：35 节点的图任务跑到 27/35 时进度条只有 25%，随后又跳到 100%。
- **根因**：成片节点把 `finishEpisode` 的 4 个子阶段（拼接/字幕/音轨/淡出）通过 `ctx.setProgress(pct, {done, total})` 上报，`done/total` 是**任务级**字段，被覆盖成 4。
- **修复**：子步骤**只上报百分比**，不再传 `done/total`；需要观测子阶段时用 `params.onStep`。
- **回归**：`tests/test-timeline.js` 断言「单节点图任务总数 = 1（未被成片子步骤覆盖成 4）」「只报百分比，不覆盖任务级 done/total」。

### 18.5 端口表自相矛盾：便签/文本 → 图片节点连不上（`PORT_RULES`）

- **症状**：`PORT_COMPAT.text = ['in']`，但 `PORT_RULES.image.in` 里没有 `'in'`，于是「便签文本 → 图片节点」在界面上连不上、走 API 也报「「image」节点没有输入端口 in」。
- **修复**：`image.in` 补 `'in'`（后端 `src/modules/actors.js` 与前端 `web/views/actors.js` 两处同源表一起改）。
- **回归**：`tests/test-timeline.js` 断言 `portOk('image','first')` 与端口表一致性；`tests/test-mcp.js` 固化端口表现状。

### 18.6 「旧中点端口」必须保留，否则历史关系线拖不动（审计抓到的回归）

- **症状**：把端口改成按类型分布后，审计立刻红：从演员卡中点拖线不再弹出连线弹窗——因为中点不再是可命中的端口了，而所有历史语义关系线都从中点起拖。
- **修复**：`portsOnSide()` 在类型化端口之外**永远附带一个名为 `null` 的中点端口**（绘制与命中都保留）。类型化端口精确命中优先，中点仍可拖出语义线。
- **回归**：`tests/canvas-audit.py` G 段（关系连线全流程）+ G2 段（类型化端口）同时全绿。

### 18.7 铺开分集后视频节点全部失败：视频必须有首帧（设计缺陷）

- **症状**：在画布上铺开一集 17 镜并执行，17 个视频节点全部 `error`：**「缺少可用关键帧（请先渲染关键帧，或改用文生视频后端）」**，成片节点随之 `skipped（上游节点失败）`。
- **根因**：`spreadEpisodeToCanvas` 只建了视频节点，没有建关键帧（出图）节点——而 `placeholder` 与云端 i2v 后端都要求首帧。
- **修复**：铺开时每镜建「关键帧（出图）→ `image`/`first` → 视频片段」，画布图因此**开箱可执行**；实测同一集 35 个节点全部完成并产出 60s 整集成片。
- **回归**：`tests/test-timeline.js` 断言关键帧节点数、`image→first` 类型化边、「分镜容器 → 视频片段为语义连线（不伪造非法端口）」。

### 18.8 时间线端口不够用 + 超长分集无处安放（`clip1..clip10` → `clip1..clip24` + 自动分块）

- **症状**：清单原设计每侧 10 个片段槽位，而演示剧本一集就是 17 镜（短剧 20~24 镜很常见）。
- **修复**：`TIMELINE_PORTS` 扩到 `clip1..clip24`（后端端口表、前端端口表、时间线模块三处同源）；镜头数超过 24 时**自动分块**成多个成片节点（标题带 `（1/2）`），块内仍从 `clip1` 起编号。
- **回归**：`tests/test-timeline.js` 用 26 镜断言「分成 2 块（24 + 2）」「第二块端口从 clip1 重新编号」。

### 18.9 前端 `el()` 不递归展平嵌套数组 → 弹窗里出现 `[object HTMLDivElement]`

- **症状**：拼接顺序预览弹窗里列出的不是每一段，而是一串 `[object HTMLDivElement],[object HTMLDivElement]…`。
- **根因**：`el(tag, attrs, [someArray])` 只会展开一层，嵌套数组被 `String()` 掉。
- **修复**：把 `[rows.length ? rows : …]` 改成直接传数组。
- **回归**：`tests/ui-smoke.py` 与手动截图核对（弹窗现显示「1. clip1 · 3s · 无台词 · kb_SH-….mp4」逐行）。

### 18.10 `canvas_nodes` 没有 `created_at` 列（写节点时的隐性坑）

- **症状**：铺开分集时报 `table canvas_nodes has no column named created_at`。
- **根因**：`canvas_nodes` 表历史上没有时间列（新表设计里也没有），而连线表有——写节点代码时容易照抄连线表的列清单。
- **修复**：节点 INSERT 去掉该列；同时**把该错误固化成测试**（`tests/test-timeline.js` 的铺开分集断言会在列清单错误时立刻失败）。

**总账**：这一轮新增/扩容测试 —— `tests/test-jobs.js` 35、`tests/test-graph.js` 182、`tests/test-mcp.js` 264、`tests/test-timeline.js` 60，`tests/canvas-audit.py` 117 → 134，全量自检 **20 阶段 / 1106 断言 → 24 阶段 / 1664 断言**，全部离线零成本可复现。

## 十九、音频闭环（音频节点）与它挖出的 2 个缺陷

画布能出片了，但成片是**静音轨**（−70 LUFS）——「音频闭环」是 LibTV 最小功能集里我们还没覆盖的一条。这一轮把「配音 / 音乐 / 音效」做成画布上的**一等节点**，并顺手挖出两个会在真实使用中立刻踩到的问题。

### 19.1 音频节点（`src/audio-node.js`）

三种模式：`tts`（按台词合成，走 `src/tts.js`，与模块 4 配音**同源的内容哈希缓存**）、`file`（引用已有音频）、`bgm`（整片背景乐）。输出端口只有 `audio`：

- 接到**视频片段的 `dub` 端口** = 该镜配音。`src/dub.js` 的 `dubEpisode` 新增「外部已提供配音文件」分支：直接用该文件（只做时长自适应），**不再调用 TTS**——所以即使没配 TTS 后端，只要有画布配音文件也能出有声音的片子。
- 接到**成片节点的 `bgm` 端口** = 整片背景乐。`executeTimeline` 依据画布连线推导音轨模式：配音 + 背景乐 → `tts_bgm`（混音 + ducking）、只有背景乐 → `bgm`、都没有 → `silent`；结果写进成片报告的 `audioPlan`（含 `providedDubs / ttsReady / hasDialogue / bgm / mode / note`）。

**实测（运行中的实例）**：给已有成片节点接上一个「背景乐」音频节点后执行计划 → **只跑 2 个节点**（背景乐 + 成片，其余 35 个节点产物未变自动跳过，成本级 **L**）→ 人工批准 + 确认码 → 重出成片。同一条片子的实测响度从 **−70 LUFS（静音轨）变为 −40.8 LUFS / 峰值 −35.6 dB**，即「静音片」变成「有背景乐的片」。

### 19.2 缺陷一：背景乐连线被当成「片段」，一接音乐就报「上游还没有产出视频」

- **症状**：给成片节点接上 `bgm` 连线后执行成片，直接报「时间线有 1 条连线的上游节点还没有产出视频（请先生成上游片段，或断开这些连线）」——音频节点当然不产视频。
- **根因**：`orderedClips()` 把**所有**指向时间线节点的连线都当作片段输入（`links.filter(l => l.to_node === timelineNodeId)`），新增的 `bgm`/`audio` 音轨连线也被算进去。
- **修复**：只认「片段连线」——`to_port` 为 `clipN` 或历史无端口连线；`bgm`/`audio` 等音轨连线单独处理。
- **回归**：`tests/test-timeline.js` 新增第 11 节（音频闭环 22 项），覆盖「配音 + 背景乐 → 混音」「只有背景乐 → bgm」「背景乐未产出 → 中文报错」等。

### 19.3 缺陷二：端口兼容表漏项，第 11 段之后连不上时间线

- **症状**：时间线端口早已扩到 `clip1..clip24`，但兼容表 `PORT_COMPAT.clip` 仍只列到 `clip10` → 手工把第 11 个片段拖到 `clip11` 会被判「不允许 clip → clip11 的连接」，只有自动铺开（走服务端直插）才连得上。
- **根因**：端口表与兼容表两处手工维护，扩端口时漏改后者。
- **修复**：兼容表补全到 `clip24`，并且 `portOk()` 增加 `^clip\d+$ → clip` 的模式匹配兜底（第 99 段也不会掉）；后端与前端两张同源表一起改。
- **回归**：`tests/test-timeline.js` 断言 `portOk('clip','clip17')`、`portOk('clip','clip99')` 均为真，`portOk('image','dub')` 为假。

**总账更新**：`tests/test-timeline.js` 60 → **82 项**；全量自检 **24 阶段 / 1664 → 1686 项断言**。

## 二十、首尾帧过渡与视频续写（生成矩阵补完）

LibTV 最小功能集的第 4 条（生成矩阵，含**首尾帧**、多图参考、**视频续写**）此前只覆盖了一半：画布上早已有 `last` 端口，但执行层是**明确抛错**「当前视频后端不支持尾帧」。这一轮把它真正做通，并补上「视频续写」这种画布原生的接法。

### 20.1 三种后端都能用尾帧

| 后端 | 尾帧怎么用 | 没准备时 |
|------|-----------|---------|
| `placeholder`（本地 ffmpeg） | 「首帧运镜 → 尾帧运镜」**交叉溶解**（`xfade`），结果里标注 `raw.lastFrame='xfade'` | 不适用（本地总能做） |
| `comfyui-h3` | 字段映射 `map.lastImageNode` 指向工作流里负责尾帧的 `LoadImage` 节点：先光栅化 → `/upload/image` → 回填该节点 | **明确报错**：请在设置里指定 `lastImageNode`，或断开尾帧连线 |
| `generic-http` | 请求体模板里的 `{{lastImage}}`（base64 / dataurl 与首帧同格式） | **明确报错**：模板里没有 `{{lastImage}}` 占位符 |

三种后端的共同红线：**给了尾帧就必须真的用上，绝不静默丢弃**——这条红线由「没准备就报错」+「本地的处理方式写进执行记录」共同保证。

### 20.2 视频续写（画布原生）

把**上一段的 `clip` 输出接到下一段的 `first` 输入**即成为「续写」：执行时用新增的 `lastFrameOf()`（`ffmpeg -sseof -0.1 -frames:v 1`）抽出上一段的**尾帧 PNG** 作为下一段首帧，节点上显示「↻ 续写（首帧取自上游片段尾帧）」，结果里带 `firstFrom='lastFrameOf'`。这条链可以无限往下接，等于把 N 个 3~5 秒片段串成一段连续长镜——而这正是「一句话做成连续镜头」在画布上的表达方式。

**实测**（`tests/test-timeline.js` 用真实 ffmpeg 三色片段）：红色片段 →（抽尾帧）→ 蓝色片段作为续写段执行 → 对新片段抽尾帧做像素采样，得到 `rgb≈(255,0,0)`，证明续写段的首帧确实承自上段尾帧；首尾帧过渡段的成片末帧采样为蓝色，证明尾帧参与了画面。

### 20.3 顺带修掉的一个 ffmpeg 陷阱

- **症状**：首尾帧过渡报 `ffmpeg 退出码 8：Option loop not found. Error opening input file .../b.mp4`。
- **根因**：写首尾帧分支时对两个输入都用了 `-loop 1 -t dur -i X`（图片 demuxer 的选项），而尾帧在测试里给的是一个 **mp4**。
- **修复**：新增 `frameInputArgs(abs, duration)` —— 图片用 `-loop 1 -t dur -i`，视频用 `-stream_loop -1 -t dur -i`，两种输入都能吃；顺带把首帧那条路径也统一到同一助手，避免以后再踩。
- **回归**：`tests/test-timeline.js` 同时覆盖「尾帧给图片」与「尾帧给视频」两种输入。

**总账更新**：`tests/test-graph.js` 182 → **184 项**（尾帧语义由「必报错」改为「两帧都给即可用，且必须如实标注」），`tests/test-timeline.js` 82 → **93 项**（新增第 10b 节：抽尾帧、续写、首尾帧过渡、模板缺占位符的诚实报错）；全量自检 **24 阶段 / 1686 → 1699 项断言**。

### 20.4 补一个「只能靠铺开分集才能建流程节点」的缺口

做续写的一键入口时发现：`image`/`video`/`shot`/`timeline` 这些**流程节点只能由「🎞 铺开分集」批量生成**，画布上没有任何入口能手工建一个——于是「自己做一张工作流」这件事在界面上是不成立的。修复：

- `src/modules/actors.js` 把可创建类型扩到 `CREATABLE_KINDS = 素材类（环境/物品/参考图/音频）+ 流程类（关键帧/视频/文本/分镜容器/成片时间线/交付终点）`，每种带齐默认参数与尺寸；
- 新增 `POST /api/canvas/continuation` + `createContinuationNode()`：一键建出续写节点并自动接好 `clip → first`（**零生成调用**）；
- 工具栏新增「➕ 流程节点」菜单（5 种），右键视频节点新增「↻ 生成续写片段」。

**回归**：`tests/test-timeline.js` 断言「5 种流程节点都能手工创建且默认参数齐备」「未知类型报中文错」「一键续写创建节点+连线且零生成调用」「从非视频节点续写报中文错」。

### 20.5 两个被「位置漂移」暴露出来的老问题

这一轮全量自检时挂了两条，追下去发现都不是新功能的锅，而是**长期潜伏、依赖具体坐标/顺序才触发**的问题：

**① 参考线吸附会把小数坐标写进库（`web/views/actors.js` 的 `snapPosition`）**

- **症状**：审计的「自由拖拽后坐标已批量落库（无小数残留）」偶发失败，落库坐标出现 `147.5555…`。
- **根因**：吸附有两条路径 —— 没有参考线时吸附到半格网格（整数）；**命中邻卡参考线时**是在「原始拖拽坐标」上加一个偏移量，而原始坐标 = 屏幕位移 ÷ 缩放，天生带小数。于是「贴齐邻卡边缘」的同时把小数带进了库。
- **修复**：吸附开启时，参考线分支也对结果取整（`x = Math.round(x); y = Math.round(y)`），即「贴齐邻卡」与「坐标取整」同时成立。
- **回归**：`tests/canvas-audit.py` 的该断言现在稳定通过（并补了失败详情：直接打印非整数节点）。

**② 矩阵模式拖拽=换位的副作用会打乱演员顺序（`tests/ui-simulate.py` 的断言前提）**

- **症状**：ui-simulate 末尾「演员默认排序未被画布拖拽打乱」偶发失败（`C-0023` 被挪了几个位置）。
- **根因**：产品行为本身是正确的 —— **矩阵模式下把卡片拖到另一张卡上 = 换位**（画布提示语也这么写）。而脚本里主画布的拖拽测试恰好会经过其它卡片，于是一次拖拽就把演员顺序推着走了几位；是否触发完全取决于当时的卡片位置（位置又随每次审计/演示漂移），所以是「位置依赖的偶发」。
- **修复**：脚本不再假设「拖拽绝不改变顺序」，而是：① 发现顺序变化时**先如实还原**（`POST /api/actors/reorder`，顺序回到脚本开始时）并断言还原成功；② 再断言最终顺序与开始时一致。这样不变量（画布拖拽不会**无声地**改变演员顺序）仍然被守住，同时不再因产品既有行为而误报。
- **回归**：`tests/ui-simulate.py` 172 项全绿（比原来多 1 项：新增「矩阵模式换位副作用可被还原」）。

## 二十一、多轨时间线（画面叠轨 / 画中画 / 字幕轨）

LibTV 最小功能集第 11 条（时间线多轨合成与长视频导出）此前只做到「单轨按序拼接 + 一条背景乐」。这一轮把它补成真正的多轨：**V1 主轨（`clip1..clip24`）+ 4 条画面叠加轨（`ov1..ov4`）+ 音轨（`bgm`）+ 字幕轨（`sub`）**，全部由画布连线决定。

### 21.1 三种轨道节点

| 节点 | 端口 | 说明 |
|------|------|------|
| `overlay`（叠加层） | `in`/`clip`/`text` → `overlay` | 三种模式：**画中画**（按宽度比例缩到角落）、**全屏叠加**（片头/转场/贴纸）、**水印**（整片常驻）。可设时间窗（出现/消失秒）、宽度占比、不透明度、淡入淡出；画面取上游片段或 `data.file` 上传的图片/视频 |
| `subtitle`（字幕轨） | `in`/`text` → `subtitle` | 现成 `.srt`（时间码原样沿用）/ 手工时间码行 / 上游文本 → 落成 SRT，供成片**硬烧**或**软字幕轨** |
| `timeline`（成片） | `clip1..24` + `bgm` + `ov1..4` + `sub` → `film` | V1 主轨拼接包装（沿用 `finishEpisode`）→ 再一次性把 4 条叠加轨合成上去 |

叠加合成本身是**一次 ffmpeg 完成**（`overlay` 滤镜链 + `enable='between(t,start,end)'` + `fade:alpha` + `colorchannelmixer=aa`），不逐轨重编码，成片时长不变。

### 21.2 实测（运行中的实例）

在演示画布上给已有成片节点再接一个「🖼️ 水印」叠加层（`overlay → ov1`）与一个字幕轨（`subtitle → sub`）：

- 执行计划只跑 **3 个节点**（叠加层 + 字幕轨 + 成片），其余 **36 个节点自动跳过**，成本级 **L**；
- 未审批执行被闸门拦住 → 人工批准 + 终端确认码 → 任务 `3/3 done`；
- 产出新成片 **60s / 3.3MB**：抽帧核对可见**左上角半透明水印**与**底部烧录字幕「你终于来了。」**。

离线自检里用三色片段做了像素级验证：画中画只在时间窗内出现在右下角（窗外是主轨红色、画面中部不受影响）、全屏叠加在时间窗内覆盖整幅、水印在片头片尾都在且为半透明、两条叠加轨一次合成同时生效、硬字幕与无字幕版底部条带像素不同、软字幕轨成片真的带 `subtitle` 流。

### 21.3 顺带修掉的缺陷：混音会把软字幕轨吃掉

- **症状**：软字幕轨成片 `ffprobe` 只有 `video+audio`，字幕流凭空消失（而报告里明明写着 `applied: true, mode: 'soft'`）。
- **根因**：`finishEpisode` 的流水线顺序是「拼接 → 字幕 → **音轨** → 淡入淡出 → 归档」；音轨阶段的 `applyAudio()` 是重新 mux（`-map 0:v -map 1:a` 等），**没有带 `-map 0:s?`**，于是上一步刚加进去的字幕流在混音时被丢弃。
- **修复**：`applyAudio` 的四个分支（静音轨 / 配音 / 背景乐 / 配音+背景乐混音）全部补上 `-map 0:s? -c:s copy`，已有字幕流一律保留。
- **回归**：`tests/test-timeline.js` 断言「软字幕轨成片带独立字幕流」。

### 21.4 一个测试侧教训（不是产品缺陷）

「硬字幕是否真的烧进画面」最初用 `blend=difference,scale=1:1` 取整幅平均差异判断，结果恒为 0 —— 字幕文字在整幅里的像素占比太小，取平均后被四舍五入掉了。改为**对底部字幕条带单独采样**（字幕所在区域的平均颜色）后判定可靠；同时片尾采样点改为按成片时长自适应（`min(1.2, 时长-0.3)`），避免贴着片尾取帧时的定位抖动。

**总账更新**：`tests/test-timeline.js` 103 → **130 项**（新增第 10c 节：画中画/全屏叠加/水印/双叠加轨/字幕轨硬烧与软轨/缺产出报错/参数归一化/多轨预览/端口规则）；全量自检 **24 阶段 / 1709 → 1737 项断言**。

### 21.5 又一个「跟运行时刻有关」的测试：产出趋势分桶

- **症状**：全量自检里 `tests/test-stats.js` 挂了 3 条（「今天 7 片 / 前天 10 图」「计费渲染数 7/10」「今天 4 条失败」），而同样的用例在凌晨跑是全绿的。
- **根因**：用例把「今天」的理解写死在断言里，而种子数据用的是「从现在往前推 N 小时」：`ep2` 的视频是 `now - 3h`、失败记录是 `now - 1h`。而 `src/stats.js` 的分桶口径是 **UTC 日期**（`created_at` 的 `YYYY-MM-DD`）。于是当本机时间处于「本地日期 ≠ UTC 日期」的窗口（例如本地 08:45 = UTC 00:45）时，`now - 3h` 会落到**前一天**的桶里 → 今天只剩 5 片，断言全错。
- **修复**：把期望值改为**由种子时间戳独立算出**（测试里自己按 UTC 日期分组统计 kind/status/backend），再与统计引擎的输出比对 —— 这样既保留「按天分桶、只算成功产出、计费只算非占位后端」的真实校验，又不再依赖运行时刻；同时新增一条「4 条失败记录全部出现在对应日期的分桶里（一条不丢）」，避免期望值退化成 0 == 0 的空断言。
- **回归**：`tests/test-stats.js` 29 → **30 项**，在任意时刻运行都稳定通过。

**同类经验**：本项目里「与时间有关」的确定性测试应遵守两条——① 断言口径与实现口径一致（都是 UTC 日期）；② 期望值由**种子数据**推算，而不是写死数字。此前 `tests/test-jobs.js`、`tests/test-render.js` 也已经按这条原则处理过（单调时钟、避免 +1s 这类悬崖时间戳）。

## 二十二、自动化制片 Agent 与流水线

一句话需求 → 演员 → 小说 → 剧本 → 画布 → 关键帧 → 视频 → 成片 → 质检 → 交付包，整条链路由 `src/studio.js` 编排，**花钱的两个阶段必须由人按下批准并输入确认码**。

### 22.1 十个阶段与两条红线

| # | 阶段 | 付费 | 做什么 |
|---|------|------|--------|
| 1 | brief | — | 一句话需求 → 制片参数（集数/每集秒数/比例/画风/题材或基调/角色数/目标字数） |
| 2 | cast | — | 按参数生成演员档案（姓名/外形/人设/音色），离线时用字典规则模板 |
| 3 | novel | — | 建小说 + 生成故事框架与分章大纲（可配置顺带写若干章正文） |
| 4 | script | — | 建剧本 → 分集规划 → 逐集分镜（纯英文提示词） |
| 5 | canvas | — | 把每集铺成「关键帧 → 视频 → 成片时间线」节点图（**只布局不生成**） |
| 6 | **keyframe** | 💸 | 渲染全部关键帧 —— **停下等人工批准** |
| 7 | **video** | 💸 | 按关键帧生成视频 —— **停下等人工批准** |
| 8 | finish | — | 按 `clip1..N` 拼接 + 字幕/音轨/叠加轨，并**等成片真正完成** |
| 9 | qc | — | 逐集质检（黑帧/静音/响度/流/时长） |
| 10 | deliver | — | 打包 zip（成片/字幕/分镜表/素材/EDL/报告/质检） |

两条红线：
1. **花钱阶段绝不自跑**：`run` 走到 `keyframe`/`video` 就返回 `reason:'awaiting_approval'`，同时创建一份 P4 计划（`pending_plan_id`）。要放行必须「人工 `approve` + 人类确认码」——`studio_resume` 工具自己也需要确认码，因此 Agent 无法自行开跑。
2. **阶段幂等 + 断点续跑**：已完成阶段默认跳过（`force=true` 才重跑）；任何阶段失败都能从那一阶段继续，不重复干前面已经做完的活。

### 22.2 一句话解析（离线可复现）

`parseBrief()` 先用 LLM（可用）把需求解析成 JSON，**失败或未配置 Key 时自动回落到离线规则**；规则分支覆盖：中文数字（`三集`、`六十秒`、`二十四集`）、比例（显式 `21:9` 优先于「电影」这类风格词）、画风（按名称/名称片段/关键词打分）、题材（题材名与标签命中才认，**没有对应题材时不硬猜**——像「悬疑」这种只有基调信号的词会记成「基调=悬疑烧脑」交给模块2 的默认题材）。

### 22.3 实测与自测（全程离线零成本）

`tests/test-studio.js`（65 项）用 mock LLM + placeholder 出图/视频跑完整条流水线：

- 免费阶段：4 位演员 → 小说 + 10 章大纲 → 2 集剧本 + 12 镜分镜 → 画布铺出 12 关键帧 / 12 视频 / 2 成片节点，**全程零生成调用**；
- 付费阶段：`run` 停在 `keyframe`，此时**执行记录 0 / 新任务 0**（反证「未批准绝不生成」）；未批准直接用码 → 被拒；批准但码错 → 仍被拒；批准 + 正确码 → 任务入队并跑完；
- 成片/质检/交付：成片落盘并登记 `episode_films`，逐集质检 `pass`，交付包 3.2MB / 23 个文件 / **0 缺失**；再次 `run` 全部跳过（幂等）。

### 22.4 一条重要的数据打通：画布产物回写 `shot_renders`

- **症状**：制片流水线跑完，成片也有了，但**质检几乎没检查到东西**（「抽查 0 个镜头视频」）、交付包缺 4 项、生产看板看不到任何渲染。
- **根因**：画布流水线的产物只写进 `canvas_node_runs`（画布自己的执行流水），而质检抽查、生产看板、交付包的 `assets/` 与 EDL 时间线全部读 `shot_renders`（模块4 的镜头渲染表）。两套记录之间没有桥。
- **修复**：制片 `finish` 阶段新增 `syncCanvasRendersToShots()` —— 按「画布节点 `data.shotId`」把已产出的关键帧/视频登记进 `shot_renders`（同镜头同类型同文件幂等跳过），并顺带**等成片任务真正结束**再往下走（此前 `finish` 提交任务就返回，「成片已产出」是假象）。
- **效果**：同一部片子质检从「0 项检查、warn」变成**逐集 `pass`**，交付包从「21 文件 / 4 缺失」变成 **23 文件 / 0 缺失**，`shot_renders` 由 0 变为 24 条（全部来自画布）。

### 22.5 顺带修掉的两个解析/调用缺陷

1. `num(null, def)` 返回 **0** 而不是默认值（`Number(null) === 0`）—— 导致「没显式传角色数」时演员只建 1 位。现在 `null/''/undefined` 一律走默认值。
2. `createScript()` 返回的是 `{script, warnings}` 而不是剧本行 —— 制片脚本阶段直接取 `.id` 会拿到 `undefined` 并在绑定 SQLite 参数时报 `Provided value cannot be bound to SQLite parameter 1`。已按真实返回结构取值并对缺失给出中文错。
3. 另外 `createNovel()` 的 `pov` 需要字典 **id**（`third-limited`）而不是中文名，`generateOutline()` 的大纲章数在 `summary.chapters` 里 —— 都已按实际契约修正。

**总账更新**：新增 `tests/test-studio.js` **71 项**、`src/studio.js`（约 700 行）、`src/routes/studio.js`、制片相关的 5 个 MCP 工具（工具总数 23 → 28）；`tests/test-mcp.js` 262 → **266 项**；全量自检 **24 阶段 / 1737 项 → 25 阶段 / 1841 项断言**。

## 二十三、LibTV 调研落地（自动补尾帧 / 首尾帧自检 / Skill 契约化）挖出的 5 个问题

> 背景：`docs/LibTV视频制作技术调研与画布改进.md` 列出 7 条可吸收机制，本轮先做第 1、2 条与第 5 条。

### 23.1 「只有首帧」的片段此前只能靠人手工再画一张尾帧图

- **症状**：首尾帧过渡能力早就有了（`last` 端口），但**尾帧图从哪来**没人管：铺开分集只铺首帧（关键帧），于是绝大多数片段永远只有首帧，首尾帧过渡形同虚设。
- **修复**：新增 `createLastFrameNode()`（`src/timeline.js`）+ 四个入口（画布右键「⌛ 自动补尾帧」/ `POST /api/canvas/auto-last` / Claw 指令「给镜 1 补尾帧」/ MCP `canvas_auto_last_frame`）。按本镜提示词 + 收尾定格语义建出图节点，落在片段正上方，自动接 `image → last`，**只建图不生成**（尾帧图仍过人工闸门）。
- **顺带定的分寸**：重复补 → 中文拒绝「该片段已经有尾帧了」；非视频节点 → 拒绝并说明；没有提示词 → 拒绝并给出两条出路（先填提示词，或手动画一张尾帧图）。

### 23.2 付费调用出手前没有任何首尾帧检查

- **症状**：后端模板没准备尾帧、或首尾帧文件被清理过，都要**跑到后端报错**才知道 —— 那一次调用已经计过费。更隐蔽的是首尾帧被填成同一张图：能跑通、能出片，但整镜静止，属于「花钱买了一张静态图」。
- **修复**：`src/graph.js` 视频分支加**出手前静态自检**：尾帧图不存在 → 直接中文报错；首尾帧同路径或同内容（同尺寸时比 SHA-1）→ 写进 `raw.firstLast.warn` 并在节点说明里标出「这一镜不会有任何运动」；只有首帧 → `raw.autoLastHint` 直接指向 23.1 的入口。

### 23.3 技能只是一串阶段 id，Agent 无法预判「现在能不能跑」

- **症状**：`skills/*.skill.json` 只声明 `stages`，缺什么能力、会产出什么、哪些错误能自动重试全靠读代码。外部 Agent（或界面）无法在**建项目之前**发现「这条流程在离线环境里跑不通」。
- **修复**：`src/skills.js` 新增 `contractOf()` —— 每个技能自带 `requires`（数组套数组 = 择一即可，例如关键帧可以是本地占位或真实出图）/ `paid`（从阶段定义推导）/ `outputs`（逐阶段中文产出物）/ `retryKinds` / `blockedReason`（中文原因，含「缺：出图后端（当前 placeholder）」这种可操作信息）。`createProduction()` 在契约不满足时**直接中文报错**并给出降级建议（改用 `canvas-only`），不硬跑。
- **避坑**：`capabilities()` 与 `contractOf()` 互相调用会**无限递归**，因此把能力矩阵拆出内核 `capabilityMatrixCore()`，两边都只依赖内核。

### 23.4 制片 Agent 页此前**没有任何 UI 自动化覆盖**

- **症状**：`tests/ui-smoke.py` 逐个挂载小说/剧本/制作台/设置四个模块，**唯独漏了「🎬 制片 Agent」页**（1106 行的控制台）。也就是说该页白屏或按钮失效，全量自检依然会全绿。
- **修复**：补上制片页断言（控制台骨架 + 技能下拉 + 契约面板 + 清空后回默认说明），并顺手把「技能选择器 + 契约面板」做进页面：选中技能即显示 `前置能力齐备 / 阶段 N / 付费阶段 / 可自动重试 / 产出物`，前置能力缺失时**「生成生产计划」按钮直接禁用**并把原因写在面板上。

### 23.5 文档里的计数在多轮迭代后互相矛盾

## 二十四、画面度量与跨镜一致性（LibTV 调研第 2 条第二层 / 第 3 条）的 5 个坑

### 24.1 「均值 + 2σ」当离群判定线，会被离群值自己抬高到永远不报

- **症状**：4 张关键帧里 3 张一样、1 张完全反相（64/64 位都不同），一致性评分**一个都没报出来**。算一下就知道：距离向量 `[0,0,0,1]` → 均值 0.25、σ≈0.43 → 判定线 `0.25+2×0.43=1.12 > 1`，等于永远不触发。
- **修复**：判定线改成抗离群统计量 **`max(阈值, min(0.5, 中位数+3×MAD))`**：中位数/MAD 不被离群值带偏；自适应项加 0.5 上限，保证它只在「组内本来就分散」时收紧；用户显式给的阈值始终是权威口径（调高就真的不报）。报告里同时给出 `median/mad/cut`，口径透明、可复核。

### 24.2 单色图会让感知哈希「退化」，差点被当成 bug

- **现象**：用 ffmpeg 生成的纯色测试图，aHash 结果是全 0 或全 1（每个像素都等于均值），距离直接拉满 64 位。
- **结论**：这是平均哈希的正常退化行为（纯色图没有高于均值的像素），真实关键帧有细节不会出现。已在方法说明里显式写明「单色/纯色图哈希会退化，属预期」，避免下一个人当成缺陷去修。

### 24.3 集号过滤写错表名：`episodes` → `script_episodes`

- **症状**：MCP 工具按集号查询直接抛错（返回 null，被上层当成「工具不可用」）。本库的集表叫 `script_episodes`，不是 `episodes`。
- **修复**：改对表名；并把「缺参数」与「调用失败」两种情况在测试里分开断言，避免后者被前者的中文报错掩盖。

### 24.4 MCP 返回值里 `summary` 撞名：人读结论被数值统计覆盖

- **症状**：工具同时返回 `{ summary: '一致性评分：…' }` 与 `...report`，而 `report` 自己也有 `summary`（数值统计），展开顺序在后 → 人读结论被覆盖成对象，界面显示 `[object Object]`。
- **修复**：人读结论固定放 `summary_text`，`summary` 保留数值统计；HTTP 路由用 `{ report, summary }` 两层结构天然不冲突。

### 24.5 工具命名空间约定被新工具打破

- **症状**：新工具取名 `consistency_score`，被既有断言（工具名必须落在 `canvas_* / job_* / studio_* / skills_*` 命名空间）拦下。
- **修复**：改名为 **`render_consistency_score`**（制作台域），并把这个新命名空间写进断言 —— 约定是活的，但要**显式登记**，不能悄悄绕过。

### 24.6 一致性评分「点下去像没反应」：50 张关键帧串行解码要 10 秒

- **症状**：制作台点「🧬 跨镜一致性」后 3 秒内什么都没发生（弹窗没出来、toast 也已经自己消失了），看起来像按钮坏了。实测 50 张关键帧 × 每张一个 `spawnSync` ffmpeg = **10.1 秒**，而且是同步阻塞事件循环（同进程的其他请求一起被堵）。

**总账更新**：新增 `src/frames.js`（画面度量：灰度差 / 感知哈希 / 中位哈希）与 `src/consistency.js`（跨镜一致性评分）；`src/graph.js` 接入运动量量化，`src/qc.js` 整集质检新增「跨镜一致性」检查项，制作台新增「🧬 跨镜一致性」按钮，新增只读 MCP 工具 `render_consistency_score`（工具 31 → **32 个**）；`tests/test-timeline.js` 147 → **162 项**，`tests/test-mcp.js` 267 → **271 项**；全量自检 **25 阶段 / 1903 → 1922 项断言**。

## 二十五、逐镜缩略轨与拖拽调序（LibTV 调研第 4 条）踩到的 5 个坑

### 25.1 顺序口径是「端口优先」，只改 slot 等于没改

- **问题**：调序最直觉的实现是「交换两条连线的 `slot`」。但 `orderedClips()` 的排序键是 **端口号 → slot → 创建时间**，只要两条边还挂在 `clip1/clip2` 上，改 slot 一点用都没有——界面显示换了顺序，成片还是老顺序（这种「看起来生效、实际没生效」最难查）。
- **修复**：`reorderTimelineClips()` **同时重写端口与 slot**：按拖拽后的顺序把 `to_port` 写成 `clip1..N`（保持端口唯一，顺带消掉重复端口）、`slot` 归一为 `0..N-1`（历史无端口边的兜底次序）。断言里专门写了「端口唯一 + slot 归一 + dry-run 预览一致」三条。

### 25.2 拖拽调序必须抢在「节点拖动」之前

- **问题**：缩略轨画在成片节点内部，第一版把命中检测放在节点拖动之后 —— 结果一按下去就把整个成片节点拖走了，缩略图纹丝不动。
- **修复**：在 `mousedown` 的**端口/连线之后、缩放手柄之前**插入缩略轨命中；`mousemove` 开头先判 `clipDrag` 并 `return`（不进入节点拖动/框选分支）；`mouseup` 先收调序态再走原有逻辑。

### 25.3 前端辅助函数被插进了 `mount()` 里，绘制函数看不见

- **问题**：`clipEntriesOf` 等辅助函数第一版插在 `mount()` 内部（`bindKeyboard()` 之后），而绘制函数 `drawAssetNode()` 在模块顶层 —— 运行时报 `clipEntriesOf is not defined`，画布上缩略轨一格都画不出来。因为是异步渲染路径，控制台也只有一行 pageerror 一闪而过。
- **修复**：把辅助函数整体提到**模块顶层**（`const` 箭头函数在模块初始化时求值，只要在所有调用之前完成即可）。

### 25.4 建连线接口返回的是 `{ link: {...} }`，审计脚本取 `.id` 全是 `undefined`

- **症状**：审计里三条负例断言全挂：错误信息变成「有 1 条连线不属于这个成片节点：」（后面空列表）和「调序数组里有重复的连线 id」—— 因为取到的是 `undefined`，`[None]` 既不算合法 id 又互相重复。
- **修复**：改成 `(_lk.get("link") or {}).get("id")`；并把这类「接口返回结构」的取值集中在一处，避免每个断言各自猜。

### 25.5 预期内的 400 会污染「全流程无 JS 错误」断言

- **问题**：负例断言（少给/外来/非成片节点）必然产生 400 响应，浏览器把它记成 console error，于是收尾的「全流程无 JS 错误」被判失败。
- **修复**：用审计里既有的 `api_soft()`（允许 4xx、解析错误体）；真机点击产生的预期 400 则用「记下错误下标、断言后删除这一段」的方式剔除，**只剔除这一次预期内的**，不做全局过滤。

**总账更新**：新增 `src/thumbs.js`（抽帧缩略图 + 指纹缓存 + 目录越界防护）与 `reorderTimelineClips()`；新增路由 `GET /api/render/thumb`、`POST /api/render/thumbs`、`POST /api/canvas/reorder-clips`；画布成片节点新增逐镜缩略轨与拖拽调序；`tests/test-timeline.js` 162 → **173 项**，`tests/canvas-audit.py` 163 → **170 项**（真机缩略轨/拖拽/写回 7 项）；全量自检 **25 阶段 / 1922 → 1940 项断言**。

## 二十七、专业后期导出（时间线三格式 / 字幕三规范）踩到的 4 个坑与 1 个真发现

### 27.1 动态 `await import()` 加进模块，静态 import 却忘了加

- **处理**：把它做成**可见的告警**（质检「字幕规范」项 + 交付包 `manifest.json` + 导出面板逐条列出），而不是悄悄裁掉。真正要改的换行策略（按语义标点切、限制两行内）留给后续：目前先把「看得见」做实。

### 27.6 顺带修掉一个潜伏已久的 1 毫秒抖动（生产看板）

- **症状**：全量自检里 `tests/test-stats.js` 偶发失败：「P95 与最长耗时可用 p95=60001 max=60001」（期望 60000）。单跑永远通过，只在整套自检（机器有负载）时冒出来。
- **根因**：测试用 `iso(msAgo) => new Date(Date.now() - msAgo)` 生成 `created_at` / `finished_at`，**两次调用各读一次 `Date.now()`**；跨毫秒时差值就变成 60001ms。这不是产品缺陷，而是**测试自己的时间基准不固定**。
- **修复**：取一次 `NOW_BASE = Date.now()`，所有种子时间戳都基于它；并保留 `±1ms` 容差断言。修完连跑两次全绿。

### 27.7 第二个偶发：任务队列套件在负载高时「4 秒等不到任务完成」

- **症状**：全量自检第 11 站 `tests/test-jobs.js` 出现 6 项连带失败（`status=running` / `progress=50` / `done=2/4`），而单跑永远通过。日志显示 handler 只跑了 2 步（`seen=[false,false]`）—— 进程在那几秒里被别的负载挤住了（本机还跑着 dsh web、grafana、rabbitmq 等常驻服务）。
- **结论**：断言的本意是「任务最终会完成且终态正确」，而不是「必须 4 秒内完成」。等待上限从 **4s 放宽到 30s**（其余套件早已是 15s / 60s / 120s，只有这一站偏紧），并把这个理由写进注释，避免以后有人又把它改回去。
- **教训**：**时间敏感的断言要区分「语义要求」与「环境噪音」** —— 前者该严格（例如「取消后不得覆写终态」），后者给足余量。

## 二十八、响度归一（EBU R128 / ATSC A/85 / 流媒体）的 3 个坑与 2 个设计取舍

### 28.1 单遍 loudnorm 会把动态压平，必须两遍法

- **问题**：`loudnorm` 只给目标值（`I=-23`）跑一遍时，它靠**动态压缩**把响度硬拉到位 —— 响度达标了，但枪战片/音乐段落的动态全被压平，听感变「糊」且发闷。
- **修复**：两遍法 —— 第一遍 `loudnorm=print_format=json` 只测量（`input_i/input_tp/input_lra/input_thresh/target_offset`），第二遍把这些实测值填回去并 `linear=true` 做**线性**归一。实测：`-51.8 → -23.01 LUFS`，动态（LRA）保持不变。

### 28.2 静音轨会被判「严重不达标」（-70 LUFS，偏离 -47 LU）

- **症状**：项目默认 `finish.audio='silent'`（未配 TTS 时不配音，成片是静音轨），接上口径后实测 `-70 LUFS` → 判定「偏离目标 47 LU」。**这不是质量问题，而是设计如此**（本来就是静音轨），却会被报成红色告警。
- **修复**：与质检里的静音轨语义对齐 —— 成片 `meta.audio.mode === 'silent'` 时返回 `level: info` + 说明「启用配音或背景乐后再按口径判定」，路由与 MCP 两边都做；`qcFile` 原本就有静音轨降级逻辑，现在两边口径一致。

### 28.3 ffmpeg 参数位置写错：`-af` 被当成输入选项

- **症状**：手搓测试命令 `ffmpeg -i sine -af volume=-30dB -f lavfi -i color=...` 直接报 `Option af cannot be applied to input url color=...`。
- **教训**：`-af` 是**输出**选项，必须放在最后一个输入之后。测试夹具命令已改正（产品代码里用的是输出侧滤镜，本来就没问题 —— 这个坑只吃了我一次试跑时间，写进日志免得再来一遍）。

### 28.4 取舍一：默认 `off`，不改变既有成片

- 老用户的成片响度是历史事实，插件式地「突然全部归一」会让交付内容变样、也会让既有断言失效。所以 `finish.loudness` 默认 `off`（原样复制），显式选了口径才处理 —— 与「付费阶段必须人工批准」同一种克制：**改变既有产物的事，必须由人显式打开**。

### 28.5 取舍二：口径是「配置」不是「代码」

- 四种目标（-23 / -24 / -14 / -16）都写在 `LOUDNESS_TARGETS` 表里，未知口径**回落到 off 而不是猜**；判定容差（±1 LU / ±1.5 LU）与真峰上限也一并写在表里。以后平台改标准只改这张表。

## 二十九、多平台版本的 3 个坑与 2 个判断

## 三十三、本轮（2026-09-30）三件事：墙钟非单调加固、定妆图被厂商拒绝、门禁抓到一次真回归

> **规模说明**：本节与前文各节不同 —— 它不是「一轮新功能踩的坑」，而是**同一天里三件性质不同的事**：一件是**环境事实**（本机墙钟非单调，不是本项目缺陷，但会把「取最新一行」和「耗时」全部算错），一件是**真机故障**（用户报「生成图片被拒绝」），一件是**门禁立功的留痕**（全量自检在中间那次的修复里真的挡住了回归）。三件都按「症状 / 根因 / 修法 / 回归 / 证据」写全。

### 33.1 本机墙钟非单调（实测 ±12.4s）：排序键与耗时全被污染

- **症状（两个都不像「时钟」问题，所以一开始被当成别的原因查）**：
  1. `tests/test-render.js` **3 次里 1 次**失败（`104 通过 / 1 失败`，与用户实测的 `105/0`、`105/0`、`104/1` 完全一致）。失败的那条断言读到的 `meta` 是**别的任务**写的（`raw.motion='push in'`，画布 DAG 口径），也就是「这一镜上一版的行」。
  2. 早前的自检产物里出现过 **`"ms": -12349`** —— 负耗时污染看板 / 报告 / 对账。
- **根因**：所有 `created_at` 都是 `nowISO()` 写下的**墙钟字符串**。本机墙钟**非单调**：E-101 落地后的独立复测（`Date.now()` 对照 `process.hrtime.bigint()` 每 250ms 采样一次、共 **65s / 259 次**）里，**>50ms 的跳变 19 次**，**最大回拨与前拨均为 12449ms**（≈ 每 3.4s 一次，**非偶发**）。于是「程序序更晚写下的行」可能带**更早**的 `created_at` —— `ORDER BY created_at DESC LIMIT 1` 取到的不是本次写入的行；同理 `Date.now() - t0` 在回拨时算出来是**负数**。
- **修法（产品侧 E-101，`src/**` 29 个文件）**：
  1. **判序一律改插入序 `rowid`**：`src/**` 里 **71 处**按 `created_at` 判序的 SQL 全部改掉。依据是这些表**都没有 `AUTOINCREMENT`**，插入时 `rowid = max(rowid) + 1`；即使删行导致 rowid 被复用，SQLite 仍保证新行 `rowid` **严格大于现存所有行**（复用只发生在「被删出的空洞 < 当前 max」上）⇒ `ORDER BY rowid DESC` 恰好等价「按插入序倒序」，**与墙钟无关**。多表 JOIN 时 rowid 有歧义，必须写 `别名.rowid`。口径写在 `src/db.js:22-44`（导出 `ORDER_INSERT_DESC` / `ORDER_INSERT_ASC`）。
  2. **同进程耗时改单调钟**：`src/util.js` 新增 `monoNow()`（`performance.now()`）、`elapsedMsSince(t0, clock)`（单调差值、下限钳 0、**可注入时钟**便于测试）、`clampMs(v)`（NaN/Infinity/负 → 0），见 `src/util.js:26-42`。
  3. **跨进程 / 跨重启的墙钟差值无法用单调钟，只能钳 0 并注明**：`jobs.created_at → finished_at` 这类落库字符串（`src/stats.js:60-66` 排除负样本）、制片报告阶段耗时、`src/schedules.js:1105-1111` 的调度延迟（这里**必须**继续用墙钟 —— 「迟到几分钟」是**真时间语义**）。

### 34.3 一条潜伏很久的付费漏洞：跑套件会真发一次 DeepSeek 请求

- **症状（不报错、不失败、不记账）**：`tests/test-adapters.js` 里有一条断言写成 `typeof llmMod.chat({ prompt: 'x' }).then === 'function'` —— 它**每次都真的调用一次 `chat()`**，打向 `api.deepseek.com`，用宿主机真实凭据，**花的是真钱**。
- **为什么长期没被发现**：**LLM token 不进 `usage:monthly` 台账**（台账只记出图 / 出片 / 配音），所以「零付费」自检与用量对比都看不出来；套件本身也一直是绿的（它要断言的只是「返回的是 Promise」）。
- **发现方式**：M-101 在逐套件统计 `fetch` 调用时，发现该套件存在**非回环**请求。
- **修法**：改为按 **`AsyncFunction` 类型**断言（`chat` 是 async 函数 ⇒ 语义等价），**零外部调用**；并用「拦截非回环 fetch」复跑确认 **非回环调用 = 0**。
