# AI 漫剧 · 电影视频工厂

一套本地运行的 **「明星定妆 → 小说 → 剧本分镜」** 一体化生产工作台。零外部依赖（只需 Node ≥ 22），打开浏览器即用。

```bash
cd ai-video-factory
node server.js          # 或 npm start
# 浏览器打开 http://127.0.0.1:8788/
```

> 首次使用建议先跑一次自检：`./scripts/verify-all.sh`（**35 个阶段**；**第 9 波**实测 **35/35 阶段全部通过、断言合计 3519、失败 0、退出码 0** —— **阶段数固定为 35，合计不是固定值**，一律以脚本输出为准，末行打印 `✅ 全部自检通过`）。
> **计数口径**：**阶段数固定为 35**（脚本里现有 35 个 `run` 阶段：25 个原有 + 第 4 波 26~30 + 第 5 波 31~34 + 第 6 波 35）；**单阶段断言数与其合计数会随代码演进**，README 不复制它们，**一律以 `./scripts/verify-all.sh` 的实际输出为准**（每阶段结尾都打印 `=== 结果：N 通过 / 0 失败 ===`，运行标签是 `N/35`；脚本头部注释与第 12 阶段标题已按实测校准为「35 个阶段 / 41 个工具」）。

## 一、四大模块与需求对照

### 模块 2 · 小说工坊

- **100 种题材**（16 大类，可搜索/筛选，均带推荐基调与开篇钩子）
- **角色规模** ≤ 200 名：可勾选模块 1 的演员 `C-xxxx` 引用，也可自定义角色（两者合计受限）
- **字数规模** ≤ 1000 万字；**章节字数** 1000–3000 字可调；叙事视角 7 种；基调；季数
- 可**上传故事框架参考范本**（自动注入大纲提示词，超长自动截断并提示）
- **两步生成**：
  1. **章节大纲**（13 个分节）：故事走向、框架逻辑、世界观、卷/季结构、章节大纲、宏伟时间线、地点档案（`L-0001`）、人物 ID 出场规划、伏笔表（埋设→回收）、反转清单、节奏卡点、章末钩子银行、**跨季章节时间回路**、全篇因果链；支持带指令**优化**与**续规划**（单次 ≤200 章、每批 20 章，可分卷继续）
  2. **完整章节**：逐章写作，每章自动携带上下文（全书框架 + 本章大纲 + 前情摘要 + 相关人物/地点 + 未回收伏笔 + 事件时间线），字数不足自动续写一次
- 章节阅读器 / 手动编辑 / 单章重写 / 导出 TXT·MD·JSON

### 模块 3 · 剧本工厂

- 从**已完成小说**转换：竖屏漫剧（1–3 分钟/集）/ 电影长片 / 网剧 / 短视频切片
- 可选 **单集时长**（30s·60s·120s·180s·40min·90min 预设 + 自定义秒数）、**单季集数**（≤500）、季数
- 可**上传转换技能文档**或载入**内置 4 套模板**（漫剧/短视频/网剧/电影），内含改编原则、桥段保留·合并·删除规则、每集结构、钩子卡点节奏、台词规则、**镜头语言中英对照表**、审查红线
- 分集规划（标题/logline/钩子/悬念收尾/覆盖章节）→ 单集剧本（场次 + 台词 + 动作）→ **分镜表**
- 分镜字段：景别/机位/运镜/转场/时长/情绪/台词/音效 + **英文正负向提示词**（风格头尾 + 角色锚点 + 镜头语言）+ 角色与地点引用 + 成本级 L/M/H；镜头时长按单集时长**自动配平**（偏差 >2% 中文告警，可一键 rebalance）
- 单镜可编辑/新增/删除（改动后自动重建提示词）；导出 JSON / CSV / Markdown / Fountain

### 模块 4 · 制作台（分镜 → 关键帧 → 视频 → 整集成片）

- **输入**：模块 3 的分镜表（每镜已有英文正/负向提示词、景别、运镜、时长、成本级）
- **关键帧**：一键把整集 / 选中镜头送去当前出图后端出图，结果绑定到镜头并在卡片上直接预览
- **视频**：三种后端
  | 后端 | 说明 |
  |---|---|
  | `placeholder` | 本地 ffmpeg 运镜成片：按镜头运镜（推/拉/摇/移/跟/升降/环绕/手持/变焦/甩/希区柯克变焦）把关键帧做成 h264 mp4，无需任何外部服务 |
  | `comfyui-h3` | 云端 MiniMax H3（内置两套官方 API 工作流：**首帧驱动 i2v** / **文生视频 t2v**，有关键帧自动用前者）。提交前拉 `/object_info` **预检节点类型/必填项/模型清单**（云实例节点版本与前端导出常不一致，这是最常见的 400 原因），关键帧若是占位 SVG 会先 **ffmpeg(librsvg) 光栅化成 PNG** 再 `/upload/image`；自动挂 **turbo LoRA 4 步**（≈45s/条，20 步 ≈120s/条）、按实例枚举映射比例与分辨率、强制关闭会把提示词外发第三方 LLM 的「提示词优化」节点；产物自带音频，超时自动 `/interrupt` 释放实例 |
  | `generic-http` | 任意厂商视频 API：请求体模板 + 响应字段路径 + 异步任务轮询 + 关键帧 base64 回填；失败按「限流/5xx/网络」自动退避重试 |
- **增量与省算力**：默认跳过已生成的镜头；可指定镜头、只给 H/M 级镜头上视频、覆盖重做、删除单条渲染
- **整集合成 + 成片包装**：按分镜顺序拼接成整集 mp4，并做后期包装 ——
  - **字幕**：按镜头时长与台词生成 SRT（自动推断说话人、跳过无台词镜、支持画外音标记），可选**烧录进画面**（libass，自动探测中文字体）或**软字幕轨**（可开关）
  - **音轨**：静音轨（保证时间轴正常）/ **AI 配音**（TTS 适配器：OpenAI 兼容 `/v1/audio/speech` 或任意厂商 HTTP 模板，按每镜时间点混音）/ **背景乐**（上传 BGM，循环 + 音量 + 淡出）
  - **画面**：淡入淡出
- **画布资产桥**：把画布上的环境/物品/参考图**绑定到剧本** → 分镜提示词自动带上场景与道具令牌（`canvas set:`）、同名地点自动合并（保留 `L-xxxx`）→ 制作台渲染关键帧时**自动使用画布参考图做参考生图**（`image.useCanvasRefs` 可关）；另可导出画布资产清单（MD/CSV/JSON）
- **画布组合出图（连线即约束）**：选中演员卡 + 环境/物品/参考图节点 → `⚡ 组合出图` → 自动合成英文提示词（人物锚点 + 场景/道具描述 + 参考图）并出图，结果同时进演员素材库与参与节点；环境/物品节点还可单独「生成概念图」
- **五类节点 + 端口连线**：演员卡 / **环境节点** / **物品节点** / **参考图节点（矩阵）** / 便签；每个节点**左右端口**可拖拽或"点两次"连接，关系标签可选（出现在/持有/使用/敌对…），**连线数量不限**，可改标签/反转/删除，删节点级联清理
- **节点与分组**：单卡缩放 / 统一尺寸 / z 层级（`]` `[`） / **便签节点**（6 色，可复制粘贴） / **分组框 Frame**（成组、整体拖动、收起展开、重命名改色、贴合内容、解散、按键自动生成） / **撤销重做 40 步**（完整快照，不丢隐藏卡片）
- **选角中枢**：左侧演员列表**拖入画布**放置、**拖进分组框自动归组**；分组右键可**批量生成定妆图**、**一键加入某部小说的选角**、复制 ID 清单、清空成员
- **整季流水线**：一键「分集规划 → 生成分镜 → 渲染关键帧 → 生成视频 → 封装成片」，可只给 H/M 级镜头上视频、可离线试跑（分镜走规则不花模型钱）、有工作量与耗时预估、产出逐集生产报告
- **出海物料（多语言字幕 + 发布元数据 + 封面）**：制作台「🌐 出海物料」选目标语言（英/日/韩/西/葡/泰/越/印尼）→ 一键生成：**多语言 SRT**（逐条翻译，**时间码与条数严格不变**，失败逐条回退原文并告警，按内容哈希缓存）、**封面帧**（从成片 12% 处按比例截 1080x1920 等）、**发布元数据**（3 个标题备选 / 简介 / 话题标签 / 引流钩子，模型生成失败自动规则兜底，并附多语言要点）；物料落在 `data/publish/<集号>/` 并**随交付包一起交付**（`publish/`）
- **配音链路（按角色配音）**：成片包装的「配音（TTS）」会**按每镜说话人取该演员档案里的「音色」**（未识别时用演员表第一位有音色的角色，没填则回退默认音色并告警）；台词**超出镜头时长自动加速**（上限 `ttsMaxSpeed`，默认 1.25x）仍超长才截断并告警；相同台词+音色**复用合成缓存**（重复封装不再重复付费）；新增音轨模式**「配音+背景乐」**——BGM 循环铺满整集并在人声处**侧链自动压低（ducking）**；封装结果里带完整配音报告（每句的音色来源、音频时长、镜头时长、适配动作、是否命中缓存）
- **成片质检（ffmpeg 实测）**：制作台「🔍 成片质检」对成片与抽查镜头跑 `ffprobe` + `blackdetect`（黑帧）+ `silencedetect`（静音）+ `ebur128`（响度），逐项给出 ✅/⚠️/❌ 与中文说明；同时校验**流缺失、分辨率/编码、时长与「镜头视频之和」是否一致、分镜覆盖（缺几镜视频）、失败镜头归类**。报告可下载 Markdown，并**随交付包一起交付**（`qc/` 目录 + 清单里的质检结论）
- **生产看板（可观测性）**：制作台「📊 生产看板」一眼看清长跑状态 —— 逐集进度百分比、近 7 天任务量与成功率（含平均耗时/P95/最近错误）、关键帧与视频的成功率与平均延迟（按后端拆分）、**失败原因 Top（按错误归类聚合，带中文标签与样例）**、产出趋势条形图（只统计成功产出，失败单独计数）、吞吐与**剩余时间估算**、本月用量与金额
- **一键交付包（zip）**：制作台「📦 导出交付包」先弹清单（集数/镜头/关键帧/视频/成片时长/体积/缺失项/失败镜头），确认后下载 zip —— 内含 `final/` 成片、`subtitles/` SRT、`storyboard/` 分镜表 CSV+JSON（含英文正负向提示词、种子、后端、采用版本标记）、`timeline/` EDL 时间线（Premiere / DaVinci / Final Cut 可直接导入）、`assets/` 每镜关键帧与片段原文件、`report.md` 生产报告（用量与金额、逐集明细、失败镜头归类）、`manifest.json` 交付清单。ZIP 为零依赖自实现（deflate + CRC32），并由 Python `zipfile` 独立校验
- **镜头版本管理**：同一镜可反复生成累积多个版本 → 卡片「🎞 版本 N/M」打开对比弹窗（关键帧看图、视频可播放、显示后端/seed/耗时），点「★ 设为采用」后**整集拼接与看板都会用该版本**（互斥、可取消采用回退到最近一次成功）；失败版本不允许被采用
- **成片管理**：同一集可反复封装互不覆盖（文件名唯一），成片可播放/下载/**删除**（记录与文件一起清）；`🧹 清理中间产物` 一键回收临时文件（服务启动时也会自动清理）
- **任务自愈**：服务重启后，上次进程被杀留下的 `running/queued` 任务会自动标记为「中断」并可重新提交，不会留下永远转圈的僵尸任务
- **满配规模已验证**：按文档上限（200 演员 / 单集 ≤200 镜 / 100 集 / 200 章）造数据实测 —— 19 个后端接口合计约 1.4s（最慢「整季工作量预估」约 0.7s），前端首屏 0.6~1.6s，200 卡位画布缩放/框选/全选均正常（详见 `tests/test-scale.js` 与 `tests/ui-scale.py`）
- **生产守护（预算 / 磁盘 / 失败重试）**：真实厂商 API 上线后的安全网 ——
  - **用量台账**：按真实后端出图/出片/配音自动记账（占位与本地 ffmpeg 不计费），按配置单价换算本月金额
  - **预算闸门**：超「本月上限」直接拒绝任务、超「单次确认阈值」先在制作台弹确认（含预估金额/已用/上限），设置页可一键清零本月用量
  - **磁盘保护**：数据目录占用分项统计（images/videos/audio/finish/uploads/tmp/work/database/**cache**），超告警阈值提示、超上限拒绝新任务。**参考图栅格化缓存（`data/cache/refs/`，REFIMG-FIX 的 SVG→PNG 缓存）此前不在统计口径里 —— 磁盘闸门漏算它**（C-101 纠正）：现在它按 `bytes/files/mb` 单列一项并计入总量（现网 `totalMB` 247.3 → 248.9）。界面入口（H-101）：设置页「数据与备份 / 磁盘保护」的 `#cache-scan`（🔍 查看可清理量，只读）与 `#cache-clean`（🧹 清理缓存，二次确认）。接口：`GET /api/render/cache`（**只看不删**，返回 `{ok,dir,exists,files,bytes,freedMB,dryRun:true,note}`）、`POST /api/render/cleanup` 新增显式开关 `{cache:true}`（连缓存一起清）与 `{dryRun:true}`（只看不删）——**不传 `cache` 时 `POST {}` 的老调用方逐字段不变**
  - **失败镜头一键重试**：按错误归类只重跑「限流/5xx/网络/超时」，鉴权/额度/审核类会列出原因让你先修配置（不会白烧额度）

### 画布可执行节点图（画布即工作流：类型化端口 → 计划 → 人工审批 → 执行 → 成片）

把模块 1 的无限画布从「素材墙」升级为**可执行工作流**：节点有强类型端口、连线可表达数据流与顺序、整图可 dry-run 出计划、必须人工审批后才执行、执行结果回写到节点并可一键成片。全部能力都可在画布上完成，**不需要碰命令行**。

| 能力 | 说明 |
|------|------|
| **类型化端口** | 每类节点带明确端口：演员/环境/物品/参考图 `image`·`ref`；关键帧（出图）`in`·`ref1..3` → `image`；视频 `first`·`last`·`ref1..2` → `clip`；分镜容器 → `clip`；成片时间线 `clip1..clip24` → `film`；交付终点 `in`。端口按类型配色并标注端口名，**连线做兼容校验**（非法连接前端当场拦、服务端再拦一次并给中文原因，例如「不允许 text → first 的连接」） |
| **语义关系线 vs 数据流边** | 不带端口的连线 = 语义关系线（对手戏 / 出现在 / 持有…），**不参与执行排序**；带端口的连线 = 数据流边（决定谁先跑、成片第几段）。两者可共存于同一张画布 |
| **槽位顺序** | 数据流边自动带槽位序号（①②③…直接画在连线上），同一输入端口接多条线时按槽位排序；成片顺序由 `clip1..N` 端口号决定（端口号 → 槽位 → 创建时间三级兜底） |
| **🎞 铺开分集** | 选剧本 + 分集 → 一键把整集铺到画布：每镜生成「关键帧（出图）→ `image`/`first` → 视频片段」，再把 17 个片段按 `clip1..clip17` 接到「成片时间线」节点。**只排版、不生成任何东西**；镜头数超过 24 时自动分成多个成片节点（标题带 `（1/2）`） |
| **🧭 执行计划（dry-run）+ 人类审核闸门** | 点「🧭 执行计划」→ 弹出计划：将执行哪些节点、可跳过哪些、预估调用次数（出图/视频分列）、成本级 L/M/H、环形依赖提示。**必须**：① 人工点「✅ 批准计划」② 填入只打印在运行服务终端（`./start.sh` 窗口，形如 `[gate] 计划 PL-xxxx 待人工确认，确认码：123456`）的 6 位确认码 ③ 服务端执行前再比对一次计划（画布被改过就拒绝）。三步缺一不可，Agent 拿不到确认码，因此**无法自行开始花钱的生成** |
| **节点内可见执行状态** | 每个节点显示「未执行 / running / done / error」「已产出 / 失败：原因」，关键帧与视频节点直接在画布上看到自己产出的画面/片段；成片节点显示「片段 N 段 · 已产出」 |
| **增量执行，绝不重复计费** | 每个节点记录**输入指纹**（提示词/参数/上游产物指纹）：指纹没变就自动跳过，只有变化或显式覆盖才重跑；一次执行 = 一个持久化任务，可取消、可续跑 |
| **只重跑单个节点** | 右键视频节点「▶ 生成 / 重跑该片段」、右键成片节点「🎬 立即成片」→ 走单节点计划 + 审批 + 确认码，产物与执行记录都会更新 |
| **手工搭图（不只靠铺开分集）** | 工具栏「➕ 流程节点」可直接创建 关键帧（出图）/ 视频片段 / 文本 / 成片时间线 / 交付终点，右键视频节点还有「↻ 生成续写片段」一键建出续写节点并自动接好 `clip → first`。所有节点都用同一套类型化端口，可以完全手工连出一张工作流 |
| **自动补尾帧（首帧 → 尾帧图）** | 只给了首帧的片段，右键「⌛ 自动补尾帧」→ 按本镜提示词 + 收尾定格语义**建一张尾帧出图节点**（落在片段正上方）并自动接好 `image → last`；同一动作还有三个入口：`POST /api/canvas/auto-last`、画布内 Claw 指令「给镜 1 补尾帧」、MCP 工具 `canvas_auto_last_frame`。**只建图不生成**：尾帧图仍走「执行计划 → 人工闸门」，重复补会被中文拒绝（提示已有尾帧） |
| **首尾帧自检（出手前拦截）** | 视频节点执行前先做静态检查：尾帧图**不存在** → 直接中文报错（不浪费一次计费调用）；首尾帧**是同一张图**（同路径或同内容）→ 明确告警「这一镜不会有任何运动」并写进结果与执行记录；只连了首帧 → 结果里给出 `raw.autoLastHint` 引导到上一行的「自动补尾帧」 |
| **多平台版本（一次成片 → 各平台规格）** | 平台规格写成数据表（`src/variants.js`）：抖音/视频号竖屏 9:16、小红书 3:4、B站/YouTube 横屏 16:9、方屏 1:1，每个平台带自己的**分辨率、字幕安全区、响度口径**。先出**规划**：算清裁切损失（竖屏转横屏会丢约 68% 画面 → 自动建议改用「模糊补边」）、字幕底边距换算后是否落在平台安全区内；再本地 ffmpeg 出片（`crop` / `blur-pad` / `black-pad` 三种补边，零成本、不调厂商接口）。入口：制作台「📱 多平台版本」、`GET|POST /api/render/variants`、MCP `render_variants`；设置 `variants.targets` 后**交付包自动带上 `variants/`** |
| **响度归一（广播/流媒体口径）** | 成片包装可设响度目标：**EBU R128（-23 LUFS）／ATSC A/85（-24 LKFS）／流媒体（-14 LUFS）／播客（-16 LUFS）**，用 ffmpeg `loudnorm` **两遍法**（先测再按实测值线性归一）—— 单遍会压平动态，两遍才既达标又保真。成片 `meta` 与质检报告都记录口径：**达标/偏离多少 LU、真峰是否超上限**都会写清楚；静音轨（未启用配音/BGM）不误判为不达标，给提示说明。默认 `off`（不改变既有成片）。入口：成片包装面板「响度归一」+「📈 测一下当前成片响度」、`GET /api/render/loudness`、MCP `render_loudness` |
| **专业后期：时间线三格式 + 字幕三规范** | 同一份镜头序列可导出 **EDL（CMX3600）/ FCP7 XML（xmeml v4）/ OTIO（OpenTimelineIO）**，三者与「界面顺序 = 成片顺序」同源同一份数据（`src/interchange.js`）；字幕可导出 **SRT / WebVTT / TTML** 并做**排版规范校验**：单行字数、行数、语速 CPS、单条停留时长、重叠、以及**安全区**（按画面高度与成片边距换算）。交付包自动带上这 6 个文件，`manifest.json` 记录逐集字幕规范结论；质检报告新增「字幕规范」检查项。入口：制作台「⤓ 时间线 XML/OTIO」「⤓ 字幕 VTT/TTML」、`GET /api/render/timeline|subtitles`、MCP `render_interchange` |
| **工作流能力匹配（降级建议）** | `src/backend-fit.js` 把「实例真正具备什么」与「这一集要什么」对表：比例、单镜时长上限、首尾帧、turbo LoRA、配音后端、计价方式 —— 跑不通的给 **block + 替代方案**（如换 placeholder 先跑通），能跑但会降级的给 **warn + 可执行建议**（如 9s 长镜拆成两条用「续写」接上；缺 turbo LoRA 时换算成「120s/条、本集约 N 分钟」）。入口：制作台「🧩 能力匹配」、`GET /api/render/backend-fit`、MCP `render_backend_fit`、制片 Agent 计划页卡片。**只判断不发请求、不改配置、不花钱** |
| **计费口径配置化 + 预计/实际对账** | `src/billing.js`：口径可配 **按次** 或 **按秒 × 分辨率阶梯**（720p ×1 / 1080p ×1.5…，设置页可改）。估算跟着口径走并给出**换口径对比**（同一集「按次 6 元 vs 按秒 31 元」）；跑完后**对账按真实产出**统计（落库 done 的关键帧/视频条数与时长，提交失败的不算），一页纸报告有「计费口径与对账」章节与逐项差额表，制片页有对账卡片。未配单价时明说「金额 0 不代表免费」，金额差额返回 null 只对账条数/秒数 |
| **队列自动暂停（预算/额度软着陆）** | 月度金额会被这一批突破时，**暂停队列而不是硬跑**：已在跑的任务跑完、排队任务留在队列里等恢复（**不失败、不丢进度、不丢产物**）。暂停状态落库（`jobs:paused`），**重启也绕不过去**；原因写清「本月将达 44 CNY，超过上限 20（已用 0）」并给出下一步（提高上限或清零台账后恢复）。验证方式：`GET /api/queue/state`、`POST /api/queue/pause|resume`；外壳顶栏出现「⏸ 队列已暂停 · 点击恢复」横幅；流水线在暂停期间停在 `queue_paused` 不推进任何阶段；暂停/恢复都进**决策时间线** |
| **Agent 决策时间线** | 把「谁在什么时候做了什么决定」摊成一条时间线（`src/decisions.js`，只读）：阶段生命周期、人工批准与确认码放行、未批准就执行被拒、计划过期/画布改动导致作废、画布快照与回滚、节点与任务失败。每条事件标注**行动者**：`human`（人类决定：批准/驳回/取消/快照）／`agent`（Agent 或 MCP 发起）／`system`（系统自动），汇总给出一句话结论「30 条事件（人类决定 5 · Agent 发起 5 · 系统自动 20），批准放行 2 次、被拒/作废 2 次」。入口：制片 Agent 页卡片、`GET /api/studio/timeline?productionId=|canvasId=`、MCP `studio_timeline` |
| **画布命名快照与回滚（版本化工作现场）** | 整张画布（卡位 / 分组 / 连线 / 视图）可打**命名快照**并随时回滚：`src/snapshots.js` + `GET|POST /api/canvas/snapshots`、`/:id/diff`、`/:id/restore`、`DELETE`；画布工具栏「📸 快照」弹窗可保存 / 看差异 / 一键回滚 / 删除。**破坏性操作（清空画布、铺开分集）前自动留一张 `kind=auto` 快照**；回滚前先算**差异**（多/少/移动/内容变了几张卡、连线增删），回滚本身也会先为当前现场自动留档 —— 回错了还能再退回来。回滚连类型化端口与 `slot` 一起还原；单画布最多 40 张，自动快照优先淘汰 |
| **逐镜缩略轨 + 拖拽调序** | 成片节点里直接画出每个片段的缩略图（服务端 ffmpeg 抽帧 + 按「路径+mtime+size」缓存，`GET /api/render/thumb`），左键拖动缩略图即可改拼接顺序；松手后 `POST /api/canvas/reorder-clips` 把新顺序写回**端口 clip1..N（保持唯一）+ slot 0..N-1**，节点上立刻显示新顺序并提示「成片会按这个顺序拼接」。少给/多给/外来连线/非成片节点一律中文拒绝；缩放 <22%（LOD 简）时不画缩略轨（省性能） |
| **首尾帧运动量量化** | 首尾帧不是同一张图也可能「几乎一样」：出手前用 ffmpeg 把两帧缩成 32×32 灰度算**平均绝对差**（0~1），差异 ≤1% 判「基本没有运动」、<4% 判「变化很轻微」，告警里直接带百分比（`raw.firstLast.distance/level/verdict`）。**本地零成本、零网络**，不依赖任何出图后端 |
| **跨镜角色一致性评分** | 按分镜 `refs.characters` 给同一角色的关键帧分组，算 **8×8 感知哈希（aHash）** 与组内**多数位中位哈希**基准的距离，判定线 `max(阈值, min(0.5, 中位数+3×MAD))`（抗离群统计量），离群镜头列进整集质检报告并给出「只重跑这几镜」的建议；制作台「🧬 跨镜一致性」按钮、`GET /api/render/consistency`、MCP `render_consistency_score` 三个入口。**代理指标、不做人脸识别**：抓「画风/明暗/构图飘」，抓不住同画风换脸；接上真实出图后把哈希换成 embedding 即可，接口不变 |
| **首尾帧过渡 + 视频续写** | 视频节点的 `first`/`last` 两个端口都可用：两帧都给 = **首尾帧过渡**（`placeholder` 用「首帧运镜 → 尾帧」交叉溶解如实表达并在结果里标注 `raw.lastFrame`；`comfyui-h3` 通过字段映射 `lastImageNode` 注入尾帧；`generic-http` 用模板里的 `{{lastImage}}` 回填）。把**上一段的 `clip` 接到下一段的 `first`** = **视频续写**：执行时自动用 ffmpeg 抽上一段的**尾帧**作为下一段首帧（无 ffmpeg 会明确报错）。给了尾帧但后端模板没准备 → 明确报中文错，绝不静默丢帧 |
| **多轨时间线（画面叠轨 / 画中画 / 字幕轨）** | 成片时间线除了 `clip1..clip24` 主轨（V1），还有 **4 条画面叠加轨 `ov1..ov4`** 与 **1 条字幕轨 `sub`**：<br>· **叠加层节点**（`🖼️`）三种模式：**画中画**（按比例缩到角落）、**全屏叠加**（片头/转场/贴纸）、**水印**（整片常驻角标）；可设「出现/消失秒数」时间窗、宽度占比、不透明度、淡入淡出；画面取接入它的上游片段，或直接上传一张图片/视频。<br>· **字幕轨节点**（`💬`）：可上传现成 `.srt`（时间码原样沿用）、手工写时间码行，或接一个文本节点；可选**烧录进画面**或**软字幕轨**（播放器可开关）。比「按台词自动生成字幕」更可控。<br>· 叠加合成**一次 ffmpeg 完成**（不逐轨重编码），时长不变；未产出/文件缺失/端口重复都会给中文报错，**不静默忽略** |
| **音频闭环（音频节点）** | 画布上新增「音频节点」：`🔊 配音（TTS 合成）`/`🎧 已有音频`/`🎵 背景乐` 三种模式。把它接到某镜的**视频节点 `dub` 端口** = 该镜配音（不再重复合成）；接到**成片节点 `bgm` 端口** = 整片背景乐，混音时自动**侧链压低（ducking）**。成片的音轨模式由画布连线决定：有配音+背景乐 → 混音、只有背景乐 → bgm、都没有 → 静音轨；每条决定都会写进成片报告（`audioPlan`）。配音按「台词+音色」缓存，重复执行不重复付费 |
| **成片顺序绝不静默出错** | 成片节点执行前校验「片段数 == 连入端口数」，端口重复或上游缺片**直接报中文错**（例如「时间线有 1 条连线的上游节点还没有产出视频」），绝不「能拼几段算几段」；右键「👁 预览拼接顺序」可先看 dry-run 顺序（每段的端口、时长、台词、文件） |
| **执行历史表** | `canvas_node_runs` 记录每次节点执行（产物、时长、后端、输入指纹、错误），前端「状态」与后端 `GET /api/canvas/node-runs`、`GET /api/graph/status` 可查 |
| **Agent 接口（MCP）** | `node scripts/mcp.js`（stdio JSON-RPC 2.0）或 HTTP `/api/mcp/call`；共 41 个工具（19 只读 / 5 计划 / 6 执行 / 11 改画布），花钱的只有 `canvas_run` / `canvas_run_node` / `studio_resume`，且**都要过审核闸门**。`GET /api/mcp/tools` 可看工具目录 |
| **数据安全** | 撤销（Ctrl+Z）与画布备份/还原都会连同**端口与槽位**一起还原，不会把数据流边退化成普通关系线；审计脚本自动备份/还原，可安全在生产实例上运行 |
| **定时排产（到点自动出片）** | `src/schedules.js` + `/api/schedules*`：一次 / 间隔 / 每天 / 每周 / 每月 / cron 六种触发规则（含时区、宽限期、漏跑补跑策略、幂等去重、暂停与预算联动），到点自动**新建制片项目**或**推进已有项目**。制作台工具栏「⏰ 排产」弹窗可**列出 / 新建 / 启停**，并用「🔎 试算」零成本预览未来 3 次触发时刻（`POST /api/schedules/preview` 是 dry-run，不落库、不入队）；单条还有「触发历史」（`GET /api/schedules/runs`）与「⏩ 手动触发一次」（`POST /api/schedules/:id/trigger`）。**定时器只负责到点提交**，付费阶段的人工批准闸门与队列暂停/月度预算/磁盘闸门一条都不绕过 |
| **阶段失败自愈（换后端重跑一次，并如实告知）** | `src/self-heal.js` + 制片 Agent：**只在「视频生成」阶段失败**且错误属于**可自愈类别**（限流 429 / 5xx / 网络 / 超时）时动手 —— 先同后端重跑一次，仍失败才沿**单向降级链**（`comfyui-h3 → generic-http → placeholder`）换后端再跑一次；审核 / 鉴权 / 额度 / 参数 / 未知一律不自愈，给中文原因与建议交人。结果与阶段 `artifact` 写明 `degraded: true`、`from`/`to` 后端与**中文告知**（损失能力、保留能力、费用口径、一集内一致性、需人工复看），换前先落账 `selfheal_events`（同一阶段同一后端**只换一次**，跨重启生效）。安全边界：换后端只改该视频节点的生成后端，**绝不替人放行任何计划**，也不改既有函数签名 |
| **画布类型筛选 + 多选批处理** | 画布工具栏「🔎 类型筛选」：按**类型（可多选）/ 分组 / 有无产物 / 是否失败 / 是否锁定**五维筛选（维度内 OR、维度间 AND，可整体反选），命中项一键**选中并框入视口**（只筛选与选中，不删除任何节点），当前筛选还会被「⇄ 多选批处理」沿用。「⇄ 多选批处理」对选区或筛选命中项批量执行 **移动 / 缩放 / 成组 / 锁定 / 解锁 / 移出画布 / 按类型重跑**：判定、中文文案、危险动作**二次确认**、主画布保护、`stale` 计划复核全部来自 `web/lib/canvas-select.js` 的纯函数（界面与测试同源），界面只按纯数据里的 `effects` 顺序发请求；「按类型重跑」这类付费动作只生成执行计划，放行仍走「🧭 执行计划」的人工批准 + 终端确认码 |

**画布上按 slot 顺序拼片的最小闭环**（离线可跑，用本地 ffmpeg 占位视频）：

```text
[关键帧 1..17（出图节点）] ──image──▶ [视频片段 1..17] ──clip1..clip17──▶ [成片时间线] ──film──▶ [交付终点]
        ▲                                                                        │
   [演员/环境/物品/参考图 素材节点] ──image/ref──▶ 组合出图                    整集 mp4（字幕/音轨/淡入淡出）
```

> 实测一（无声成片）：演示剧本 `SC-0002` 的 S01E001（17 镜）在专用画布上铺开后，计划显示「35 个节点、17 次出图 + 17 次视频、成本级 H」；人工批准 + 确认码通过后，**35/35 节点全部完成**，产出整集成片（60s，静音轨，实测 −70 LUFS）。
>
> 实测三（多轨）：在同一张画布上再接一个「🖼️ 水印」叠加层（`overlay → ov1`）与一个字幕轨（`subtitle → sub`）→ 计划只跑 3 个节点（叠加层 + 字幕轨 + 成片，其余 36 个节点自动跳过，成本级 L）→ 批准 + 确认码后重出成片：60s、带左上角半透明水印、底部烧录字幕「你终于来了。」（抽帧核对）。
>
> 实测二（音频闭环）：在成片节点上再接一个「🎵 背景乐」音频节点（指向已上传的音乐）→ 执行计划**只跑 2 个节点**（背景乐 + 成片，其余 35 个节点产物未变自动跳过，成本级 L）→ 批准 + 确认码后重出成片，实测响度 **−40.8 LUFS / 峰值 −35.6 dB**（同一条片从「静音」变成「有背景乐」，且人声处自动压低）。

### 自动化制片 Agent（一句话需求 → 成片 + 交付包）

把前面所有模块串成一条**可断点续跑、花钱必须人工批准**的流水线：给一句话需求，Agent 自己走完十个阶段，产出成片、质检报告与交付包。

| 阶段 | 付费 | 做什么 |
|------|------|--------|
| 需求解析 | — | 一句话 → 集数 / 每集秒数 / 比例 / 画风 / 题材或基调 / 角色数 / 目标字数（模型解析失败自动回落离线规则，中文数字也认） |
| 建演员 | — | 按参数生成演员档案（姓名/外形/人设/音色），离线用字典模板 |
| 小说与大纲 | — | 建小说 + 故事框架 + 分章大纲 |
| 剧本与分镜 | — | 建剧本 → 分集规划 → 逐集分镜（纯英文提示词） |
| 画布铺开 | — | 每集铺成「关键帧 → 视频 → 成片时间线」节点图（**只布局不生成**） |
| **关键帧出图** | 💸 | **停下等人工批准** |
| **视频生成** | 💸 | **停下等人工批准** |
| 整集成片 | — | `clip1..N` 拼接 + 字幕/音轨/叠加轨，并**等成片真正产出** |
| 成片质检 | — | 逐集黑帧/静音/响度/流/时长检查 |
| 交付包 | — | zip（成片 / 字幕 / 分镜表 / 素材 / EDL / 报告 / 质检） |

**两条硬红线**：① 花钱阶段绝不自跑 —— 走到关键帧/视频就生成一份 P4 计划并停下，必须「人工批准 + 输入只打印在服务端终端的确认码」才放行（连 `studio_resume` 工具自己也要确认码）；② 阶段幂等 —— 已完成的阶段自动跳过，失败可从该阶段续跑，不重复干活、不重复花钱。

**用法**：界面上「🎬 制片 Agent」页一句话 + 高级参数 → 生成生产计划 → 开始执行 → 到付费阶段按提示批准并填确认码 → 继续 → 下载交付包。Agent 侧有 5 个 MCP 工具：`studio_create` / `studio_status` / `studio_run` / `studio_run_stage` / `studio_resume`。

> 实测（全程离线零成本，`tests/test-studio.js` 141 项）：4 位演员 → 小说 + 10 章大纲 → 2 集剧本 + 12 镜分镜 → 画布 12 关键帧 / 12 视频 / 2 成片节点，**免费阶段全程零生成调用**；`run` 停在关键帧且**执行记录 0 / 新任务 0**（未批准绝不生成的反证）；未批准用码、批准但码错都被拒；批准 + 正确码后跑完；成片登记 `episode_films`、逐集质检 `pass`、交付包 23 个文件 0 缺失；再次 `run` 全部跳过。

## 三、配置

界面右上角「⚙️ 设置」（写入 `config/config.json`）：

- **文本生成 LLM**：默认 DeepSeek（`https://api.deepseek.com` + `deepseek-chat`），Key 会依次从 `config.json` → 环境变量 `DEEPSEEK_API_KEY` → `~/.dsh/.credentials.yaml` 读取；也可切任意 OpenAI 兼容端点；没有 Key 时可切 `mock`（离线模板）跑通流程。
- **出图后端**（4 选 1）：
  | 后端 | 说明 |
  |---|---|
  | `placeholder` | 本地占位出图（渲染含 ID/类型/提示词/负面词的 SVG 定妆卡），无需任何外部服务，开箱即用 |
  | `generic-http` | **通用 HTTP 模板**：把厂商文档里的请求体照抄进模板、把响应里图片位置写进「响应图片字段路径」即可；支持 `${prompt}/${negative}/${width}/${height}/${seed}/${model}/${refImage}` 变量、base64 或 URL 取图、异步任务轮询、参考图回填 |
  | `openai-images` | OpenAI 兼容 `/v1/images/generations`（参考生图自动走 `/v1/images/edits`） |
  | `comfyui` | ComfyUI（本地/云端 API 模式），配置工作流 JSON 路径 + 节点映射 |

「🧪 测试出图」「🔌 测试连接」可一键验证链路。

- **视频后端**（模块 4 用，3 选 1）：
  | 后端 | 说明 |
  |---|---|
  | `placeholder` | 本地 ffmpeg 运镜（默认，开箱即用，把关键帧做成推/拉/摇/移等镜头的 mp4） |
  | `comfyui-h3` | 云端 ComfyUI + MiniMax H3：填实例地址即可（**工作流路径留空 = 用内置官方 H3 模板**：有关键帧走首帧驱动 i2v，无则文生视频 t2v）。可选 `preferKeyframe`（首帧优先）/ `useTurbo`（4 步加速）/ `megapixels`（分辨率）/ `preflight`（提交前预检）/ `videoNode`（视频节点 id）/ `map`（节点映射）。设置页有「探测」按钮：一次返回显卡显存、节点校验结论、模型缺失清单、是否支持首帧、turbo LoRA 是否可用，实例 503 会明确提示「正在启动 / 已释放」 |
  | `generic-http` | 任意厂商视频 API 模板（请求体模板 / 响应视频字段路径 / 异步轮询） |

## 五、边界与下一步

- **真实出图需自备接口**：内置的 `placeholder` 只保证流程闭环；接上任意出图 API 后，画布封面、素材库、参考生图基准会自动换成真实画面。
- **LLM 预算**：小说大纲单次 ≤200 章（每批 20 章）、剧本分镜默认每集 ≤4 次调用，超限自动降级为离线规则并在 `warnings` 里中文提示；100 集全量建议逐集生成。
- **镜头上限**：每集默认 ≤200 镜（电影长片可在 `scripts.options` 调整），超限会拉长单镜时长并告警。
- **视频**：模块 4 已打通「关键帧 → 视频 → 整集成片」。默认用本地 ffmpeg 运镜占位；接上云端 MiniMax H3 或任意视频 API 即为真实 AI 视频。ComfyUI H3 链路（内置两套官方工作流 + `/object_info` 预检 + SVG 光栅化上传 + turbo 加速 + 超时中断 + 尾帧节点映射）已有 68 项离线自检覆盖，**只需在「设置 → 视频」填一个可用实例地址即可开跑**；实测可用的云实例会给出显卡与节点校验结论，地址失效时探测会提示「正在启动 / 已释放」并需要换新地址。
- **全模块可离线复现**：`node scripts/simulate-all.js` 用临时库把「演员 → 画布 → 小说 → 剧本 → 关键帧 → 视频 → 整集成片 → 资产桥」整条链路跑一遍（83 项断言 + ffprobe 校验），报告落在 `docs/全模块功能模拟测试报告.md`；`./scripts/verify-all.sh` 已把它登记为**第 21 个阶段**（脚本里的阶段标题是 `21/35 全模块端到端模拟…`）。
- **真实拉通的唯一缺口**：出图（关键帧）仍需你自备出图 API；关键帧是真实的，H3 图生视频的画面一致性才成立。占位 SVG 关键帧虽能自动光栅化喂给 H3，但成片只会是「占位卡在动」。
- **长篇成本**：1000 万字量级的小说是分章多次调用的工程，建议先跑小规模（10–20 章）验证设定与文风，再批量开跑。
